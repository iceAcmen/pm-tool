## C1 台账对模型的三条可见性路线

**核心主张**：让对话里的模型不经过人转述就能知道台账现状，存在三条互不相同的路线（常驻注入 / 按需拉取 / 文件零代码），且都必须回答"占多少上下文预算"。

**成员**：
- push 常驻注入：D1-02、D2-01、D4-04、D5-03、D3-11（台账即 AGENTS.md 持久上下文）、D1-R3-14（台账先生成今日台词脚本推给会话）
- poll 按需：D3-21（问"当前项目"才喂快照）、D2-02（台账渲染成按需加载的 PM skill）、只读工具族 D1-01、D2-07、D3-01、D4-01、D5-01
- 文件零代码进上下文：D2-06（PROJECTS.md 借 AGENTS.md）、D5-13（静态 pm-board.md）、D4-R2-18（带有效期戳的 AGENTS.md 看板）
- 预算治理与认知安全：D1-32（注入字节预算）、D1-R3-13（自适应水位，主任务紧张时让位）、D1-R3-12（台账侧事件触发主动亮相）、D1-R3-11（反向：模型工作状态推回台账）、D1-R2-12、D2-R2-10、D3-R2-09、D4-R2-11、D5-R2-09（注入摘要新鲜度戳/置信降级/模型说法与台账对账，防陈旧当真相）

**边界**：只处理"模型怎么读到台账"，不含任何写动作（归 C2），不含人在面板/聊天里看到的渲染（归 C12）。
**重叠**：D1-R3-01（反向工具 `pm_absorb_promises` 由台账主动读会话）与 C4 捕获同源；D4-R2-18 的有效期戳与 C14 新鲜度/档案重叠。
**内部张力轴**：push 常驻 vs poll 按需 vs 文件载体；固定字节预算 vs 自适应水位；台账→模型 vs 模型→台账（D1-R3-11）。

**核心主张**：单人单写者下，"每笔动作弹审批卡"与"agent 全自主"是光谱两端，中间存在"窄白名单自批 + 事后审计抽查 + 可撤销事件流"的成立带；真源方向也可以从台账翻到会话。

**成员**：

**边界**：回答"谁能动笔、笔落多宽、谁事后核"；任务够不够格算完成归 C6；会话载体的纯展示性绑定归 C10。
**重叠**：D1-R3-05/07 与 C10 的 todo/goal 结存共享机制；D1-R3-04 与 C6 审计共享 subagent。
**内部张力轴**：全只读逐笔审批 ↔ 窄白名单直写+事后撤销 ↔ 规则自批 ↔ 全自主；台账为真源 ↔ 会话为真源。
