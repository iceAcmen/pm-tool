# 视角扫描清单（仅作「漏没漏」质检表 · 严禁作为结论框架或聚类中心）

> 用途：阶段1 质量门与阶段2 覆盖说明时，逐条扫描想法池是否有空白；空白要区分「真没有（在该维度有明确理由不产生想法）」还是「没想到」。
> 纪律：本清单只用于查漏，不得用于组织想法、不得在发散开始前展示给发散者。

## 1. 角色维度
- 个人贡献者 PM（自己盯执行）
- 团队 Leader / 跨团队协调者（盯别人、对上汇报）
- 被服务的工程师（任务落到其 Git/MR，不登录本工具）
- 个人开发者 / 独立软件创始人（离职后身份）
- 未来其他用户、开源受众、被汇报者（上级/客户）

## 2. 时间尺度
- 实时（对话进行中的当下）
- 日/周（站会、周报、临期提醒）
- 季度（里程碑、绩效、阶段复盘）
- 年（多个项目、人员成长）
- 跨年（10 年数据资产、平台更替）

## 3. 数据流向
- 宿主 → 插件（会话/上下文/证据流入台账）
- 插件 → 宿主（台账进入模型上下文/工具/卡片）
- 双向（状态绑定/同步）
- 插件 → 外部系统（Git/MR/群/日历/文档）
- 外部系统 → 插件（执行证据回流）
- 无流（刻意隔离、纯文件）

## 4. 抽象层次
- 数据/存储层（文件格式、schema、事件、投影、版本）
- 能力/工具层（模型工具、命令、后台任务、MCP、技能）
- 事件/生命周期层（订阅、订阅、触发、定时）
- 上下文/认知层（模型可见性、记忆、压缩、注意力）
- 交互层（对话卡片、业务节点、面板、审批、通知）
- 工作流层（多步编排、HITL、跨会话续行）
- 产品形态层（插件、独立应用、MCP server、协议/文件格式、无头内核）
- 分发/商业层（开源、收费、bundled profile、合规计费）

## 5. 融合深度谱系（检查轴，不是评分）
- 完全隔离 / 刻意无连接
- 现状命令字符串通道
- 宿主 → 插件的单向只读
- 插件 → 宿主的单向事件广播
- 模型只读工具（台账可见不可写）
- 模型可起草 + HITL 确认落库
- 双向状态绑定 / 生命周期联动
- 共享内核 / 数据模型合一
- 身份倒置：插件变成被任意客户端消费的服务（MCP server）
- 离开平台：独立应用 / 纯开放文件 + 任意前端

## 6. 学科视角（事后查漏，非发散框架）
- 认知科学：注意力、工作记忆、长期记忆、认知负荷、外部认知
- 人因/交互设计：模式切换成本、可见性、反馈、防错
- 组织社会学：角色边界、仪式（站会/周报）、问责与可追溯
- 经济学：成本结构、转换成本、锁定、激励相容、公地
- 系统论：反馈回路、边界、耦合/内聚、涌现
- 控制论：可观测性、可控性、前馈/反馈、稳态
- 信息论：信号/噪声、溯源、保真、熵
- 演化论：变异-选择-保留、可进化性
- 委托代理/博弈论：自主权、信任、道德风险、人对 agent 的授权

## 7. 触发方式
- 人主动触发（命令/面板/对话）
- agent 主动发起（循环内）
- 事件驱动（领域变更/会话事件/git 事件）
- 定时（schedule）
- 外部 webhook/钩子
- 无触发（静态、只读、按需）

## 8. 生命周期与归属
- 会话内短命状态（agent 拥有）
- 项目周期（跨会话，人拥有）
- 跨项目（人员/组织/模板）
- 跨年（档案/资产）

## 9. 极端/反常识区（必须显式扫一次）
- 零融合甚至零宿主依赖
- 完全吞并：pm-tool 内化宿主全部能力
- 反向：宿主成为插件（pm-tool 成为 dsh 的项目管理后端）
- 无界面（纯文件/纯 CLI/纯对话）
- 无 agent（彻底离线工具化）
- 多宿主（同一内核跑在 dsh / Claude Code / Cursor / 其他）
- 台账成为模型操作系统的一部分（模型默认读项目）
- 让项目数据反过来管理 agent（给 agent 派活、考核 agent）
- 废弃本产品 / 被宿主原生能力替代的诚实讨论
