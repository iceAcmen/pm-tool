## A. 补漏（稀疏区新想法）

### D5-R2-01 估时校准 + what-if 日期情景模拟（补 A1：面向未来的规划智能）

- **机制**：任务在现有 `effortHours`（实际工时，已落地）旁加一个可选 `estimateHours`（开工前估的）；完成后本地统计「估/实偏差」按任务类型（拆解自标题/优先级）滚动出个人偏差基线；另做一个纯算术的 what-if 面板：拖动某任务的 dueDate，即时重算下游里程碑偏移与关键链 slack（复用 ADL-051 只读 CPM），只给「若 X 滑到 D 日，M2 将顺延几天」的数字，不做黑箱概率预测、不自动改期。
- **具体场景**：PM 估「登录风控 4h」，实际填了 9h；三个月后面板显示「同类联调任务平均高估 2.1 倍，下次可乘 2」；排期会上 PM 把某任务拖到下周三，面板立刻显示「M2 slack 从 3 天压到 0，进入关键链」，PM 自己决定要不要调。
- **触点**：纯本地派生（新增可选 estimateHours 字段、加法式 schema）；复用 `criticalPath(tasks)`（ADL-051，ES/EF/LS/LF/slack 已存在）、`effortHours`（task.ts L66）；不接模型、不预测。
- **来源观察**：池子几乎全是状态记录与回看（completedDate/completion-history/report-diff），无人碰开工前估时与向前模拟；task schema 只有实际工时无估算（changelog v0.7.4 补的是 effortHours 非 estimate）；ADL-051 明确把「自动排期/资源平衡」列为长期观望，what-if 只读模拟正好落在它划出的缝里。

### D5-R2-02 项目模板库 + 组合取舍视图（补 A2：项目组合层）

- **机制**：把一个结项项目「另存为模板」：只存 WBS 骨架（层级/标题占位/里程碑槽位/高发风险清单/交付物类型），不存人名与日期；新项目可从模板实例化，骨架落地后再改。组合层增加一个跨项目派生视图：按人汇总在手任务数、按季度汇总各项目健康灯与里程碑密度，给「这个季度是否同时开太多」的取舍参考数字，不自动砍项目。
- **具体场景**：做过三次「官网改版」后存成模板；第四次开新项目时一键带出 12 条骨架任务、3 个里程碑槽、4 条历史高发风险（如「第三方限流」）；组合视图显示「赵六手上 9 条、3 个项目同时有 at_risk 里程碑」，PM 自己判断推迟哪个。
- **触点**：现有 project/task/milestone/risk/deliverable 实体；模板存为独立只读 JSON（不进运行时七表或作为特殊 projectKind）；people-load.ts 聚合范式扩到跨项目。
- **来源观察**：池子无项目复用/模板概念（D2-17 dogfood、D1-29 方法论 skill 都是单次使用）；requirements 无模板实体；11 号协作契约已把 projectId 当真实归属边界，跨项目视图是现有数据的自然扩展。

### D5-R2-03 【反向写外部】经外部 MCP 把台账任务建成 issue / 卡片 / 日历事件（补 A3：从台账写向外系统）

- **机制**：与 D1-11/D2-30/D1-09 的「只读拉外部证据」反向——配好外部 MCP（GitHub/Jira/飞书项目/日历）后，台账任务可经 MCP 工具**创建**外部 issue/卡片/日历事件，结果回写任务的 `repoUrl/branch/evidenceUrl` 作为双向链接；创建动作仍是草稿→人确认→执行，外部系统失败回滚草稿、不留半截。
- **具体场景**：PM 在任务抽屉点「建到 GitHub」，草稿卡显示「将在 repo X 创建 issue《登录风控》，正文含验收清单」，确认后 issue 生成、任务上记下 issue 编号链接；里程碑目标日期可一键建成团队日历事件，团队在自己日历里看到排期。
- **触点**：`packages/mcp/mcp-client`（调外部 server 的写工具；现状池子里只用来读）；任务现有 repoUrl/branch/evidenceUrl 字段；草稿确认制复用 ask-apply 链路。
- **来源观察**：池子里外部系统全是只读回流（D1-09 webhook 读 PR、D1-11 读证据、D2-30 只读 GitHub），无一条向外写；D1-21 只导出 iCal/CSV 文件让别人消费，不等于主动建事件；UX-11「台账↔Git/Jira 两张皮」目前只在证据侧修补。

### D5-R2-04 会中实时捕获槽：边说边落候选，而非会后粘贴归纳（补 A4：会议实时辅助）

- **机制**：会议进行中，面板/侧边开一条常驻「捕获槽」：PM 边听边敲关键词或点选「决议/行动项/风险」标签，输入即进临时队列；会末不用从头归纳，队列里已是结构化候选，逐条 confirm 成 meeting 决议/行动项；支持拍白板照即贴（接 D3-18 附件）；全程不落正式库直到会末确认。
- **具体场景**：站会 15 分钟，PM 在捕获槽里敲「张三：周五前交登录接口｜风险：第三方额度未定」，随手拍白板照贴上；会末点「收尾」，队列两条已被预填好负责人/日期，PM 改两个字定稿，而不是会后对着空白纪要框回忆。
- **触点**：现有 meeting 实体 + meeting-summarize 解析纯函数（改为吃实时队列而非粘贴文本）；attachment 白板照；临时队列只在面板内存/草稿箱。
- **来源观察**：现状 R8 纪要、R15 归纳全是「会后粘贴速记/文件→模型归纳→confirm」（meeting-source 三来源：粘贴/文件/历史会议），会中那一刻是空白；池子里 D2-16/D1-25 是会后从会话日志抽，都不是会中。

### D5-R2-05 从 Jira / 飞书项目 / Excel 迁入与共存（补 A5：迁入与共存）

- **机制**：除现有 csv/markdown 导入外，提供 Jira 导出 CSV、飞书项目导出、多列 Excel 的结构映射器（列名→字段的可配置映射表，模糊匹配 title/assignee/dueDate/status），导入走 jobs 后台预览→confirm；共存模式：导入后保留外部链接字段，定期「对账」显示外部已关闭而台账仍 open 的漂移，不做实时双向同步。
- **具体场景**：离职前从老 Jira 导出 CSV，映射「Summary→title、Assignee→assignee、Due→dueDate」，预览 87 条、跳过 3 条重复后落库；两个月后对账视图列出「Jira 已 done 但台账 open 的 5 条」，PM 选择同步状态还是保留台账口径。
- **触点**：现有 csv-import.ts/task-import.ts 预览→confirm 链路；jobs 后台（D1-30/D3-23 已提批量导入后台化，本条补的是**外部格式与对账**）；纯本地文件读取，不直连 SaaS。
- **来源观察**：池子里 D1-30/D3-23 只讲「大批量导入走后台」，未讲来源格式与共存漂移；requirements R4 导出已支持，导入侧只有 csv/markdown；11 号契约刻意不做多人实时协作，对账视图比双向同步契合单写者红线。

### D5-R2-06 离开电脑：手机只读看板 + 文字确认回写通道（补 A5：移动端/离机场景）

- **机制**：借本地 MCP server（D2-27/D3-15/D4-20 已提被手机连）或一个极简 HTTP 只读端点，手机浏览器打开本项目健康灯/逾期/今日行动项；确认类动作（勾完成、批准草稿）通过一条经 dsh SDK/消息通道回传的文字指令完成，不做手机端全功能编辑。
- **具体场景**：通勤路上 PM 在手机上看到「2 条逾期、1 条待批草稿」，回一条「t-0007 完成」，到家打开 dsh 已落库；复杂编辑仍回电脑做。
- **触点**：本地 MCP server 只读工具面；`sdk`（D1-31 已提 JSON-RPC 借模型，本条补指令回写）；手机不直连 Coding Plan key（只读不调模型）。
- **来源观察**：D3-08/D2-27 只顺带提了一句「手机浏览器看静态看板」，无回写通道；billing plan 个人开发者成本敏感、场景多为单机；现状 dsh Web 只信任本机 loopback（KB-014），手机无原生入口。

### D5-R2-07 持续只读状态页：给领导/客户自助看的活看板（补 A6：对外持续形态）

- **机制**：与 D4-21「一次性静态 HTML 导出」不同，起一个本机只读 HTTP 端点（自己的极小 http 服务或 webServer 路由），按项目暴露一个免登录只读页面：健康灯、里程碑时间线、本期完成曲线、风险摘要；每次打开实时读当前台账（只读、无任何写控件），可局域网访问或临时生成带过期的分享链接。
- **具体场景**：领导每周不问 PM，自己打开那个地址看「官网项目绿灯、M2 已完成、本周完成 6 条」；页面数据永远是最新快照，PM 不用每周手动导出发邮件；客户侧只暴露指定项目、隐去内部风险细节。
- **触点**：本地只读 HTTP（注意 dsh Web 只信任 loopback、无局域网远程，故需自己的服务或临时隧道）；现有派生视图（health/reminders/completion-history）；只读不接模型。
- **来源观察**：D4-21 是导出瞬间快照发出去即脱钩；池子里无「持续可自助访问」形态；KB-014 指出 dsh Web 无局域网远程，对外分享现状无路，这正是状态页要解的。

### D5-R2-08 角色化 PMO 班底：风险官 / 史官 / 催办员 / 调度员四个常驻只读角色（补 A7：多智能体角色分工）

- **机制**：区别于 D4-18 一次性巡检、D4-28 虚拟 assignee、D5-07 单项目常驻副驾，设四个**角色固定、职责互斥**的轻量子代理，各自只产出指定类型草稿汇入同一个「收件箱」：风险官（每日扫概率×影响矩阵，只提新风险/升级建议）、史官（归档会议决议、周报定稿、结项提炼）、催办员（只整理「到点未动」清单，不发打扰）、调度员（只推演排期冲突与负载，不改日期）；人在收件箱统一批。
- **具体场景**：周一早上收件箱有四张卡片：风险官「R-0002 概率应上调为 high」、史官「上周 3 场会议决议已归档待确认」、催办员「2 条逾期 3 天未动」、调度员「M2 与 M3 资源撞车」；PM 一次清空，角色各自不越权。
- **触点**：subagent-spawn-in-process（按角色喂不同 system 边界）；只读工具面；provenance 账本记每条建议的角色来源；角色清单本身可在设置里开关。
- **来源观察**：池子的多智能体想法都是「一个通用子代理干一次」（D3-22 巡检、D4-18 审计、D5-07 常驻副驾、D4-28 仿真人），无角色分工与职责互斥；R4 主体存疑，但角色班底把「为什么要多个 agent」拆成了四个具体职责问题逐个验。

### D5-R2-09 认知安全：新鲜度戳、置信降级、模型说法与台账自动对账（补 A8：注入数据过期/误导）

- **机制**：所有注入模型的台账摘要/工具返回都带「快照时刻 + 距今天数 + 未覆盖实体数」三个元数据；模型回答引用具体记录时必须带记录 id；面板提供「对账」动作：把模型刚说的（如「t-0003 已完成」）与台账当前值逐条比对，不一致即标红；陈旧摘要（如超过 N 天未刷新）在上下文里自动降级标注「可能过期，需重查」，禁止模型把草稿当已落库事实。
- **具体场景**：模型基于两天前的注入摘要说「风险已关闭」，对账视图显示「台账里 R-0002 仍是 open，模型说法与现状不符」；草稿里被确认前的动作一律显示「未应用」徽标，模型不得声称已改。
- **触点**：buildAskContext（ask-copilot.ts）扩展元数据头；只读工具返回包一层 freshness envelope；provenance 账本的 applied/pending 状态作对账来源；纯本地。
- **来源观察**：D1-32 只讲注入预算/不挤压窗口，未讲数据过期与错误呈现；provenance-store 已有 confirmed/pending/applied/conflict/failed 状态，正是对账原料却没被用于「模型说法 vs 现状」校验；R2 机器可操作性的背面就是误导风险。

### D5-R2-10 仪式与疲劳治理：晨会三行、建议合并配额、草稿箱自动过期、提醒聚合（补 A9：行为/仪式层与失败模式）

- **机制**：正面定义仪式：每天首次打开面板生成「三行晨会」（今日到期/逾期/待批各取 Top），周报/站会有固定模板位；反面设计失败模式：建议合并（同类诊断气泡一轮只出一条，不刷屏）、建议配额（每会话最多 N 条、超了进折叠区）、草稿箱 TTL（7 天未确认的草稿自动归档并提示）、提醒聚合（N 条同类提醒合成一条「共 5 条逾期」而非 5 条通知）。
- **具体场景**：早上面板只有三行，不被 20 条建议淹没；一周后回草稿箱看到「3 条未确认已归档」，不会被旧草稿垃圾淹没；逾期提醒只在晨会出现一次，不整天弹。
- **触点**：现有 suggestion-engine（诊断气泡 kind 五类，D5 池里已存在）加合并/配额规则；reminders.ts 聚合；纯面板行为，不接宿主推送。
- **来源观察**：D1-24 是「极致沉默」的哲学极端，D4-26 同方向；但无人正面设计「建议疲劳/提醒噪音/草稿垃圾化」的具体失败模式阈值；ADL-039 打开即派生 + suggestion-engine 已经是建议源头，缺的是节流机制。

### D5-R2-11 【极端】完全吞并：pm-tool 内化自己的 agent runtime，dsh 对话循环被取代（补 A10 上半）

- **机制**：走到另一极端——pm-tool 不再借 dsh 的对话循环，而是内置自己的执行循环（自带 prompt 装配、工具调用循环、审批中断），dsh 只提供模型通道与存储；面板本身就是工作台，台账驱动的动作在面板内闭环，主对话沦为可选。
- **具体场景**：PM 不开 dsh 聊天窗口，在 pm 面板里直接让内置循环「把逾期任务重排、给我草稿」，循环在面板侧跑完、逐条批准；dsh 的 agent loop 与 pm 互不干扰。
- **触点**：反向于 D2-15（面板嵌对话），本条是面板自带循环；模型通道复用 LlmGateway（ai-client.ts）；存储仍走 PmDomain。
- **来源观察**：池子里融合方向全是「pm 进 dsh loop」（D1-01/D4-01 只读工具注册进宿主 loop）；无人考虑 pm 自己长一个 loop；R5 平台存在性的最激进形态即自我闭环。

### D5-R2-12 退出协议：dsh 原生长出项目管理能力时，本产品如何让位（补 A10 下半：被替代路线）

- **机制**：预先写好一条「退场路径」：检测宿主原生长出项目/任务能力时，pm-tool 转型为「导入器 + 审计器」——把本地台账一键映射成原生实体（迁移工具），并继续作为独立审计/历史层留在旁边；插件本身不与原生功能竞争，版本号停止加功能只修迁移。
- **具体场景**：两年后 dsh 原生带了任务面板，PM 点「迁移到原生」，七实体按字段映射过去，pm-tool 转为只读历史档案 + 迁移校验器；不存在「两套功能硬打」的尴尬。
- **触点**：现有 export/backup 格式作为迁移中间格式；11 号契约的开放字段位；不依赖宿主未来 API（迁移器按当时原生格式另写）。
- **来源观察**：池子全部假设 pm-tool 长期存在，无「宿主原生替代」预案；R5 平台存在性问的是离开 dsh，本条问的是被 dsh 吸收；开源/插件市场（D5-R2-13）也需要退场叙事。

### D5-R2-13 开源治理 / 插件市场发布 / 定价 / 「PM 方法论即产品」（补 A11：商业分发层）

- **机制**：三条并列分发路线：① 开源治理——core 以宽松协议公开、贡献者指南、版本/changelog 透明，单人先自用后公开；② 插件市场——按 dsh 插件打包规范（D2-28 已提 npm 包）发到可发现市场，profile 示例、截图、一句话定位齐备；③ 定价分层：内核/命令/离线 CRUD 免费，模板包、检查单、评分公式、汇报模板作为付费「方法论包」；卖点不是工具而是「一套被用过的 PM 做法」。
- **具体场景**：别人在插件市场搜到「单人 AI 项目管理台」，免费用核心，付费 9.9 买「独立开发者项目模板包 + 周报复盘模板」；方法论（怎么拆 WBS、怎么登记风险）与软件分离可单独卖。
- **触点**：D2-28 npm 包发布；D1-29/D3-16 方法论 skill 可商品化；personal-billing-plan 的成本红线（C2 免费额度、标准 API 计费）决定付费层不能烧模型。
- **来源观察**：池子商业层只有 D4-24（独立应用标准 API）、D5-23（留在 dsh 是合规选择）、D1-26（单机可读当卖点）；无开源治理/市场/定价/方法论产品化；requirements 与 billing plan 均未谈分发。

## B. 杂交（新机制，非并列）

### D5-R2-14 杂交 D4-05（workspace-changes 证据自动采集）× D2-12（全新 subagent 独立验收审计）

- **新机制**：D2-12 的审计员只喂标题+快照，D4-05 只回挂文件清单；杂交后：审计 subagent 启动时直接带上本轮真实 diff 片段与 present 产物清单，让它判断「证据是否足以支持完成」，结论引用具体文件/hunk 而非泛泛而谈；审计意见本身回挂为证据草稿，PM 确认后才标完成。
- **具体场景**：PM 想标 M1 达成，审计员不再只说「1 条任务无证据」，而是指出「t-0003 的 diff 只改了样式、未触及验收清单第 2 条要求的接口，证据不足」，并把对应 hunk 片段附在审计报告里。
- **亲本**：D4-05（session/event 聚合成 workspace-changes 证据草稿）× D2-12（全新进程内子级独立验收审计，无父历史）。
- **触点**：`ctx.workspaceChanges.summary/diff`；subagent-spawn-in-process 喂 diff 文本；provenance 记审计来源。
- **新在哪**：亲本一个只采证据、一个只看标题；杂交让审计结论建立在客观 diff 上，形成「采集→独立评判→回挂」闭环。

### D5-R2-15 杂交 D3-13（任务反向开工建会话）× D4-27（台账考核 agent 会话）

- **新机制**：D3-13 开工时自动把任务号写进会话初始上下文与会话元数据；会话结束后自动聚合该会话的轮次、workspace-changes 文件量、present 产物、feedback 评分，生成一份「本次执行报告」草稿回挂任务——把「任务发起会话」和「会话被台账考核」接成双向自动链，无需人工绑定。
- **具体场景**：点「开工」建的会话结束，任务抽屉自动出现执行报告草稿：「本次 8 轮、改 6 文件、完成清单 3/4、评分 4/5」，PM 确认后补进证据区；哪个任务空转（轮次多但零改动）自动标可疑。
- **亲本**：D3-13（抽屉点开工自动建会话带上下文）× D4-27（把 agent 会话当被跟踪资源、统计轮次/文件量/评分）。
- **触点**：sessions.create() 绑定 taskId 元数据；session-query + workspace-changes + feedback；执行报告草稿落任务 evidenceUrl。
- **新在哪**：亲本一个只管发起、一个只管事后统计；杂交让「发起→执行→被考核→回挂」自动成环，任务与会话的绑定不再靠人工挂关键词（对照 D2-19）。

### D5-R2-16 杂交 D1-24（打开时的差异回顾）× D4-30（备份目录即版本链 + 相邻 diff）

- **新机制**：D1-24 的「你不在的这段时间变化了什么」不再用内存快照对比，而是直接接 D4-30 的自动备份链，把上次打开时点对应的备份副本与当前台账做相邻 diff，差异回顾按实体分组（新增 N 任务/改了 K 字段/关了 M 风险），点开即看每处前后值；没开过备份链也能退化为内存对比。
- **具体场景**：两周没开，再打开首页就是一页基于备份链 diff 的「期间变更回顾」，而不是空白看板；误操作后可直接在同一页看到变更并回退到某份备份。
- **亲本**：D1-24（极致沉默、只靠打开时差异制造回顾）× D4-30（自动时间戳副本 + 相邻副本 diff 视图）。
- **触点**：core/backup.ts 自动副本；相邻 diff 复用 report-diff 口径；纯本地。
- **新在哪**：亲本一个有回顾哲学但无历史来源、一个有版本链但无主动呈现；杂交让沉默回顾有了客观 diff 地基。

### D5-R2-17 杂交 D1-29（PM 方法论 skill）× D4-19/D2-14（WBS 编译成 workflow DAG）

- **新机制**：方法论 skill 在 DAG 编译前加一道「可行性门」：skill 里写明哪类项目（调研/可并行叶子多/验收客观）适合扇出、哪类（强依赖串行/需人判断）禁止编译；编译前先过这道门给出「本项目扇出适配度」判断，不满足就退回普通清单，避免把不适合的 WBS 硬编译成 DAG。
- **具体场景**：PM 拿一个强串行的合规审查项目去「运行 DAG」，方法论门先拦：「本项目 7 条任务全是 FS 串联、无可并行叶子，不建议扇出」，只给出依赖顺序而不编译。
- **亲本**：D1-29（例会/周报/风险/WBS 方法论写成 skill）× D4-19/D2-14（WBS+predecessorIds 编译为 workflow 扇出 DAG）。
- **触点**：skill-filesystem SKILL.md；workflow 编译前的静态判定（读 predecessorIds 连通性/并行度）；不调模型也能算适配度。
- **新在哪**：亲本一个是静态手册、一个是直接编译；杂交让方法论成为编译的准入判据，而非事后参考。

## C. 反叛（攻击本轮池的明显共识：只读工具 + 审批 seam + 证据闭环 + 轻融合 + 独立内核 + 离线优先）

### D5-R2-18 反叛「只读工具是安全的半瞎陷阱」

- **主张**：共识把「模型只读、写全走审批卡」当成安全基石，但在单人单写者、无并发、无外人误操作的前提下，只读让模型永远在台账外面打转：它能看见却不能动，每一步都要 PM 转手批准，摩擦大于收益，最后沦为「模型说得对但落不了地」的半截体验。单人场景下，给模型有限写权限（限定白名单动作：勾完成、关已解除风险、挪自己建议过的日期）+ 自动留痕 + 事后一键撤销，比逐条审批更快，错误成本有 provenance 账本兜底。
- **成立条件**：① 确实长期单人单写者、无多端并发（11 号契约当前状态）；② 写动作白名单极窄（不含删除/不含改他人/不含改交付日期）；③ 每笔自动留痕可撤销、可回滚；④ 用 D5-R2-09 的对账保证模型不把草稿当已落库。任一条件破裂（多人、可删除、无撤销）则回到审批 seam。
- **触点**：挑战 D1-01/D2-07/D3-01/D4-01（只读工具族）与 D1-03/D2-08/D3-02/D4-02（审批 seam 共识）；provenance-store 的 undo 句柄与审计是反叛的安全网。
- **来源观察**：R4 调用主体存疑、R2 读写边界；单人场景下「审批」的防护对象（并发误写、外人篡改）根本不存在，防护成本却始终支付。

### D5-R2-19 反叛「人类可读 JSON 十年档案是浪漫错觉」

- **主张**：共识把「一份人类可读 JSON、十年后照样打开」当长寿信仰（D1-26/D3-14/D4-25）。但可读不等于可用：十年后没人会手工翻陌生目录里几百个 per-record JSON 文件，格式纯洁也挡不住语义腐化（字段名变了、口径变了）；真正长寿的不是存储格式，而是「定期自动导出为当时标准格式 + 附带可重建/可转换工具」，归档应主动放弃实时性、放弃继续被编辑。
- **成立条件**：① 接受「档案是死的快照，不是活库」，不再追求档案可写；② 结项/每年自动导出一份通用格式（Markdown/HTML/PDF 合集）+ 一份迁移说明；③ 把维护精力从「保持 JSON 纯洁」转到「可导出、可重建、可被新工具读」。
- **触点**：挑战 D3-14（Markdown 唯一真源）、D4-25（纯开放文件+静态查看器）、D1-26（10 年可读卖点）；复用现有 export/backup/office-to-pdf 做定期固化。
- **来源观察**：C5 可读可迁移被当成目的；ADL-041 备份恢复只解决「不丢」，没解决「十年后看得懂、用得上」。

### D5-R2-20 反叛「PM 维护台账本身才是该被消灭的问题」兼叛「离线优先哲学」

- **主张**：共识默认「人录入、人维护一本台账」是产品前提，离线优先只是存储约束；真正的低采用根源恰恰是手动维护这本账——没人愿意每天另录一遍自己刚说过/做过的事。离线优先被抬成哲学后，反而把「自动捕获」挡在门外。目标不该是让人维护一本账，而是让账从工作流里自动长出来（D1-25/D2-16 方向推到底），离线只是「数据落本地」的技术约束，不是「拒绝自动采集」的产品立场。
- **成立条件**：① 自动抽取候选 + 人只做确认/丢弃，录入动作趋近于零；② 离线约束只作用于存储（本地 JSON），不作用于捕获（会话日志/git/附件都是本地可得）；③ 确认制保留人对事实的最终签字，自动不等于自动落库。
- **触点**：把 D1-25/D2-16（被动捕获/自动投影）从「疯狂」提为默认形态；session-query/attachment/workspace-changes 全在本地可获，与离线不矛盾。
- **来源观察**：UX-11 两张皮、R1 证据断点本质都是「人要重复录入」；ADL-032 拒绝常驻 daemon 被泛化成了拒绝一切自动化；本条区分「常驻后台进程」（反对）与「本地被动捕获」（不反对）。

### D5-R2-21 反叛「独立内核 / 薄适配层」共识

- **主张**：D2-05/D3-07/D4-23/D5-14 一致主张抽零依赖 pm-core + 薄适配层。但单人维护、生命周期 2 年尺度下，多一层抽象（PmDomain 接口、后端注入、适配层）就是多一份自己维护的代码；上游真 break 时，直接贴合 dsh 重写接线，往往比养一个永不复用的内核便宜。独立内核是为「被多个壳复用」准备的，而复用场景目前并不存在——这是给想象中的需求付现实的维护税。
- **成立条件**：① 明确短期（1–2 年）不打算出第二个壳/第二个客户端；② 上游升级频率低、breaking 少；③ 一旦出现第二个消费端（MCP server/独立 App）再抽内核不迟，接口边界（11 号契约 PmDomain）现在先守住、物理拆分后置。
- **触点**：挑战 D2-05/D3-07/D4-23（抽 pm-core）、D5-14；保留 product/11 §一「域接口唯一边界」作为软约束，反对的是提前物理剥离。
- **来源观察**：R3 最小独立内核被当成默认答案； feasibility-map 主体一栏反复提醒「无主体的能力接进来维护成本由一人承担」，抽象层同理——无复用主体的抽象也是维护税。
