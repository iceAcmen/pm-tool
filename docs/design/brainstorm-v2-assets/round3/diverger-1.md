## 一、压力测试逐条

### P1. 只读工具族（D5-01 / D1-01 / D2-07 / D3-01 / D4-01，五人同构）
- **① 推到最大**：七实体 × 全部视图 × 单条 get × 列表 × 搜索 × 派生统计，全注册成 `pm_*` 工具，模型对台账的每个面都能直接读。
  - **判定：崩（在工具数与返回体量边界上）**。推理链：工具 schema 全部进系统提示词，工具数一多模型出现选择困难（选错/漏选）；只读工具返回全量 JSON 直接灌进上下文，compaction 提前触发、主任务被挤；前提「读不消耗确认轮次所以越多越好」只在实体少、工具少时成立。**成立条件**：实体 <30、工具 <10、返回分页/摘要化。
- **② 砍到最小**：只留一个 `pm_search(keyword)`，其余读全部退回 `/pm` 命令与面板。
  - **判定：反而成立**。单人小项目一个关键词搜索就覆盖 80% 问答；最小可行内核 = 一个只读搜索工具 + 现有命令通道，零新增视图。
- **③ 反常识倒置**：工具方向反过来——不是「模型读台账」，而是注册一个反向工具让台账在派生时读模型会话（把承诺/决议从会话里捞回台账）。
  - **判定：反而成立（长出变体 D1-R3-01）**。主客体从「台账被查」换成「台账主动取」，与 D1-25/D2-16 被动捕获同源，但工具化后可被确定性调度。

### P2. 审批 seam / pm_propose（D5-02 / D1-03 / D3-02 / D2-08 / D4-02，五人同构）
- **① 推到最大**：每个动作、每个字段、每一步都弹审批卡——改备注、勾 checklist、补证据链接、标状态，无一例外。
  - **判定：崩（在审批疲劳边界上）**。推理链：单人自己批自己，60s 超时默认拒绝把合法动作也杀掉；模型被连续拒绝后学会「不提议」，采纳率 N≈0 被流程自我实现（正是 D2-R2-18 说的半瞎陷阱）。前提「事前每笔拦 = 安全」在多人不可信模型时代成立，在单人可逆场景不成立。**成立条件**：审批只留给不可逆/对外动作（删除、改期、出站写外部）。
- **② 砍到最小**：零审批卡，模型只是会拼 `/pm` 命令字符串，落库走现有命令通道。
  - **判定：反而成立**。现状本来就是命令通道，seam 只是包装层；最小内核不需要新 interaction 接线。
- **③ 反常识倒置**：审批人不是人，而是一条可配置的授权规则引擎——白名单内动作模型自批自留痕，人只事后抽查。
  - **判定：反而成立（长出变体 D1-R3-02）**。把「人逐笔点头」换成「规则批量放行 + 事后审计」，审批主体从人让位给规则，人退到例外位。

### P3. D1-23 agent 自主执行 PM（台账退只读账本 + 异常升级）
- **① 推到最大**：全自主——状态推进、风险开关、挪日期、重排关键链全自己做，人只收异常报警。
  - **判定：崩（在无人纠偏闭环边界上）**。推理链：单人无外部监督，模型把没做完的标 done 会形成错误闭环；goal-round-driver 预算耗尽后自循环空转；错误沿 predecessorIds 依赖扩散。**成立条件**：动作全部可逆 + 全量审计流在场 + 客观证据门（只允许「非空 checklist 全勾」才自动 done，复用 progress-derivation.ts 的诚实口径，status=done 不伪造百分比）。
- **② 砍到最小**：自主权限缩到「只勾 checklist + 挂证据链接」，其余一律提议。
  - **判定：反而成立**。这两个动作恰好是客观进度真源已支持的安全动作，误判面最小。
- **③ 反常识倒置**：自主的不是 agent，而是台账自己——事件流到达即自更新，agent 降级为记录员。
  - **判定：反而成立（长出变体 D1-R3-03）**。与 D1-R2-23「消灭维护台账」合流，写主体从模型换成数据本身。

### P4. D3-R2-17 / D1-R2-20 反叛：单人直接写 + 事后撤销
- **① 推到最大**：全字段直接写（含改期、改派、删任务、建风险），人晚上扫审计流一次性回滚。
  - **判定：崩（在撤销时效边界上）**。推理链：现状 undo 句柄 TTL 10min / 最多 3 条 / 一次性 / 重启失效（provenance-store.ts L28-29），晚上才看早已超 TTL，撤销通道接不住「事后」；第二个人出现即并发冲突。**成立条件**：窄白名单（不含删/改期/改派）+ 审计流无限期保留并提供历史版本回滚（突破 10min TTL）+ 单写者恒定。
- **② 砍到最小**：只开一个写口——勾 checklist，其他照旧审批。
  - **判定：反而成立**。最小直接写面，误判与撤销成本都趋近零。
- **③ 反常识倒置**：事后审计不由人翻流，而由一个独立审计 subagent 自动跑，人只看它的结论卡。
  - **判定：反而成立（长出变体 D1-R3-04）**。审查主体从人换成独立子代理，与 D2-12 里程碑审计员合流但常态化。

### P5. D4-R2-23 反叛：深双向绑定单人反而对
- **① 推到最大**：七实体 ↔ 会话 todo/goal/工作区目录全字段实时双向，一侧改另一侧同步。
  - **判定：崩（在寿命错配边界上）**。推理链：会话结束 todo 消失，双向同步会把台账清空；会话 fork/重启产生两个副本需要 CAS，单人看似无冲突但长寿实体（里程碑/风险）被短命载体带走；上游字段升级回归面全量暴露。**成立条件**：只绑「短命↔短命」（进行中任务 ↔ 会话 todo），长寿实体不进双向。
- **② 砍到最小**：只绑一个布尔（勾选状态），其余单向。
  - **判定：反而成立**。一个布尔同步没有冲突解决问题。
- **③ 反常识倒置**：会话才是真源，台账只是会话结束时固化的持久缓存快照。
  - **判定：反而成立（长出变体 D1-R3-05）**。事实源方向颠倒：先在会话里干活，台账负责结账，而不是台账当祖宗供着。

### P6. D1-27 / D5-21 goal 镜像（单向绑 goal，观察后丢弃）
- **① 推到最大**：整个项目（健康分、全部任务、风险）绑成会话 goal，goal-round-driver 全程自动续行。
  - **判定：崩（在 goal 模型容量边界上）**。推理链：goal 是「每会话单一完成目标」，项目是多目标集合，状态机装不下全貌；会话结束 goal 消失会造成「项目被放弃」错觉；自动续行烧免费池（约 50 次/天，KB-034）。**成立条件**：只绑单条 P0 / 单个里程碑，不绑项目全貌。
- **② 砍到最小**：一次性实验，跑完即清（D5-21 本来就是这个形态）。
  - **判定：反而成立**。低成本试了再判，不沉淀任何绑定。
- **③ 反常识倒置**：不让 goal 镜像台账，而是台账派生 goal——开工时台账自动生成当前会话 goal，goal 消亡不影响台账。
  - **判定：反而成立（长出变体 D1-R3-06）**。方向从「goal 读台账」翻成「台账推 goal」，寿命分层天然安全。

### P7. D5-20 todo 临时镜像（禁止回写，结束即弃）
- **① 推到最大**：每个会话自动全量镜像开放子树到 todo，且强制禁止回写。
  - **判定：崩（在认知双轨边界上）**。推理链：会话里勾一堆、台账不动，用户产生「勾了=记了」的错觉，正式档案与手头清单脱节；禁止回写在高频使用下变成持续挫败。**成立条件**：只作只读预览，并明确标注「勾选不落库」。
- **② 砍到最小**：零镜像，开工手打一条待办。
  - **判定：反而成立**（即现状），todo 接线本就可以不做。
- **③ 反常识倒置**：禁止回写翻成「只准回写」——todo 是唯一操作台，台账只在会话结束时从 todo 固化结存。
  - **判定：反而成立（长出变体 D1-R3-07）**。与 P5-③ 同源：操作台在会话，档案在台账，单向结账。

### P8. D1-R2-12 / D2-R2-10 / D4-R2-11 / D5-R2-09 新鲜度戳与对账
- **① 推到最大**：模型每句话带置信度，每次回答自动与库内逐条对账，差异全标红。
  - **判定：崩（在额度与警告疲劳边界上）**。推理链：对账本身多一轮工具调用，50 次/天免费池撑不住；过度警告造成狼来了，真陈旧被忽略；模型为躲对账干脆不提具体数字。**成立条件**：只对「落库声明」（声称已改/已完成/已关闭）对账，不对事实性陈述逐条对账。
- **② 砍到最小**：注入段头只打一个 capturedAt 时间戳，无自动对账。
  - **判定：反而成立**。一个时间戳成本极低，已经给了人肉眼判断新鲜度的锚。
- **③ 反常识倒置**：故意保留一份上一版快照，让模型新旧对比着回答，把「陈旧」从缺陷变成对照工具。
  - **判定：反而成立（长出变体 D1-R3-08）**。陈旧副本不再要被消灭，而是当时光机对照层。

### P9. D1-05 会话内多轮副驾（会话变量 + 记忆续问，结束消散）
- **① 推到最大**：副驾跨会话永久记住全部项目问答史，随 user 贯穿所有会话。
  - **判定：崩（在 R3 寿命错配边界上）**。推理链：跨会话记忆 = 长期状态，撞寿命分层；旧会话里的过期结论污染新会话；记忆无限膨胀。**成立条件**：记忆只会话内，结束即消散（原想法本来就是）。
- **② 砍到最小**：单轮 Q&A，无续问（即现状 ask-copilot）。
  - **判定：反而成立**。单轮够用时不必造记忆。
- **③ 反常识倒置**：副驾不记项目，项目档案记副驾——把副驾里有价值的问答固化进会议/报告实体，记忆离开会话进台账。
  - **判定：反而成立（长出变体 D1-R3-09）**。记忆主体从会话翻成台账实体，借 D1-28 session-reference 固化。

### P10. D5-07 每项目专属 PM subagent 长会话常驻
- **① 推到最大**：每个项目一个永不关闭、持续待命的 PM 官，长期记忆该项目。
  - **判定：崩（在常驻主体边界上）**。推理链：N 个项目 = N 条常驻子会话，进程/上下文/额度线性开销；单人不会同时问 N 个常驻官；子会话漂移跑偏无人纠。**成立条件**：按需 spawn、问完即弃。
- **② 砍到最小**：spawn 一次问完 kill（D3-22 巡检式只读子代理）。
  - **判定：反而成立**。一次性只读诊断无常驻成本。
- **③ 反常识倒置**：主会话是子 agent 的副驾——PM subagent 是主体，主会话只是它与人的收发室。
  - **判定：反而成立（长出变体 D1-R3-10）**。主客体互换：子代理主导诊断，人远程指挥与裁决。

### P11. D1-02 / D5-03 / D2-01 / D4-04 持久 push 注入
- **① 推到最大**：全量七实体每轮系统提示词注入。
  - **判定：崩（在 token/缓存边界上）**。推理链：token 爆炸、cacheReadTokens 失效（每轮内容变）、模型被 PM 元数据干扰主任务、免费池消耗加快。**成立条件**：几百字摘要 + 硬字节预算（D1-32）。
- **② 砍到最小**：零注入，只留只读工具按需 pull（D3-21 路线）。
  - **判定：反而成立**。不常驻也能查，省预算。
- **③ 反常识倒置**：注入方向反转——不是台账进提示词，而是把模型当前工作状态（在改哪几个文件、刚跑完哪轮）常驻推回台账。
  - **判定：反而成立（长出变体 D1-R3-11）**。D1-06 证据回挂的常驻版，推送方向从台账→模型翻成模型→台账。

### P12. D3-21 按需 pull（问「当前项目」才喂快照）
- **① 推到最大**：每轮都自动 pull 全量快照（等于变相 push）。
  - **判定：崩**。失去按需意义，token 与 P11-① 同病。
- **② 砍到最小**：无工具，纯 `/pm` 命令手动查（现状）。
  - **判定：反而成立**。单人低频查询时命令够用。
- **③ 反常识倒置**：由台账决定何时被看见——模型不主动问，台账在「有人该知道」时把自己摆到模型面前（条件触发亮相）。
  - **判定：反而成立（长出变体 D1-R3-12）**。拉取主体从模型翻成数据侧事件，是 D1-12 schedule 的进化形态。

### P13. D1-32 注入预算治理（compaction/spill 配套）
- **① 推到最大**：预算压到 0，禁止一切注入。
  - **判定：反而成立**：退回纯工具路线，与 P11-② 同。
- **② 砍到最小**：无预算，全量进上下文。
  - **判定：崩**：即原想法自己警告的反噬——PM 元数据把主开发任务挤出窗口、compaction 提前。
- **③ 反常识倒置**：预算不是固定字节数，而是随主任务上下文占用动态伸缩——主任务紧张时注入让位、空闲时扩容。
  - **判定：反而成立（长出变体 D1-R3-13）**。固定预算翻成自适应水位，让位优先级让给主任务。

### P14. D2-16 / D1-25 被动捕获（台账是会话/git 的投影，人只确认）
- **① 推到最大**：全自动，会话/git 里抽出什么直接落库，人零参与。
  - **判定：崩（在误抽拦截边界上）**。推理链：闲聊被当承诺、幽灵任务堆积；抽取错误无人拦截，台账质量塌掉。**成立条件**：草稿箱 + 人确认这一道不能省（原想法本就保留确认）。
- **② 砍到最小**：只抽「明确承诺句」一种句式。
  - **判定：反而成立**。窄抽取面误报最低。
- **③ 反常识倒置**：对话是台账的投影——台账先生成对话脚本/待办台词，人只是照着说。
  - **判定：反而成立（长出变体 D1-R3-14）**。谁产生谁：不再是对话生台账，而是台账生对话。

### P15. D4-28 assignee 建模为可 spawn 虚拟子 agent（团队仿真）
- **① 推到最大**：每个名字都 spawn 一个虚拟人自报进度，多虚拟人开仿真团队会议。
  - **判定：崩（在仿真失真边界上）**。推理链：仿真自陈被误当真人状态；纯推演玩具开销不小；单人无团队可仿真。**成立条件**：结果明确标注「仿真自陈、非真人确认」，仅用于排期推演。
- **② 砍到最小**：不 spawn，负载视图只显示名字与 open 数。
  - **判定：反而成立**。people-load 已能给数，不需要角色扮演。
- **③ 反常识倒置**：不是仿真人回答 PM，而是真人被建模成台账里的可调度资源单元，台账向真人派活。
  - **判定：反而成立（长出变体 D1-R3-15）**。虚拟反过来落到真人：人成为台账的执行资源。

## 二、极端中长出的新变体（全保留，不评分）

### D1-R3-01【P1-③】反向只读工具：让台账主动读模型会话
- **机制**：注册一个方向相反的只读工具 `pm_absorb_promises`，由确定性逻辑从指定会话日志里捞承诺/决议候选，回写草稿箱；方向是「台账取模型」，不是「模型查台账」。
- **具体场景**：会话结束触发一次抽取，草稿箱出现 3 条候选，PM 逐条确认；工具本身不写正式表。
- **触点**：session-query、现有草稿箱/confirm 链路。
- **来源观察**：D1-25/D2-16 被动捕获靠监听，本变体把它变成可被调度的确定性工具。

### D1-R3-02【P2-③】规则化自动审批闸：白名单内自批，人只事后抽查
- **机制**：把审批从「人逐笔点头」改成「授权规则引擎」：窄白名单动作（勾 checklist、补证据、改备注）模型自批并写 provenance，超白名单（删/改期/改派/出站写）才弹人工卡；人在审计流事后抽查。
- **具体场景**：agent 勾完 checklist 直接留痕，PM 晚上只看到一张「本日自批 12 条、待人工 2 条」汇总。
- **触点**：copilot.ts 白名单收窄、provenance-store、D4-29 审计流。
- **来源观察**：P2-① 审批疲劳推理链；D3-R2-17/D1-R2-20 的直接写主张落到规则闸形态。

### D1-R3-03【P3-③】事件自更新台账：数据自己写自己，agent 当记录员
- **机制**：workspace-changes/会话结束等事件到达后，由确定性规则直接更新台账字段（勾 checklist、挂证据），agent 只做解释不做裁决。
- **具体场景**：git diff 显示某文件测试全绿，对应 checklist 项自动勾上，agent 只在旁边写一句说明。
- **触点**：workspace-changes、progress-derivation 客观门、事件流。
- **来源观察**：D1-R2-23「消灭维护台账」的机制化；P3-① 无人纠偏靠客观门兜底。

### D1-R3-04【P4-③】独立审计 subagent 常态化事后抽查
- **机制**：每天（或会话批次结束）派一个无父历史的只读审计子代理，扫本日自批/直接写动作，产出「可疑 N 条」结论卡，人只审结论不翻原始流。
- **具体场景**：早上收到审计卡「3 条 done 无证据链接、1 条改期无依据」，PM 逐条撤销或补证。
- **触点**：subagent-spawn-in-process、D2-12 审计员、provenance 账本。
- **来源观察**：P4-① 撤销 TTL 10min 接不住事后，故由审计员前置发现。

### D1-R3-05【P5-③】会话真源 + 周期固化：台账是会话的结存缓存
- **机制**：进行中工作以会话 todo/对话为真源，台账不实时同步，只在会话结束/周期点把确认过的内容固化为档案；会话消失不拖垮台账。
- **具体场景**：开发会话里 todo 随便勾随便删，结束时系统问「把这几条结存进台账？」，选过的才落。
- **触点**：tool-todo、会话结束钩子、confirm 草稿。
- **来源观察**：P5-① 寿命错配推理链；D3-24 单向导出的「真源方向」反转版。

### D1-R3-06【P6-③】台账派生 goal：开工自动生成会话目标
- **机制**：选中项目开工时，台账自动把下一条 P0 生成会话 goal 推给宿主，goal 是派生品，消亡不回写台账。
- **具体场景**：点「开工 t-12」，会话 goal 自动挂上「完成 t-12」，会话关掉 goal 消失，台账不动。
- **触点**：goal create、任务开工（D3-13）。
- **来源观察**：P6-① goal 装不下项目全貌，只派生单任务。

### D1-R3-07【P7-③】todo 为操作台、台账为结存：只准回写
- **机制**：会话 todo 是唯一操作清单，勾选/删除只发生在会话；结束时单向回提为完成候选落台账，禁止双向。
- **具体场景**：会话里勾掉 3 条，结束面板出现「3 条候选完成」，确认即结存。
- **触点**：tool-todo 整表替换、D1-R2-18 回收单行道。
- **来源观察**：D5-20「禁止回写」的方向反转。

### D1-R3-08【P8-③】新旧双快照对照回答：陈旧副本当时光机
- **机制**：保留上一版快照，模型被问现状时同时给新旧两版差异，旧版标注「历史快照」而非错误。
- **具体场景**：「这条任务什么时候改的？」模型答「上周快照是 in_progress，今天变为 done」，差异本身成为答案。
- **触点**：D4-30 备份版本链、report-diff 相邻快照。
- **来源观察**：P8-① 过度对账崩塌；陈旧从缺陷转为对照层。

### D1-R3-09【P9-③】会话精华回流台账实体：记忆离开会话进档案
- **机制**：副驾多轮问答中被标记「有价值」的结论，固化进对应会议/报告/决策实体，不随会话消散。
- **具体场景**：三轮追问得出的排期结论，一键存进 M1 里程碑备注，下个会话还在。
- **触点**：session-reference 有界快照、meeting/decision 实体。
- **来源观察**：P9-① 跨会话记忆崩塌；记忆主体从会话翻成台账。

### D1-R3-10【P10-③】子 agent 为主体、人远程指挥收发室
- **机制**：PM subagent 是诊断主体（自主跑完跨项目巡检并给方案），主会话只承担向人转达与接收指令，而非反过来。
- **具体场景**：子代理先跑完给出诊断包，主会话等 PM 一句「采纳哪几条」。
- **触点**：subagent spawn、D5-08 workflow 扇出。
- **来源观察**：P10-① 常驻崩塌；主客体互换但不常驻。

### D1-R3-11【P11-③】模型工作状态常驻推回台账（注入反向）
- **机制**：不再把台账推进提示词，而是把「当前在改哪些文件/刚跑完哪轮」周期性推回任务证据区，形成自动更新的执行流。
- **具体场景**：开发进行中，t-12 证据区自动累计「14:20 改 file a、15:02 改 file b」，无需人挂链接。
- **触点**：workspace-changes 常驻订阅、evidenceUrl 草稿。
- **来源观察**：P11-① push 注入 token 崩塌；方向反转成模型→台账。

### D1-R3-12【P12-③】事件触发的主动亮相：台账决定何时被看见
- **机制**：不等人问、不轮询，由台账侧事件（逾期/里程碑临近/风险升级）触发一次简短亮相进会话，平时静默。
- **具体场景**：t-12 逾期那一刻，会话里出现一条短卡，不是定时轰炸而是事件驱动。
- **触点**：domain/changed（进程内）、schedule 兜底、reminders 派生。
- **来源观察**：P12-② 纯手动查的被动；拉取主体翻成数据侧事件。

### D1-R3-13【P13-③】自适应注入水位：随主任务占用伸缩
- **机制**：注入字节预算不固定，主任务上下文占用高时压缩/让位，空闲时扩容到全量摘要。
- **具体场景**：正在跑长代码任务时注入只剩一行健康灯；闲聊时展开今日议程。
- **触点**：compaction 水位信号、context section 动态长度。
- **来源观察**：P13-② 无预算反噬；固定预算翻成自适应。

### D1-R3-14【P14-③】台账台词驱动对话：台账先生成待办脚本
- **机制**：开工前台账生成一段「今天该说/该做什么」的台词脚本推给会话，对话照着台账走，而非对话自由生长再回捞。
- **具体场景**：早起点一下，会话开场即拿到今日 3 条台词，逐条推进逐条结存。
- **触点**：buildAskContext、议程生成、confirm。
- **来源观察**：P14-① 全自动误抽崩塌；产生者反转。

### D1-R3-15【P15-③】真人作为台账可调度资源单元
- **机制**：不仿真虚拟人，而是把真人建模为台账里的资源单元，台账按负载向真人派活、回收，人是执行端。
- **具体场景**：组合视图直接给真人排「本周 5 条上限」，超负载即提示派不下去。
- **触点**：people-load、组合取舍（D1-R2-05）、出站写日历（D1-R2-06）。
- **来源观察**：P15-① 仿真失真；虚拟落到真人资源。

## 三、自检
- 施压对象 15 个（≥12）；每条 ≥2 种施压；三种类型覆盖：最大 P1①–P15①、最小 P1②/P2②/P3②/P4②/P5②/P6②/P7②/P8②/P9②/P10②/P11②/P12②/P13①/P14②/P15②、倒置 P1③…P15③，三类全覆盖。
- 判定：15 处「崩」（均为①最大或个别②最小的极端位：P1①、P2①、P3①、P4①、P5①、P6①、P7①、P8①、P9①、P10①、P11①、P12①、P13②、P14①、P15①），其余最小/倒置位均「反而成立」；每条崩都给了前提/边界条件，每条成立都给了条件。
- 新变体 15 条（D1-R3-01…15）全保留；未复述池中已有完整想法，仅引用编号。
