# 阶段1 第3轮 · 极端化施压 —— D2（簇：证据闭环与自动捕获）

> 压力测试，不是红队论证：不评分、不批判可行性，专注边界条件与崩点；每条给具体条件。三种施压模式：**①推到最大**（无处不在/全自动/无限制）、**②砍到最小**（一条命令/一次性/零接线/零 UI）、**③反常识倒置**（主客体互换/因果倒置/黑白反转）。每条至少做 2 种，三种全程覆盖。
> 母本编号引用自 round1-pool / round2-pool。压力过程中长出的新变体单独编号 D2-R3-01 …，全保留。

---

## 压测 01 · workspace-changes git diff 回挂任务证据（母本 D1-06 / D4-05 / D5-04，同一机制三变体）

**母本机制**：订阅 session/event，把本轮 git 工作树快照 + 文件 diff 摘要收成只读证据候选，人确认后挂任务 evidenceUrl，绝不自动改状态。

- **① 推到最大**：每轮所有改动自动按文件路径/关键词匹配到任务，无确认直接写进 evidenceUrl，甚至据此自动建议完成。
  - 判定：**崩**。推理链：
    1. 误匹配——一个会话常同时改多个项目/多个任务的文件，确定性路径匹配无法区分「这条改动属于哪条承诺」，错挂比不挂更糟；
    2. 覆盖盲区——workspace-changes 只记文件工具编辑与 git 快照，shell 命令造成的改动不出现（D5-04 来源观察已注明），推到最大后这部分工作永远无证据，形成「做了但系统看不见」的假空转；
    3. 仓库前提——非 git 目录（纯文档、手写笔记）时空转；
    4. 证据爆炸——每轮都挂，抽屉里堆满 hunk 清单，人不看。
  - 成立边界：只在「一个会话对应一条任务、仓库是 git、改动文件路径可由人在草稿里确认」三个条件同时满足时，半自动（人确认）才成立。
- **② 砍到最小**：删掉所有事件订阅与自动聚合，只留一条命令 `/pm evidence <taskId> <url>`，人手贴一个链接。
  - 判定：**反而成立**。单写者手动贴链接成本极低，自动管道最头疼的匹配/误挂/盲区问题全部消失；代价是没有人会贴（这是采纳问题，不是机制问题）。
- **③ 反常识倒置**：证据不等人去挂，而是**证据主动找人**——捕获到的改动先进「孤儿证据池」，系统反向提议「这批改动可能属于 t-00xx，或要不要新建一条任务」，人做归属裁决；找不到归属的改动也不丢弃，留在池子里供周报复用。
  - 新变体见 **D2-R3-01**。

## 压测 02 · session-query FTS5 回捞历史会话当证据/素材（母本 D1-07 / D4-06 / D5-05）

**母本机制**：按任务标题/关键词 FTS5 搜历史会话，把命中轮次作为只读引用挂证据区/周报素材，人勾选。

- **① 推到最大**：每次打开任务、每次写周报，全库语义回捞所有相关历史会话片段自动铺满证据区。
  - 判定：**崩**。推理链：
    1. FTS5 关键词误命中（同词不同事，如「登录」出现在十几条无关会话）；
    2. 隐私与噪音——旧会话含大量无关闲聊/私人内容，铺满后证据区变成垃圾场；
    3. cwd 亲和错位（D1-07 依赖 cwd 匹配），跨目录项目会捞错；
    4. session-query 默认排除调用方会话、需 sqlite 后端，环境缺失时静默退化。
  - 成立边界：只在「人主动发起一次回捞、命中条数有上限、命中片段只列标题+日期不铺正文」时成立。
- **② 砍到最小**：零回捞，证据区只放人手贴的外部链接，会话日志完全不读。
  - 判定：**成立**（退回现状的保守形态）；最小内核就是任务抽屉一个粘贴框。
- **③ 反常识倒置**：黑白反转——**会话原文才是权威现实，台账数字只是缓存**；当台账记录与会话原文冲突时（台账说完成、原文显示只是讨论），系统标红「与原始会话不符」，而不是让会话给台账当佐证。
  - 新变体见 **D2-R3-02**。

## 压测 03 · 被动捕获收件箱 / 台账吃对话（母本 D1-25 / D5-19）

**母本机制**：从会话日志/git/速记/附件自动抽候选任务/风险/行动项进待认领收件箱，人只归类确认。

- **① 推到最大**：零确认，抽取结果直接入库成为正式任务/风险。
  - 判定：**崩**。推理链：
    1. 误报污染——模型把闲聊、假设、「下次再说」当成承诺直接落库，错条目散进各实体后，单写者难以逐条回滚；
    2. 抽取无确定性校验，错误率无上限；
    3. 收件箱自动清零后，人失去「我确认过」的心理所有权，台账可信度反而下降。
  - 成立边界：高置信候选才进箱、人必须逐条确认、误报可一键丢弃且不扩散。
- **② 砍到最小**：不监听任何流，收件箱只在人手动点「采集本周」时跑一次。
  - 判定：**成立**。一次手动触发换一批候选，零常驻、零误报累积。
- **③ 反常识倒置**：负向默认——对话里说的一切默认「不记」，只有人明确说出「记下来/落进台账」这句话时才留候选；沉默是默认，捕获是例外。
  - 新变体见 **D2-R3-03**（置信分层 + 误报配额）。

## 压测 04 · 会中实时捕获（母本 D2-R2-06 / D1-R2-07 / D3-R2-05 / D5-R2-04 / D4-R2-06 麦克风 STT）

**母本机制**：会中边说边落候选行动项气泡，当场认领/丢弃，散会拼纪要；D4-R2-06 更进一步用本地 SenseVoice STT 实时转写抽取。

- **① 推到最大**：麦克风常开、全天候监听所有对话，自动转写并抽取承诺。
  - 判定：**崩**。推理链：
    1. 隐私——常开麦录下非工作对话；
    2. STT 错误率（本地 SenseVoice 错字/断句）直接变成错误行动项；
    3. 边开会边管理分散注意力，候选气泡不断打断会议流；
    4. 降噪失败：客套/铺垫被抽成行动项。
  - 成立边界：人显式开启「现场模式」、只录当前会议、候选当场可丢、STT 只做草稿。
- **② 砍到最小**：无会中模式，回到会后粘贴速记（R15 现状）。
  - 判定：**成立**（零增量但零风险）；最小内核=一个边说边打的临时文本框，不接 STT、不自动抽。
- **③ 反常识倒置**：会中只允许「记一句」的极简动作（一句话级别），升格成正式行动项全部留到会后；会中不做任何管理判断，只做速记。
  - 新变体见 **D2-R3-04**（散会后 60 秒黄金认领窗口）。

## 压测 05 · 附件白板照/截图挂证据（母本 D1-08 / D4-07 / D5-10 / D2-32）

**母本机制**：白板照/截图/设计稿经 attachment 内容寻址存储挂到会议/交付物/任务，只存句柄不复制字节。

- **① 推到最大**：所有日常截图自动 OCR、自动归类挂到相关任务。
  - 判定：**崩**。推理链：
    1. 日常截图量远大于会议/交付物，内容寻址存储被淹没；
    2. 图片无文字索引，归类靠模型又回到误匹配；
    3. 碎片化——每条任务都挂几张图，纪要反而找不到关键那张；
    4. 隐私截图（误截屏）进了台账。
  - 成立边界：人手动拖入、只挂会议/交付物两层、图片是引用不是复制。
- **② 砍到最小**：附件只是一个文件引用框，零模型识别、零自动归类。
  - 判定：**成立**。
- **③ 反常识倒置**：主次反转——图片才是会议本体，文字纪要只是图片 OCR 出来的副产品；白板照为主件，文字是配图说明。
  - 新变体见 **D2-R3-05**（附件只允许挂会议/交付物，禁止挂每条任务）。

## 压测 06 · GitHub webhook 正向 + 轮询反向（母本 D1-09）

**母本机制**：正向 webhook 收 PR opened/merged 事件变候选草稿（需公网入口）；反向 web_fetch/MCP 手动/周期拉取回填。

- **① 推到最大**：webhook 实时双向，所有 PR 事件自动改任务状态。
  - 判定：**崩**。推理链：
    1. localhost 无公网入口，正向天然跑不起来（D1-09 自己已注明，需内网穿透/部署）；
    2. 验签、重复交付（webhook 会重投，deliveryId 不去重就制造重复草稿）；
    3. 自动改状态越权——PR merged 不等于任务验收通过；
    4. 外部仓库权限/网络不可控。
  - 成立边界：只做反向手动/周期只读拉取，事件永远只产候选草稿。
- **② 砍到最小**：删掉 webhook 与周期轮询，只留面板一个「刷新仓库状态」按钮，点一次 web_fetch 拉一次。
  - 判定：**反而成立**。本地可跑、零常驻、零公网依赖。
- **③ 反常识倒置**：不接 GitHub 让 GitHub 给台账喂证据；反过来**让 GitHub 成为唯一事实源，台账只做本地只读镜像视图**，台账不再是计划权威。
  - 新变体见 **D2-R3-06**（deliveryId 幂等去重作为最小必备件）。

## 压测 07 · 台账→外部系统出站写（母本 D2-R2-05 / D4-R2-05 / D1-R2-06 / D3-R2-04 / D5-R2-03）

**母本机制**：经外部 MCP 写工具把任务建成 Jira issue/飞书卡片/日历事件，人审批后发出，外部 ticket id 回挂，默认关闭、逐条显式触发。

- **① 推到最大**：台账↔Jira 双向实时同步，两边改动互相写回。
  - 判定：**崩**。推理链：
    1. 单写者原则被破坏（11 号协作契约：无 CAS、无 rev、纯覆盖写），双写冲突无法收敛；
    2. 字段映射漂移（Jira 自定义字段随对方改）；
    3. 离线分叉——断网时两边各改各的，回来无法合并；
    4. 外部 API 变更导致静默失败。
  - 成立边界：单向出站、显式触发、只增不级联删除、留可撤销日志。
- **② 砍到最小**：零 MCP，只留一个「复制任务为 issue 文本」按钮，人自己粘贴到外部。
  - 判定：**成立**（价值低但零风险）；最小内核就是格式化一段可粘贴文本。
- **③ 反常识倒置**：出站方向反转——本地台账不主动写外部，外部 issue 反向成为任务的唯一存在，本地只留一个指针句柄，外部是主、本地是缓存。
  - 新变体见 **D2-R3-07**（出站只增日志 + 撤销队列，外部删除绝不级联）。

## 压测 08 · dogfood 自身仓库，commit 即证据（母本 D2-17）

**母本机制**：用本工具管 pm-tool 自己的开发 backlog，任务号写进 commit message，git log 关联任务作只读证据草稿。

- **① 推到最大**：commit message 带任务号就自动把任务标 done。
  - 判定：**崩**。推理链：
    1. 提交粒度≠任务粒度（一个 commit 改多处、一个任务多个 commit、一个 commit 只是中间修复）；
    2. 开发仓库与未来业务项目混淆，dogfood 数据污染正式台账；
    3. 提交信息随意时任务号挂错；
    4. 自动 done 绕过验收清单。
  - 成立边界：commit 号只作只读线索，完成判定仍在 checklist/人。
- **② 砍到最小**：dogfood 只把自身 backlog 手动录进台账，完全不读 git。
  - 判定：**成立**。
- **③ 反常识倒置**：不是用 git 证据证明任务完成，而是**用台账任务反向约束提交**——没有任务号的 commit 被 pre-commit hook 提示拦截，先有计划改动才能提交。
  - 新变体见 **D2-R3-08**（任务号可选强约束 hook 提示，非自动完成）。

## 压测 09 · 计划↔执行承诺对账（母本 D2-21 / D1-R2-19）

**母本机制**：用 completion-history 真实 completedDate + 相邻快照 diff，纯派生「上期承诺 N、兑现 M、延期 K、新增 L」对账表。

- **① 推到最大**：每条承诺逐句追责，未兑现全部标红、对账到每句话、跨周期追溯。
  - 判定：**崩**。推理链：
    1. 单人场景变成自我责备表，仪式负担大于价值；
    2. 历史承诺脱离当时语境（本来就放弃了的事被反复揪出）；
    3. 陈年旧账累积，对账表失去当下指导意义。
  - 成立边界：只对同周期承诺对账，跨周期自动失效。
- **② 砍到最小**：周报末尾人手填三行「上期承诺/兑现/未兑现」，零技术。
  - 判定：**成立**。
- **③ 反常识倒置**：对账方向反转——不追「没做到」，只追「意外做到了什么」（正向惊喜清单：计划外完成、超额、被忽略却做好的事），未兑现静默处理。
  - 新变体见 **D2-R3-09**（承诺保鲜期：只在同周期内对账，过期自动归档不追责）。

## 压测 10 · 证据自动闭环杂交（母本 D2-R2-16 自证周报 / D5-R2-14 审计带 diff / D1-R2-16 任务→会话→证据管道）

**母本机制**：到点自动开会话、会话结束自动收 diff 证据、审计员带真实 hunk 判断证据是否够、周报条目自动绑证据片段，人只在收口确认。

- **① 推到最大**：全链路自动——自动开会话、自动收证据、自动建议完成，人只按一个总确认。
  - 判定：**崩**。推理链：
    1. 自动开会话产生大量空转会话（开了但没干活）；
    2. 证据误绑后总确认一键全放，人退化为橡皮图章；
    3. 自动化越完整，人越不看证据，闭环变成自我感动；
    4. 环境前提（schedule 可投递、session 可创建）缺失时管道静默断。
  - 成立边界：自动只到「备齐候选」，收口确认必须人逐条看。
- **② 砍到最小**：闭环只剩「周报草稿里手动贴一条证据链接」，其余全自动全删。
  - 判定：**成立**。
- **③ 反常识倒置**：证据不是用来**证明**完成，而是用来**否证**——默认任务完成，审计员的职责是挑出「证据缺失/证据不符」的反例，举证责任反转。
  - 新变体见 **D2-R3-10**（空转会话：轮次多但零改动，自动标为「可疑未完成」反向挂回任务）。

## 压测 11 · 开工建会话→执行报告自动回挂（母本 D5-R2-15）

**母本机制**：点开工自动建带 taskId 元数据的会话，结束后聚合轮次/文件量/present/feedback 成执行报告草稿回挂。

- **① 推到最大**：每个任务自动开会话，结束自动聚合报告。
  - 判定：**崩**。推理链：
    1. 会话数量爆炸（大量任务从不开会话则永远无报告，形成歧视性缺失）；
    2. taskId 元数据易随 fork/复用丢失，绑定断链；
    3. 用轮次/文件量冒充完成（聊得多≠做完）。
  - 成立边界：人显式点开工才建，报告只陈述事实不宣称完成。
- **② 砍到最小**：点开工手动建会话，结束人手贴一句总结。
  - 判定：**成立**。
- **③ 反常识倒置**：不统计执行量（轮次/文件量），只审计「会话与任务是否真相关」——相关性存疑的高执行量反而标红，防止用忙碌冒充完成。
  - （并入 D2-R3-10，不单列新编号。）

## 压测 12 · 证据新鲜度对账卡（母本 D4-R2-15）

**母本机制**：证据捕获时间戳 vs 任务 updatedAt 偏差超窗标「可能不覆盖最新」，三类证据按新鲜度排序，可一键重取。

- **① 推到最大**：每条证据实时监控过期，过期即自动撤下。
  - 判定：**崩**。推理链：旧证据常常仍然有效（一张白板照三个月后照样说明当时分工），按时间自动撤下误删；阈值 arbitrariness（24h？7 天？）无客观依据。
  - 成立边界：只标注偏差、不撤下、不排名，重取由人发起。
- **② 砍到最小**：证据只显示捕获日期，不做偏差计算。
  - 判定：**成立**。
- **③ 反常识倒置**：越旧的证据越权威（历史快照不可篡改，旧证据代表「当时事实」）；新鲜度不用于优劣排序，只用于**时态标注**（当时事实 / 现状证据）。
  - 新变体见 **D2-R3-11**（证据带时态双标签，不按新旧排名）。

## 压测 13 · 投影→干活→回收单行道（母本 D1-R2-18，对照 D5-20 禁止回写）

**母本机制**：开工把开放子树镜像进会话 todo/goal，会话结束把 todo 勾选结果单向回收为完成候选，goal 不回写。

- **① 推到最大**：会话 todo 勾选自动回写台账完成。
  - 判定：**崩**。推理链：会话勾选常是临时清单项（「查个资料」），不是台账承诺；自动回写污染正式状态；D5-20 原本禁止回写正是为此。
  - 成立边界：回收只产候选草稿，人确认；或干脆保持 D5-20 的禁止回写。
- **② 砍到最小**：不回收，todo 纯演示投影（D5-20 原方案）。
  - 判定：**成立**。
- **③ 反常识倒置**：回收方向反转——台账勾选驱动会话 todo 勾选（人在面板勾完，会话侧清单同步），而不是会话驱动台账。
  - （方向变体，不单列新编号。）

## 压测 14 · 会议直读历史会话补速记（母本 D3-17）

**母本机制**：会后归纳时直读相关历史会话有界快照，补充粘贴速记里的遗留行动项。

- **① 推到最大**：自动把所有相关历史会话塞进纪要正文。
  - 判定：**崩**。冗长、无关片段混入、纪要失焦、模型把旧讨论当新决议。
  - 成立边界：只列候选标题由人选，不自动进正文。
- **② 砍到最小**：纪要仍只靠粘贴，零会话读取（ADL-025 现状边界）。
  - 判定：**成立**。
- **③ 反常识倒置**：不在会后补历史，而在**会前**生成「本次开会前应读的历史片段包」；历史服务于即将发生的会，而非追认已经开完的会。
  - 新变体见 **D2-R3-12**（会前准备包，与会后捕获分开）。

## 压测 15 · present/workspace-changes 回填 evidenceUrl 草稿（母本 D2-18）

**母本机制**：订阅轮次结束，把 present 声明与本轮文件改动整理成只读证据草稿挂任务，人确认才写，不自动改状态。

- **① 推到最大**：present 声明 + 文件改动自动等同完成证据，自动标 done。
  - 判定：**崩**。推理链：present 只是展示声明（可能展示半成品/演示版）；文件改动≠满足验收清单；两者都只是「发生过动作」，不是「达到标准」。
  - 成立边界：证据只作线索，完成判定权永远在 checklist 客观项 + 人。
- **② 砍到最小**：evidenceUrl 纯手动粘贴框，零事件监听。
  - 判定：**成立**。
- **③ 反常识倒置**：证据越丰富越可疑——「挂满证据的完成」反而触发审计员二次核对（过度举证=辩护心虚），裸完成（人一句话声明）默认通过。

## 压力过程中长出的新变体（全保留，未评分）

### D2-R3-01 孤儿证据池：证据主动找人（压测01 倒置）
- **机制**：自动捕获的改动/会话片段若确定性匹配不到任何任务，不丢弃，进孤儿证据池；系统周期性反向提议「这批痕迹可能属于某任务，或该新建一条」，人裁决归属；池内痕迹也供周报复用。主客体从「人找证据」翻成「证据等人认领」。
- **触点**：workspace-changes/session-query 候选 + 一个只读孤儿表 + 归属草稿。
- **边界条件**：池容量有界、过期清理，防止痕迹堆积。

### D2-R3-02 会话原文为权威、台账为缓存（压测02 倒置）
- **机制**：台账记录与会话原文冲突时，系统标红「与原始会话不符」，以原文为准提示台账修正，而非会话给台账佐证；台账降级为可被原文纠正的派生层。
- **触点**：session-query 原文比对、冲突标红草稿。
- **边界条件**：只标冲突、不自动改台账；单人语境下「原文」也可能是错的，仍留人声裁决。

### D2-R3-03 置信分层收件箱 + 误报配额（压测03 修正）
- **机制**：捕获候选按置信分三层：高置信直接进待认领箱、中置信排队等批量处理、低置信直接丢弃；每周期误报（被人丢弃的）设配额，超配额自动收紧抽取口径。
- **触点**：suggestion-engine 范式扩展、provenance 丢弃计数。
- **边界条件**：没有高置信时宁可空箱，不用噪声凑数。

### D2-R3-04 散会后 60 秒黄金认领窗口（压测04 倒置）
- **机制**：不开全程实时模式；散会后给一个 60 秒短窗口，系统把刚结束会议的转写/速记里的候选行动项快速弹出，人在窗口内批量认领/丢弃，过期候选保留到次日草稿箱。会中只速记、会后短窗口升格。
- **触点**：meeting 定稿流程 + 短时窗口 UI。
- **边界条件**：窗口可跳过；超时不自动落库。

### D2-R3-05 附件只挂会议/交付物两层（压测05 收敛）
- **机制**：禁止把图片附件挂到每条任务；附件只允许挂在会议纪要与交付物两个实体下，任务需要看图时从所属会议/交付物引用，避免图片碎片化。
- **触点**：attachment 句柄 + schema 层挂载位置限制。
- **边界条件**：任务侧只读引用，不复制。

### D2-R3-06 webhook 事件 deliveryId 幂等去重（压测06 最小必备件）
- **机制**：即便不接 webhook，也先实现 deliveryId 去重登记；将来接入时重投事件不产生重复草稿，去重表只增、短 TTL。
- **触点**：provenance/idempotency 范式。
- **边界条件**：无 webhook 时此表为空，零成本挂着。

### D2-R3-07 出站只增日志 + 撤销队列，外部删除绝不级联（压测07 安全边界）
- **机制**：每条出站写留只增日志（外部 ticket id、时间、载荷快照）；提供「撤销单条」（发备注关闭/更新），本地删除任务绝不触发删除外部 issue；双向同步永久不做。
- **触点**：新增 outbound 日志表、mcp-client 写工具、approval seam。
- **边界条件**：外部系统不支持撤销时只留日志不假装可撤。

### D2-R3-08 任务号反向约束提交（pre-commit hook 提示，压测08 倒置）
- **机制**：不是 commit 自动完成任务，而是开发仓库 pre-commit hook 提示「本次提交未关联任务号」，人补号或明确豁免；任务号是提交的前置礼貌，不是完成的证据。
- **触点**：本地 git hook（只读提示，非拦截强制）。
- **边界条件**：纯提示不阻断，dogfood 专用、不推广到业务项目。

### D2-R3-09 承诺保鲜期：只同周期对账，过期自动归档（压测09 收敛）
- **机制**：每条承诺带保鲜期（默认一个报告周期），跨周期未兑现自动转归档「历史未决」，不再进入当期对账表追责；对账只面对当下。
- **触点**：completion-history + 周期边界纯函数。
- **边界条件**：归档可手动捞回，但不主动翻旧账。

### D2-R3-10 空转会话反向标「可疑未完成」（压测10/11 合成）
- **机制**：执行报告里轮次多但零文件改动/零 present 的会话，不记为「已工作」，反向给任务挂一条可疑提示「聊了但没产出，是否真完成？」；用忙碌度反证完成，而非用忙碌度证明完成。
- **触点**：session-query 轮次统计 + workspace-changes 文件量 + 草稿提示。
- **边界条件**：纯提示，不改状态；纯讨论型任务（调研/决策）豁免此判定。

### D2-R3-11 证据时态双标签：当时事实 / 现状证据，不按新旧排名（压测12 倒置）
- **机制**：每条证据打「当时事实」（历史快照、不可篡改、代表那一刻）或「现状证据」（最新改动、代表现在）标签，并列展示而非按新鲜度排序；旧的不当作失效，新的不当作更权威。
- **触点**：evidenceUrl 元数据标签、纯派生排序改为分组。
- **边界条件**：标签由捕获时机自动打，人可改。

### D2-R3-12 会前准备包：开会前自动列应读历史（压测14 倒置）
- **机制**：会议创建/开始前，按项目与议题关键词从历史会话/报告里捞相关决策片段，生成「会前应读包」给参会人；历史服务于即将发生的会，会后补记只靠粘贴。
- **触点**：session-query 只读、meeting 创建流程、有界快照（session-reference）。
- **边界条件**：包内容人可删，不自动写进纪要。
