# D3 · 阶段1 第3轮：极端化压力测试 —— 簇「产品形态与平台归属」

> 执行者：D3。母本取自 round1-pool.md / round2-pool.md 中本簇（独立 pm-core/薄适配层、本地 MCP server、静态 viewer/纯开放文件、独立 App、完全吞并 runtime、被原生替代退出协议、PROJECTS.md 文件路线、零遥测/单机十年卖点、npm 开源/市场/定价、SDK/TUI 壳、格式供应商、反向薄壳、合规端口、极致被动）。
> 纪律：发散期压力测试，不评分、不做可行性终判，只找「崩在哪 / 什么条件下反而成立」的边界。每个母本至少 2 种施压，三种模式（推到最大 / 砍到最小 / 反常识倒置）合计覆盖。过程中长出的变体单独编号 D3-R3-x，全保留。

## 施压 1｜母本：独立 pm-core 纯内核 + 薄适配层（D1-19、D2-05、D3-07、D4-23、D5-14；反叛 D3-R2-21、D5-R2-21）

### 1a. 推到最大
- **极端形态**：把内核抽成一个真正多后端可插拔的库——存储可换 JSON/本地库/远程，UI 可换面板/静态站/MCP，模型可换 dsh llm/标准 API/Ollama，七实体、zod 校验、CPM、健康分、导出全部进 core，适配层只剩胶水；为将来任何第二个壳留足接口。
- **判定：崩（前提：第二个壳出现之前）**。
- **推理链**：现有代码里真正无语义、换壳可复用的只有 health 分、report-diff、`core/gantt.ts` 只读 CPM（`criticalPath()`、slack、前置依赖图）这类纯函数；而七实体语义（任务/里程碑/风险/证据/effortHours/manualProgress）、父子互斥、编号规则、草稿确认制都与「人怎么用这个产品」耦合。抽象层越全，单人要同时维护「core 契约 + 每个后端实现」，上游 dsh 一次 breaking（ADL-034 升级断点本就在适配层），抽象层反而多一跳转发要修。**崩的边界条件**：复用主体数 = 1（只有 dsh 一个壳），此时抽象是给想象中的第二个客户付现实维护税（与 D5-R2-21 同）。**成立条件**：第二个壳真实立项（MCP server 或独立 App 被决定要做），且 core 里 80% 是纯函数。

### 1b. 砍到最小
- **极端形态**：物理上什么都不抽，只在代码里守住 product/11 的 `PmDomain` 接口边界（存储后端可换），等到第二个消费端出现再动手；唯一可抽的只有 health/report-diff/CPM 三个无语义纯函数。
- **判定：反而成立**。
- **推理链**：`PmDomain` 接口本来就只是存储后端抽象（product/11「换后端零改动」），把它误推广成「换壳零改动」才是过度承诺；砍到只剩纯函数后，没有任何「为想象需求维护的层」，上游 break 直接贴合重写接线，单人成本最低。**成立条件**：1–2 年内明确不出第二个壳；上游 breaking 频率低。

### 1c. 反常识倒置
- **极端形态**：主客体互换——pm-core 不是「我为换壳准备的仓库」，而是**反向被 dsh 官方吸收的捐赠候选**：把 core 写得标准、无 dsh 私有依赖，目标是让未来 dsh 原生团队直接拿走七实体模型；宿主反过来「跪求插件贡献者」。
- **判定：有条件成立**。
- **推理链**：倒置点在于独立内核的价值不是「我另立门户」，而是「让官方省掉重写」；成立条件是 core 确实无 cordis/私有依赖（目前 `src/index.ts` 仍 `inject=['commands','storageDomain']`，需先脱钩），且官方存在采纳路径。崩点：官方根本不接收外部贡献，捐赠变独角戏。
- **变体 D3-R3-01**：只抽「无语义纯函数包」（health/report-diff/CPM/对账）为独立小库发布，实体语义留在插件内不抽——把「独立内核」从架构口号缩成一份可独立测试的纯函数工具集。

## 施压 2｜母本：本地 MCP server，dsh 只是众多客户端之一（D1-10、D2-27、D3-15、D4-20、D5-15）

### 2a. 推到最大
- **极端形态**：pm-tool 起一个本地 MCP server，把七实体全部 CRUD 工具暴露出去，手机 MCP 客户端、另一台机器、其他 agent、同事都能连、都能写；写仍走确认，但确认也由各客户端发起。
- **判定：崩（边界：并发写 / 单写者假设）**。
- **推理链**：`docs/backup-sync.md` 与现状都是**单写者、单台机器**假设，无版本号、无 CAS、无 last-write-wins 冲突合并（provenance-store 每项目 cap 20 是本地操作账本，不是并发事务）。两个客户端同时改一条任务，后写覆盖先写，台账无感知损坏。第二层崩点：MCP 生态本身若未被目标用户采用（生态失败），为一个没普及的协议自建 server 是零收益投入。**崩的边界条件**：连接的写客户端 ≥2，或 MCP 协议在 12 个月内未成为该人群默认接口。

### 2b. 砍到最小
- **极端形态**：server 只暴露**一个只读工具** `pm_health_lights`（逾期/临期/高影响风险/今日行动项），无任何写工具、无确认、无状态变更。
- **判定：反而成立**。
- **推理链**：只读面不碰单写者假设，零并发风险；手机/其他 agent 只「看」不「改」，确认仍回电脑（与 D5-R2-08 移动只读一致）。成立条件：server 只是 dsh 已有本地服务的一个额外只读出口，不新增写面。

### 2c. 反常识倒置
- **极端形态**：「MCP server」这个外壳是借口，真实目的只服务**一个特定客户端**（比如手机只读，或未来自己的 TUI），根本不追求「众多客户端之一」；把多端通用当卖点是自欺。
- **判定：有条件成立 / 暴露真实需求**。
- **推理链**：倒置点——公开通用接口与真实使用面（1 个客户端）不匹配时，维护通用协议的成本被白付。成立条件：承认 server 是为某个具体客户端铺的路，不为通用性交协议税。
- **变体 D3-R3-02**：最小本地只读端点（一个 HTTP GET `/status` 或单只 MCP 只读工具），不建完整 MCP server，只给手机/浏览器一个健康灯页面。

## 施压 3｜母本：静态 viewer / 纯开放文件，dsh 可装可不装（D2-26、D3-08、D4-25、D5-18；Markdown 真源 D3-14 另见施压 13）

### 3a. 推到最大
- **极端形态**：静态站要实时刷新、多人在线查看、自动从 JSON 增量更新、甚至内嵌轻协作评论，变成一个常驻 web 应用。
- **判定：崩**。
- **推理链**：静态文件无状态、无后端、无鉴权、无写；一旦要实时/多人/回写，必须长出一个轻后端，「零宿主、双击即开」的前提当场死亡，退化成又一个要部署要维护的服务。KB-014/delivery §9 现状只信任本机 loopback，远程多人连是额外一整套访问控制。**崩的边界条件**：观众 ≥2 人且要求实时，或出现任何写回需求。

### 3b. 砍到最小
- **极端形态**：一个 `index.html` + 一份 `data/*.json`，双击打开只读渲染，无构建、无依赖、无网络；十年后任何浏览器都能开。
- **判定：反而成立**。
- **推理链**：现有 `core/export.ts` 已经能写 Markdown 到 exports/，把同一批 JSON 渲染成静态 HTML 是纯本地确定性输出，不依赖 dsh 是否安装、模型是否在线。成立条件：定位为「快照/档案/给别人看的一次性视图」，不要求它继续编辑。

### 3c. 反常识倒置
- **极端形态**：与「数据开放、可被任何人消费」相反——静态包**故意不开放**：带口令/加密，只发给指定人，「打不开」本身是隐私卖点；不追求通用可读，追求授权可读。
- **判定：有条件成立**。
- **推理链**：倒置点是 D1-26「开放文件十年可读」把开放当美德，而真实 PM 台账含风险/进展/个人判断，对外分享本就需授权。成立条件：产品定位偏私人档案；崩点：一旦要对外状态页（R2-07/R2-09），不开放就与分发冲突。
- **变体 D3-R3-06**：隐私保险箱定位——台账不可导出、不开放、加密落盘，「谁也拿不走」替代「谁都读得到」成为长寿卖点（详见施压 8c）。

## 施压 4｜母本：独立本地 App，AI 走方舟标准 API 按量（D4-24）

### 4a. 推到最大
- **极端形态**：独立 App 长成可分享的团队应用——账号、多项目、多人协作、云同步、订阅计费。
- **判定：崩（边界：单人带宽 + 成本结构）**。
- **推理链**：`docs/personal-billing-plan.md` 明确：脱离 dsh 独立部署持 Coding Plan key **违规**，必须走标准 API 按量付费，¥40/月套餐合规优势消失；单人维护账号体系/同步/合规/计费本身是全职工作。**崩的边界条件**：用户数 >1 且需要云同步，或开始按 token 按量付费导致成本不可控。

### 4b. 砍到最小
- **极端形态**：独立 App 退化为一个纯本地文件读写 + 视图壳，AI 能力整个删掉（只读、只导出），模型调用留给 dsh 或别处。
- **判定：反而成立**。
- **推理链**：剥掉模型后 App 只是个更漂亮的 JSON 查看/编辑器，无 key、无合规、无按量成本，与施压 3 的静态站同构。成立条件：AI 草稿不是该壳的职责。

### 4c. 反常识倒置
- **极端形态**：独立 App 的真实卖点不是功能，而是「**脱离 dsh 的心理备份**」——用户买/留它只为「万一 dsh 没了我还在」，卖的是保险不是生产力。
- **判定：有条件成立**。
- **推理链**：倒置点——功能上独立 App 重复了面板已有视图，其存在意义是降低对宿主的依附焦虑；成立条件：宿主停更/弃用焦虑是真实情绪（R5 平台存在性）；崩点：若宿主稳定，备份价值无人感知。

## 施压 5｜母本：完全吞并，pm-tool 内化最小 agent runtime（D1-R2-14、D2-R2-11、D3-R2-11、D4-R2-13、D5-R2-11）

### 5a. 推到最大
- **极端形态**：pm-tool 自己实现完整 agent loop：prompt 装配、多轮工具调用、上下文压缩、审批中断、模型路由、错误重试全自研，dsh 只剩可替换模型通道和窗口。
- **判定：崩**。
- **推理链**：这等于重写半个 harness——上下文管理、工具调度、function-calling 兼容、模型差异、会话状态都是 dsh 已经做过且在演进的部分，单人重做必然「追上但追不平」，并背上与上游平行演进的双份维护。`personal-billing-plan.md` 里免费池模型随机、function-calling 不保证（KB-034）等坑，自研循环要自己再踩一遍。**崩的边界条件**：要求多轮自主/工具循环而非一次性文本生成（ADL-036 现状本就是一次性生成、确定性落库在我方代码）。

### 5b. 砍到最小
- **极端形态**：只内化「单轮取一段模型文本」这一步（现状就是如此：AI 只生成草稿文本，落库由我方 zod 代码做），不养循环，不借多轮。
- **判定：反而成立（=现状）**。
- **推理链**：最小吞并就是现在的形态——不持有 loop，只借一次性模型输出；这恰好是 ADL-036 的边界，成立条件与现状一致。

### 5c. 反常识倒置
- **极端形态**：吞并到一半自我取消——pm-tool 把自己长出的 loop 重新还给 dsh，只保留面板与台账，发现「自己当 runtime」是伪需求。
- **判定：反而成立（作为一个自然收敛点）**。
- **推理链**：倒置点是吞并的终点不是取代宿主，而是试错后确认宿主循环够用；成立条件：实测自主循环带来的增量低于维护成本。
- **变体 D3-R3-07**：「吞并自我取消」剧本——先做出最小内置循环做 A/B，一个版本后若增量不明显则拆回，保留卸载路径，避免吞并变成沉没成本。

## 施压 6｜母本：被宿主原生替代时的退出/退役协议（D1-R2-14、D2-R2-12、D3-R2-11、D4-R2-13、D5-R2-12）

### 6a. 推到最大
- **极端形态**：常驻监测宿主版本是否长出等价 PM 能力，自动双写过渡、并行运行、自动迁移、迁移校验器长期维护。
- **判定：崩（边界：退役事件可能永不发生）**。
- **推理链**：为一个概率未知、时间未知（dsh 何时/是否原生长出看板）的事件，长期养一个迁移监测器和双写层，是持续维护税；宿主原生格式未来才知道，现在写的映射表届时多半要重写。**崩的边界条件**：12–24 个月内宿主未长出该能力，监测器成为死代码；或作者在退役发生前已停更。

### 6b. 砍到最小
- **极端形态**：只留一页纸迁移说明（七实体字段→未来原生功能对照）+ 现有 `core/export.ts` 的 JSON/Markdown 导出，零运行时代码、零自动监测。
- **判定：反而成立**。
- **推理链**：退役本质是「数据能带走、历史读得到」，现有导出通道已满足 90%；一份字段映射文档成本为零。成立条件：承认迁移届时手动做，不追求自动化。

### 6c. 反常识倒置
- **极端形态**：产品以「**主动被替代**」为成功设计——逐个把成熟功能送给宿主原生，自己主动退役，被吸收即胜利（捐赠式退休），而不是抵抗。
- **判定：有条件成立**。
- **推理链**：倒置点把「被替代」从失败改写成交付完成；成立条件：维护者目标是做完一件事而非长期占有市场；崩点：若作者想长期运营，主动让位与收入目标冲突。
- **变体 D3-R3-03**：捐赠式退休清单——每个功能标注「可被原生替代的成熟度」，到点主动标记 deprecated 并停止加功能，只修迁移，把退出写成 roadmap 的一节而非应急预案。

## 施压 7｜母本：PROJECTS.md 文件路线，借 AGENTS.md / agent-instructions 零代码进上下文（D2-06、D5-13；杂交 D4-R2-18 带有效期戳）

### 7a. 推到最大
- **极端形态**：PROJECTS.md 与 JSON 双向实时同步，每轮对话后自动回写，保持文件与库完全一致，agent 改文件也能落回实体。
- **判定：崩（双写漂移）**。
- **推理链**：AGENTS.md/agent-instructions 是**指令载体不是数据库**，被 agent 自由改写后编号、父子互斥、环检测（gantt 前置依赖图）这些 zod 约束在纯文本里难以保证；两处真源必然漂移，人手改 md 后回写可能破坏结构。**崩的边界条件**：文件被双向写；只读投影（只渲染不回写）则不崩。

### 7b. 砍到最小
- **极端形态**：一次性手动/命令渲染一份 PROJECTS.md 快照进工作区，只读、不回写、不自动刷新，AGENTS.md 仅引用它。
- **判定：反而成立**。
- **推理链**：纯读时派生（ADL-039「读时派生」精神），不新增真源；成立条件：接受文件是会过期的快照，配合 D4-R2-18 的有效期戳警告。

### 7c. 反常识倒置
- **极端形态**：让 md 文件反过来成为唯一真源，pm-tool 只是 PROJECTS.md 的一个渲染/校验器——文件统治插件，而不是插件统治文件。
- **判定：有条件成立 / 暴露张力**。
- **推理链**：倒置点与 D3-14（Markdown 真源）合流；成立条件：用户本来就习惯手改文本、结构化约束可以放宽；崩点：一旦需要 CPM 关键链/自动编号/健康分，纯文本承载不住（见施压 13）。

## 施压 8｜母本：零遥测承诺 / 单机单写者「十年可读」硬卖点（D1-22、D1-26）

### 8a. 推到最大
- **极端形态**：把「绝不联网、绝不上报、绝不外发」做到加密级封闭，拒绝一切外部连接、外部读取、外部分享，网络能力全部关闭。
- **判定：崩（与对外价值自相矛盾）**。
- **推理链**：封闭与池内大量方向直接冲突——对外状态页（R2-07/09）、反向写外部（R2-04/05）、手机只读（D5-R2-08）、插件市场分发（D2-R2-13）都需要出网或被他人读取。把技术约束（单机自用）抬成产品信条后，产品自我封闭、永远只有一个本机读者（呼应 D3-R2-19 反叛）。**崩的边界条件**：目标包含任何他人阅读/外部同步/公开分发。

### 8b. 砍到最小
- **极端形态**：卖点只写一句「你的数据不出本机」，不建任何额外机制、不做加密架构、不做联网禁令开关。
- **判定：反而成立**。
- **推理链**：现状本就零上报（全仓无遥测代码），承诺成本为零；成立条件：把它作为一句隐私声明，而非一套被工程化牺牲其他能力的定位。

### 8c. 反常识倒置
- **极端形态**：与「开放文件十年可读」相反，**不可导出、不开放、强加密**才是卖点——一本谁也拿不走、连作者换机都要口令的私人档案。
- **判定：有条件成立**。
- **推理链**：倒置点把 D1-26 的「可被未来任何人读」换成「只属于当下这个人」；成立条件：定位为私人记忆/个人复盘档案；崩点：与「十年后迁移/可移交」彻底对立，作者换机/离职即丢失。

## 施压 10｜母本：反向薄壳 / AI 通道迁出 dsh，插件退回纯离线 CRUD（D1-20、D5-17）

### 10a. 推到最大

- **推理链**：倒置主客体：谁依附谁？只要数据格式开放、导出完整，壳（dsh）可换，账不换；成立条件：开放格式 + 成品导出扎实（反而是施压 3/13 的功课），壳随时可弃。

## 施压 11｜母本：退化成格式供应商，台账写成 iCal/CSV/Markdown 让已有工具消费（D1-21）

### 11a. 推到最大
- **极端形态**：双向适配 iCal 订阅、CSV、Excel、Notion、Obsidian、飞书等全格式，进得来也出得去，pm-tool 只做校验器+编辑器。
- **判定：崩（被外部格式绑架）**。
- **推理链**：每个外部格式一个维护面，格式由对方版本决定变更（iCal 规范、Excel 导出、Notion API），单人被多个上游格式变更牵着走；双向同步还要解决与施压 2 相同的写冲突。**崩的边界条件**：适配格式 ≥2 且要求双向。

### 11b. 砍到最小
- **极端形态**：只单向导出一份 iCal 订阅（截止日期/里程碑进用户已有日历）+ 一份 CSV，只读消费，不回写。
- **判定：反而成立**。
- **推理链**：单向导出无冲突，用户已有日历/Excel 直接消费，pm-tool 不承担维护对方格式的双向责任；成立条件：定位为「喂给现有工具」，不追求成为对方工具的管理器。

### 11c. 反常识倒置
- **极端形态**：不当供应商，反过来让别的工具成为 pm-tool 的只读前端——pm-tool 是唯一事实源，别人来读我，而不是我去适配别人。
- **判定：有条件成立**。
- **推理链**：倒置点把「我写进你的格式」换成「你来读我的标准格式」；成立条件：开放 JSON/静态站足够好读（施压 3b）；崩点：用户现有工具不认自定义格式，供给方心态落不到现实工作流。

## 施压 12｜母本：独立 CLI/TUI 壳经 sdk JSON-RPC 只借模型（D1-31）

### 12a. 推到最大
- **极端形态**：TUI 复刻面板全部九视图、多项目切换、草稿确认、编辑齐全，成为 dsh 之外的完整第二前端。
- **判定：崩（第二套 UI 维护）**。
- **推理链**：面板已在 dsh 内实现，再维护一套终端 UI 是双份视图代码；真实 TUI 用户（终端重度用户）与 dsh 图形面板用户大概率不重叠，第二前端用户数趋零。**崩的边界条件**：没有明确的无 GUI 使用场景（服务器/SSH）作为刚需。

### 12b. 砍到最小
- **极端形态**：一个 `pmcli` 只做查询和导出（`pmcli status`、`pmcli export`），不做编辑、不做确认、不接模型。
- **判定：反而成立**。
- **推理链**：命令行只读查询成本低，可挂进脚本/alias，复用现有 PmDomain 只读方法；成立条件：服务自动化而非终端交互人群。

### 12c. 反常识倒置
- **极端形态**：CLI 根本不是给人用的，而是给脚本和另一个 agent 用的**机器接口**——它是 MCP server 的前身/兄弟，人只是顺便能用。
- **判定：反而成立（身份重定义后成立）**。
- **推理链**：倒置点把「人用 TUI」改成「机器管道」，CLI 输出结构化 JSON 供脚本消费；成立条件：目标是自动化巡检/定时导出，而非人坐在终端前。
- **变体 D3-R3-05**：机器优先 CLI——所有命令输出结构化 JSON、支持管道，TUI 交互层砍光，把它定位成自动化接口而非第二个前端。

## 施压 13｜母本：Markdown 唯一真源，JSON 仅派生缓存（D3-14；关联反叛 D3-R2-18 静态成品才长寿）

### 13a. 推到最大
- **极端形态**：七实体全部存为 md + frontmatter，协作与版本走 git diff，结构化关系（前置依赖、父子、编号）全在纯文本里表达和校验。
- **判定：崩（结构承载不住）**。
- **推理链**：`core/gantt.ts` 的 CPM 关键链、`predecessorIds[]` 环检测、任务父子互斥、自动编号、健康分都依赖类型化结构与 zod 校验；纯文本 frontmatter 里这些约束易被人直接改坏，git diff 无法表达依赖图语义。**崩的边界条件**：项目需要关键链/自动编号/健康分等结构化派生。

### 13b. 砍到最小
- **极端形态**：只有叙事层（周报、会议纪要、复盘文字）存 md，任务/风险/里程碑等结构实体仍存 JSON。

### 13c. 反常识倒置
- **极端形态**：md 真源也会烂，真正的真源是**定时固化的 PDF/静态归档**——结构 JSON 和 md 都是当期工作态，档案本体是不可再改的渲染成品（接 D3-R2-18）。
- **判定：有条件成立（作为寿命分层的顶层）**。
- **推理链**：倒置点把「正在编辑的文件」与「留给未来的档案」分开；成立条件：里程碑/项目结束时固化一份成品；崩点：固化需要额外动作，无人执行则档案层空缺。
