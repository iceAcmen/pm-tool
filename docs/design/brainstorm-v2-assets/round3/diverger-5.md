# D5 · 阶段1 第3轮：极端化施压（规划智能与项目组合簇）

> 簇范围：估时校准、what-if 沙盘、延期预测、项目模板库、组合取舍视图、迁移共存、持续状态页、移动端、office/PDF 导出、日历/外站写入。
> 已通读 round1-pool 与 round2-pool。每个母本至少压 2 种极端（推到最大 / 砍到最小 / 反常识倒置），三种模式全簇覆盖。判定只给边界条件，不评分。新变体单独编号 D5-R3-x，全部保留。

## 施压单元 1：估时校准闭环（母本 D1-R2-01 / D2-R2-01 / D3-R2-01 / D4-R2-01 / D5-R2-01）

### ① 推到最大
每条任务强制填 estimateHours；实时拟合个人速度曲线；WBS 草稿按校准系数锁死工时；系数跨项目、跨人共享。
### ② 判定：**崩（在样本小/任务异质时）**
- 推理链：中位数+四分位需要同类样本，**N<10 同类任务时系数是噪声而不是信号**，高估 40% 这个结论可能只来自 2 条任务；强制填估时本身就是一笔新录入摩擦，直接撞上「该被消灭的是维护录入」（D3-R2-20/D5-R2-20）；一次性创新任务（第一次做的功能）与重复维护任务被强行归一，系数把异常当常态；WBS 由模型拆出、本就没有工时概念，硬加 estimate 字段在草稿链路上断档。
- **成立条件**：同类任务 N≥30、任务类型稳定（重复型多）、PM 本来就愿意填工时；否则崩。
### ③ 砍到最小
只剩一条 `/pm estimate <taskId>` 打印「同类历史实际工时中位数」，无持久系数、无 UI、不回填、不喂模型。**反而成立**：50 条任务内一个只读聚合即可用，零维护。
### ④ 反常识倒置
「估时永远错才是价值」：校准系数不该让下次更准，而该把「你一贯高估 40%」本身变成谈判与汇报材料；越追求估时准越有害——伪精确麻痹决策者。
### ⑤ 新变体
- **D5-R3-01**（由倒置长出）：偏差页只展示系统性偏误方向（「联调类你一贯高估、文档类你一贯低估」），**绝不生成「修正后估时」**，把偏误当自我认知材料而非预测工具。

## 施压单元 2：what-if 排期沙盘（母本 D1-R2-02 / D2-R2-02 / D3-R2-02 / D4-R2-02）

### ① 推到最大
全参数自由拖拽（日期/负责人/删任务/加任务）、AI 陪聊推演、多情景并排评分、自动推荐「最优解」。
### ② 判定：**崩（无工作量数据 + 单人无争用）**
- 推理链：CPM 只按日历天偏移算 ES/EF/LS/LF/slack（ADL-051 已明确不建模 lag、不做资源平衡），**挪人不重算工作量压平**，沙盘给出的是「日历幻觉」而不是负载现实；单人场景没有第二个真实资源，「某人过载」是自己跟自己比；多情景并排制造选择疲劳，最优解推荐需要估时数据（单元 1 已判小样本崩）。
- **成立条件**：任务带 predecessorIds 依赖链、只做日期敏感性、情景≤2 个；扁平无依赖清单上沙盘退化为无意义滑动。
### ③ 砍到最小
一条命令 `/pm what-if move <task> +5d`，打印关键链是否移动、哪个里程碑滑出、谁 slack 归零，纯文本，无拖拽 UI、不落库。**反而成立**。
### ④ 反常识倒置
沙盘最该推演的不是「怎么保 M1」而是「主动砍掉哪条任务 M1 反而更稳」——沙盘用于放弃而非保全。
### ⑤ 新变体
- **D5-R3-02**（由倒置长出）：沙盘只提供「删减情景」（删哪条非关键任务，M1 回到安全 slack），不提供「延长/补人情景」；把决策引向范围裁剪而非时间膨胀。

## 施压单元 3：延期预测区间（母本 D1-R2-03）

### ① 推到最大
每日刷新乐观/基准/悲观三条线、自动标红、按阈值推送 PM。
### ② 判定：**崩（项目早期 + 速率非平稳）**
- 推理链：completion-history 周序列在前 4–6 周方差极大，**样本<6 周时区间宽到无信息**；单人项目节奏被假期、中断、切换项目扭曲，周完成速率非平稳，用滑动速率外推等于把噪声当趋势；区间预测给人虚假确定感，比不预测更危险。
- **成立条件**：项目连续≥6 周稳定产出、无大块中断、backlog 规模稳定；早期项目直接崩。
### ③ 砍到最小
里程碑旁只显示原始比值「近 4 周完成 X 条 / backlog Y 条」，不给区间、不给预计日期。**反而成立且更诚实**：让 PM 自己心算，系统不背预测责任。
### ④ 反常识倒置
预测的价值不在「预计哪天完成」，而在「暴露当前速率撑不到 dueDate」——宁可只报达标/不达标红灯，不报日期。
### ⑤ 新变体
- **D5-R3-03**（由倒置长出）：删除一切日期预测，只输出一个布尔「按近 4 周速率能否在 dueDate 前清完 backlog」，能/不能 + 缺口条数，不给区间。

## 施压单元 4：项目模板库（母本 D1-R2-04 / D2-R2-03 / D3-R2-03a / D4-R2-03 / D5-R2-02）

### ① 推到最大
行业模板市场、模板版本继承、实例与模板双向同步、模板评分下载。
### ② 判定：**崩（项目数=1 + 模板抹平特殊性）**
- 推理链：单人 **项目数=1 时无模板可抽**，市场是空的；模板把「这次项目的特殊性」抹成通用骨架，新项目被迫继承上次的错误假设（上次的风险清单未必适用于这次）；实例↔模板双向同步会污染历史实例。
- **成立条件**：同类项目做过≥2 次、且第二次确实重复第一次的结构；一次性探索项目套模板即崩。
### ③ 砍到最小
「另存为」一份 Markdown 骨架文本，新建时直接喂给现有 task-import 链路，无 templates 目录、无实例解耦、无模板维护。**反而成立**。
### ④ 反常识倒置
模板禁止复用：每个项目强制从零建，因为模板传递的是「上次的假设」，而项目的价值在于识别这次哪里不同。
### ⑤ 新变体
- **D5-R3-04**（由倒置长出）：模板降级为「风险检查清单提醒」（开新项目时提示「这类项目别漏了：第三方依赖/权限/发布窗口」），**不实例化任何任务骨架**，只做防漏清单。

## 施压单元 5：组合取舍视图（母本 D1-R2-05 / D2-R2-04 / D3-R2-03b / D4-R2-04 / D5-R2-02）

### ① 推到最大
自动给项目打分排名、自动建议砍/停、战略权重建模、组合优化算法求解。
### ② 判定：**崩（项目数=1 + 健康分是活动噪声）**
- 推理链：**active 项目=1 时视图空转**；单人所谓「组合」是自己在项目间切换注意力，没有真实多资源争用，people-load 跨项目聚合无对象；「14 天无活动」可能是正常冬眠等待外部输入，健康分把冬眠误判为失衡；自动打分需要战略权重，单人无从客观赋值。
- **成立条件**：active 项目≥3、确实在争同一注意力/同一截止窗口、PM 主动做季度聚焦；N=1 或项目长期异步等待时崩。
### ③ 砍到最小
全局一页只读卡片：每个项目一行（最近完成数/逾期数/临期里程碑），无规则引擎、无「建议砍」文案。**反而成立**（现状 GlobalBoard 已是雏形）。
### ④ 反常识倒置
取舍视图的正确输出不是「砍哪个」，而是「哪个可以被允许停着不动」——主动给项目发「休眠许可」，反对所有项目持续点亮。
### ⑤ 新变体
- **D5-R3-05**（由倒置长出）：视图只识别「可安全休眠」的项目（长期无活动、无临期承诺、无未决高风险），给一个「允许暂停」标记；休眠项目不计入健康灯、不进入催促清单，而不是建议砍掉。

## 施压单元 6：Jira/飞书/Excel 迁入与共存（母本 D1-R2-08 / D2-R2-07 / D3-R2-06a / D4-R2-07 / D5-R2-05）

### ① 推到最大
直连 Jira/飞书 API 实时双向同步、冲突自动合并、增量镜像、状态双向映射。
### ② 判定：**崩（单写者红线 + 字段语义失真 + 凭据网络）**
- 推理链：11 号契约与 backup-sync 单写者原则下，双向同步必然产生冲突，而产品明确不做自动合并；Jira status（Done/In Progress/Won't Do）≠ 本地 status（todo/in_progress/blocked/done），语义映射失真，迁入即错；直连 SaaS 需要凭据、网络、权限，违背离线 CRUD。
- **成立条件**：一次性离线 CSV/XLSX 迁入 + 只读外链；实时双向同步在单人场景崩。
### ③ 砍到最小
只扩 csv-import 的 HEADER_MAP 认 Jira 导出列（Issue Key/状态/经办人/截止），无 externalRef 字段、无增量、无对账视图。**反而成立**。
### ④ 反常识倒置
迁入是单向死刑：迁完即把旧系统记录冻结为只读快照，**不共存**；共存制造两套事实源的永久对账负担。
### ⑤ 新变体
- **D5-R3-06**（由倒置长出）：迁入即归档——旧系统导出文件打包进一次备份，删除所有持续外链与对账入口，本地成为唯一事实源，旧系统只在备份里被翻到。

## 施压单元 7：持续只读状态页（母本 D1-R2-10 / D2-R2-08 / D3-R2-07 / D4-R2-09 / D5-R2-07）

### ① 推到最大
多项目公开门户、访问控制、外部评论、订阅通知、客户可留言反馈。
### ② 判定：**崩（外部打不开 + 读者可能为 0）**
- 推理链：dsh Web 只信本机 loopback、无局域网远程（KB-014、delivery.md §9），外部读者根本打不开，公网穿透超出本机工具边界；H11「潜在他人阅读」长期未满足，可能领导从不点链接，持续维护白名单/脱敏成为新的自嗨负担；评论/反馈把只读页拖回协作系统。
- **成立条件**：确有≥1 个固定外部读者主动、反复打开；读者=0 时整页崩为自嗨。
### ③ 砍到最小
退回一次性手动导出 HTML（D4-21/D1-15），无服务、无路由、无持续刷新；读者每月只看 1 次时，持续服务是过度工程。**反而成立**。
### ④ 反常识倒置
状态页故意只给过期信息：页面永远显示「上周快照」，刻意滞后一周，倒逼读者开会沟通，防止状态页变成拖延现场讨论的替代品。
### ⑤ 新变体
- **D5-R3-07**（由倒置长出）：状态页只展示**已结项项目档案**（历史交付/复盘），不展示任何进行中项目；进行中的事留在对话里谈，公开页只做「过去做成了什么」的资历陈列。

## 施压单元 8：移动端 / 离开电脑（母本 D1-R2-09 / D2-R2-07 移动层 / D3-R2-06b / D4-R2-08 / D5-R2-06）

### ① 推到最大
手机全功能编辑、推送通知、语音建任务、手机审批、离线同步。
### ② 判定：**崩（公网入口缺失 + 单写者被打破 + 场景只需 30 秒）**
- 推理链：loopback 约束下手机无公网入口；移动端写直接打破单写者；通勤/外出真实场景只要「瞄一眼有没有要炸的」，全功能编辑的开发成本远超价值；手机审批链路要回传确认，链路失败留半截草稿。
- **成立条件**：只读查看 + 一条入站文字落候选草稿；手机端写操作崩。
### ③ 砍到最小
不建任何通道：把「今日 3 行」写进用户自己的日历备注/便签，纯静态文本，零开发。**反而成立**。
### ④ 反常识倒置
离开电脑时最好什么都看不到：断联是刻意保护，防止假期/通勤变成待命；移动端只提供「确认现在无需处理」的出口。
### ⑤ 新变体
- **D5-R3-08**（由倒置长出）：移动端页面只显示一条「现在无需处理」的确认页，隐藏全部数字与清单；只有当存在高影响阻塞/临期时才翻出三条，否则永远是平静页。

## 施压单元 9：office/PDF 导出（母本 round1 D1-14 / D3-19 / D4-13 / D5-11）

### ① 推到最大
全套 PPT 模板库、自动配图、排版美化、多格式（docx/pptx/xlsx/pdf）批量导出、品牌色定制。
### ② 判定：**崩（汇报频率低 + 依赖链重）**
- 推理链：单人向领导汇报频率是月/季度级，维护模板库的成本 > 偶发收益；skill-office + LibreOffice Kit 依赖链重，结构检查/渲染失败面多；导出是一次性动作，不值得产品化成模板系统。
- **成立条件**：偶尔一份 PDF/docx 用现成默认模板成立；模板库产品化崩。
### ③ 砍到最小
Markdown 直接浏览器打印成 PDF，不接 skill-office、不调 LibreOffice。**反而成立**。
### ④ 反常识倒置
汇报材料最佳格式是把数字直接贴进领导已在看的群/文档，独立 PPT 反而打断信息流；导出应最小到「可复制的纯文本块」。
### ⑤ 新变体
- **D5-R3-09**（由倒置长出）：只导出一段可直接粘贴进 IM/邮件的纯文本摘要（完成 N、逾期 M、下周 K 条），不生成任何文件，复制即发。

## 施压单元 10：台账→外部系统出站写（建 issue/MR/日历事件）（母本 D1-R2-06 / D2-R2-05 / D3-R2-04 / D4-R2-05 / D5-R2-03）

### ① 推到最大
批量双向同步、自动建单、外部状态回写、全项目镜像进 Jira、出站日志/撤回/更新全矩阵。
### ② 判定：**崩（重复录入 + 依赖他人环境）**
- 推理链：单人本来就在本地管，写外部等于把刚消灭的「重复录入」请回来；MCP 外部 server 的配置/凭据/可用性取决于他人环境，本机离线时整面隐藏；双向同步撞单写者红线；出站日志的撤回/更新/对账是一套小型同步系统。
- **成立条件**：偶尔一条需要外部协作者时，手动建单+贴链接成立；常态化同步崩。
### ③ 砍到最小：手动复制标题+贴外部链接，零集成、零 MCP。**成立**。
### ④ 反常识倒置
方向应反过来：外部系统才是事实源，本地只做只读镜像（即 D1-11/D2-30 只读回流），本地永不写外部，避免双写。
### ⑤ 新变体
- **D5-R3-10**（由倒置长出）：出站写功能永久关闭，只保留只读拉取；本地台账定位为「外部系统的本地观察台」，任何协作事实以外部系统为准。

## 施压单元 11：iCal 日历导出/订阅（母本 round1 D1-21 的 iCal 分支）

### ① 推到最大
双向日历同步、自动发会议邀请、日历冲突检测、参加人可见。
### ② 判定：**崩（日历是别人的地盘 + 无工作日历模型）**
- 推理链：ADL-051 已明确本地无权威工作日历/lag，日期只是墙钟；回写别人的日历易制造重复邀请；单人无参加人，冲突检测无对象；双向同步再次撞单写者。
- **成立条件**：只读 iCal 订阅（截止日进自己日历）成立；双向写崩。
### ③ 砍到最小：手动把截止日抄进自己日历，不产 iCal。**成立**。
### ④ 反常识倒置
日历不该接收截止日期，只接收「准备哨」：截止日留在台账，日历只放提前 N 天的准备提醒。
### ⑤ 新变体
- **D5-R3-11**（由倒置长出）：iCal 只导出里程碑开始前 N 天的「准备事件」（提前备料/预审），**不导出截止日本身**；截止日只在台账里，日历制造缓冲而不是制造死线。

## 施压单元 12：一次性随身只读包（母本 D3-R2-06b / D2-R2-07 移动层：邮件/IM 转发的静态 HTML/PDF 合集）

### ① 推到最大
随身包自动定期生成、多格式、带交互筛选、可在手机上点击钻取。
### ② 判定：**崩（与持续状态页同质 + 手机钻取无意义）**
- 推理链：定期自动生成与 D4-21 一次性导出、D5-R2-07 持续页三者重叠，三选一即可；手机上点击钻取任务详情的使用频次极低，交互开发浪费；自动定期生成又需要定时器（撞 ADL-032 拒绝常驻）。
- **成立条件**：一次性、手动、单文件、纯静态浏览；自动化/交互钻取崩。
### ③ 砍到最小：周报定稿时顺手导出一份 PDF 挂在交付物上，无独立「随身包」概念。**成立**。
### ④ 反常识倒置
随身包不该带进行中工作，而该只带「离线时需要拍板的 3 件事」——把包压缩成一张决策清单，不是项目全量镜像。
### ⑤ 新变体
