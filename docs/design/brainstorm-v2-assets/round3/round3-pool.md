## 一、压力测试逐条

### P1. 只读工具族（D5-01 / D1-01 / D2-07 / D3-01 / D4-01，五人同构）
- **① 推到最大**：七实体 × 全部视图 × 单条 get × 列表 × 搜索 × 派生统计，全注册成 `pm_*` 工具，模型对台账的每个面都能直接读。
  - **判定：崩（在工具数与返回体量边界上）**。推理链：工具 schema 全部进系统提示词，工具数一多模型出现选择困难（选错/漏选）；只读工具返回全量 JSON 直接灌进上下文，compaction 提前触发、主任务被挤；前提「读不消耗确认轮次所以越多越好」只在实体少、工具少时成立。**成立条件**：实体 <30、工具 <10、返回分页/摘要化。
- **② 砍到最小**：只留一个 `pm_search(keyword)`，其余读全部退回 `/pm` 命令与面板。
  - **判定：反而成立**。单人小项目一个关键词搜索就覆盖 80% 问答；最小可行内核 = 一个只读搜索工具 + 现有命令通道，零新增视图。
- **③ 反常识倒置**：工具方向反过来——不是「模型读台账」，而是注册一个反向工具让台账在派生时读模型会话（把承诺/决议从会话里捞回台账）。
  - **判定：反而成立（长出变体 D1-R3-01）**。主客体从「台账被查」换成「台账主动取」，与 D1-25/D2-16 被动捕获同源，但工具化后可被确定性调度。

### P2. 审批 seam / pm_propose（D5-02 / D1-03 / D3-02 / D2-08 / D4-02，五人同构）
- **① 推到最大**：每个动作、每个字段、每一步都弹审批卡——改备注、勾 checklist、补证据链接、标状态，无一例外。
  - **判定：崩（在审批疲劳边界上）**。推理链：单人自己批自己，60s 超时默认拒绝把合法动作也杀掉；模型被连续拒绝后学会「不提议」，采纳率 N≈0 被流程自我实现（正是 D2-R2-18 说的半瞎陷阱）。前提「事前每笔拦 = 安全」在多人不可信模型时代成立，在单人可逆场景不成立。**成立条件**：审批只留给不可逆/对外动作（删除、改期、出站写外部）。
- **② 砍到最小**：零审批卡，模型只是会拼 `/pm` 命令字符串，落库走现有命令通道。
  - **判定：反而成立**。现状本来就是命令通道，seam 只是包装层；最小内核不需要新 interaction 接线。
- **③ 反常识倒置**：审批人不是人，而是一条可配置的授权规则引擎——白名单内动作模型自批自留痕，人只事后抽查。
  - **判定：反而成立（长出变体 D1-R3-02）**。把「人逐笔点头」换成「规则批量放行 + 事后审计」，审批主体从人让位给规则，人退到例外位。

### P3. D1-23 agent 自主执行 PM（台账退只读账本 + 异常升级）
- **① 推到最大**：全自主——状态推进、风险开关、挪日期、重排关键链全自己做，人只收异常报警。
  - **判定：崩（在无人纠偏闭环边界上）**。推理链：单人无外部监督，模型把没做完的标 done 会形成错误闭环；goal-round-driver 预算耗尽后自循环空转；错误沿 predecessorIds 依赖扩散。**成立条件**：动作全部可逆 + 全量审计流在场 + 客观证据门（只允许「非空 checklist 全勾」才自动 done，复用 progress-derivation.ts 的诚实口径，status=done 不伪造百分比）。
- **② 砍到最小**：自主权限缩到「只勾 checklist + 挂证据链接」，其余一律提议。
  - **判定：反而成立**。这两个动作恰好是客观进度真源已支持的安全动作，误判面最小。
- **③ 反常识倒置**：自主的不是 agent，而是台账自己——事件流到达即自更新，agent 降级为记录员。
  - **判定：反而成立（长出变体 D1-R3-03）**。与 D1-R2-23「消灭维护台账」合流，写主体从模型换成数据本身。

### P4. D3-R2-17 / D1-R2-20 反叛：单人直接写 + 事后撤销
- **① 推到最大**：全字段直接写（含改期、改派、删任务、建风险），人晚上扫审计流一次性回滚。
  - **判定：崩（在撤销时效边界上）**。推理链：现状 undo 句柄 TTL 10min / 最多 3 条 / 一次性 / 重启失效（provenance-store.ts L28-29），晚上才看早已超 TTL，撤销通道接不住「事后」；第二个人出现即并发冲突。**成立条件**：窄白名单（不含删/改期/改派）+ 审计流无限期保留并提供历史版本回滚（突破 10min TTL）+ 单写者恒定。
- **② 砍到最小**：只开一个写口——勾 checklist，其他照旧审批。
  - **判定：反而成立**。最小直接写面，误判与撤销成本都趋近零。
- **③ 反常识倒置**：事后审计不由人翻流，而由一个独立审计 subagent 自动跑，人只看它的结论卡。
  - **判定：反而成立（长出变体 D1-R3-04）**。审查主体从人换成独立子代理，与 D2-12 里程碑审计员合流但常态化。

### P5. D4-R2-23 反叛：深双向绑定单人反而对
- **① 推到最大**：七实体 ↔ 会话 todo/goal/工作区目录全字段实时双向，一侧改另一侧同步。
  - **判定：崩（在寿命错配边界上）**。推理链：会话结束 todo 消失，双向同步会把台账清空；会话 fork/重启产生两个副本需要 CAS，单人看似无冲突但长寿实体（里程碑/风险）被短命载体带走；上游字段升级回归面全量暴露。**成立条件**：只绑「短命↔短命」（进行中任务 ↔ 会话 todo），长寿实体不进双向。
- **② 砍到最小**：只绑一个布尔（勾选状态），其余单向。
  - **判定：反而成立**。一个布尔同步没有冲突解决问题。
- **③ 反常识倒置**：会话才是真源，台账只是会话结束时固化的持久缓存快照。
  - **判定：反而成立（长出变体 D1-R3-05）**。事实源方向颠倒：先在会话里干活，台账负责结账，而不是台账当祖宗供着。

### P6. D1-27 / D5-21 goal 镜像（单向绑 goal，观察后丢弃）
- **① 推到最大**：整个项目（健康分、全部任务、风险）绑成会话 goal，goal-round-driver 全程自动续行。
  - **判定：崩（在 goal 模型容量边界上）**。推理链：goal 是「每会话单一完成目标」，项目是多目标集合，状态机装不下全貌；会话结束 goal 消失会造成「项目被放弃」错觉；自动续行烧免费池（约 50 次/天，KB-034）。**成立条件**：只绑单条 P0 / 单个里程碑，不绑项目全貌。
- **② 砍到最小**：一次性实验，跑完即清（D5-21 本来就是这个形态）。
  - **判定：反而成立**。低成本试了再判，不沉淀任何绑定。
- **③ 反常识倒置**：不让 goal 镜像台账，而是台账派生 goal——开工时台账自动生成当前会话 goal，goal 消亡不影响台账。
  - **判定：反而成立（长出变体 D1-R3-06）**。方向从「goal 读台账」翻成「台账推 goal」，寿命分层天然安全。

### P7. D5-20 todo 临时镜像（禁止回写，结束即弃）
- **① 推到最大**：每个会话自动全量镜像开放子树到 todo，且强制禁止回写。
  - **判定：崩（在认知双轨边界上）**。推理链：会话里勾一堆、台账不动，用户产生「勾了=记了」的错觉，正式档案与手头清单脱节；禁止回写在高频使用下变成持续挫败。**成立条件**：只作只读预览，并明确标注「勾选不落库」。
- **② 砍到最小**：零镜像，开工手打一条待办。
  - **判定：反而成立**（即现状），todo 接线本就可以不做。
- **③ 反常识倒置**：禁止回写翻成「只准回写」——todo 是唯一操作台，台账只在会话结束时从 todo 固化结存。
  - **判定：反而成立（长出变体 D1-R3-07）**。与 P5-③ 同源：操作台在会话，档案在台账，单向结账。

### P8. D1-R2-12 / D2-R2-10 / D4-R2-11 / D5-R2-09 新鲜度戳与对账
- **① 推到最大**：模型每句话带置信度，每次回答自动与库内逐条对账，差异全标红。
  - **判定：崩（在额度与警告疲劳边界上）**。推理链：对账本身多一轮工具调用，50 次/天免费池撑不住；过度警告造成狼来了，真陈旧被忽略；模型为躲对账干脆不提具体数字。**成立条件**：只对「落库声明」（声称已改/已完成/已关闭）对账，不对事实性陈述逐条对账。
- **② 砍到最小**：注入段头只打一个 capturedAt 时间戳，无自动对账。
  - **判定：反而成立**。一个时间戳成本极低，已经给了人肉眼判断新鲜度的锚。
- **③ 反常识倒置**：故意保留一份上一版快照，让模型新旧对比着回答，把「陈旧」从缺陷变成对照工具。
  - **判定：反而成立（长出变体 D1-R3-08）**。陈旧副本不再要被消灭，而是当时光机对照层。

### P9. D1-05 会话内多轮副驾（会话变量 + 记忆续问，结束消散）
- **① 推到最大**：副驾跨会话永久记住全部项目问答史，随 user 贯穿所有会话。
  - **判定：崩（在 R3 寿命错配边界上）**。推理链：跨会话记忆 = 长期状态，撞寿命分层；旧会话里的过期结论污染新会话；记忆无限膨胀。**成立条件**：记忆只会话内，结束即消散（原想法本来就是）。
- **② 砍到最小**：单轮 Q&A，无续问（即现状 ask-copilot）。
  - **判定：反而成立**。单轮够用时不必造记忆。
- **③ 反常识倒置**：副驾不记项目，项目档案记副驾——把副驾里有价值的问答固化进会议/报告实体，记忆离开会话进台账。
  - **判定：反而成立（长出变体 D1-R3-09）**。记忆主体从会话翻成台账实体，借 D1-28 session-reference 固化。

### P10. D5-07 每项目专属 PM subagent 长会话常驻
- **① 推到最大**：每个项目一个永不关闭、持续待命的 PM 官，长期记忆该项目。
  - **判定：崩（在常驻主体边界上）**。推理链：N 个项目 = N 条常驻子会话，进程/上下文/额度线性开销；单人不会同时问 N 个常驻官；子会话漂移跑偏无人纠。**成立条件**：按需 spawn、问完即弃。
- **② 砍到最小**：spawn 一次问完 kill（D3-22 巡检式只读子代理）。
  - **判定：反而成立**。一次性只读诊断无常驻成本。
- **③ 反常识倒置**：主会话是子 agent 的副驾——PM subagent 是主体，主会话只是它与人的收发室。
  - **判定：反而成立（长出变体 D1-R3-10）**。主客体互换：子代理主导诊断，人远程指挥与裁决。

### P11. D1-02 / D5-03 / D2-01 / D4-04 持久 push 注入
- **① 推到最大**：全量七实体每轮系统提示词注入。
  - **判定：崩（在 token/缓存边界上）**。推理链：token 爆炸、cacheReadTokens 失效（每轮内容变）、模型被 PM 元数据干扰主任务、免费池消耗加快。**成立条件**：几百字摘要 + 硬字节预算（D1-32）。
- **② 砍到最小**：零注入，只留只读工具按需 pull（D3-21 路线）。
  - **判定：反而成立**。不常驻也能查，省预算。
- **③ 反常识倒置**：注入方向反转——不是台账进提示词，而是把模型当前工作状态（在改哪几个文件、刚跑完哪轮）常驻推回台账。
  - **判定：反而成立（长出变体 D1-R3-11）**。D1-06 证据回挂的常驻版，推送方向从台账→模型翻成模型→台账。

### P12. D3-21 按需 pull（问「当前项目」才喂快照）
- **① 推到最大**：每轮都自动 pull 全量快照（等于变相 push）。
  - **判定：崩**。失去按需意义，token 与 P11-① 同病。
- **② 砍到最小**：无工具，纯 `/pm` 命令手动查（现状）。
  - **判定：反而成立**。单人低频查询时命令够用。
- **③ 反常识倒置**：由台账决定何时被看见——模型不主动问，台账在「有人该知道」时把自己摆到模型面前（条件触发亮相）。
  - **判定：反而成立（长出变体 D1-R3-12）**。拉取主体从模型翻成数据侧事件，是 D1-12 schedule 的进化形态。

### P13. D1-32 注入预算治理（compaction/spill 配套）
- **① 推到最大**：预算压到 0，禁止一切注入。
  - **判定：反而成立**：退回纯工具路线，与 P11-② 同。
- **② 砍到最小**：无预算，全量进上下文。
  - **判定：崩**：即原想法自己警告的反噬——PM 元数据把主开发任务挤出窗口、compaction 提前。
- **③ 反常识倒置**：预算不是固定字节数，而是随主任务上下文占用动态伸缩——主任务紧张时注入让位、空闲时扩容。
  - **判定：反而成立（长出变体 D1-R3-13）**。固定预算翻成自适应水位，让位优先级让给主任务。

### P14. D2-16 / D1-25 被动捕获（台账是会话/git 的投影，人只确认）
- **① 推到最大**：全自动，会话/git 里抽出什么直接落库，人零参与。
  - **判定：崩（在误抽拦截边界上）**。推理链：闲聊被当承诺、幽灵任务堆积；抽取错误无人拦截，台账质量塌掉。**成立条件**：草稿箱 + 人确认这一道不能省（原想法本就保留确认）。
- **② 砍到最小**：只抽「明确承诺句」一种句式。
  - **判定：反而成立**。窄抽取面误报最低。
- **③ 反常识倒置**：对话是台账的投影——台账先生成对话脚本/待办台词，人只是照着说。
  - **判定：反而成立（长出变体 D1-R3-14）**。谁产生谁：不再是对话生台账，而是台账生对话。

### P15. D4-28 assignee 建模为可 spawn 虚拟子 agent（团队仿真）
- **① 推到最大**：每个名字都 spawn 一个虚拟人自报进度，多虚拟人开仿真团队会议。
  - **判定：崩（在仿真失真边界上）**。推理链：仿真自陈被误当真人状态；纯推演玩具开销不小；单人无团队可仿真。**成立条件**：结果明确标注「仿真自陈、非真人确认」，仅用于排期推演。
- **② 砍到最小**：不 spawn，负载视图只显示名字与 open 数。
  - **判定：反而成立**。people-load 已能给数，不需要角色扮演。
- **③ 反常识倒置**：不是仿真人回答 PM，而是真人被建模成台账里的可调度资源单元，台账向真人派活。
  - **判定：反而成立（长出变体 D1-R3-15）**。虚拟反过来落到真人：人成为台账的执行资源。

## 二、极端中长出的新变体（全保留，不评分）

### D1-R3-01【P1-③】反向只读工具：让台账主动读模型会话
- **机制**：注册一个方向相反的只读工具 `pm_absorb_promises`，由确定性逻辑从指定会话日志里捞承诺/决议候选，回写草稿箱；方向是「台账取模型」，不是「模型查台账」。
- **具体场景**：会话结束触发一次抽取，草稿箱出现 3 条候选，PM 逐条确认；工具本身不写正式表。
- **触点**：session-query、现有草稿箱/confirm 链路。
- **来源观察**：D1-25/D2-16 被动捕获靠监听，本变体把它变成可被调度的确定性工具。

### D1-R3-02【P2-③】规则化自动审批闸：白名单内自批，人只事后抽查
- **机制**：把审批从「人逐笔点头」改成「授权规则引擎」：窄白名单动作（勾 checklist、补证据、改备注）模型自批并写 provenance，超白名单（删/改期/改派/出站写）才弹人工卡；人在审计流事后抽查。
- **具体场景**：agent 勾完 checklist 直接留痕，PM 晚上只看到一张「本日自批 12 条、待人工 2 条」汇总。
- **触点**：copilot.ts 白名单收窄、provenance-store、D4-29 审计流。
- **来源观察**：P2-① 审批疲劳推理链；D3-R2-17/D1-R2-20 的直接写主张落到规则闸形态。

### D1-R3-03【P3-③】事件自更新台账：数据自己写自己，agent 当记录员
- **机制**：workspace-changes/会话结束等事件到达后，由确定性规则直接更新台账字段（勾 checklist、挂证据），agent 只做解释不做裁决。
- **具体场景**：git diff 显示某文件测试全绿，对应 checklist 项自动勾上，agent 只在旁边写一句说明。
- **触点**：workspace-changes、progress-derivation 客观门、事件流。
- **来源观察**：D1-R2-23「消灭维护台账」的机制化；P3-① 无人纠偏靠客观门兜底。

### D1-R3-04【P4-③】独立审计 subagent 常态化事后抽查
- **机制**：每天（或会话批次结束）派一个无父历史的只读审计子代理，扫本日自批/直接写动作，产出「可疑 N 条」结论卡，人只审结论不翻原始流。
- **具体场景**：早上收到审计卡「3 条 done 无证据链接、1 条改期无依据」，PM 逐条撤销或补证。
- **触点**：subagent-spawn-in-process、D2-12 审计员、provenance 账本。
- **来源观察**：P4-① 撤销 TTL 10min 接不住事后，故由审计员前置发现。

### D1-R3-05【P5-③】会话真源 + 周期固化：台账是会话的结存缓存
- **机制**：进行中工作以会话 todo/对话为真源，台账不实时同步，只在会话结束/周期点把确认过的内容固化为档案；会话消失不拖垮台账。
- **具体场景**：开发会话里 todo 随便勾随便删，结束时系统问「把这几条结存进台账？」，选过的才落。
- **触点**：tool-todo、会话结束钩子、confirm 草稿。
- **来源观察**：P5-① 寿命错配推理链；D3-24 单向导出的「真源方向」反转版。

### D1-R3-06【P6-③】台账派生 goal：开工自动生成会话目标
- **机制**：选中项目开工时，台账自动把下一条 P0 生成会话 goal 推给宿主，goal 是派生品，消亡不回写台账。
- **具体场景**：点「开工 t-12」，会话 goal 自动挂上「完成 t-12」，会话关掉 goal 消失，台账不动。
- **触点**：goal create、任务开工（D3-13）。
- **来源观察**：P6-① goal 装不下项目全貌，只派生单任务。

### D1-R3-07【P7-③】todo 为操作台、台账为结存：只准回写
- **机制**：会话 todo 是唯一操作清单，勾选/删除只发生在会话；结束时单向回提为完成候选落台账，禁止双向。
- **具体场景**：会话里勾掉 3 条，结束面板出现「3 条候选完成」，确认即结存。
- **触点**：tool-todo 整表替换、D1-R2-18 回收单行道。
- **来源观察**：D5-20「禁止回写」的方向反转。

### D1-R3-08【P8-③】新旧双快照对照回答：陈旧副本当时光机
- **机制**：保留上一版快照，模型被问现状时同时给新旧两版差异，旧版标注「历史快照」而非错误。
- **具体场景**：「这条任务什么时候改的？」模型答「上周快照是 in_progress，今天变为 done」，差异本身成为答案。
- **触点**：D4-30 备份版本链、report-diff 相邻快照。
- **来源观察**：P8-① 过度对账崩塌；陈旧从缺陷转为对照层。

### D1-R3-09【P9-③】会话精华回流台账实体：记忆离开会话进档案
- **机制**：副驾多轮问答中被标记「有价值」的结论，固化进对应会议/报告/决策实体，不随会话消散。
- **具体场景**：三轮追问得出的排期结论，一键存进 M1 里程碑备注，下个会话还在。
- **触点**：session-reference 有界快照、meeting/decision 实体。
- **来源观察**：P9-① 跨会话记忆崩塌；记忆主体从会话翻成台账。

### D1-R3-10【P10-③】子 agent 为主体、人远程指挥收发室
- **机制**：PM subagent 是诊断主体（自主跑完跨项目巡检并给方案），主会话只承担向人转达与接收指令，而非反过来。
- **具体场景**：子代理先跑完给出诊断包，主会话等 PM 一句「采纳哪几条」。
- **触点**：subagent spawn、D5-08 workflow 扇出。
- **来源观察**：P10-① 常驻崩塌；主客体互换但不常驻。

### D1-R3-11【P11-③】模型工作状态常驻推回台账（注入反向）
- **机制**：不再把台账推进提示词，而是把「当前在改哪些文件/刚跑完哪轮」周期性推回任务证据区，形成自动更新的执行流。
- **具体场景**：开发进行中，t-12 证据区自动累计「14:20 改 file a、15:02 改 file b」，无需人挂链接。
- **触点**：workspace-changes 常驻订阅、evidenceUrl 草稿。
- **来源观察**：P11-① push 注入 token 崩塌；方向反转成模型→台账。

### D1-R3-12【P12-③】事件触发的主动亮相：台账决定何时被看见
- **机制**：不等人问、不轮询，由台账侧事件（逾期/里程碑临近/风险升级）触发一次简短亮相进会话，平时静默。
- **具体场景**：t-12 逾期那一刻，会话里出现一条短卡，不是定时轰炸而是事件驱动。
- **触点**：domain/changed（进程内）、schedule 兜底、reminders 派生。
- **来源观察**：P12-② 纯手动查的被动；拉取主体翻成数据侧事件。

### D1-R3-13【P13-③】自适应注入水位：随主任务占用伸缩
- **机制**：注入字节预算不固定，主任务上下文占用高时压缩/让位，空闲时扩容到全量摘要。
- **具体场景**：正在跑长代码任务时注入只剩一行健康灯；闲聊时展开今日议程。
- **触点**：compaction 水位信号、context section 动态长度。
- **来源观察**：P13-② 无预算反噬；固定预算翻成自适应。

### D1-R3-14【P14-③】台账台词驱动对话：台账先生成待办脚本
- **机制**：开工前台账生成一段「今天该说/该做什么」的台词脚本推给会话，对话照着台账走，而非对话自由生长再回捞。
- **具体场景**：早起点一下，会话开场即拿到今日 3 条台词，逐条推进逐条结存。
- **触点**：buildAskContext、议程生成、confirm。
- **来源观察**：P14-① 全自动误抽崩塌；产生者反转。

### D1-R3-15【P15-③】真人作为台账可调度资源单元
- **机制**：不仿真虚拟人，而是把真人建模为台账里的资源单元，台账按负载向真人派活、回收，人是执行端。
- **具体场景**：组合视图直接给真人排「本周 5 条上限」，超负载即提示派不下去。
- **触点**：people-load、组合取舍（D1-R2-05）、出站写日历（D1-R2-06）。
- **来源观察**：P15-① 仿真失真；虚拟落到真人资源。

## 压测 01 · workspace-changes git diff 回挂任务证据（母本 D1-06 / D4-05 / D5-04，同一机制三变体）

**母本机制**：订阅 session/event，把本轮 git 工作树快照 + 文件 diff 摘要收成只读证据候选，人确认后挂任务 evidenceUrl，绝不自动改状态。

- **① 推到最大**：每轮所有改动自动按文件路径/关键词匹配到任务，无确认直接写进 evidenceUrl，甚至据此自动建议完成。
  - 判定：**崩**。推理链：
    1. 误匹配——一个会话常同时改多个项目/多个任务的文件，确定性路径匹配无法区分「这条改动属于哪条承诺」，错挂比不挂更糟；
    2. 覆盖盲区——workspace-changes 只记文件工具编辑与 git 快照，shell 命令造成的改动不出现（D5-04 来源观察已注明），推到最大后这部分工作永远无证据，形成「做了但系统看不见」的假空转；
    3. 仓库前提——非 git 目录（纯文档、手写笔记）时空转；
    4. 证据爆炸——每轮都挂，抽屉里堆满 hunk 清单，人不看。
  - 成立边界：只在「一个会话对应一条任务、仓库是 git、改动文件路径可由人在草稿里确认」三个条件同时满足时，半自动（人确认）才成立。
- **② 砍到最小**：删掉所有事件订阅与自动聚合，只留一条命令 `/pm evidence <taskId> <url>`，人手贴一个链接。
  - 判定：**反而成立**。单写者手动贴链接成本极低，自动管道最头疼的匹配/误挂/盲区问题全部消失；代价是没有人会贴（这是采纳问题，不是机制问题）。
- **③ 反常识倒置**：证据不等人去挂，而是**证据主动找人**——捕获到的改动先进「孤儿证据池」，系统反向提议「这批改动可能属于 t-00xx，或要不要新建一条任务」，人做归属裁决；找不到归属的改动也不丢弃，留在池子里供周报复用。
  - 新变体见 **D2-R3-01**。

## 压测 02 · session-query FTS5 回捞历史会话当证据/素材（母本 D1-07 / D4-06 / D5-05）

**母本机制**：按任务标题/关键词 FTS5 搜历史会话，把命中轮次作为只读引用挂证据区/周报素材，人勾选。

- **① 推到最大**：每次打开任务、每次写周报，全库语义回捞所有相关历史会话片段自动铺满证据区。
  - 判定：**崩**。推理链：
    1. FTS5 关键词误命中（同词不同事，如「登录」出现在十几条无关会话）；
    2. 隐私与噪音——旧会话含大量无关闲聊/私人内容，铺满后证据区变成垃圾场；
    3. cwd 亲和错位（D1-07 依赖 cwd 匹配），跨目录项目会捞错；
    4. session-query 默认排除调用方会话、需 sqlite 后端，环境缺失时静默退化。
  - 成立边界：只在「人主动发起一次回捞、命中条数有上限、命中片段只列标题+日期不铺正文」时成立。
- **② 砍到最小**：零回捞，证据区只放人手贴的外部链接，会话日志完全不读。
  - 判定：**成立**（退回现状的保守形态）；最小内核就是任务抽屉一个粘贴框。
- **③ 反常识倒置**：黑白反转——**会话原文才是权威现实，台账数字只是缓存**；当台账记录与会话原文冲突时（台账说完成、原文显示只是讨论），系统标红「与原始会话不符」，而不是让会话给台账当佐证。
  - 新变体见 **D2-R3-02**。

## 压测 03 · 被动捕获收件箱 / 台账吃对话（母本 D1-25 / D5-19）

**母本机制**：从会话日志/git/速记/附件自动抽候选任务/风险/行动项进待认领收件箱，人只归类确认。

- **① 推到最大**：零确认，抽取结果直接入库成为正式任务/风险。
  - 判定：**崩**。推理链：
    1. 误报污染——模型把闲聊、假设、「下次再说」当成承诺直接落库，错条目散进各实体后，单写者难以逐条回滚；
    2. 抽取无确定性校验，错误率无上限；
    3. 收件箱自动清零后，人失去「我确认过」的心理所有权，台账可信度反而下降。
  - 成立边界：高置信候选才进箱、人必须逐条确认、误报可一键丢弃且不扩散。
- **② 砍到最小**：不监听任何流，收件箱只在人手动点「采集本周」时跑一次。
  - 判定：**成立**。一次手动触发换一批候选，零常驻、零误报累积。
- **③ 反常识倒置**：负向默认——对话里说的一切默认「不记」，只有人明确说出「记下来/落进台账」这句话时才留候选；沉默是默认，捕获是例外。
  - 新变体见 **D2-R3-03**（置信分层 + 误报配额）。

## 压测 04 · 会中实时捕获（母本 D2-R2-06 / D1-R2-07 / D3-R2-05 / D5-R2-04 / D4-R2-06 麦克风 STT）

**母本机制**：会中边说边落候选行动项气泡，当场认领/丢弃，散会拼纪要；D4-R2-06 更进一步用本地 SenseVoice STT 实时转写抽取。

- **① 推到最大**：麦克风常开、全天候监听所有对话，自动转写并抽取承诺。
  - 判定：**崩**。推理链：
    1. 隐私——常开麦录下非工作对话；
    2. STT 错误率（本地 SenseVoice 错字/断句）直接变成错误行动项；
    3. 边开会边管理分散注意力，候选气泡不断打断会议流；
    4. 降噪失败：客套/铺垫被抽成行动项。
  - 成立边界：人显式开启「现场模式」、只录当前会议、候选当场可丢、STT 只做草稿。
- **② 砍到最小**：无会中模式，回到会后粘贴速记（R15 现状）。
  - 判定：**成立**（零增量但零风险）；最小内核=一个边说边打的临时文本框，不接 STT、不自动抽。
- **③ 反常识倒置**：会中只允许「记一句」的极简动作（一句话级别），升格成正式行动项全部留到会后；会中不做任何管理判断，只做速记。
  - 新变体见 **D2-R3-04**（散会后 60 秒黄金认领窗口）。

## 压测 05 · 附件白板照/截图挂证据（母本 D1-08 / D4-07 / D5-10 / D2-32）

**母本机制**：白板照/截图/设计稿经 attachment 内容寻址存储挂到会议/交付物/任务，只存句柄不复制字节。

- **① 推到最大**：所有日常截图自动 OCR、自动归类挂到相关任务。
  - 判定：**崩**。推理链：
    1. 日常截图量远大于会议/交付物，内容寻址存储被淹没；
    2. 图片无文字索引，归类靠模型又回到误匹配；
    3. 碎片化——每条任务都挂几张图，纪要反而找不到关键那张；
    4. 隐私截图（误截屏）进了台账。
  - 成立边界：人手动拖入、只挂会议/交付物两层、图片是引用不是复制。
- **② 砍到最小**：附件只是一个文件引用框，零模型识别、零自动归类。
  - 判定：**成立**。
- **③ 反常识倒置**：主次反转——图片才是会议本体，文字纪要只是图片 OCR 出来的副产品；白板照为主件，文字是配图说明。
  - 新变体见 **D2-R3-05**（附件只允许挂会议/交付物，禁止挂每条任务）。

## 压测 06 · GitHub webhook 正向 + 轮询反向（母本 D1-09）

**母本机制**：正向 webhook 收 PR opened/merged 事件变候选草稿（需公网入口）；反向 web_fetch/MCP 手动/周期拉取回填。

- **① 推到最大**：webhook 实时双向，所有 PR 事件自动改任务状态。
  - 判定：**崩**。推理链：
    1. localhost 无公网入口，正向天然跑不起来（D1-09 自己已注明，需内网穿透/部署）；
    2. 验签、重复交付（webhook 会重投，deliveryId 不去重就制造重复草稿）；
    3. 自动改状态越权——PR merged 不等于任务验收通过；
    4. 外部仓库权限/网络不可控。
  - 成立边界：只做反向手动/周期只读拉取，事件永远只产候选草稿。
- **② 砍到最小**：删掉 webhook 与周期轮询，只留面板一个「刷新仓库状态」按钮，点一次 web_fetch 拉一次。
  - 判定：**反而成立**。本地可跑、零常驻、零公网依赖。
- **③ 反常识倒置**：不接 GitHub 让 GitHub 给台账喂证据；反过来**让 GitHub 成为唯一事实源，台账只做本地只读镜像视图**，台账不再是计划权威。
  - 新变体见 **D2-R3-06**（deliveryId 幂等去重作为最小必备件）。

## 压测 07 · 台账→外部系统出站写（母本 D2-R2-05 / D4-R2-05 / D1-R2-06 / D3-R2-04 / D5-R2-03）

**母本机制**：经外部 MCP 写工具把任务建成 Jira issue/飞书卡片/日历事件，人审批后发出，外部 ticket id 回挂，默认关闭、逐条显式触发。

- **① 推到最大**：台账↔Jira 双向实时同步，两边改动互相写回。
  - 判定：**崩**。推理链：
    1. 单写者原则被破坏（11 号协作契约：无 CAS、无 rev、纯覆盖写），双写冲突无法收敛；
    2. 字段映射漂移（Jira 自定义字段随对方改）；
    3. 离线分叉——断网时两边各改各的，回来无法合并；
    4. 外部 API 变更导致静默失败。
  - 成立边界：单向出站、显式触发、只增不级联删除、留可撤销日志。
- **② 砍到最小**：零 MCP，只留一个「复制任务为 issue 文本」按钮，人自己粘贴到外部。
  - 判定：**成立**（价值低但零风险）；最小内核就是格式化一段可粘贴文本。
- **③ 反常识倒置**：出站方向反转——本地台账不主动写外部，外部 issue 反向成为任务的唯一存在，本地只留一个指针句柄，外部是主、本地是缓存。
  - 新变体见 **D2-R3-07**（出站只增日志 + 撤销队列，外部删除绝不级联）。

## 压测 08 · dogfood 自身仓库，commit 即证据（母本 D2-17）

**母本机制**：用本工具管 pm-tool 自己的开发 backlog，任务号写进 commit message，git log 关联任务作只读证据草稿。

- **① 推到最大**：commit message 带任务号就自动把任务标 done。
  - 判定：**崩**。推理链：
    1. 提交粒度≠任务粒度（一个 commit 改多处、一个任务多个 commit、一个 commit 只是中间修复）；
    2. 开发仓库与未来业务项目混淆，dogfood 数据污染正式台账；
    3. 提交信息随意时任务号挂错；
    4. 自动 done 绕过验收清单。
  - 成立边界：commit 号只作只读线索，完成判定仍在 checklist/人。
- **② 砍到最小**：dogfood 只把自身 backlog 手动录进台账，完全不读 git。
  - 判定：**成立**。
- **③ 反常识倒置**：不是用 git 证据证明任务完成，而是**用台账任务反向约束提交**——没有任务号的 commit 被 pre-commit hook 提示拦截，先有计划改动才能提交。
  - 新变体见 **D2-R3-08**（任务号可选强约束 hook 提示，非自动完成）。

## 压测 09 · 计划↔执行承诺对账（母本 D2-21 / D1-R2-19）

**母本机制**：用 completion-history 真实 completedDate + 相邻快照 diff，纯派生「上期承诺 N、兑现 M、延期 K、新增 L」对账表。

- **① 推到最大**：每条承诺逐句追责，未兑现全部标红、对账到每句话、跨周期追溯。
  - 判定：**崩**。推理链：
    1. 单人场景变成自我责备表，仪式负担大于价值；
    2. 历史承诺脱离当时语境（本来就放弃了的事被反复揪出）；
    3. 陈年旧账累积，对账表失去当下指导意义。
  - 成立边界：只对同周期承诺对账，跨周期自动失效。
- **② 砍到最小**：周报末尾人手填三行「上期承诺/兑现/未兑现」，零技术。
  - 判定：**成立**。
- **③ 反常识倒置**：对账方向反转——不追「没做到」，只追「意外做到了什么」（正向惊喜清单：计划外完成、超额、被忽略却做好的事），未兑现静默处理。
  - 新变体见 **D2-R3-09**（承诺保鲜期：只在同周期内对账，过期自动归档不追责）。

## 压测 10 · 证据自动闭环杂交（母本 D2-R2-16 自证周报 / D5-R2-14 审计带 diff / D1-R2-16 任务→会话→证据管道）

**母本机制**：到点自动开会话、会话结束自动收 diff 证据、审计员带真实 hunk 判断证据是否够、周报条目自动绑证据片段，人只在收口确认。

- **① 推到最大**：全链路自动——自动开会话、自动收证据、自动建议完成，人只按一个总确认。
  - 判定：**崩**。推理链：
    1. 自动开会话产生大量空转会话（开了但没干活）；
    2. 证据误绑后总确认一键全放，人退化为橡皮图章；
    3. 自动化越完整，人越不看证据，闭环变成自我感动；
    4. 环境前提（schedule 可投递、session 可创建）缺失时管道静默断。
  - 成立边界：自动只到「备齐候选」，收口确认必须人逐条看。
- **② 砍到最小**：闭环只剩「周报草稿里手动贴一条证据链接」，其余全自动全删。
  - 判定：**成立**。
- **③ 反常识倒置**：证据不是用来**证明**完成，而是用来**否证**——默认任务完成，审计员的职责是挑出「证据缺失/证据不符」的反例，举证责任反转。
  - 新变体见 **D2-R3-10**（空转会话：轮次多但零改动，自动标为「可疑未完成」反向挂回任务）。

## 压测 11 · 开工建会话→执行报告自动回挂（母本 D5-R2-15）

**母本机制**：点开工自动建带 taskId 元数据的会话，结束后聚合轮次/文件量/present/feedback 成执行报告草稿回挂。

- **① 推到最大**：每个任务自动开会话，结束自动聚合报告。
  - 判定：**崩**。推理链：
    1. 会话数量爆炸（大量任务从不开会话则永远无报告，形成歧视性缺失）；
    2. taskId 元数据易随 fork/复用丢失，绑定断链；
    3. 用轮次/文件量冒充完成（聊得多≠做完）。
  - 成立边界：人显式点开工才建，报告只陈述事实不宣称完成。
- **② 砍到最小**：点开工手动建会话，结束人手贴一句总结。
  - 判定：**成立**。
- **③ 反常识倒置**：不统计执行量（轮次/文件量），只审计「会话与任务是否真相关」——相关性存疑的高执行量反而标红，防止用忙碌冒充完成。
  - （并入 D2-R3-10，不单列新编号。）

## 压测 12 · 证据新鲜度对账卡（母本 D4-R2-15）

**母本机制**：证据捕获时间戳 vs 任务 updatedAt 偏差超窗标「可能不覆盖最新」，三类证据按新鲜度排序，可一键重取。

- **① 推到最大**：每条证据实时监控过期，过期即自动撤下。
  - 判定：**崩**。推理链：旧证据常常仍然有效（一张白板照三个月后照样说明当时分工），按时间自动撤下误删；阈值 arbitrariness（24h？7 天？）无客观依据。
  - 成立边界：只标注偏差、不撤下、不排名，重取由人发起。
- **② 砍到最小**：证据只显示捕获日期，不做偏差计算。
  - 判定：**成立**。
- **③ 反常识倒置**：越旧的证据越权威（历史快照不可篡改，旧证据代表「当时事实」）；新鲜度不用于优劣排序，只用于**时态标注**（当时事实 / 现状证据）。
  - 新变体见 **D2-R3-11**（证据带时态双标签，不按新旧排名）。

## 压测 13 · 投影→干活→回收单行道（母本 D1-R2-18，对照 D5-20 禁止回写）

**母本机制**：开工把开放子树镜像进会话 todo/goal，会话结束把 todo 勾选结果单向回收为完成候选，goal 不回写。

- **① 推到最大**：会话 todo 勾选自动回写台账完成。
  - 判定：**崩**。推理链：会话勾选常是临时清单项（「查个资料」），不是台账承诺；自动回写污染正式状态；D5-20 原本禁止回写正是为此。
  - 成立边界：回收只产候选草稿，人确认；或干脆保持 D5-20 的禁止回写。
- **② 砍到最小**：不回收，todo 纯演示投影（D5-20 原方案）。
  - 判定：**成立**。
- **③ 反常识倒置**：回收方向反转——台账勾选驱动会话 todo 勾选（人在面板勾完，会话侧清单同步），而不是会话驱动台账。
  - （方向变体，不单列新编号。）

## 压测 14 · 会议直读历史会话补速记（母本 D3-17）

**母本机制**：会后归纳时直读相关历史会话有界快照，补充粘贴速记里的遗留行动项。

- **① 推到最大**：自动把所有相关历史会话塞进纪要正文。
  - 判定：**崩**。冗长、无关片段混入、纪要失焦、模型把旧讨论当新决议。
  - 成立边界：只列候选标题由人选，不自动进正文。
- **② 砍到最小**：纪要仍只靠粘贴，零会话读取（ADL-025 现状边界）。
  - 判定：**成立**。
- **③ 反常识倒置**：不在会后补历史，而在**会前**生成「本次开会前应读的历史片段包」；历史服务于即将发生的会，而非追认已经开完的会。
  - 新变体见 **D2-R3-12**（会前准备包，与会后捕获分开）。

## 压测 15 · present/workspace-changes 回填 evidenceUrl 草稿（母本 D2-18）

**母本机制**：订阅轮次结束，把 present 声明与本轮文件改动整理成只读证据草稿挂任务，人确认才写，不自动改状态。

- **① 推到最大**：present 声明 + 文件改动自动等同完成证据，自动标 done。
  - 判定：**崩**。推理链：present 只是展示声明（可能展示半成品/演示版）；文件改动≠满足验收清单；两者都只是「发生过动作」，不是「达到标准」。
  - 成立边界：证据只作线索，完成判定权永远在 checklist 客观项 + 人。
- **② 砍到最小**：evidenceUrl 纯手动粘贴框，零事件监听。
  - 判定：**成立**。
- **③ 反常识倒置**：证据越丰富越可疑——「挂满证据的完成」反而触发审计员二次核对（过度举证=辩护心虚），裸完成（人一句话声明）默认通过。
  - （认知反转，不单列新编号。）

## 压力过程中长出的新变体（全保留，未评分）

### D2-R3-01 孤儿证据池：证据主动找人（压测01 倒置）
- **机制**：自动捕获的改动/会话片段若确定性匹配不到任何任务，不丢弃，进孤儿证据池；系统周期性反向提议「这批痕迹可能属于某任务，或该新建一条」，人裁决归属；池内痕迹也供周报复用。主客体从「人找证据」翻成「证据等人认领」。
- **触点**：workspace-changes/session-query 候选 + 一个只读孤儿表 + 归属草稿。
- **边界条件**：池容量有界、过期清理，防止痕迹堆积。

### D2-R3-02 会话原文为权威、台账为缓存（压测02 倒置）
- **机制**：台账记录与会话原文冲突时，系统标红「与原始会话不符」，以原文为准提示台账修正，而非会话给台账佐证；台账降级为可被原文纠正的派生层。
- **触点**：session-query 原文比对、冲突标红草稿。
- **边界条件**：只标冲突、不自动改台账；单人语境下「原文」也可能是错的，仍留人声裁决。

### D2-R3-03 置信分层收件箱 + 误报配额（压测03 修正）
- **机制**：捕获候选按置信分三层：高置信直接进待认领箱、中置信排队等批量处理、低置信直接丢弃；每周期误报（被人丢弃的）设配额，超配额自动收紧抽取口径。
- **触点**：suggestion-engine 范式扩展、provenance 丢弃计数。
- **边界条件**：没有高置信时宁可空箱，不用噪声凑数。

### D2-R3-04 散会后 60 秒黄金认领窗口（压测04 倒置）
- **机制**：不开全程实时模式；散会后给一个 60 秒短窗口，系统把刚结束会议的转写/速记里的候选行动项快速弹出，人在窗口内批量认领/丢弃，过期候选保留到次日草稿箱。会中只速记、会后短窗口升格。
- **触点**：meeting 定稿流程 + 短时窗口 UI。
- **边界条件**：窗口可跳过；超时不自动落库。

### D2-R3-05 附件只挂会议/交付物两层（压测05 收敛）
- **机制**：禁止把图片附件挂到每条任务；附件只允许挂在会议纪要与交付物两个实体下，任务需要看图时从所属会议/交付物引用，避免图片碎片化。
- **触点**：attachment 句柄 + schema 层挂载位置限制。
- **边界条件**：任务侧只读引用，不复制。

### D2-R3-06 webhook 事件 deliveryId 幂等去重（压测06 最小必备件）
- **机制**：即便不接 webhook，也先实现 deliveryId 去重登记；将来接入时重投事件不产生重复草稿，去重表只增、短 TTL。
- **触点**：provenance/idempotency 范式。
- **边界条件**：无 webhook 时此表为空，零成本挂着。

### D2-R3-07 出站只增日志 + 撤销队列，外部删除绝不级联（压测07 安全边界）
- **机制**：每条出站写留只增日志（外部 ticket id、时间、载荷快照）；提供「撤销单条」（发备注关闭/更新），本地删除任务绝不触发删除外部 issue；双向同步永久不做。
- **触点**：新增 outbound 日志表、mcp-client 写工具、approval seam。
- **边界条件**：外部系统不支持撤销时只留日志不假装可撤。

### D2-R3-08 任务号反向约束提交（pre-commit hook 提示，压测08 倒置）
- **机制**：不是 commit 自动完成任务，而是开发仓库 pre-commit hook 提示「本次提交未关联任务号」，人补号或明确豁免；任务号是提交的前置礼貌，不是完成的证据。
- **触点**：本地 git hook（只读提示，非拦截强制）。
- **边界条件**：纯提示不阻断，dogfood 专用、不推广到业务项目。

### D2-R3-09 承诺保鲜期：只同周期对账，过期自动归档（压测09 收敛）
- **机制**：每条承诺带保鲜期（默认一个报告周期），跨周期未兑现自动转归档「历史未决」，不再进入当期对账表追责；对账只面对当下。
- **触点**：completion-history + 周期边界纯函数。
- **边界条件**：归档可手动捞回，但不主动翻旧账。

### D2-R3-10 空转会话反向标「可疑未完成」（压测10/11 合成）
- **机制**：执行报告里轮次多但零文件改动/零 present 的会话，不记为「已工作」，反向给任务挂一条可疑提示「聊了但没产出，是否真完成？」；用忙碌度反证完成，而非用忙碌度证明完成。
- **触点**：session-query 轮次统计 + workspace-changes 文件量 + 草稿提示。
- **边界条件**：纯提示，不改状态；纯讨论型任务（调研/决策）豁免此判定。

### D2-R3-11 证据时态双标签：当时事实 / 现状证据，不按新旧排名（压测12 倒置）
- **机制**：每条证据打「当时事实」（历史快照、不可篡改、代表那一刻）或「现状证据」（最新改动、代表现在）标签，并列展示而非按新鲜度排序；旧的不当作失效，新的不当作更权威。
- **触点**：evidenceUrl 元数据标签、纯派生排序改为分组。
- **边界条件**：标签由捕获时机自动打，人可改。

### D2-R3-12 会前准备包：开会前自动列应读历史（压测14 倒置）
- **机制**：会议创建/开始前，按项目与议题关键词从历史会话/报告里捞相关决策片段，生成「会前应读包」给参会人；历史服务于即将发生的会，会后补记只靠粘贴。
- **触点**：session-query 只读、meeting 创建流程、有界快照（session-reference）。
- **边界条件**：包内容人可删，不自动写进纪要。

## 施压 1｜母本：独立 pm-core 纯内核 + 薄适配层（D1-19、D2-05、D3-07、D4-23、D5-14；反叛 D3-R2-21、D5-R2-21）

### 1a. 推到最大
- **极端形态**：把内核抽成一个真正多后端可插拔的库——存储可换 JSON/本地库/远程，UI 可换面板/静态站/MCP，模型可换 dsh llm/标准 API/Ollama，七实体、zod 校验、CPM、健康分、导出全部进 core，适配层只剩胶水；为将来任何第二个壳留足接口。
- **判定：崩（前提：第二个壳出现之前）**。
- **推理链**：现有代码里真正无语义、换壳可复用的只有 health 分、report-diff、`core/gantt.ts` 只读 CPM（`criticalPath()`、slack、前置依赖图）这类纯函数；而七实体语义（任务/里程碑/风险/证据/effortHours/manualProgress）、父子互斥、编号规则、草稿确认制都与「人怎么用这个产品」耦合。抽象层越全，单人要同时维护「core 契约 + 每个后端实现」，上游 dsh 一次 breaking（ADL-034 升级断点本就在适配层），抽象层反而多一跳转发要修。**崩的边界条件**：复用主体数 = 1（只有 dsh 一个壳），此时抽象是给想象中的第二个客户付现实维护税（与 D5-R2-21 同）。**成立条件**：第二个壳真实立项（MCP server 或独立 App 被决定要做），且 core 里 80% 是纯函数。

### 1b. 砍到最小
- **极端形态**：物理上什么都不抽，只在代码里守住 product/11 的 `PmDomain` 接口边界（存储后端可换），等到第二个消费端出现再动手；唯一可抽的只有 health/report-diff/CPM 三个无语义纯函数。
- **判定：反而成立**。
- **推理链**：`PmDomain` 接口本来就只是存储后端抽象（product/11「换后端零改动」），把它误推广成「换壳零改动」才是过度承诺；砍到只剩纯函数后，没有任何「为想象需求维护的层」，上游 break 直接贴合重写接线，单人成本最低。**成立条件**：1–2 年内明确不出第二个壳；上游 breaking 频率低。

### 1c. 反常识倒置
- **极端形态**：主客体互换——pm-core 不是「我为换壳准备的仓库」，而是**反向被 dsh 官方吸收的捐赠候选**：把 core 写得标准、无 dsh 私有依赖，目标是让未来 dsh 原生团队直接拿走七实体模型；宿主反过来「跪求插件贡献者」。
- **判定：有条件成立**。
- **推理链**：倒置点在于独立内核的价值不是「我另立门户」，而是「让官方省掉重写」；成立条件是 core 确实无 cordis/私有依赖（目前 `src/index.ts` 仍 `inject=['commands','storageDomain']`，需先脱钩），且官方存在采纳路径。崩点：官方根本不接收外部贡献，捐赠变独角戏。
- **变体 D3-R3-01**：只抽「无语义纯函数包」（health/report-diff/CPM/对账）为独立小库发布，实体语义留在插件内不抽——把「独立内核」从架构口号缩成一份可独立测试的纯函数工具集。

## 施压 2｜母本：本地 MCP server，dsh 只是众多客户端之一（D1-10、D2-27、D3-15、D4-20、D5-15）

### 2a. 推到最大
- **极端形态**：pm-tool 起一个本地 MCP server，把七实体全部 CRUD 工具暴露出去，手机 MCP 客户端、另一台机器、其他 agent、同事都能连、都能写；写仍走确认，但确认也由各客户端发起。
- **判定：崩（边界：并发写 / 单写者假设）**。
- **推理链**：`docs/backup-sync.md` 与现状都是**单写者、单台机器**假设，无版本号、无 CAS、无 last-write-wins 冲突合并（provenance-store 每项目 cap 20 是本地操作账本，不是并发事务）。两个客户端同时改一条任务，后写覆盖先写，台账无感知损坏。第二层崩点：MCP 生态本身若未被目标用户采用（生态失败），为一个没普及的协议自建 server 是零收益投入。**崩的边界条件**：连接的写客户端 ≥2，或 MCP 协议在 12 个月内未成为该人群默认接口。

### 2b. 砍到最小
- **极端形态**：server 只暴露**一个只读工具** `pm_health_lights`（逾期/临期/高影响风险/今日行动项），无任何写工具、无确认、无状态变更。
- **判定：反而成立**。
- **推理链**：只读面不碰单写者假设，零并发风险；手机/其他 agent 只「看」不「改」，确认仍回电脑（与 D5-R2-08 移动只读一致）。成立条件：server 只是 dsh 已有本地服务的一个额外只读出口，不新增写面。

### 2c. 反常识倒置
- **极端形态**：「MCP server」这个外壳是借口，真实目的只服务**一个特定客户端**（比如手机只读，或未来自己的 TUI），根本不追求「众多客户端之一」；把多端通用当卖点是自欺。
- **判定：有条件成立 / 暴露真实需求**。
- **推理链**：倒置点——公开通用接口与真实使用面（1 个客户端）不匹配时，维护通用协议的成本被白付。成立条件：承认 server 是为某个具体客户端铺的路，不为通用性交协议税。
- **变体 D3-R3-02**：最小本地只读端点（一个 HTTP GET `/status` 或单只 MCP 只读工具），不建完整 MCP server，只给手机/浏览器一个健康灯页面。

## 施压 3｜母本：静态 viewer / 纯开放文件，dsh 可装可不装（D2-26、D3-08、D4-25、D5-18；Markdown 真源 D3-14 另见施压 13）

### 3a. 推到最大
- **极端形态**：静态站要实时刷新、多人在线查看、自动从 JSON 增量更新、甚至内嵌轻协作评论，变成一个常驻 web 应用。
- **判定：崩**。
- **推理链**：静态文件无状态、无后端、无鉴权、无写；一旦要实时/多人/回写，必须长出一个轻后端，「零宿主、双击即开」的前提当场死亡，退化成又一个要部署要维护的服务。KB-014/delivery §9 现状只信任本机 loopback，远程多人连是额外一整套访问控制。**崩的边界条件**：观众 ≥2 人且要求实时，或出现任何写回需求。

### 3b. 砍到最小
- **极端形态**：一个 `index.html` + 一份 `data/*.json`，双击打开只读渲染，无构建、无依赖、无网络；十年后任何浏览器都能开。
- **判定：反而成立**。
- **推理链**：现有 `core/export.ts` 已经能写 Markdown 到 exports/，把同一批 JSON 渲染成静态 HTML 是纯本地确定性输出，不依赖 dsh 是否安装、模型是否在线。成立条件：定位为「快照/档案/给别人看的一次性视图」，不要求它继续编辑。

### 3c. 反常识倒置
- **极端形态**：与「数据开放、可被任何人消费」相反——静态包**故意不开放**：带口令/加密，只发给指定人，「打不开」本身是隐私卖点；不追求通用可读，追求授权可读。
- **判定：有条件成立**。
- **推理链**：倒置点是 D1-26「开放文件十年可读」把开放当美德，而真实 PM 台账含风险/进展/个人判断，对外分享本就需授权。成立条件：产品定位偏私人档案；崩点：一旦要对外状态页（R2-07/R2-09），不开放就与分发冲突。
- **变体 D3-R3-06**：隐私保险箱定位——台账不可导出、不开放、加密落盘，「谁也拿不走」替代「谁都读得到」成为长寿卖点（详见施压 8c）。

## 施压 4｜母本：独立本地 App，AI 走方舟标准 API 按量（D4-24）

### 4a. 推到最大
- **极端形态**：独立 App 长成可分享的团队应用——账号、多项目、多人协作、云同步、订阅计费。
- **判定：崩（边界：单人带宽 + 成本结构）**。
- **推理链**：`docs/personal-billing-plan.md` 明确：脱离 dsh 独立部署持 Coding Plan key **违规**，必须走标准 API 按量付费，¥40/月套餐合规优势消失；单人维护账号体系/同步/合规/计费本身是全职工作。**崩的边界条件**：用户数 >1 且需要云同步，或开始按 token 按量付费导致成本不可控。

### 4b. 砍到最小
- **极端形态**：独立 App 退化为一个纯本地文件读写 + 视图壳，AI 能力整个删掉（只读、只导出），模型调用留给 dsh 或别处。
- **判定：反而成立**。
- **推理链**：剥掉模型后 App 只是个更漂亮的 JSON 查看/编辑器，无 key、无合规、无按量成本，与施压 3 的静态站同构。成立条件：AI 草稿不是该壳的职责。

### 4c. 反常识倒置
- **极端形态**：独立 App 的真实卖点不是功能，而是「**脱离 dsh 的心理备份**」——用户买/留它只为「万一 dsh 没了我还在」，卖的是保险不是生产力。
- **判定：有条件成立**。
- **推理链**：倒置点——功能上独立 App 重复了面板已有视图，其存在意义是降低对宿主的依附焦虑；成立条件：宿主停更/弃用焦虑是真实情绪（R5 平台存在性）；崩点：若宿主稳定，备份价值无人感知。

## 施压 5｜母本：完全吞并，pm-tool 内化最小 agent runtime（D1-R2-14、D2-R2-11、D3-R2-11、D4-R2-13、D5-R2-11）

### 5a. 推到最大
- **极端形态**：pm-tool 自己实现完整 agent loop：prompt 装配、多轮工具调用、上下文压缩、审批中断、模型路由、错误重试全自研，dsh 只剩可替换模型通道和窗口。
- **判定：崩**。
- **推理链**：这等于重写半个 harness——上下文管理、工具调度、function-calling 兼容、模型差异、会话状态都是 dsh 已经做过且在演进的部分，单人重做必然「追上但追不平」，并背上与上游平行演进的双份维护。`personal-billing-plan.md` 里免费池模型随机、function-calling 不保证（KB-034）等坑，自研循环要自己再踩一遍。**崩的边界条件**：要求多轮自主/工具循环而非一次性文本生成（ADL-036 现状本就是一次性生成、确定性落库在我方代码）。

### 5b. 砍到最小
- **极端形态**：只内化「单轮取一段模型文本」这一步（现状就是如此：AI 只生成草稿文本，落库由我方 zod 代码做），不养循环，不借多轮。
- **判定：反而成立（=现状）**。
- **推理链**：最小吞并就是现在的形态——不持有 loop，只借一次性模型输出；这恰好是 ADL-036 的边界，成立条件与现状一致。

### 5c. 反常识倒置
- **极端形态**：吞并到一半自我取消——pm-tool 把自己长出的 loop 重新还给 dsh，只保留面板与台账，发现「自己当 runtime」是伪需求。
- **判定：反而成立（作为一个自然收敛点）**。
- **推理链**：倒置点是吞并的终点不是取代宿主，而是试错后确认宿主循环够用；成立条件：实测自主循环带来的增量低于维护成本。
- **变体 D3-R3-07**：「吞并自我取消」剧本——先做出最小内置循环做 A/B，一个版本后若增量不明显则拆回，保留卸载路径，避免吞并变成沉没成本。

## 施压 6｜母本：被宿主原生替代时的退出/退役协议（D1-R2-14、D2-R2-12、D3-R2-11、D4-R2-13、D5-R2-12）

### 6a. 推到最大
- **极端形态**：常驻监测宿主版本是否长出等价 PM 能力，自动双写过渡、并行运行、自动迁移、迁移校验器长期维护。
- **判定：崩（边界：退役事件可能永不发生）**。
- **推理链**：为一个概率未知、时间未知（dsh 何时/是否原生长出看板）的事件，长期养一个迁移监测器和双写层，是持续维护税；宿主原生格式未来才知道，现在写的映射表届时多半要重写。**崩的边界条件**：12–24 个月内宿主未长出该能力，监测器成为死代码；或作者在退役发生前已停更。

### 6b. 砍到最小
- **极端形态**：只留一页纸迁移说明（七实体字段→未来原生功能对照）+ 现有 `core/export.ts` 的 JSON/Markdown 导出，零运行时代码、零自动监测。
- **判定：反而成立**。
- **推理链**：退役本质是「数据能带走、历史读得到」，现有导出通道已满足 90%；一份字段映射文档成本为零。成立条件：承认迁移届时手动做，不追求自动化。

### 6c. 反常识倒置
- **极端形态**：产品以「**主动被替代**」为成功设计——逐个把成熟功能送给宿主原生，自己主动退役，被吸收即胜利（捐赠式退休），而不是抵抗。
- **判定：有条件成立**。
- **推理链**：倒置点把「被替代」从失败改写成交付完成；成立条件：维护者目标是做完一件事而非长期占有市场；崩点：若作者想长期运营，主动让位与收入目标冲突。
- **变体 D3-R3-03**：捐赠式退休清单——每个功能标注「可被原生替代的成熟度」，到点主动标记 deprecated 并停止加功能，只修迁移，把退出写成 roadmap 的一节而非应急预案。

## 施压 7｜母本：PROJECTS.md 文件路线，借 AGENTS.md / agent-instructions 零代码进上下文（D2-06、D5-13；杂交 D4-R2-18 带有效期戳）

### 7a. 推到最大
- **极端形态**：PROJECTS.md 与 JSON 双向实时同步，每轮对话后自动回写，保持文件与库完全一致，agent 改文件也能落回实体。
- **判定：崩（双写漂移）**。
- **推理链**：AGENTS.md/agent-instructions 是**指令载体不是数据库**，被 agent 自由改写后编号、父子互斥、环检测（gantt 前置依赖图）这些 zod 约束在纯文本里难以保证；两处真源必然漂移，人手改 md 后回写可能破坏结构。**崩的边界条件**：文件被双向写；只读投影（只渲染不回写）则不崩。

### 7b. 砍到最小
- **极端形态**：一次性手动/命令渲染一份 PROJECTS.md 快照进工作区，只读、不回写、不自动刷新，AGENTS.md 仅引用它。
- **判定：反而成立**。
- **推理链**：纯读时派生（ADL-039「读时派生」精神），不新增真源；成立条件：接受文件是会过期的快照，配合 D4-R2-18 的有效期戳警告。

### 7c. 反常识倒置
- **极端形态**：让 md 文件反过来成为唯一真源，pm-tool 只是 PROJECTS.md 的一个渲染/校验器——文件统治插件，而不是插件统治文件。
- **判定：有条件成立 / 暴露张力**。
- **推理链**：倒置点与 D3-14（Markdown 真源）合流；成立条件：用户本来就习惯手改文本、结构化约束可以放宽；崩点：一旦需要 CPM 关键链/自动编号/健康分，纯文本承载不住（见施压 13）。

## 施压 8｜母本：零遥测承诺 / 单机单写者「十年可读」硬卖点（D1-22、D1-26）

### 8a. 推到最大
- **极端形态**：把「绝不联网、绝不上报、绝不外发」做到加密级封闭，拒绝一切外部连接、外部读取、外部分享，网络能力全部关闭。
- **判定：崩（与对外价值自相矛盾）**。
- **推理链**：封闭与池内大量方向直接冲突——对外状态页（R2-07/09）、反向写外部（R2-04/05）、手机只读（D5-R2-08）、插件市场分发（D2-R2-13）都需要出网或被他人读取。把技术约束（单机自用）抬成产品信条后，产品自我封闭、永远只有一个本机读者（呼应 D3-R2-19 反叛）。**崩的边界条件**：目标包含任何他人阅读/外部同步/公开分发。

### 8b. 砍到最小
- **极端形态**：卖点只写一句「你的数据不出本机」，不建任何额外机制、不做加密架构、不做联网禁令开关。
- **判定：反而成立**。
- **推理链**：现状本就零上报（全仓无遥测代码），承诺成本为零；成立条件：把它作为一句隐私声明，而非一套被工程化牺牲其他能力的定位。

### 8c. 反常识倒置
- **极端形态**：与「开放文件十年可读」相反，**不可导出、不开放、强加密**才是卖点——一本谁也拿不走、连作者换机都要口令的私人档案。
- **判定：有条件成立**。
- **推理链**：倒置点把 D1-26 的「可被未来任何人读」换成「只属于当下这个人」；成立条件：定位为私人记忆/个人复盘档案；崩点：与「十年后迁移/可移交」彻底对立，作者换机/离职即丢失。
- **变体 D3-R3-06（重列）**：隐私保险箱产品线——加密本地落盘、默认不导出、对外只发带口令的单次快照，卖点从「可读」变「安全」。

## 施压 9｜母本：npm 开源治理 / 插件市场 / 分层定价 / 方法论即产品（D2-28、D1-R2-15、D2-R2-13、D3-R2-12、D4-R2-14、D5-R2-13）

### 9a. 推到最大
- **极端形态**：全功能开源、建 issue 社区、维护贡献流程、做模板商城、订阅制、付费模板包 + 一对一校准服务，方法论商品化为收入主线。
- **判定：崩（边界：单人带宽 + 付费意愿）**。
- **推理链**：开源后 issue/PR/版本兼容是单人持续事务；免费内核蚕食付费层；目标用户（单人 AI 开发者）对「9.9 模板包/方法论」付费意愿弱——方法论可被用户自己总结，软件又免费，付费锚点不稳。**崩的边界条件**：公开仓库收到外部贡献/用户，或出现需要支持响应的付费用户。

### 9b. 砍到最小
- **极端形态**：只发一个私有 npm link（现状 `package.json private:true`、本地 link 装载本就如此），不公开、不 LICENSE、不定价。
- **判定：反而成立（=现状）**。
- **推理链**：自用阶段零治理成本；成立条件：明确不追求外部用户，公开推迟到有真实第二个用户。

### 9c. 反常识倒置
- **极端形态**：不靠卖软件也不靠卖方法论赚钱，把开源当**履历/被官方收录的入场券**——目标是被 dsh 官方注意、吸纳或雇佣，开源是信用资产不是收入来源。
- **判定：有条件成立**。
- **推理链**：倒置点把商业逻辑从「向用户收费」换成「向生态展示」；成立条件：维护者职业路径与该生态绑定；崩点：官方无吸纳通道，开源只攒了星星无变现。
- **变体 D3-R3-04**：开源履历路线——只公开 core/纯函数与方法论 skill，不开 issue 不做社区，把仓库当作品集，定价层整体取消。

## 施压 10｜母本：反向薄壳 / AI 通道迁出 dsh，插件退回纯离线 CRUD（D1-20、D5-17）

### 10a. 推到最大
- **极端形态**：彻底去 dsh 化，模型全换本地 Ollama 离线运行，Coding Plan key 完全不用，dsh 与产品无任何关系。
- **判定：崩（边界：模型质量 + 合规）**。
- **推理链**：本地开源模型在草稿质量/function-calling 上明显弱于在线模型，ADL-036 的草稿体验直接塌陷；且 ¥40/月套餐是现状合规且低成本的车道，放弃它换「纯粹独立」代价过高。**崩的边界条件**：本地模型达到可接受草稿质量之前。

### 10b. 砍到最小
- **极端形态**：只在 `ai-client.ts`（LlmGateway）留一个可替换接口，默认仍走 dsh llm，不迁出、不自建。
- **判定：反而成立（= D5-23 合规端口）**。
- **推理链**：留接口不动默认路径，零迁移成本；成立条件：把「可换通道」作为软约束，而非现在就换。

### 10c. 反常识倒置
- **极端形态**：不是「pm-tool 迁出 dsh」，而是反过来——**dsh 可以被迁出/替换，台账才是唯一锚点**；主体是数据不是壳，dsh 只是当前可换的一个前端。
- **判定：反而成立（与 R5 平台存在性一致）**。
- **推理链**：倒置主客体：谁依附谁？只要数据格式开放、导出完整，壳（dsh）可换，账不换；成立条件：开放格式 + 成品导出扎实（反而是施压 3/13 的功课），壳随时可弃。

## 施压 11｜母本：退化成格式供应商，台账写成 iCal/CSV/Markdown 让已有工具消费（D1-21）

### 11a. 推到最大
- **极端形态**：双向适配 iCal 订阅、CSV、Excel、Notion、Obsidian、飞书等全格式，进得来也出得去，pm-tool 只做校验器+编辑器。
- **判定：崩（被外部格式绑架）**。
- **推理链**：每个外部格式一个维护面，格式由对方版本决定变更（iCal 规范、Excel 导出、Notion API），单人被多个上游格式变更牵着走；双向同步还要解决与施压 2 相同的写冲突。**崩的边界条件**：适配格式 ≥2 且要求双向。

### 11b. 砍到最小
- **极端形态**：只单向导出一份 iCal 订阅（截止日期/里程碑进用户已有日历）+ 一份 CSV，只读消费，不回写。
- **判定：反而成立**。
- **推理链**：单向导出无冲突，用户已有日历/Excel 直接消费，pm-tool 不承担维护对方格式的双向责任；成立条件：定位为「喂给现有工具」，不追求成为对方工具的管理器。

### 11c. 反常识倒置
- **极端形态**：不当供应商，反过来让别的工具成为 pm-tool 的只读前端——pm-tool 是唯一事实源，别人来读我，而不是我去适配别人。
- **判定：有条件成立**。
- **推理链**：倒置点把「我写进你的格式」换成「你来读我的标准格式」；成立条件：开放 JSON/静态站足够好读（施压 3b）；崩点：用户现有工具不认自定义格式，供给方心态落不到现实工作流。

## 施压 12｜母本：独立 CLI/TUI 壳经 sdk JSON-RPC 只借模型（D1-31）

### 12a. 推到最大
- **极端形态**：TUI 复刻面板全部九视图、多项目切换、草稿确认、编辑齐全，成为 dsh 之外的完整第二前端。
- **判定：崩（第二套 UI 维护）**。
- **推理链**：面板已在 dsh 内实现，再维护一套终端 UI 是双份视图代码；真实 TUI 用户（终端重度用户）与 dsh 图形面板用户大概率不重叠，第二前端用户数趋零。**崩的边界条件**：没有明确的无 GUI 使用场景（服务器/SSH）作为刚需。

### 12b. 砍到最小
- **极端形态**：一个 `pmcli` 只做查询和导出（`pmcli status`、`pmcli export`），不做编辑、不做确认、不接模型。
- **判定：反而成立**。
- **推理链**：命令行只读查询成本低，可挂进脚本/alias，复用现有 PmDomain 只读方法；成立条件：服务自动化而非终端交互人群。

### 12c. 反常识倒置
- **极端形态**：CLI 根本不是给人用的，而是给脚本和另一个 agent 用的**机器接口**——它是 MCP server 的前身/兄弟，人只是顺便能用。
- **判定：反而成立（身份重定义后成立）**。
- **推理链**：倒置点把「人用 TUI」改成「机器管道」，CLI 输出结构化 JSON 供脚本消费；成立条件：目标是自动化巡检/定时导出，而非人坐在终端前。
- **变体 D3-R3-05**：机器优先 CLI——所有命令输出结构化 JSON、支持管道，TUI 交互层砍光，把它定位成自动化接口而非第二个前端。

## 施压 13｜母本：Markdown 唯一真源，JSON 仅派生缓存（D3-14；关联反叛 D3-R2-18 静态成品才长寿）

### 13a. 推到最大
- **极端形态**：七实体全部存为 md + frontmatter，协作与版本走 git diff，结构化关系（前置依赖、父子、编号）全在纯文本里表达和校验。
- **判定：崩（结构承载不住）**。
- **推理链**：`core/gantt.ts` 的 CPM 关键链、`predecessorIds[]` 环检测、任务父子互斥、自动编号、健康分都依赖类型化结构与 zod 校验；纯文本 frontmatter 里这些约束易被人直接改坏，git diff 无法表达依赖图语义。**崩的边界条件**：项目需要关键链/自动编号/健康分等结构化派生。

### 13b. 砍到最小
- **极端形态**：只有叙事层（周报、会议纪要、复盘文字）存 md，任务/风险/里程碑等结构实体仍存 JSON。
- **判定：反而成立**。
- **推理链**：文字本就适合 md，结构留在 JSON，各取所长；成立条件：承认 md 不承担实体事实。

### 13c. 反常识倒置
- **极端形态**：md 真源也会烂，真正的真源是**定时固化的 PDF/静态归档**——结构 JSON 和 md 都是当期工作态，档案本体是不可再改的渲染成品（接 D3-R2-18）。
- **判定：有条件成立（作为寿命分层的顶层）**。
- **推理链**：倒置点把「正在编辑的文件」与「留给未来的档案」分开；成立条件：里程碑/项目结束时固化一份成品；崩点：固化需要额外动作，无人执行则档案层空缺。

## 施压 14｜母本：留在 dsh 登记为 ¥40 合规选择，背后留标准 API 端口（D5-23）

### 14a. 推到最大
- **极端形态**：同时兼容 dsh 套餐、标准 API、本地 Ollama、多家云 provider，运行时一键切换，每种都完整测试。
- **判定：崩（provider 矩阵 + 合规边界）**。
- **推理链**：personal-billing-plan 明确脱离 dsh 持 Coding Plan key 违规，多 provider 矩阵使合规边界模糊；每个 provider 的模型差异、function-calling、限流都要测，单人测试面爆炸。**崩的边界条件**：默认通道之外真的接入 ≥2 个备选并长期维护。

### 14b. 砍到最小
- **极端形态**：只在 ai-client 留一个接口签名，默认 dsh llm 不动，不实现任何备选。
- **判定：反而成立（=现状）**。
- **推理链**：端口思想是软约束，零实现成本；成立条件：明确「留口子」而非「现在多通」。

### 14c. 反常识倒置
- **极端形态**：¥40/月套餐不是「被迫留在 dsh 的妥协」，而是**产品存在的商业模式本身**——套餐养工具，留在宿主不是退让，而是这个产品唯一成立的经济模型。
- **判定：反而成立（重新定性后成立）**。
- **推理链**：倒置点把「依附」改写成「借力成立」：没有 ¥40 合规车道，独立按量模型成本让单人个人产品不可持续；成立条件：产品定位就是 dsh 生态内的个人插件，不打算独立售卖。
- **变体 D3-R3-08**：套餐即商业模式叙事——对外定位明确为「寄生在合规套餐上的零额外成本工具」，把放弃独立按量作为刻意选择而非遗憾。

### 15a. 推到最大
- **极端形态**：被动推到连备份都手动、零提醒、零主动、项目档案结束即沉默，产品存在感压到最低。

### 15b. 砍到最小

### 15c. 反常识倒置

- **推理链**：倒置点把 D1-26「十年可读」翻成「用完即焚」；成立条件：项目为短周期、不留长期价值；崩点：与复盘/历史复用/证据追溯需求冲突。

## S1 · schedule 到点轻提醒（D1-12 / D2-10 / D4-08）

### 【推最大】每个截止、每条依赖、每个临期里程碑都挂一条 schedule，全天候到点进会话
- **极端形态**：台账里每条带日期/前置的记录都自动生成定时器；工作日每 30 分钟扫一次，逾期即冒泡，临期 3 天/1 天/当天/每小时各触发一次；会话里随时插一条「t-0003 还剩 2 小时」。
- **判定：崩。** 推理链：①schedule 到期是作为普通 follow-up 消息进**原会话**，不是 OS 推送/邮件，dsh 没开/会话没活就投递不到，且每个重复任务只补发最近一次错过时点，人离开电脑两天，积压提醒要么只补一条、要么全丢；②免费车道约 50 次/天上限，每条提醒若走模型润色，一天几十条直接烧穿额度；③提醒密度超过人能处理的速率，进入「全部忽略」状态，提醒与没提醒等价。**边界条件**：只对 high 严重度、且人明确在场（会话活跃）时投递，才可能成立；一旦需要 host 常开、headless 环境，schedule 通道本身不可用（需 Web Session controller+持久化后端）。
- **变体 D4-R3-01【分级事件总线】**：提醒分两级——high（逾期/阻塞/里程碑撞期）才走 schedule 进会话；其余（P2 临期、普通到期）不挂定时器，只在人下次打开时由读时派生（ADL-039 现状）攒成一条聚合清单。定时器只服务「人不在场也必须知道」的少数事件，不服务台账全量。

### 【砍最小】只剩一条命令，零 schedule 接线
- **极端形态**：删掉所有定时器，人在会话里说「今天有什么到期」，一条只读命令纯函数算出逾期/临期列表返回；不注册任何 schedule_create。
- **判定：反而成立。** 推理链：现状 reminders.ts 本来就是读时派生、无常驻（ADL-039），砍到最小等于回到现状；单人单写者、自己定的截止自己记得，缺的只是「问的时候能立刻答」，一条命令足够。**成立条件**：人会主动开口问；若人不问就会忘，砍最小把「主动想起来」的责任全还给人。
- **变体 D4-R3-02【零定时器的纯问内核】**：把提醒能力压缩成一个无状态纯函数 `dueNow(records, now)`，任何宿主接线（schedule/面板/状态页）都只是它的不同外壳；内核本身不含时间、不含状态。

### 【倒置】定时任务被禁止：唯一触发是「人打开」，系统永不主动开口
- **极端形态**：产品宪法里写死「不注册任何 schedule、不主动投递」，所有到期信息只在人打开面板/发问时出现；把 ADL-039 的读时派生从「实现选择」抬到「产品禁令」。
- **判定：在短周期/天天在场成立，在长周期/人会离开时崩。** 推理链：倒置后系统零打扰、零 token、零依赖 host 常开；但项目跨月、人休假两周、或人本来就靠系统兜底记忆时，「不问就不知道」等于把遗忘风险完全转嫁给人。**成立条件**：项目周期短（周级）、人每天在场、无对外承诺节点；**崩的条件**：有外部 deadline、人会断联、需要被「推着走」。
- **变体 D4-R3-03【禁令式默认 + 单点例外】**：默认全禁定时器，只允许「硬 deadline 前 N 小时」一个例外槽，且该槽必须由人手动为单条记录显式开启，系统永不自动挂。

## S2 · 周期自动周报（D1-13 / D1-R2-19）

### 【推最大】每周自动生成、自动对账、自动落库，无人介入
- **极端形态**：周五 17:00 jobs 自动跑快照→narrate→承诺兑现表→session-query 痕迹，直接写入 reports 表并归档，草稿确认制也取消。
- **判定：崩。** 推理链：①周报的价值在「叙述与判断」，自动落库的是数字流水，无人读的例行公文；②自动落库绕过 ask-apply 确认，错误口径（calcVersion 不一致、证据不足 null）被固化进档案；③免费车道 50 次/天，narrate 调模型是固定成本，周周烧；④承诺对账需要人对「未兑现」做解释，自动版只会记「未兑现」不记原因。**边界条件**：只自动填数字栏、叙述栏留空等人写（D1-R2-19 本来就是这个姿态），自动落库是越界。
- **变体 D4-R3-04【无变化静默周报】**：周报草稿只在「本期有可量化变化（completedDate 新增/风险升降/里程碑变动）」时才生成；本期零变化则周五静默，只在计数页留「本周无变更，未生成周报」，不产出空文。

### 【砍最小】手动一条命令，无周期、无 jobs、无快照对比
- **极端形态**：`/pm report narrate` 当场读当前台账生成草稿，不存快照、不对比上期、不挂周期。
- **判定：反而成立。** 推理链：现状 collectProjectReport 数字是确定性的，narrate 只是包一层；砍最小丢掉的只是「上期承诺对账」这层增值，核心数字仍在。**成立条件**：人记得自己上周承诺了什么；承诺对账（D2-21）被砍掉后，自我承诺的连续性丢失。
- **变体 D4-R3-05【手动触发的最小周报】**：保留纯函数数字聚合，去掉 schedule/jobs/快照链，作为一条命令存在；周期与快照对比作为可选增强层挂在外面。

### 【倒置】写转拉：周报不由 PM 定时写，而由阅读方（leader/客户）拉状态页触发
- **极端形态**：PM 不写周报；领导/客户打开常驻只读状态页（D4-R2-09）自助看实时数字，周报这个产物被取消，「写报告」动作消失。
- **判定：在对内自助场景成立，在需要向上叙述/承诺时崩。** 推理链：数字可拉，但「为什么延期、下周打算怎么办」的叙述无法从状态页自动长出；倒置消灭了汇报负担，也消灭了向上沟通的固定触点。**成立条件**：阅读方只需要事实数字、不要判断；**崩的条件**：需要解释、承诺、对齐预期。
- **变体 D4-R3-06【拉取式数字 + 触发式叙述】**：状态页永远自助可拉（数字层），仅当 leader 主动问「本周怎么样」时，系统才把数字草稿推给 PM 补两句叙述，叙述不按固定周期生产。

## S3 · jobs 后台批量（D2-11 / D3-23）

### 【推最大】每个小动作都起 job，全后台异步
- **极端形态**：加一条任务、勾一个清单、改个日期都开 JobHandle，进拉取式输出环，完成发会话通知。
- **判定：崩。** 推理链：单人小量数据下，这些操作是毫秒级同步完成，起 job 的句柄管理、owner cleanup、通知环开销远大于收益；通知环每步都「完成了」，制造与 S1 同类的噪音；jobs 是为长任务（批量导入、全库重算）设计的，用在短任务上是大炮打蚊子。**边界条件**：只在操作预计超过阈值（如导入 >50 行、全库重算、跨项目巡检）时才升级为 job。
- **变体 D4-R3-07【阈值升级 job】**：同步快操作当场做完；仅当估计工作量超阈值（行数/实体数/跨项目数）才 spawn job，面板给进度环，完成一条通知而非每条通知。

### 【砍最小】不用 jobs，全同步，面板转圈即可
- **极端形态**：删掉 jobs 接线，导入/重算都在主线程同步跑，UI 转圈。
- **判定：反而成立（小数据量）。** 推理链：七实体本地 JSON、单人几十到几百条记录，同步计算无感知延迟；砍最小省掉 JobHandle/cancel/输出环/owner cleanup 整套机制。**崩的条件**：记录量涨到数百上千、或导入/重算真正需要秒级以上，同步会卡 UI。
- **变体 D4-R3-08【同步内核 + 可选异步壳】**：批量逻辑写成同步纯函数，jobs 只是可选包装；默认同步，量大时由调用方决定是否套 job。

### 【倒置】jobs 不是为「不阻塞人」，而是为「人不在场时也排队等着」
- **极端形态**：重新定义 job 的用途——不是并发提速，而是「人休假两周期间，批量导入/重算任务排好队，等人回来一次性执行」；job 面向缺席，而非面向并发。
- **判定：在异步批处理成立，在「无人时自动跑」崩。** 推理链：倒置把 job 从「并发工具」改成「待办队列」，逻辑自洽；但想让人不在场时自动跑，仍需 host 常开+持久化后端，schedule/jobs 在 headless/纯 SDK 不可用，无人值守自动执行的前提不成立。**成立条件**：job 只是本地排队、人回来再执行；**崩的条件**：期待后台自动完成。
- **变体 D4-R3-09【缺席队列】**：批量任务在 host 关闭期间只登记为待办项，host 下次启动时按序提示执行，不假装自己在后台跑过。

## S4 · 巡检 subagent（D4-18 / D3-22）

### 【推最大】N 个巡检 agent 常驻、高频扫全库
- **极端形态**：为每条风险/每个项目/每个团队派一个常驻 subagent，每小时扫一次，发现异常就出草稿；agent 数量随项目数线性增长。
- **判定：崩。** 推理链：①每次巡检都调模型，免费车道 50 次/天撑不住 100 个 agent 每小时扫；②单人单写者无多主体前提（R4），巡检发现的异常最终还是同一个人看；③大部分异常（逾期、临期、未关闭风险）是确定性规则，纯函数免费就能算，花模型钱巡检是重复付费；④常驻 subagent 的上下文随会话寿命/compaction 漂移，巡检口径不稳。**边界条件**：只对确定性规则覆盖不了的「语义异常」（承诺与实际措辞矛盾、风险措辞自相矛盾）才花模型。
- **变体 D4-R3-10【两层巡检】**：第一层确定性规则（逾期/临期/高影响未关闭/负载超阈值）免费秒出，不调模型；第二层仅当规则命中可疑项时，spawn 一次性只读 subagent 做语义判断，不常驻。

### 【砍最小】零 subagent，全部走确定性 suggestion-engine
- **极端形态**：不 spawn 任何 agent，巡检=现有诊断气泡（kind 五类）纯函数输出。
- **判定：反而成立。** 推理链：现状 suggestion-engine 已经在做规则诊断，砍最小只是承认「单人场景模型巡检边际收益低」；省掉 spawn-in-process 的进程与 token。**成立条件**：异常都能写成规则；语义模糊的洞察（这条计划不合理）被放弃。
- **变体 D4-R3-11【无 agent 巡检内核】**：把巡检抽成规则集合+匹配器，模型层是后期可选插件，内核零 agent。

### 【倒置】不是 agent 巡台账，而是台账「被动冒异常」，agent 不主动扫
- **极端形态**：取消主动巡检；系统不周期性扫描，异常只在「字段被变更、证据被补、承诺被做」的事件发生瞬间被检查并当场冒泡，无事发生即安静。
- **判定：成立。** 推理链：主动扫描的大部分发现是「本来就一直存在、只是这次又扫到」的陈旧异常，价值低；事件触发只对新变化反应，token 只花在变动上。**成立条件**：异常会随动作暴露；**崩的条件**：历史遗留问题（三个月前就没关的风险）不被动作触发，永远不冒泡——需靠 S11 的打开时差异回顾兜底。
- **变体 D4-R3-12【事件触发式巡检】**：检查挂在写动作之后（改期/关风险/标完成瞬间跑对应规则），无定时轮询；陈旧项由打开时一次性补扫。

## S5 · 里程碑独立验收审计（D2-12 / D5-R2-14 / D1-R2-17）

### 【推最大】每个任务每次状态变更都派全新审计 subagent
- **极端形态**：勾一条 checklist、标 in_progress 都 spawn 无历史审计员核对。
- **判定：崩。** 推理链：审计价值集中在「里程碑/交付达成」这一少数高价值节点，逐条审计把单位成本摊到最不值钱的动作上；全新无历史 subagent 每次重新喂快照，重复耗 token；审计员自身有误报率（D1-R2-17），高频审计误报总量被放大，人开始连审计报告都忽略。**边界条件**：审计只在「拟标达成/交付」触发，且用 D1-R2-17 履历给老误报项降权。
- **变体 D4-R3-13【节点审计 + 误报降权】**：审计 subagent 仅在人点「拟达成/交付」时一次性 spawn；审计结论写只增事件流，历史命中率高的检查项前置、老误报项自动弱化（D1-R2-17 履历机制落地）。

### 【砍最小】零审计 agent，人对照 checklist 自验
- **极端形态**：取消 subagent，里程碑达成时人自己逐条对验收清单/checklist，证据自己贴。
- **判定：反而成立（单人、验收客观时）。** 推理链：单人就是验收人，独立审计的「第三方视角」在单人场景缺少真正的独立性——审计员也是同一个模型、同一套台账；自验成本最低。**崩的条件**：验收标准含主观判断、或需要对外背书（向客户证明完成），此时独立视角才有增量。
- **变体 D4-R3-14【自验清单 + 可选背书】**：默认人对 checklist 自验；仅当里程碑对外（有客户/交付物）时，可选 spawn 一次审计员出背书报告，不默认跑。

### 【倒置】黑白反转：审计员不是挑毛病，而是主动为完成「找证据背书」，挑缺口只是副产物
- **极端形态**：审计员的第一任务变成「收集一切支持达成的证据并给出背书」，只在证据实在找不到时才标注缺口；角色从验收官变成吹鼓手。
- **判定：边界内成立，越界即崩。** 推理链：单人自验容易「觉得做完了」，一个主动找证据的角色反而能把散落证据收拢；但如果吹鼓手偏向性太强，会把证据不足也说成达成，丧失验收意义。**成立条件**：背书必须显式列出「已找到的证据 hunk/文件」，缺口单列且不可省略，证据不达标时背书无效；**崩的条件**：背书措辞压倒缺口标注。
- **变体 D4-R3-15【背书型审计报告】**：报告结构=「支持达成的证据清单（逐条引用 diff/hunk/会话）」+「未覆盖的验收项」两栏，前者为主后者必现，禁止只给结论不给证据。

## S6 · 四角色 PMO 班底（D1-R2-11 / D2-R2-09 / D5-R2-08 / D4-R2-10）

### 【推最大】四个常驻 agent 各配定时轮值、各自 spawn、草稿箱四分
- **极端形态**：风险官/史官/催办员/调度员全部常驻持久会话，各挂 schedule 定时扫，结果分四个收件区。
- **判定：崩。** 推理链：①4 个常驻 subagent × 定时扫描，免费 50 次/天远超；②四角色产出高度重叠（催办员的临期清单=规则，风险官的高影响未关闭=规则，调度员的负载冲突=纯函数 CPM），真正需要模型的只有史官归档叙事；③agent-team 是 experimental、无稳定性保证，常驻 roster 冷恢复口径未稳；④单人面对四份草稿，统一确认的摩擦高于自己扫一眼。**边界条件**：四个角色里三个是确定性视图，只留史官一个可选项。
- **变体 D4-R3-16【角色视图而非常驻 agent】**：风险官/催办员/调度员实现为同一只读引擎的四个筛选视图（纯函数），不养 agent；仅史官叙事可选一次性 subagent。「班底」是界面分组，不是四个进程。

### 【砍最小】一个草稿箱 + 人自己分四类，零角色 agent
- **极端形态**：取消角色分工，所有规则结果进同一个列表，人自己看出哪条是风险、哪条是临期。
- **判定：反而成立。** 推理链：单人项目量小，分类认知负担极低；砍最小省掉角色提示词、分触发条件、独立 spawn 整套结构。**成立条件**：项目数 ≤2、风险数 ≤10；项目组合变大（S7 多项目）时分类视图才有价值。
- **变体 D4-R3-17【单箱分组标签】**：单草稿箱内用轻量标签（风险/临期/负载/归档）分组，标签是派生字段，不对应独立 agent。

### 【倒置】班子管理真人，而不是给 PM 提建议
- **极端形态**：角色职能反转——催办员不是提醒 PM「自己的任务到期」，而是替 PM 去盯真人团队成员（谁逾期、谁该交什么）；风险官向真人发升级建议。
- **判定：单人场景崩，多人场景才成立。** 推理链：当前单写者、无真人成员，倒置对象不存在，班子空转；这也正好把 R4 主体问题逼出来——角色班底的真正舞台是未来多人协作，不是单人。**成立条件**：有真实可指派的成员、外部系统可触达（S2 出站写）；**崩的条件**：单写者。
- **变体 D4-R3-18【角色接口预留、单人空转】**：四角色先写成对「成员对象」操作的接口（当前成员只有 PM 自己），单人时班底自动空转不出稿，未来接真人时无需重构。

## S7 · workflow 扇出 DAG（D4-19 / D2-14 / D5-08 / D5-R2-17）

### 【推最大】所有 WBS 自动编译成可执行 DAG，agent 并行自动跑到底
- **极端形态**：一建项目就把任务树编译成 workflow，parallel() 扇出多个 agent 同时执行，pipeline() 串依赖，阻塞父级直到结算。
- **判定：崩。** 推理链：①单人无并行主体，扇出多个 agent 是自己跟自己并行；②强串行/需人判断的项目硬扇出，D5-R2-17 可行性门本来就要拦；③workflow 在 PTC Node 沙箱运行、阻塞父级，自动跑到底会耗尽额度且产出无人验收；④goal/budget 上限到了就停，停在中间态无人收尾。**边界条件**：DAG 只做依赖关系可视化，不执行。
- **变体 D4-R3-19【只读 DAG 视图】**：predecessorIds 编译成依赖图/阻塞链高亮（哪条被前置卡住），纯展示、零 agent、零执行；可行性门（D5-R2-17）作为「是否值得扇出」的静态判定先于任何编译。

### 【砍最小】静态 WBS 树 + 前置关系字段，无 workflow
- **极端形态**：不接 workflow，任务树和 predecessorIds 就是全部。
- **判定：反而成立。** 推理链：现状七实体已含树结构与前置字段，单人串行执行本来就不需要编排器；砍最小去掉模型编写扇出脚本、沙箱运行时整套。**成立条件**：任务在人脑中按序推进；**崩的条件**：多项目并行、需同时跟踪多条流。
- **变体 D4-R3-20【树即 DAG】**：把前置关系直接渲染为树的连线/阻塞角标，不引入 workflow 运行时。

### 【倒置】DAG 不由 PM 事前编译，而由工作实际发生顺序「事后长出」
- **极端形态**：不预先规划 DAG；系统从真实执行轨迹（git 提交先后、会话先后、证据挂接顺序）反推出实际发生顺序，再与计划树对照，画出「计划 vs 实际」偏差图。
- **判定：成立。** 推理链：事后真实轨迹是客观的（workspace-changes/session-query 已有原料），暴露的是「计划以为并行、实际串行」这类真实偏差，比事前编译更诚实。**成立条件**：执行留痕完整；**崩的条件**：无留痕或跨工具。
- **变体 D4-R3-21【事后实际 DAG 回放】**：结项时用完成记录/证据时间戳反推真实执行顺序，与计划树叠加成偏差视图，用于复盘而非指挥执行。

## S8 · goal 绑任务自动续行（D2-13 / D5-21 / D1-27）

### 【推最大】每个 P0 都挂 goal，goal-round-driver 自动多轮续行直到完成
- **极端形态**：所有高优任务绑持久 goal，驱动器自动开 round、调 agent、续行，无需人介入。
- **判定：崩。** 推理链：①自动续行在无人看时空转，轮次烧额度（免费 50 次/天）；②goal 是会话级短命对象，绑长寿里程碑会造成寿命错配（D5-21 实验后即弃的原因）；③续行停在 budget 上限，中间态无人收；④goal 进度只在会话内，回写台账会污染（D1-27 单向镜像就是防这个）。**边界条件**：goal 只挂「单轮可完成的叶子任务」，续行上限 1–2 轮。
- **变体 D4-R3-22【短叶 goal + 硬续行上限】**：goal 仅绑定单条可一轮完成的叶子，自动续行最多 2 轮即停并交回人；里程碑/长目标绝不挂 goal。

### 【砍最小】不挂 goal，人自己推进
- **极端形态**：取消 goal 接线，任务推进靠人在会话里直接做。
- **判定：反而成立。** 推理链：goal 解决的是「会话内聚焦、防止跑题」，单人主动发起的任务本就聚焦；砍最小去掉 create/pause/resume/complete/block 状态机。**成立条件**：单轮可完成；**崩的条件**：一个会话要拆多轮、需要保持目标不漂移。
- **变体 D4-R3-23【可选聚焦环】**：goal 作为人主动开启的一次性聚焦工具，不自动绑定、不自动续行。

### 【倒置】goal 从油门变刹车：偏离即停，而非驱动往前
- **极端形态**：goal 不再用于驱动续行，而是作为「偏离检测」——agent 每轮自报是否还在目标内，跑偏立即 pause/block 并交还人，goal 是停止线不是发动机。
- **判定：成立且与单人安全兼容。** 推理链：自动往前的风险是空转，自动叫停的价值是止损；刹车不需要连续驱动，token 成本低，且可与 auto-review 逐轮审查互补。**成立条件**：goal 描述明确可判定；**崩的条件**：目标模糊到无法判断偏离。
- **变体 D4-R3-24【刹车式 goal】**：goal 只做偏离守卫，命中偏离条件自动暂停并交回，不主动推进；保留 create/block/clear，去掉自动续行。

## S9 · 仪式卡 + 建议疲劳节流（D4-R2-12 / D5-R2-10 / D1-R2-13 / D3-R2-10）

### 【推最大】每分钟都有仪式槽，配额/阈值全调到最严
- **极端形态**：晨会三行、午间复检、下班收口、周报槽、里程碑仪式全天排满；建议配额 1 条/会话、草稿 TTL 1 天。
- **判定：崩。** 推理链：仪式本身变成另一个要维护的负担（仪式主义），三行晨会天天开却无事可报；配额调参地狱（1 条太紧漏掉关键，阈值随人漂移）；TTL 过短把还没来得及看的合法草稿清掉。**边界条件**：仪式只在「有异常可报」时出现。
- **变体 D4-R3-25【静默晨会】**：每日仪式槽默认不开；仅当存在逾期/阻塞/待批时才生成三行，无事则当天晨会缺失，系统不硬造内容。

### 【砍最小】无固定仪式，打开即看
- **极端形态**：删掉所有仪式卡/配额/TTL，人随时打开看现状。
- **判定：反而成立。** 推理链：与 S11 极致沉默同源，仪式是「外部节奏」，单人可自建节奏；砍最小零维护。**成立条件**：人有自己的工作节奏；**崩的条件**：人需要外部结构强迫自己回看。
- **变体 D4-R3-26【无仪式纯看盘】**：仪式层整体可关，只留默认看板。

### 【倒置】无消息本身被观测为信号：连续 N 天零变更触发一次回顾
- **极端形态**：沉默不再是「没发生事」，而是被计量——连续 7 天台账零变更，系统主动给一条「项目静默一周，是否停滞/遗忘」的提示；沉默是要被报告的异常。
- **判定：成立，补 S11 短板。** 推理链：极致沉默只回顾「变化」，变化为零时反而盲；倒置把零活动也当信号，捕捉「项目被遗忘」。**成立条件**：项目本应活跃；**崩的条件**：项目本就是等待期/冬眠期，会误报。
- **变体 D4-R3-27【静默停滞探针】**：可配置项目预期活跃周期，连续 N 天零变更触发一条停滞提示；等待期项目可标记冬眠豁免。

## S10 · 自适应沉默 / 低采纳自静默（D2-R2-17 / D3-R2-14）

### 【推最大】采纳率驱动一切，样本极小也立即降频/静默
- **极端形态**：每条建议记录采纳与否，近 3 条采纳率低就静默，实时调整所有建议频率。
- **判定：崩（冷启动误杀）。** 推理链：①新建议还没被看到，小样本采纳率无意义即被静默；②采纳率低可能是「当时时机不对」而非建议无价值，静默后永不恢复；③自我静默后模型/人都不知道它还存在，等于功能消失。**边界条件**：冷启动保护期 + 静默≠删除 + 严重度升级强制冒泡。
- **变体 D4-R3-28【保护期 + 可唤醒静默】**：新类建议先给固定保护期（如首 10 条）不参与降频；静默只压「主动投递」不删除记录，人可在设置里手动唤醒；严重度升到逾期/阻塞时无视静默强制冒泡。

### 【砍最小】一个全局开关（全收/全静），零学习
- **极端形态**：不要响应历史、不要采纳率、不要降频曲线，设置里只有「接收建议/关闭建议」。
- **判定：反而成立。** 推理链：单人偏好稳定，一个开关覆盖 80% 需求；砍掉本地计数、反馈闭环、阈值调参。**成立条件**：人愿意自己拨开关；**崩的条件**：人懒得调，希望系统自己懂。
- **变体 D4-R3-29【二态开关内核】**：自适应层全部外置，内核只暴露 mute/all 两态。

### 【倒置】采纳率高反而沉默，被反复拒绝的才换方式再提
- **极端形态：因果反转**——最常被采纳的建议默认人已经在做，系统少打扰；被连续拒绝的同类建议，系统换一种表达/时机再试一次，而不是永久静默。
- **判定：反常识但局部成立。** 推理链：奖励「已经做好的事安静」，把注意力预算留给「一直被拒、可能是表达错了」的项；但永久不重试也会漏掉真不需要的项。**成立条件**：拒绝附带简单原因（不需要/时机未到/已完成），系统据此换方式而非消失；**崩的条件**：拒绝无原因，系统无法区分「拒错」与「不需要」。
- **变体 D4-R3-30【奖励安静、重试被拒】**：高采纳类降频至背景；被拒类带一个「重试配额」（同类最多换 2 种表达），仍拒则永久归档；与 D4-R3-28 保护期互补。

## S11 · 极致沉默哲学（D1-24 / D4-26）

### 【推最大】彻底零信号、零常驻、零推送，连打开时差异回顾都关掉
- **极端形态**：产品完全被动，连两次快照差异都不对比，人看到什么就是什么。
- **判定：在短周期天天在场成立，长周期/人离开时崩。** 推理链：推到绝对被动=零打扰零成本，但两周休假后回来，没有任何「期间变化/我落下什么」的线索，项目靠纯记忆；D1-24 的差异回顾正是为了救这个，连它一起关就把唯一的被动信息源也丢了。**成立条件**：项目周级、人每天在场；**崩的条件**：跨月、断联、外部承诺。
- **变体 D4-R3-31【被动回顾保留为唯一出口】**：极致沉默只禁主动投递，保留「打开时基于备份链的差异回顾」（D5-R2-16）作为唯一信息回流，这是沉默哲学的安全网，不可一并砍掉。

### 【砍最小】沉默本身已是最小，无需再砍
- **判定：成立。** 推理链：零接线、零定时器、零常驻 agent，是本簇的最小可行形态；它证明了 PM 工具可以不依赖任何主动能力存在。
- **变体**：无新变体（母本即最小）。

### 【倒置】沉默不是「功能缺失」，而是出厂默认宪法；提醒都是 opt-in 的申请来的特权
- **极端形态**：把沉默写成产品第一原则——默认一切安静，任何提醒/推送/主动建议都必须由人逐条申请开启，系统从不默认替人开。
- **判定：成立，且是 S1/S9/S10 的总开关。** 推理链：把「主动」从默认翻成例外，所有噪音问题在宪法层消解；需要提醒的人自己申请，产品不赌大众偏好。**成立条件**：申请成本低（一键）；**崩的条件**：默认全静让新用户以为产品没有提醒能力。
- **变体 D4-R3-32【沉默宪法】**：产品默认态=全静默；schedule、建议投递、仪式槽、PMO 出稿全部为 opt-in 显式开关，设置页把「默认安静、按需开启」写成首条说明。

## S12 · PMO × jobs 轮值 × inbox 汇流（D4-R2-16）

### 【推最大】四角色按 jobs 轮值表 7×24 跑，inbox 实时汇流
- **极端形态**：排一张角色轮值时间表，jobs 定时唤醒风险官/史官/催办员/调度员，草稿实时进共享 inbox。
- **判定：崩。** 推理链：轮值表本身要维护；jobs/schedule 需 host 常开，headless 不可用；7×24 在单人空转，token 与通知双重消耗。**边界条件**：轮值改为「打开时按需当场跑」。
- **变体 D4-R3-33【打开即轮值】**：取消 jobs 定时轮值，人打开 inbox 时当场按角色规则跑一遍（确定性部分免费，史官可选），出稿即清，零常驻零表。

### 【砍最小】inbox 只是一个列表，无轮值无汇流结构
- **判定：反而成立。** 推理链：汇流的价值是集中确认，单列表即达成；砍掉轮值调度。
- **变体 D4-R3-34【单清单收件箱】**：所有草稿无角色分区进一列表，确认动作统一。

### 【倒置】不是人收建议，而是建议自己按严重度投票排队，人只看 Top1
- **极端形态**：inbox 不按到达顺序列，而按严重度×新鲜度自动排序，只把最该处理的一条顶到最前，其余折叠；人不做分拣。
- **判定：成立。** 推理链：单人确认精力有限，排序省掉分拣动作；排序是纯函数（严重度/逾期天数/未覆盖证据），不调模型。**成立条件**：严重度字段可靠；**崩的条件**：多条同级重要，Top1 机制漏掉次优。
- **变体 D4-R3-35【Top1 收件箱】**：inbox 默认只展开最高优先级一条，其余折叠为「还有 N 条」，人处理完自动降下一条。

## S13 · 冲刺三段链：沙盘→goal→审计（D4-R2-17）

### 【推最大】三段全自动：沙盘选任务、goal 自动驱动、审计自动通过，人只签字
- **极端形态**：what-if 沙盘自动选出冲刺任务，goal 自动续行执行，审计自动判定达成，人只在末尾签字。
- **判定：崩。** 推理链：三段各自的判断（选哪条、跑偏没、够不够格）在单人全自动下无人兜底；goal 空转（S8）、审计误报（S5）、沙盘假设无人拍板，链条把三处风险串联放大。**边界条件**：每段收口都留人批准，自动只做准备不做决定。
- **变体 D4-R3-36【三段备料、人做三个决定】**：沙盘备候选、goal 备驱动、审计备报告，三个收口决策全留人，链条只减少准备工作不代替判断。

### 【砍最小】只留人推 goal，沙盘/审计去掉
- **判定：反而成立（小冲刺）。** 推理链：单任务冲刺不需要沙盘推演和独立审计；砍最小回到 S8 形态。
- **变体 D4-R3-37【按需插拔三段】**：沙盘/goal/审计是三个可独立插拔的配件，按冲刺大小选用，不强制成链。

### 【倒置】验收先于计划：先审计现状缺口，再定沙盘，最后才立 goal
- **极端形态**：冲刺顺序反过来——先派审计员盘点「现状缺什么、证据差什么」，据缺口做沙盘选补项，最后才立 goal 去补；从「计划→执行→验收」翻成「验收→计划→执行」。
- **判定：成立且反常识合理。** 推理链：先看清缺口再选目标，避免为不存在的缺口排期；单人下这是诚实的自审顺序。**成立条件**：审计能给出明确缺口清单；**崩的条件**：从零开始的全新项目无现状可审。
- **变体 D4-R3-38【缺口先行冲刺】**：新冲刺启动第一步=现状缺口审计，第二步沙盘围绕缺口选任务，第三步立 goal；全新无现状项目跳过第一步。

## S14 · 三态副驾：同一常驻 agent 换帽子（D2-R2-15）

### 【推最大】一个常驻 agent 长期记项目全历史，辅助/审计/考核三态随阶段自动切换
- **极端形态**：常驻子线程长期存活，平时辅助、里程碑切审计、月底切考核，共享同一上下文。
- **判定：崩。** 推理链：常驻上下文随 compaction 漂移，长期记忆口径不稳；辅助态的偏见会传染给审计态（D2-R2-15 自己也强调审计要独立视角，同一主体换帽子削弱了独立性）；常驻 token 持续成本；experimental 形态无稳定性保证。**边界条件**：三态各用全新无历史 agent，只共享喂进去的快照。
- **变体 D4-R3-39【无共享上下文的三态】**：辅助/审计/考核三次调用各起全新 subagent，只喂当前快照，防止辅助偏见污染独立审计；「同一主体换帽子」被「三个独立视角」取代。

### 【砍最小】三态都用一次性 subagent，无常驻
- **判定：反而成立。** 推理链：一次性 spawn 成本低、无漂移、无偏见；常驻唯一优势「记得历史」在单人台账里由确定性快照替代。
- **变体 D4-R3-40【一次性三视角】**：需要哪态当场 spawn 哪态，快照由台账喂，不留常驻。

### 【倒置】去共享：三个 agent 互不知晓，人自己综合，而非一个 agent 内部切换
- **极端形态**：取消「同一主体」，辅助员/审计员/考核员互不通气、各自独立出稿，由人在主线程综合三份意见。
- **判定：成立，独立性最强。** 推理链：独立视角不共享偏见，代价是人要综合；单人综合成本可接受。**成立条件**：三份草稿都短；**崩的条件**：意见冲突时无人裁决（单人即裁决人，故不崩）。
- **变体 D4-R3-41【三独立稿 + 人裁决】**：三态并行独立出稿，主线程人对照裁决，系统不替人做一致性合并。

## S15 · 任务→会话→证据自动闭环（D1-R2-16）

### 【推最大】到点自动开会话、自动干活、自动回挂 diff、自动标完成
- **极端形态**：任务到期 schedule 自动开会话，agent 自动执行，结束自动把 diff 挂回并标 done。
- **判定：崩。** 推理链：无人在场时空转；证据被当成完成（D5-R2-14 审计的必要性）；自动标完成绕过确认；host 不开则到点无会话；免费额度被自动会话消耗。**边界条件**：自动只到「开会话+收证据草稿」，标完成留人。
- **变体 D4-R3-42【半自动闭环】**：到点/手动只自动开会话并在结束时收 diff 证据草稿，「附证据+确认完成」必须人点；自动只搬运，不判定完成。

### 【砍最小】手动点开工，单步，无自动串联
- **判定：反而成立。** 推理链：D3-13 手动开工建会话已是现状；砍掉 schedule 触发与自动回挂，证据人自己贴。
- **变体 D4-R3-43【单步开工】**：保留手动开工，证据回挂作为可选一键动作。

### 【倒置】会话找任务，而非任务找会话：结束时会话反向认领它服务过的任务
- **极端形态**：不预先把任务绑给会话；会话结束时由 session-query 反查本轮内容，自动匹配它可能服务的任务，提出「本轮是否服务 t-0003」的认领候选，人确认后挂证据。
- **判定：成立，补绑定难题。** 推理链：反向认领避免「开工时人工挂任务号」的漏绑；匹配是只读+草稿，人确认。**成立条件**：会话内容含任务号/关键词；**崩的条件**：一轮跨多任务，认领歧义（此时出多个候选等人分）。
- **变体 D4-R3-44【会话反向认领】**：会话结束生成「本轮疑似服务任务」候选列表（FTS5 按任务号/关键词匹配），人确认绑定后回挂证据，免除事前人工绑定。

## 压测中反复出现的边界条件（供后续轮次取用，不评分）
1. **host 常开依赖**：schedule/jobs/自动轮值都需 Web Session controller+持久化后端，headless/纯 SDK/关机期间全部失效；这是「推最大」类想法最集中的崩点。
2. **免费车道 50 次/天上限**：任何「N 个常驻 agent × 高频扫描/自动续行/自动会话」组合先在此撞墙；确定性规则是免费替代层。
3. **单人主体（R4）**：多角色/多 agent/并行扇出/班子管真人在单人单写下空转，它们的真实舞台是未来多人。
4. **会话寿命错配**：goal/常驻 subagent 是短命对象，里程碑/项目是长寿对象，绑定即漂移。
5. **冷启动与样本**：采纳率自适应在小样本/新类上误杀，需要保护期与可唤醒。
6. **自验独立性幻觉**：单人下「独立审计」独立性有限，背书/自验/三独立视角是不同补法。

## 施压单元 1：估时校准闭环（母本 D1-R2-01 / D2-R2-01 / D3-R2-01 / D4-R2-01 / D5-R2-01）

### ① 推到最大
每条任务强制填 estimateHours；实时拟合个人速度曲线；WBS 草稿按校准系数锁死工时；系数跨项目、跨人共享。
### ② 判定：**崩（在样本小/任务异质时）**
- 推理链：中位数+四分位需要同类样本，**N<10 同类任务时系数是噪声而不是信号**，高估 40% 这个结论可能只来自 2 条任务；强制填估时本身就是一笔新录入摩擦，直接撞上「该被消灭的是维护录入」（D3-R2-20/D5-R2-20）；一次性创新任务（第一次做的功能）与重复维护任务被强行归一，系数把异常当常态；WBS 由模型拆出、本就没有工时概念，硬加 estimate 字段在草稿链路上断档。
- **成立条件**：同类任务 N≥30、任务类型稳定（重复型多）、PM 本来就愿意填工时；否则崩。
### ③ 砍到最小
只剩一条 `/pm estimate <taskId>` 打印「同类历史实际工时中位数」，无持久系数、无 UI、不回填、不喂模型。**反而成立**：50 条任务内一个只读聚合即可用，零维护。
### ④ 反常识倒置
「估时永远错才是价值」：校准系数不该让下次更准，而该把「你一贯高估 40%」本身变成谈判与汇报材料；越追求估时准越有害——伪精确麻痹决策者。
### ⑤ 新变体
- **D5-R3-01**（由倒置长出）：偏差页只展示系统性偏误方向（「联调类你一贯高估、文档类你一贯低估」），**绝不生成「修正后估时」**，把偏误当自我认知材料而非预测工具。

## 施压单元 2：what-if 排期沙盘（母本 D1-R2-02 / D2-R2-02 / D3-R2-02 / D4-R2-02）

### ① 推到最大
全参数自由拖拽（日期/负责人/删任务/加任务）、AI 陪聊推演、多情景并排评分、自动推荐「最优解」。
### ② 判定：**崩（无工作量数据 + 单人无争用）**
- 推理链：CPM 只按日历天偏移算 ES/EF/LS/LF/slack（ADL-051 已明确不建模 lag、不做资源平衡），**挪人不重算工作量压平**，沙盘给出的是「日历幻觉」而不是负载现实；单人场景没有第二个真实资源，「某人过载」是自己跟自己比；多情景并排制造选择疲劳，最优解推荐需要估时数据（单元 1 已判小样本崩）。
- **成立条件**：任务带 predecessorIds 依赖链、只做日期敏感性、情景≤2 个；扁平无依赖清单上沙盘退化为无意义滑动。
### ③ 砍到最小
一条命令 `/pm what-if move <task> +5d`，打印关键链是否移动、哪个里程碑滑出、谁 slack 归零，纯文本，无拖拽 UI、不落库。**反而成立**。
### ④ 反常识倒置
沙盘最该推演的不是「怎么保 M1」而是「主动砍掉哪条任务 M1 反而更稳」——沙盘用于放弃而非保全。
### ⑤ 新变体
- **D5-R3-02**（由倒置长出）：沙盘只提供「删减情景」（删哪条非关键任务，M1 回到安全 slack），不提供「延长/补人情景」；把决策引向范围裁剪而非时间膨胀。

## 施压单元 3：延期预测区间（母本 D1-R2-03）

### ① 推到最大
每日刷新乐观/基准/悲观三条线、自动标红、按阈值推送 PM。
### ② 判定：**崩（项目早期 + 速率非平稳）**
- 推理链：completion-history 周序列在前 4–6 周方差极大，**样本<6 周时区间宽到无信息**；单人项目节奏被假期、中断、切换项目扭曲，周完成速率非平稳，用滑动速率外推等于把噪声当趋势；区间预测给人虚假确定感，比不预测更危险。
- **成立条件**：项目连续≥6 周稳定产出、无大块中断、backlog 规模稳定；早期项目直接崩。
### ③ 砍到最小
里程碑旁只显示原始比值「近 4 周完成 X 条 / backlog Y 条」，不给区间、不给预计日期。**反而成立且更诚实**：让 PM 自己心算，系统不背预测责任。
### ④ 反常识倒置
预测的价值不在「预计哪天完成」，而在「暴露当前速率撑不到 dueDate」——宁可只报达标/不达标红灯，不报日期。
### ⑤ 新变体
- **D5-R3-03**（由倒置长出）：删除一切日期预测，只输出一个布尔「按近 4 周速率能否在 dueDate 前清完 backlog」，能/不能 + 缺口条数，不给区间。

## 施压单元 4：项目模板库（母本 D1-R2-04 / D2-R2-03 / D3-R2-03a / D4-R2-03 / D5-R2-02）

### ① 推到最大
行业模板市场、模板版本继承、实例与模板双向同步、模板评分下载。
### ② 判定：**崩（项目数=1 + 模板抹平特殊性）**
- 推理链：单人 **项目数=1 时无模板可抽**，市场是空的；模板把「这次项目的特殊性」抹成通用骨架，新项目被迫继承上次的错误假设（上次的风险清单未必适用于这次）；实例↔模板双向同步会污染历史实例。
- **成立条件**：同类项目做过≥2 次、且第二次确实重复第一次的结构；一次性探索项目套模板即崩。
### ③ 砍到最小
「另存为」一份 Markdown 骨架文本，新建时直接喂给现有 task-import 链路，无 templates 目录、无实例解耦、无模板维护。**反而成立**。
### ④ 反常识倒置
模板禁止复用：每个项目强制从零建，因为模板传递的是「上次的假设」，而项目的价值在于识别这次哪里不同。
### ⑤ 新变体
- **D5-R3-04**（由倒置长出）：模板降级为「风险检查清单提醒」（开新项目时提示「这类项目别漏了：第三方依赖/权限/发布窗口」），**不实例化任何任务骨架**，只做防漏清单。

## 施压单元 5：组合取舍视图（母本 D1-R2-05 / D2-R2-04 / D3-R2-03b / D4-R2-04 / D5-R2-02）

### ① 推到最大
自动给项目打分排名、自动建议砍/停、战略权重建模、组合优化算法求解。
### ② 判定：**崩（项目数=1 + 健康分是活动噪声）**
- 推理链：**active 项目=1 时视图空转**；单人所谓「组合」是自己在项目间切换注意力，没有真实多资源争用，people-load 跨项目聚合无对象；「14 天无活动」可能是正常冬眠等待外部输入，健康分把冬眠误判为失衡；自动打分需要战略权重，单人无从客观赋值。
- **成立条件**：active 项目≥3、确实在争同一注意力/同一截止窗口、PM 主动做季度聚焦；N=1 或项目长期异步等待时崩。
### ③ 砍到最小
全局一页只读卡片：每个项目一行（最近完成数/逾期数/临期里程碑），无规则引擎、无「建议砍」文案。**反而成立**（现状 GlobalBoard 已是雏形）。
### ④ 反常识倒置
取舍视图的正确输出不是「砍哪个」，而是「哪个可以被允许停着不动」——主动给项目发「休眠许可」，反对所有项目持续点亮。
### ⑤ 新变体
- **D5-R3-05**（由倒置长出）：视图只识别「可安全休眠」的项目（长期无活动、无临期承诺、无未决高风险），给一个「允许暂停」标记；休眠项目不计入健康灯、不进入催促清单，而不是建议砍掉。

## 施压单元 6：Jira/飞书/Excel 迁入与共存（母本 D1-R2-08 / D2-R2-07 / D3-R2-06a / D4-R2-07 / D5-R2-05）

### ① 推到最大
直连 Jira/飞书 API 实时双向同步、冲突自动合并、增量镜像、状态双向映射。
### ② 判定：**崩（单写者红线 + 字段语义失真 + 凭据网络）**
- 推理链：11 号契约与 backup-sync 单写者原则下，双向同步必然产生冲突，而产品明确不做自动合并；Jira status（Done/In Progress/Won't Do）≠ 本地 status（todo/in_progress/blocked/done），语义映射失真，迁入即错；直连 SaaS 需要凭据、网络、权限，违背离线 CRUD。
- **成立条件**：一次性离线 CSV/XLSX 迁入 + 只读外链；实时双向同步在单人场景崩。
### ③ 砍到最小
只扩 csv-import 的 HEADER_MAP 认 Jira 导出列（Issue Key/状态/经办人/截止），无 externalRef 字段、无增量、无对账视图。**反而成立**。
### ④ 反常识倒置
迁入是单向死刑：迁完即把旧系统记录冻结为只读快照，**不共存**；共存制造两套事实源的永久对账负担。
### ⑤ 新变体
- **D5-R3-06**（由倒置长出）：迁入即归档——旧系统导出文件打包进一次备份，删除所有持续外链与对账入口，本地成为唯一事实源，旧系统只在备份里被翻到。

## 施压单元 7：持续只读状态页（母本 D1-R2-10 / D2-R2-08 / D3-R2-07 / D4-R2-09 / D5-R2-07）

### ① 推到最大
多项目公开门户、访问控制、外部评论、订阅通知、客户可留言反馈。
### ② 判定：**崩（外部打不开 + 读者可能为 0）**
- 推理链：dsh Web 只信本机 loopback、无局域网远程（KB-014、delivery.md §9），外部读者根本打不开，公网穿透超出本机工具边界；H11「潜在他人阅读」长期未满足，可能领导从不点链接，持续维护白名单/脱敏成为新的自嗨负担；评论/反馈把只读页拖回协作系统。
- **成立条件**：确有≥1 个固定外部读者主动、反复打开；读者=0 时整页崩为自嗨。
### ③ 砍到最小
退回一次性手动导出 HTML（D4-21/D1-15），无服务、无路由、无持续刷新；读者每月只看 1 次时，持续服务是过度工程。**反而成立**。
### ④ 反常识倒置
状态页故意只给过期信息：页面永远显示「上周快照」，刻意滞后一周，倒逼读者开会沟通，防止状态页变成拖延现场讨论的替代品。
### ⑤ 新变体
- **D5-R3-07**（由倒置长出）：状态页只展示**已结项项目档案**（历史交付/复盘），不展示任何进行中项目；进行中的事留在对话里谈，公开页只做「过去做成了什么」的资历陈列。

## 施压单元 8：移动端 / 离开电脑（母本 D1-R2-09 / D2-R2-07 移动层 / D3-R2-06b / D4-R2-08 / D5-R2-06）

### ① 推到最大
手机全功能编辑、推送通知、语音建任务、手机审批、离线同步。
### ② 判定：**崩（公网入口缺失 + 单写者被打破 + 场景只需 30 秒）**
- 推理链：loopback 约束下手机无公网入口；移动端写直接打破单写者；通勤/外出真实场景只要「瞄一眼有没有要炸的」，全功能编辑的开发成本远超价值；手机审批链路要回传确认，链路失败留半截草稿。
- **成立条件**：只读查看 + 一条入站文字落候选草稿；手机端写操作崩。
### ③ 砍到最小
不建任何通道：把「今日 3 行」写进用户自己的日历备注/便签，纯静态文本，零开发。**反而成立**。
### ④ 反常识倒置
离开电脑时最好什么都看不到：断联是刻意保护，防止假期/通勤变成待命；移动端只提供「确认现在无需处理」的出口。
### ⑤ 新变体
- **D5-R3-08**（由倒置长出）：移动端页面只显示一条「现在无需处理」的确认页，隐藏全部数字与清单；只有当存在高影响阻塞/临期时才翻出三条，否则永远是平静页。

## 施压单元 9：office/PDF 导出（母本 round1 D1-14 / D3-19 / D4-13 / D5-11）

### ① 推到最大
全套 PPT 模板库、自动配图、排版美化、多格式（docx/pptx/xlsx/pdf）批量导出、品牌色定制。
### ② 判定：**崩（汇报频率低 + 依赖链重）**
- 推理链：单人向领导汇报频率是月/季度级，维护模板库的成本 > 偶发收益；skill-office + LibreOffice Kit 依赖链重，结构检查/渲染失败面多；导出是一次性动作，不值得产品化成模板系统。
- **成立条件**：偶尔一份 PDF/docx 用现成默认模板成立；模板库产品化崩。
### ③ 砍到最小
Markdown 直接浏览器打印成 PDF，不接 skill-office、不调 LibreOffice。**反而成立**。
### ④ 反常识倒置
汇报材料最佳格式是把数字直接贴进领导已在看的群/文档，独立 PPT 反而打断信息流；导出应最小到「可复制的纯文本块」。
### ⑤ 新变体
- **D5-R3-09**（由倒置长出）：只导出一段可直接粘贴进 IM/邮件的纯文本摘要（完成 N、逾期 M、下周 K 条），不生成任何文件，复制即发。

## 施压单元 10：台账→外部系统出站写（建 issue/MR/日历事件）（母本 D1-R2-06 / D2-R2-05 / D3-R2-04 / D4-R2-05 / D5-R2-03）

### ① 推到最大
批量双向同步、自动建单、外部状态回写、全项目镜像进 Jira、出站日志/撤回/更新全矩阵。
### ② 判定：**崩（重复录入 + 依赖他人环境）**
- 推理链：单人本来就在本地管，写外部等于把刚消灭的「重复录入」请回来；MCP 外部 server 的配置/凭据/可用性取决于他人环境，本机离线时整面隐藏；双向同步撞单写者红线；出站日志的撤回/更新/对账是一套小型同步系统。
- **成立条件**：偶尔一条需要外部协作者时，手动建单+贴链接成立；常态化同步崩。
### ③ 砍到最小：手动复制标题+贴外部链接，零集成、零 MCP。**成立**。
### ④ 反常识倒置
方向应反过来：外部系统才是事实源，本地只做只读镜像（即 D1-11/D2-30 只读回流），本地永不写外部，避免双写。
### ⑤ 新变体
- **D5-R3-10**（由倒置长出）：出站写功能永久关闭，只保留只读拉取；本地台账定位为「外部系统的本地观察台」，任何协作事实以外部系统为准。

## 施压单元 11：iCal 日历导出/订阅（母本 round1 D1-21 的 iCal 分支）

### ① 推到最大
双向日历同步、自动发会议邀请、日历冲突检测、参加人可见。
### ② 判定：**崩（日历是别人的地盘 + 无工作日历模型）**
- 推理链：ADL-051 已明确本地无权威工作日历/lag，日期只是墙钟；回写别人的日历易制造重复邀请；单人无参加人，冲突检测无对象；双向同步再次撞单写者。
- **成立条件**：只读 iCal 订阅（截止日进自己日历）成立；双向写崩。
### ③ 砍到最小：手动把截止日抄进自己日历，不产 iCal。**成立**。
### ④ 反常识倒置
日历不该接收截止日期，只接收「准备哨」：截止日留在台账，日历只放提前 N 天的准备提醒。
### ⑤ 新变体
- **D5-R3-11**（由倒置长出）：iCal 只导出里程碑开始前 N 天的「准备事件」（提前备料/预审），**不导出截止日本身**；截止日只在台账里，日历制造缓冲而不是制造死线。

## 施压单元 12：一次性随身只读包（母本 D3-R2-06b / D2-R2-07 移动层：邮件/IM 转发的静态 HTML/PDF 合集）

### ① 推到最大
随身包自动定期生成、多格式、带交互筛选、可在手机上点击钻取。
### ② 判定：**崩（与持续状态页同质 + 手机钻取无意义）**
- 推理链：定期自动生成与 D4-21 一次性导出、D5-R2-07 持续页三者重叠，三选一即可；手机上点击钻取任务详情的使用频次极低，交互开发浪费；自动定期生成又需要定时器（撞 ADL-032 拒绝常驻）。
- **成立条件**：一次性、手动、单文件、纯静态浏览；自动化/交互钻取崩。
### ③ 砍到最小：周报定稿时顺手导出一份 PDF 挂在交付物上，无独立「随身包」概念。**成立**。
### ④ 反常识倒置
随身包不该带进行中工作，而该只带「离线时需要拍板的 3 件事」——把包压缩成一张决策清单，不是项目全量镜像。
### ⑤ 新变体
- **D5-R3-12**（由倒置长出）：随身包 = 单页「离线决策单」：只列需要本人拍板的待决项（选 A/B、批/不批），其余全部不带；无背景数字、无全量看板，飞机上 2 分钟读完即可决断。
