# D3 · 阶段1 饱和终检（第4轮·轻量）：方向空间是否还有池外新类别？

> 通读范围：round1-pool.md（146）、round2-pool.md（109）、round3-pool.md（75 施压单元 + 91 极端变体），合计 346 条。
> 判定标准：只有「连类别都没有」的才算新方向；同一方向的变体、另一个极端形态、另一个 UI 细节不计。本轮不新增评分、不做可行性判断，只做质量门证据。

## 总结论
**存在 3 个三轮 346 条都没触及的新类别**（N1–N3）；其余强迫试过的 10 个角度均已被池内某类想法覆盖，逐角度说明如下。新类别数量不多，说明方向空间已接近饱和，剩余空白集中在「目的翻转」（举证、休息、职业）而非「接线/形态」。

## 一、发现的新方向（3 条）

### N1【新类别】外部监管 / 法务 / 第三方审计举证：台账目的从「自我管理」翻成「对外举证」
- **为什么三轮没覆盖**：池内「审计」出现 115 次，全部是**内部里程碑自验审计员**（D2-12、D5-R2-14、D1-R2-17 可学习审计履历、S5），审完给自己看；「合规」25 次全部是 API key / 计费合规（personal-billing-plan、D5-23），不是对外监管合规。没有任何一条把台账当作**在客户验收、采购留证、责任界定、纠纷追溯时能独立出示给第三方**的证据链——目的不同，对数据的要求也不同（不可篡改、时间戳可信、删除也留痕、可移交无自证歧义），而池内 D4-29 全局只增事件流一直只被用于「自己回滚」。
- **一句话机制**：把 D4-29 只增事件流从「本机回滚账本」升级为「对外举证包」：每条承诺/变更/证据附单调时间与来源，物理删除不抹除只标废弃，导出一份可独立验证的时间线给第三方看。
- **最极端形态**：台账是一份法律级档案——任何「我当时答应过什么、依据什么证据算完成、谁在何时改了什么」都能在断网、换机器后独立出示，删除动作本身也成为不可抹除的记录；产品的核心交付物不是看板，而是一份可在验收/审计/纠纷时被采信的举证包。
- **来源观察**：池内证据闭环（D1-06/D4-05 workspace-changes、D1-07/D4-06 session-query、D2-R2-16 自证周报）全部面向「自己回看」，无一条面向外部检查者；provenance-store（每项目 cap 20 有界账本）本就是为回滚设计，容量与留存策略也不是举证级。

### N2【新类别】反工作 / 休息边界保护：产品目标从「推进项目」翻成「限制推进、保护人」
- **为什么三轮没覆盖**：池内「建议疲劳/提醒噪音」（D4-R2-12、D5-R2-10、D2-R2-17 自适应沉默、S10/S11 沉默哲学）处理的都是「少打扰、别垃圾化」，方向仍然是**更好地服务于推进**；全池 0 次出现倦怠/耗竭/休息/下班边界/反内卷/数字极简，没有一条把产品目标设为「主动劝停、守住非工作时间、防止项目管理吞噬生活」。这是问题本身翻转：用户不是要更高效，而是要防止自己被台账和催促绑架。
- **一句话机制**：不推任务、只守边界——非工作时段全静默，检测到连续深夜/周末活动、同一任务反复拉扯「永远进行中」时主动喊停而非催办，月度报告给的是休息与停摆统计而非完成率。
- **最极端形态**：产品的 KPI 是「让你少打开它」；它主动识别燃烧信号（连续投入、无休冲刺、任务挂起过久反复改期）并建议停止/归档，台账里长期挂着的任务被标「建议放弃」而非「逾期催促」，与 D1-24/D4-26 的「被动沉默」不同：那是不开口，这是开口劝停。
- **来源观察**：池内所有主动动作（schedule 提醒 D1-12/D4-08、周报 D1-13、催办员 D3-R2-08）都朝「往前推」单向发力；S9 倒置只做到「零变更触发一次回顾」，未触及保护休息时段。

### N3【新类别】终身职业成就证据库：跨项目聚合，面向晋升/求职/述职（换时间尺度 + 换用途）
- **为什么三轮没覆盖**：池内档案都是**单项目生命周期**内的（D1-26 单项目十年可读、D2-04 项目档案跨会话快照、D2-R2-14 项目时光机）；组合视图（D1-R2-05、D2-R2-04、D4-R2-04）是**当前并行项目**的保/缓/砍取舍，不是把所有已结束项目的可带走成果跨项目沉淀。全池 0 次出现求职/晋升答辩/简历/职业成就墙；「履历/作品集」在池中仅指开源仓库当作品集（D3-R3-04）和审计员命中率履历（D1-R2-17），均非个人职业资产。
- **一句话机制**：项目归档时自动抽取「可带走的成果条目」（交付物、量化结果、可展示证据）进一个独立于任何项目的终身成就层，跨项目累积，可导出为述职/面试素材。
- **最极端形态**：台账一辈子累积成个人职业信用档案，与单个项目生命周期解耦，离职、换机、换工作都带走；它不再回答「这个项目做完没」，而回答「我这些年做成了什么、有什么证据」，是可长期生长的个人成就库而非项目结束即封冻的档案。
- **来源观察**：现有导出（core/export.ts、D1-14 PDF、状态页 D1-R2-10）都是单项目一次性产物；effortHours/证据链接散在各项目内，无跨项目聚合层。

## 二、强迫试过但判定「已被覆盖」的角度（10 个，附池内编号）

### 角度 A：换用户——非软件行业 / 非工作人生项目（搬家、婚礼、备考、健身、读书、写作连载）
- **判定：已覆盖，不构成新类别。** 机制（台账 + 证据 + 里程碑 + 周报）本身行业中立，换行业只是换模板：项目模板库（D1-R2-04、D2-R2-03、D4-R2-03、D5-R2-02）+ 开放文件/格式供应商（D1-21、D4-25、D2-26）已让产品不绑定 git/MR；人生项目只是一个新模板实例，没有新机制。证据来源（照片/账单）已由附件挂证据（D1-08、D2-32）覆盖。

### 角度 B：换时间尺度/技术范式——五年后（模型无限便宜、端侧、AGI 自主执行、dsh 范式更替）
- **判定：已覆盖。** 各极端都已被占：本地 Ollama 去 dsh（D5-17、D1-20）、完全吞并内置 runtime（D2-R2-11、D5-R2-11、D4-R2-13）、D1-23 agent 自主执行 PM、被宿主原生替代的退出协议（D2-R2-12、D5-R2-12、D3-R2-11）、十年档案/固化成品（D1-26、D3-R2-18）。范式变化后的每一极都有母本。

### 角度 C：故意失败 / 主动放弃的产品
- **判定：已覆盖。** D2-29 什么都不做冻结 v0.7.4、D1-24/D4-26 极致沉默、D3-R3-15c 项目结束档案自焚（用完即焚反长寿）、D2-R2-12/D5-R2-12 主动退役协议。

### 角度 D：换商业模式——买断、捐赠、机构采购、企业版、许可证选择
- **判定：已覆盖（变体级）。** 开源治理/插件市场/分层定价/方法论即产品（D1-R2-15、D2-R2-13、D4-R2-14、D5-R2-13、D3-R2-12）+ D3-R3-04 开源履历路线 + D3-R3-08 套餐即商业模式。买断/捐赠只是定价档位变体，机构/企业版是分层定价的延伸，单人阶段不产生新机制。

### 角度 E：换用户关系——真人导师/教练/学员陪跑（教学传承）
- **判定：已半覆盖，不构成新类别。** 对外只读状态页（D1-R2-10、D2-R2-08、D5-R2-07）让他人查看，方法论 skill（D1-29、R2-15）可被他人单独使用；真人导师双向反馈只是「状态页 + 多人关系」的一个具体实例，未新增机制。

### 角度 F：游戏化 / 动机激励（积分、徽章、成就墙）
- **判定：已被反向覆盖，不构成新类别。** 池内方向是反游戏化的克制：建议配额、建议疲劳负反馈（D4-R2-12、D5-R2-10）、自适应沉默（D2-R2-17）、极致沉默宪法（S11）；积分徽章只是装饰层，不改变产品类别。

### 角度 G：换技术范式——实体纸、打印看板、无屏幕、硬件出口
- **判定：已覆盖。** PDF/Word/PPT 导出（D1-14、D2-31、D4-13、压测09）、静态站/单文件 HTML（D1-15、D2-26、D4-41）、iCal 订阅（D1-21、压测11）；打印只是静态成品的一个出口，白板照作附件（D1-08、D2-32）已含实体媒介。

### 角度 H：换规模——多人/团队/结对（含双人最小多人）
- **判定：已覆盖。** D4-28 assignee 建模为虚拟子 agent（团队仿真）、MCP server 多客户端（D2-27/D4-20，R3 压测 2a 已测并发写崩点）、状态页给协作方、深双向绑定单人反而对（D4-R2-23 反叛）。双人结对只是多人的最小实例。

### 角度 I：细节变体——多语言、时区、国际化
- **判定：变体级，非类别。** 时区已被提及（3 处），多语言是文案层，不改变产品机制与方向。

### 角度 J：换范式——无模型 / 纯确定性工具（不依赖 LLM 也能用）
- **判定：已覆盖。** D4-25 纯开放文件 + 静态查看器、D1-21 格式供应商、S4 砍最小（零 subagent，全确定性 suggestion-engine）、D5-17 AI 通道迁出退回纯离线 CRUD。

## 三、空白处性质备注（供阶段3 取用，不评分）
- 3 个新类别有一个共同点：**都不是「pm-tool 怎么接 dsh」的问题，而是「台账为谁、为什么目的存在」的目的层翻转**——对外举证（N1）、保护人（N2）、个人终身资产（N3）。它们与本仓源码能力（事件流、证据、导出）都能接上，但三轮 346 条的注意力全部集中在「接线、形态、自主度、商业」，没有进入目的翻转层。
- 其余方向空间（读写边界、证据闭环、注入/调度、平台归属、规划智能、组合、迁入、移动、PMO、认知安全、仪式、吞并/退出、商业分发）均已被反复压到最大/最小/倒置，未发现连类别都缺失的角落。
