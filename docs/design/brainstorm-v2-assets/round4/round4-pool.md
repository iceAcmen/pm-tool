## 一、发现的新方向（2 条）

### N1. 新类别：毕业导向 / 反活跃成功度量（工具以「用户不再需要打开它」为成功）
- **为什么 346 条都没覆盖**：全池的成功/采纳度量全是「提高使用」取向——D5-22 采纳率、D1-16/D4-16 被读 N 次/被采用 M 次、D4-R3-28 保护期、D2-R2-17 自适应沉默都是在争取「多被用、少被拒」；产品退出只发生在「产品对宿主」一层（D3-R3-03 捐赠式退休、功能被原生替代），没有任何一条把「用户对工具」的毕业（教会了、能独立了、可以不再打开）当作成功指标。grep「毕业/自愈/不再需要打开/闲置率/成功指标」三轮全部 0 命中。
- **一句话机制**：把度量轴从「活跃度/采纳率」翻成「连续 N 周零干预也自转」，面板给出「可毕业」信号（这个项目你已经不需要我提醒/记录了），工具主动建议自己退场，而不是想尽办法留人。
- **最极端形态**：产品出厂即倒计时——每个项目建档时带一条「毕业线」，工具的全部努力是让自己尽快被该项目卸载；达成毕业线后只留一份只读档案，主动停止一切提醒、建议、注入，面板对该项目显示「已毕业，勿扰」，重新激活需要人显式找回。
- **与近邻的边界（避免误判为变体）**：D1-24/D4-26/D4-R3-32 沉默哲学是「少打扰」，目的仍是留在身边待命；D5-R3-05 休眠许可是让项目停着不动、工具继续在；N1 是「以自身被弃用为胜利」，成功度量方向相反，是问题本身的反转，不是噪音调节。

### N2. 新类别：反工作 / 可持续节奏（产品目的是保护人，而不是帮人把事做完）
- **为什么 346 条都没覆盖**：全池是 throughput（交付量）取向——闭环、催办、周报、过载告警（people-load 过载阈值只是一个数字灯）、建议节流（D1-R2-13/D4-R2-12）保护的是「用户不被工具烦」，不是「用户不被工作压」。grep「倦怠/休息/burnout/正念/反内卷/保护休息/少承诺/限制承接/WIP上限/下班保护/勿扰」三轮全部 0 命中；「节奏」7 处全是例会/仪式 cadence，「过载」11 处全是 open 任务数告警，无一指向人的可持续性。
- **一句话机制**：产品立场从「帮你多交付」翻成「帮你少承诺、守住边界、限制在制品 WIP、识别你正在过度承接」，主动劝拒新承诺、给休息留白，成功标准是长期可持续而非本期吞吐量。
- **最极端形态**：默认 WIP 硬上限（同时进行 N 条即拒绝登记新承诺并劝你先砍一条）；非工作时间/周末/夜间一切静默且不补推；每月出一份「负荷体检」而非「完成战报」，重点写「本月你承接了多少、哪周超载、建议下季砍掉什么」；工具会主动说「这个请求你不该接」，而不是帮你接。
- **与近邻的边界（避免误判为变体）**：people-load 过载阈值是被动告警、D1-R2-13 建议疲劳是减少工具噪音，二者都不改变「帮你把事推进」的立场；N2 是立场反转（保护休息优先于交付），属于换了问题本身，不是同一机制的调参。

## 二、试了但判定「已覆盖、非新方向」的角度（7 个，给池内编号）

### 角度 1：非字节/非软件行业 PM（换个用户：装修、婚礼、考研、健身、家务、生活目标）
- **判定：变体，已覆盖**。三轮 grep「装修/婚礼/考研/健身/家务/生活/学生/自由职业/创业/读书/旅行」全 0，确实没人写非软件场景；但非软件用户没有 git/agent 会话/workspace-changes，证据机制失效后，落点正是**独立壳家族**：D1-19 纯文件内核、D2-26/D4-25 静态站直接读 JSON、D4-24 独立本地 App 走标准 API、D5-18 脱离 dsh Web 壳、D3-R3-05 机器优先 CLI。换用户只是换数据皮肤，七实体/周报/风险方法论不变，不产生新机制。

### 角度 2：五年后技术环境（换时间尺度/技术范式：常驻 ambient agent、语音无处不在、本地强模型、设备即代理）
- **判定：变体，已覆盖**。未来常驻代理形态 = D1-23 自主执行 PM + D5-07 常驻 PM 子会话 + D2-R2-11/D5-R2-11 内化 runtime 吞并的组合，第3轮已被推到最大压过；本地模型兜底由 D5-17（AI 通道迁出 dsh、Ollama）与 R3 施压 4 覆盖；退出被替代路线由 D3-R3-03/D2-R2-12 覆盖。技术范式换了，单人记项目/证据闭环的问题没变。

### 角度 3：故意失败的产品 / 反目标（产品从一开始就设计成没人用/用完即弃）
- **判定：大部分已覆盖，残余并入 N1**。产品对宿主的主动退役 = D3-R3-03 捐赠式退休清单 + D5-R3-05 休眠许可 + D1-R2-14/D2-R2-12 退出协议；「一次性用完即删」的产品哲学与用户侧毕业重合，即 N1，不单列。

### 角度 4：监管/法务视角（合规交付、不可篡改举证链、对外审计出示）
- **判定：变体，已覆盖**。原料齐备：D4-29 全局 append-only 事件流、provenance-store 账本（applied/undone/conflict/failed）、D3-R3-06 隐私保险箱（加密本地落盘/单次口令快照）、D1-22 零遥测合规卖点；对外出示只是导出+封存格式，由 D1-14/D5-R3-09 导出家族 + D4-30 版本链承载，不产生新机制。

### 角度 5：教育/学习场景（换个用户：学生、备考、技能学习追踪）
- **判定：变体，已覆盖**。学习计划/复习追踪是个人目标记录，落独立壳家族（同角度 1）；间隔重复等学习机制不属于本产品问题空间，且无 dsh 编码语境支撑。

### 角度 6：多人协作 / 实时同步（换个用户基数：团队、跨人实时编辑）
- **判定：被主动关闭，非遗漏**。11 号协作契约刻意只留字段位不做多人；D1-26 反向把「单机单写者」做成硬卖点；D4-R2-23 反叛只论证单人下双向安全，未开多人。这是框定书刻意排除的方向，不是没触及。

### 角度 7：游戏化 / 公开承诺 / 社交问责（换商业模式与激励）
- **判定：变体，已覆盖**。公开承诺/对外展示 = D1-R2-10/D5-R2-07 持续状态页 + D1-R2-06 出站写外部；社交问责需要第二人，撞单写者红线被排除；游戏化积分/勋章在池中无命中，但它是表皮激励层，不改七实体与证据机制，属变体非类别。

### （附加）灾难恢复/备份作为独立产品
- **判定：已覆盖**。D4-30 备份目录即版本链、D1-26 dsh 卸载自检包（doctor+全量导出+独立 viewer）、D3-R3-06 保险箱、ADL-041 备份恢复。

### （附加）语音原生/无面板唯一界面
- **判定：已覆盖**。D2-25 拆 Web 面板退回斜杠命令、D3-12 取消面板只留只读看板、D1-R2-07 会中 STT 实时捕获。

## 新类别 N1 · 失败记忆层：项目墓地 / 死因档案 / 失败教训库

**为什么 346 条都没覆盖**
- 全池的「失败」二字全部是系统语境：建议被拒、回滚、产品腐烂、系统失败模式（D4-R2-12/D5-R2-10 的「失败模式设计」是防建议刷屏，D1-R2-22/D3-R2-19 是「被动葬送产品」，D2-R3-10 空转会话可疑标）。
- 全池的「复盘」全部是成功项目的进度复盘：估时校准（D1-R2-01/D2-R2-01）、承诺兑现对账（D2-21/D1-R2-19）、审计履历（D1-R2-17）、里程碑审计（D2-12）——对象都是「做完了或在做的项目」。
- 组合取舍（D1-R2-05/D2-R2-04/D4-R2-04）只在当下给「保/缓/砍」候选，不沉淀「为什么砍、当时哪个假设错了、哪些危险信号早出现过」；D5-R3-05 的「可安全休眠标记」只是暂停，不是死亡，且明确「不计健康灯、不追责」，不留死因。
- 现有归档状态（archived）、版本链（D4-30）、审计流（D4-29）记录的是「发生过什么」，不回答「这个项目为什么死、下次别怎么死」。这是一个独立的知识对象，不是任务实体的一个状态值。

**一句话机制**
项目被关停/放弃时，除了落个状态，另填一张「死因卡」：停在哪一步、当时错信的假设、最早出现的危险信号、如果重来会先砍哪块；所有死因卡聚成独立的失败档案库，下次立项/选模板前先检索「同类项目死过几次、怎么死的」，失败与完成并列进档案。

**最极端形态**
产品反过来以失败为默认主角：完成项目是少数派，界面首屏是「本季度已体面停掉 N 个项目」的墓地墙；立项第一步强制先查相似死因，没有失败记录的新想法反而不给过；系统的主要成就感来自「成功止损」而非「完成交付」。

## 新类别 N2 · 人的可持续层：能量预算 / 拒单闸 / 留白配额 / 反完成主义

**为什么 346 条都没覆盖**
- people-load / 争用提示（D2-R2-04、D3-25 个人负载、D4-R2-04 组合取舍）是**客观任务计量**：谁手上任务多、谁工时争用，优化的是任务分配效率，对象是「任务」不是「人」。
- 建议疲劳/提醒节流（D4-R2-12、D5-R2-10、D2-R2-17 自适应沉默、D1-24/D4-26 极致沉默）管的是**信息打扰**：少弹建议、少推送，对象是「进来的消息」。
- 「休假」在池内只作为崩点场景出现（D4-R3 S1/S11：人休假两周后回来落线索），从未成为产品要主动保护的功能；能量/留白/拒单/反完成/烂尾/可持续节奏等词三轮零命中。
- 这一层的目标与池内所有机制相反：池内都在帮你「把事做完、把账记得更全、把承诺兑现」，这一层主张「有些事不该接、不该做完、该留空、该休息」，第一受益人是人的状态而非项目进度。

**一句话机制**
给人（而非任务）设一条个人能量预算线：当前开放承诺接近预算时，新任务录入被拦一道软闸「当前负载已到你的 X 分，确定再接？」；每周留强制留白配额，休假/断档期系统主动静默且不补催；显式允许「烂尾清单」——有些任务合法地不做完，不进逾期红榜、不计健康灯。

**最极端形态**
产品的最高 KPI 不是完成率，而是「本周人有没有过载、有没有留白、有没有拒绝掉不必要的承诺」；完成率高反而触发警告（你是不是又在硬撑）；拒绝新任务被记为正面成就，逾期红榜里分出「该完成没完成」和「本来就不该接」两列，后者不红。

## 新类别 N3 · 动机与正反馈层：庆祝 / 成就 / 完成仪式感 / 轻游戏化

**为什么 346 条都没覆盖**
- 三轮 346 条的语气全程冷峻：记录、对账、审计、巡检、催办、降噪、纠偏、留痕；grep 庆祝/成就/连胜/游戏化/激励/正反馈/勋章/情绪价值全部零命中（池内「徽章」只是任务逾期状态的颜色标签，D3-03/D5-09 卡片渲染，与激励无关）。
- 仪式卡（D4-R2-12、D5-R2-10 晨会三行/周报槽）是**节奏容器**，解决「什么时候看」，不含情绪反馈；自证周报（D2-R2-16）是证据汇编，不制造完成时刻的正反馈。
- 这一层对象是人的动机维持，与 N2（保护人不过载）互补但不同：N2 是减法（少接、休息），N3 是加法（完成时被看见、被奖励、有成就感），属于独立的产品情绪设计类别。

**一句话机制**
在客观状态层之外加一层轻情绪反馈：任务/里程碑完成时给一个克制的完成时刻（不打断的小庆祝、个人连胜天数、完成集合墙），里程碑验收通过后留一条「值得记住」的高光记录，供日后回看自己做成过什么；纯本地、不排行榜、不社交。

**最极端形态**
面板打开第一眼不是逾期红榜，而是「你已经做完的墙」；每完成一个 P0 解锁一段个人项目印记，工具反复用过去的完成史给人供电，催办只占角落极小面积，产品整体气质从「监工」翻成「教练」。

> 新度自评：N1、N2 为扎实空白类别；N3 较轻（偏情绪/包装层），但它与仪式卡、状态页确实不同类，故保留，交由后续轮次判断是否降级为变体。

## 一、发现的新方向（3 条）

### N1【新类别】外部监管 / 法务 / 第三方审计举证：台账目的从「自我管理」翻成「对外举证」
- **为什么三轮没覆盖**：池内「审计」出现 115 次，全部是**内部里程碑自验审计员**（D2-12、D5-R2-14、D1-R2-17 可学习审计履历、S5），审完给自己看；「合规」25 次全部是 API key / 计费合规（personal-billing-plan、D5-23），不是对外监管合规。没有任何一条把台账当作**在客户验收、采购留证、责任界定、纠纷追溯时能独立出示给第三方**的证据链——目的不同，对数据的要求也不同（不可篡改、时间戳可信、删除也留痕、可移交无自证歧义），而池内 D4-29 全局只增事件流一直只被用于「自己回滚」。
- **一句话机制**：把 D4-29 只增事件流从「本机回滚账本」升级为「对外举证包」：每条承诺/变更/证据附单调时间与来源，物理删除不抹除只标废弃，导出一份可独立验证的时间线给第三方看。
- **最极端形态**：台账是一份法律级档案——任何「我当时答应过什么、依据什么证据算完成、谁在何时改了什么」都能在断网、换机器后独立出示，删除动作本身也成为不可抹除的记录；产品的核心交付物不是看板，而是一份可在验收/审计/纠纷时被采信的举证包。
- **来源观察**：池内证据闭环（D1-06/D4-05 workspace-changes、D1-07/D4-06 session-query、D2-R2-16 自证周报）全部面向「自己回看」，无一条面向外部检查者；provenance-store（每项目 cap 20 有界账本）本就是为回滚设计，容量与留存策略也不是举证级。

### N2【新类别】反工作 / 休息边界保护：产品目标从「推进项目」翻成「限制推进、保护人」
- **为什么三轮没覆盖**：池内「建议疲劳/提醒噪音」（D4-R2-12、D5-R2-10、D2-R2-17 自适应沉默、S10/S11 沉默哲学）处理的都是「少打扰、别垃圾化」，方向仍然是**更好地服务于推进**；全池 0 次出现倦怠/耗竭/休息/下班边界/反内卷/数字极简，没有一条把产品目标设为「主动劝停、守住非工作时间、防止项目管理吞噬生活」。这是问题本身翻转：用户不是要更高效，而是要防止自己被台账和催促绑架。
- **一句话机制**：不推任务、只守边界——非工作时段全静默，检测到连续深夜/周末活动、同一任务反复拉扯「永远进行中」时主动喊停而非催办，月度报告给的是休息与停摆统计而非完成率。
- **最极端形态**：产品的 KPI 是「让你少打开它」；它主动识别燃烧信号（连续投入、无休冲刺、任务挂起过久反复改期）并建议停止/归档，台账里长期挂着的任务被标「建议放弃」而非「逾期催促」，与 D1-24/D4-26 的「被动沉默」不同：那是不开口，这是开口劝停。
- **来源观察**：池内所有主动动作（schedule 提醒 D1-12/D4-08、周报 D1-13、催办员 D3-R2-08）都朝「往前推」单向发力；S9 倒置只做到「零变更触发一次回顾」，未触及保护休息时段。

### N3【新类别】终身职业成就证据库：跨项目聚合，面向晋升/求职/述职（换时间尺度 + 换用途）
- **为什么三轮没覆盖**：池内档案都是**单项目生命周期**内的（D1-26 单项目十年可读、D2-04 项目档案跨会话快照、D2-R2-14 项目时光机）；组合视图（D1-R2-05、D2-R2-04、D4-R2-04）是**当前并行项目**的保/缓/砍取舍，不是把所有已结束项目的可带走成果跨项目沉淀。全池 0 次出现求职/晋升答辩/简历/职业成就墙；「履历/作品集」在池中仅指开源仓库当作品集（D3-R3-04）和审计员命中率履历（D1-R2-17），均非个人职业资产。
- **一句话机制**：项目归档时自动抽取「可带走的成果条目」（交付物、量化结果、可展示证据）进一个独立于任何项目的终身成就层，跨项目累积，可导出为述职/面试素材。
- **最极端形态**：台账一辈子累积成个人职业信用档案，与单个项目生命周期解耦，离职、换机、换工作都带走；它不再回答「这个项目做完没」，而回答「我这些年做成了什么、有什么证据」，是可长期生长的个人成就库而非项目结束即封冻的档案。
- **来源观察**：现有导出（core/export.ts、D1-14 PDF、状态页 D1-R2-10）都是单项目一次性产物；effortHours/证据链接散在各项目内，无跨项目聚合层。

## 新方向 1（明确成立）：人的保护面 / 可持续层——「项目服务人」而非「人服务项目」

### 为什么三轮 346 条都没覆盖
- 池里所有「少打扰」机制——D1-R2-13 建议配额与沉默期、D5-R2-10 建议合并/草稿 TTL/提醒聚合、D2-R2-17 自适应沉默、D1-24/D4-26 极致沉默、S9 仪式节流——**目标都是「让建议更好被采纳、把项目推得更顺」**，降噪是为了推进，不是为了让人停下来。
- D3-25 个人负载视图、D4-R2-04 组合取舍是「项目争用/资源聚焦」视角，度量的是任务量分配，不是人的状态。
- 关键词全池反查：倦怠 0、休息 0、留白 0、burnout 0、情绪仅 1 处（且是描述宿主弃用焦虑，非功能）、周末仅 1 处（手机看盘场景）、健康 50 处全部是「健康灯/health」而非 wellbeing。
- 池内价值主体从头到尾是「项目/任务」，没有任何一条把「保护执行的人」设为目标。

### 一句话机制
在推进侧（提醒/到期/催办/进度）之外，增设一条对称的「保护侧」：记录人的状态/能量/负荷上限，主动劝停、周末与夜间静默、把休息和留白当一等公民，项目让位于人。

### 最极端形态
产品默认替人踩刹车：检测到连续 N 个夜间/周末会话、单日在册任务超个人上限、或一周零休整时，系统不再催办，反而给出「今天到此为止」的收工提示并冻结当日新建议；休息/留白作为与 task 并列的一类实体被显式排进计划，项目进度曲线与可持续曲线并列展示，宁可项目慢也不让人过载。

### 与池内相邻想法的分界（避免被误判为变体）
- 区别于 D2-R2-17/D5-R2-10：那些是「减少噪音以提高采纳」，本方向是「主动停止推进以保护人」，价值主体相反。
- 区别于 D3-25 负载：那是项目间资源争用（理性分配），本方向是人的健康边界（保护主体）。
- 诚实边界：这条落在锁定问题框（R1–R5 全是项目/台账/宿主关系）的外侧，是否属于本产品方向空间需评审门裁定；它不需要 dsh 宿主能力也能成立，更像产品价值观分支而非融合方案。

## 新方向 2（弱候选，标注边界）：纵向层级缺口——项目之上的愿景层、项目之下的习惯层

### 为什么三轮没覆盖
- 七实体与全部想法都夹在「周 / 里程碑 / 交付物」中段：向上没有「项目为什么存在、北极星/年度目标」的活实体，向下没有「日常重复动作/习惯」层。
- D1-26「十年可读」是归档存档，不是活的目标层；D4-R2-04 的「战略权重」只是给项目打个标签，不是可分解、可追踪的上层目标；关键词反查：愿景 0、OKR 0、路线图 0、打卡 0、习惯仅出现在组织者清单措辞里，无对应功能。

### 一句话机制
在项目之上加一层可分解的长期目标（愿景/年度 OKR，向下拆成项目），在项目之下加一层日常重复动作（习惯/周期行为，向上汇入项目），工具从「单项目中段记录」变成「愿景—项目—习惯」纵向贯通。

### 最极端形态
一个北极星目标挂着多个项目，每个项目是它的阶段性分解；每天的习惯动作（练、写、读）自动计入相关项目的投入，年底把习惯曲线与项目达成并置，回答「我这一年到底往愿景走了多远」。

### 诚实降级说明
这是弱候选：上层与 D4-R2-04 组合取舍、D1-R2-03 模板库相邻，下层与 S9 仪式卡、completion-history 按周聚合相邻，很可能被评审门判为现有机制的纵向延伸而非独立类别；且同样落在 R1–R5 框外。列出仅为不漏，不主张其为硬空白。

## 一、边界外真空白类别（3 个，均非本轮问题空间内的遗漏）

### N1. 实物世界 / 供应链层（BOM、采购、供应商跟进、库存、到货验收）
- **为什么 346 条都没覆盖**：池内全部实体是数字的——task/milestone/risk/deliverable/meeting/report/project，证据是 git diff、会话文本、附件截图、webhook；交付物是文档/代码/文件。grep「物料/采购/供应商/库存/实物」全池 0 命中（「供应商」仅作为第三方限流风险词出现，不是被管理对象）。没有任何一条把「向谁买、买什么、到货没有、验收什么」作为一等实体。
- **一句话机制**：在七实体之外加「物料/采购单」实体，台账跟踪供应商报价、到货状态、物理验收照片，与任务依赖链挂钩（物料不到则任务 blocked）。
- **最极端形态**：一个用 dsh 管开店/办活动/做硬件的人，台账自动汇总「还欠 3 家供应商的货、2 笔尾款未付、1 张发票未收」，把数字任务管理平移到物理交付。
- **边界说明**：dsh 是编码宿主，无采购/物流触点，此类别在当前宿主里无接线点，属于换行业。

### N2. 个人生活 / 人生项目（非工作目标：家庭事务、健康习惯、财务记账、学习、旅行、人生路线图）
- **为什么 346 条都没覆盖**：全池语境 100% 是工作项目（周报、交付物、deadline、领导汇报、健康灯是项目健康分）。grep「生活/人生/家庭/财务/旅行/记账（义为账务）」0 命中；「健康」3 处全是项目健康分，「目标」38 处全是工作 goal。没有任何一条把台账用于工作之外。
- **一句话机制**：同一套台账实体去工作化，承载「装修进度、健身计划、存款目标、备考、一次旅行的待办」，与工作项目并列在全局视图。
- **最极端形态**：台账变成个人一生的项目总线，工作项目只是其中一个并行分支，季度组合视图同时排工作冲刺、体检复查、家庭装修、攒钱目标的优先级。
- **边界说明**：这是换用户+换问题（从职业 PM 到自我管理），与 dsh 编码场景脱钩；教学/学生课程项目、老师看全班属于本类别的延伸，同样零命中。

### N3. 法务/合规留存与对外举证（法定留存期、PIPL 个人信息、可呈堂证据、删权/导出权）
- **为什么 346 条都没覆盖**：池内「合规」只有两条线——D1-22 零遥测卖点、D5-23 ¥40 计费合规；审计流/provenance（D5-R2-14、D2-R3-04、S5 里程碑验收审计）目的是**自我追溯**，不是对外举证。grep「法律/法务」0 命中，没有留存期限、法律效力、隐私合规设计、应要求删除/导出的概念。
- **一句话机制**：台账记录带法定留存期标签，到期自动封存/销毁；提供「应某人要求导出全部个人数据/删除全部记录」的合规动作，证据链可作为对外（纠纷、审计）举证材料。
- **最极端形态**：台账自证合规——任何一次确认落库都带不可篡改时间戳与操作人，十年后发生劳动/协作纠纷时能导出一份可举证的承诺与交付时间线。
- **边界说明**：单人本地工具无外部监管义务，此类别在多人/团队商业化时才会成为需求，属换问题（自我追溯→对外举证）。
