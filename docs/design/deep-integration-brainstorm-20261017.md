> 日期：2026-10-17 ｜ 性质：**纯探讨，零代码改动**，未创建/修改仓库现有任何文件，仅新增本设计文档
> 触发：用户否决两条常规路线——① MCP/命令外接型（agent 当用户调 PM）② 工作区原生共享记忆型，要求**完全颠覆常规、大胆畅想**
> 组织方式：5 个子智能体按 5 个互斥视角并行脑暴，共产出 **20 个原始脑洞**；本文件经去重、碰撞、收敛为 **5 个颠覆方向 + 1 套推荐组合拳**

## 0. 一页结论

**一句话主题：把 pm-tool 从「System of Record（记录系统）」变成「System of Agency（能动系统）」——项目不再是一份你打开查看的档案，而是一个会主动开口、反向塑造 agent 行为、拥有记忆与预感、并对交付行使裁决权的存在。**

20 个脑洞收敛为 5 个颠覆方向：

| # | 方向 | 一句话 | 主要来源脑洞 | 疯狂度 | 落地度 |
|---|------|--------|-------------|--------|--------|
| 1 | **一切即流**：项目是河，不是表 | 状态＝事件流的临时投影，无人查询不坍缩，一切皆可回放 | 事件即真相、量子态项目、双向流总线、任意时刻回溯、问则有、说出即存在 | 8/10 | 7/10 |
| 2 | **潜意识引力场**：项目反向塑造 agent | 目标与禁区注入每一步推理，agent 在自己的项目里不可能失忆 | 引力场常数、潜意识层、项目心跳 | 8/10 | 7/10 |
| 3 | **记忆生命体**：会记得、会遗忘、会预感 | compaction 产物＝长期记忆，模板＝基因，衰减式遗忘靠复述保鲜，代谢异常＝预感，决策可反事实重演 | 三层记忆体、衰减遗忘、代谢预感、时间树 | 8/10 | 6.5/10 |
| 4 | **幕僚与空间**：项目成为可相处的存在 | 每个项目一个数字幕僚＋一座可走入的城市，风险在「查看」之前先被「感到」 | 幕僚长、状态即呼吸、天际线府邸、群岛与天气 | 8/10 | 7/10 |
| 5 | **承诺法庭**：交付先过项目的审判 | 验收 rubric 凌驾模型自评，里程碑不可无声滑过，承诺有履约账 | 验收法官、围城之战、承诺契约 | 7/10 | 7/10 |

**推荐组合拳（§5）**：P0 三件事——①事件流「入向+出向」最小闭环（承诺/风险自动流入、到期回流会话）；②「项目主动开口」投递通道（衰减复述＋心跳简报）；③幕僚长晨间简报（情绪确定性派生）。三者共享同一条基础设施、全部只读/可逆/不推翻现状，是「能动系统」的第一块地基。

## 1. 背景：为什么前两条常规路线不够

用户否决的两条路线本质是**同一类动作**：①把 PM 暴露给 agent 当工具调用（MCP 外接）；②把 PM 与宿主的工作区/记忆共享（原生协同）。它们的共同前提是：**项目仍然是一个被动的、需要有人（用户或 agent）主动去查的数据对象**。在这两个前提下，再好的接入也只是让「查」更顺滑——这是优化，不是范式。

本次脑暴所有派系不约而同地杀死了同一个假设：**「项目状态是死的、被动的、需要人去看的」。**

现状的三处结构性断裂，恰好是三个派系的切入点：

| 断裂 | 现状 | 对应方向 |
|---|---|---|
| 缺「入向流」 | 宿主会议纪要/讨论不流入 PM，90% 的承诺与风险散落在会话里 | 方向一（双向流总线） |
| 缺「出向流」 | PM 到期/风险不回流会话，只躺在面板红角标里没人点开 | 方向一、三、四（投递通道） |
| 缺「上下文在场」 | llm 懒读不带会话上下文，agent 跨会话失忆、解题跑偏 | 方向二（引力场） |

## 2. 五个颠覆方向

### 方向一：一切即流 —— 项目是河，不是表（事件溯源内核）

> 来源：流原教旨派（事件即真相、量子态项目、双向流总线、任意时刻回溯）＋ 界面消亡派（问则有、说出即存在）碰撞收敛

**核心机制**
1. **只追加事件日志，状态是投影**：废除「tasks/milestones/risk_issues/meetings 表为真相源」，改存事件日志——`task.created`、`task.deferred`、`commitment.made`、`decision.reached`、`risk.raised`、`deliverable.handed`，信封含 `{eventId, ts, causationId, correlationId, actor, type, payload, schemaVersion}`。现有 storageDomain 表降级为可丢弃的投影缓存。pm-tool 已有种子：`provenance.ts`（不可变历史链、内容指纹、不洗白重校）、`derived.ts`/`progress-derivation.ts`（纯函数、零写盘）正是投影脚手架；宿主 `session` 包本身不存状态、存 checkpoint 与迁移链、靠重放恢复，是可照抄的先例。
2. **不观测不坍缩（量子态）**：无人查询时不维护任何派生状态——不缓存健康分、不扫逾期表；只在观测瞬间（开面板/提问/命令）从事件流现场 fold，用完即散。`llm` 用 `ctx.reflect.get('llm')` 懒读的哲学推广到最后一刻才求值。
3. **双流打通（PM＝流处理器）**：入向——订阅宿主 `session` 消息流/`context`/`feedback`，抽取 `commitment.made`/`decision.reached`/`risk.mentioned` 三类原始事件（复用 `meeting-summarize` 车道与 `idempotency` 去重）；出向——fold 出的逾期/风险升级/承诺到期经 `interaction` 推送、`schedule` 定时观测触发、必要时派 `jobs`。`mcp` 作为未来其他 agent/客户端订阅同一流的出口。
4. **一切皆可回放**：给定时刻 T，从日志重放到 T，fold 出当时任务/进度/健康灯；与 `session-query` 聊天日志按时间戳/因果缝成统一时间线，回答「上个月 15 号我看到什么」「这风险谁在哪个会提的」。
5. **说出即存在（捕获语义）**：任务/风险/承诺/验收项在被对话说出口并确认的瞬间诞生——识别承诺句 → `interaction/user-questions` 轻量确认 → 写一条带 provenance 的言语记录，不需要任何录入表单。

**颠覆点**：违反「必须持久化当前状态」（只持久化发生过的事实，投影可蒸发）；违反「改任务＝写任务行」（一切修改是追加新事件，旧记录永不覆盖）；违反「状态要实时可见、后台持续维护」（没人看的状态是浪费且必然腐化）。

**对用户的价值（字节 PM · 火山引擎私有化交付）**：私有化交付口头承诺多、事后扯皮靠证据——事件流保留每次延期/口径变更的原始事实且不被洗白，验收可逐条举证；消灭「看板绿、实际黄」的缓存失真，不为「表格与现实同步」交租；换机器/重装重放即恢复；多端多人天然是同一流的订阅者（离职后多设备也能存活）。

**实现路径与风险**
- P0-a：选一个项目，从 session/session-query-sqlite 离线拉会话抽取 commitment 入日志，人工确认（先不实时订阅，验证准确率）
- P0-b：`schedule` 定时 fold，逾期/高风险经 `interaction`/`feedback` 回注，先发提醒不自动改状态
- P1：实时订阅，causationId 挂回原消息，误报追加更正事件；`health`/`stats` 只读命令改现场 fold
- P2：表成缓存→停写表→日志文件化（.jsonl）脱离 storageDomain；多项目分流 topic、跨流聚合
- 风险：技术——抽取误报（靠人工闸门＋置信度透明兜底）、schema 演进与 fold 性能（借 `compaction` 快照摊销）、观测瞬间延迟（用短命 TTL 而非全懒）；采用——用户心智从「看到的即事实」转到「倒影」；伦理——会话静默捕获的隐私边界（见 §6-D1）

**排期**：P0（双流最小闭环）→ P1（现场 fold 化、回放）→ P2（全量事件化、文件化）

### 方向二：潜意识引力场 —— 项目反向塑造 agent

> 来源：引力场派（引力场常数、项目心跳）＋ 界面消亡派（潜意识层）碰撞收敛

**核心机制**
1. **目标即物理定律（场方程注入）**：为每个会话绑定 active project，把北极星目标、硬性禁区（must-not-do）、不可妥协验收项编译成「场方程」，走宿主 `context` 包 `agent-instructions` 同款接缝：以 `source.kind='pm-gravity'` 的持久 user-role 消息进入会话历史，项目变更按 digest 增量刷新，并像 baseline 指令一样标记为 **compaction 不可压缩块**（否则长会话压缩后场就散了）。同时把项目北极星镜像写入宿主 `goal` 包 `ctx.goals`，让宿主自带的「持久目标」机制天然保持在场。
2. **潜意识层（无 UI 在场）**：不向宿主 layout/sidebar 注入任何可见面板；在宿主每次生成回复前，把「当前对话主题对应项目的关键约束与未决项」压缩成几行中性事实片段静默拼进上下文窗口。用户体验不是「我打开了 PM」，而是「这 agent 怎么突然更懂我这个项目了」。
3. **pre-step hook 软拉回**：挂载宿主 `agent/pre-step` hook，每步工具调用前用**确定性规则**比对该步与场方程——明显越界走 `ask`/`block`；轻度漂移走 `rewrite`，把「当前项目 X 的约束是……」补进该步而非直接打断。一期只做注入（零打断），二期加软拉回，三期才开放 block 硬约束（默认关闭）。
4. **引力梯度（自创延伸）**：复用 gantt.ts 已算出的 criticalPath/slack——关键路径任务（slack=0）在每步提示里加权排前，非关键路径请求被建议延后。场不均匀，越接近交付节点引力越强。
5. **项目心跳**：用宿主 `schedule` 为 active project 武装持久脉冲（每日/里程碑前），载荷由 PM 从自己的表确定性汇编（临近/at_risk 里程碑、超龄 risk_issues、到期 deliverables）；脉冲经 `jobs` 注册为后台自检，agent 必须回答「是否在轨？距上次脉冲发生了什么？有无承诺在滑？」并写回 reports；空闲超时且里程碑 at_risk 时 schedule 主动插脉冲（项目主动敲门）。

**颠覆点**：违反「PM 工具是被动的、等用户来查」与「agent 自己负责记住目标」。这里不存在「忘了项目目标」的时刻——遗忘在物理上不可能发生，因为场包裹每一步推理；PM 从查询对象变成推理环境本身；注意力方向反转：项目→agent→用户。

**对用户的价值**：项目动辄数月、跨会话与上下文压缩，最大损耗是 agent 中途解题跑偏、范围蔓延；场方程让「不做什么」「为谁做」始终在场，对外交付前的 scope 收口由系统兜底。心跳把例行巡检从人身上卸给项目，风险在冒泡成事故前主动浮出。

**实现路径与风险**
- 一期：system-prompt 注入＋持久场消息（纯只读、零打断）
- 二期：pre-step 的 rewrite/ask 软拉回；心跳确定性简报（不触发模型轮次，零成本）
- 三期：block 硬约束（默认关闭）；心跳接 jobs 后台自检写回 reports；里程碑检查点接 plan-mode 审批
- 风险：每请求 token 成本与注入稳定性；约束过紧扼杀主动性（硬禁区须用户显式声明）；schedule 依赖 Host Web Session controller（headless 降级策略）；自动轮次有 API 成本；隐藏注入的透明性/追责问题（出错时分不清「哪句是 agent 自己说的、哪句是 PM 塞的」）

**排期**：P0（只读注入＋心跳简报）→ P1（软拉回、自检轮次）→ P2（硬约束、plan-mode 检查点）

### 方向三：记忆生命体 —— 会记得、会遗忘、会预感

> 来源：记忆生命体派（三层记忆体、衰减遗忘、代谢预感、时间树）＋ 流原教旨派（任意时刻回溯的推演面）碰撞收敛

**核心机制**
1. **三层记忆体**：工作记忆＝绑定到项目的宿主活会话流（消费 `session-projection` 快照，经 `session-query` 含 FTS5 精确读取带项目标签的实时日志）；长期记忆＝宿主 `compaction-basic`/`command-compact` 的摘要产物直接转储为带日期的「记忆痕迹」（夜间借 `schedule` 离线整合成主题簇，白天可被 FTS5 召回）；遗传记忆＝项目结项时把 decision-log ADL、被关风险、真实 `effortHours/completedDate` 节奏提炼成可继承的「基因片段」，新项目自动读取匹配基因组——**继承的是「倾向与易感点」而非任务清单**（同类项目高发坑直接以先天风险候选载入）。
2. **衰减遗忘·间隔复述**：给每条易被遗忘的承诺（里程碑 targetDate、风险应对 owner、ADL 行动项）记「记忆强度」，随日历时间衰减；用 `session-query` 统计提及/确认频次作「复述成功」信号，按 spaced repetition 曲线拉长/缩短复习间隔；跌破阈值时借 `schedule` 把一条「项目自言自语式复述」投进原会话：「三周前你承诺 X 交付给客户，现在还成立吗？」连续 N 次无回应迁入「墓碑区」（已遗忘/已放弃），消除僵尸任务污染健康分。与现有 `computeReminders` 的本质区别：现有是「到期倒计时」，本层是「记忆保鲜倒计时」，管承诺**是否还被记得、还成立**。
3. **代谢率与项目预感**：用 `session-stats`（真实投入轮次/墙钟时间）、`completion-history`、实际 effortHours vs 估算、blocked 时长分布，为**每个项目自己**拟合节奏基线；偏离基线（投入高但客观进度不动＝「吃得多不长肉」；blocked 超历史同类；里程碑间隔被拉长）聚合为体感判断：「按你自己过去的节奏，X 里程碑大概率要滑几天」。预感不等 dueDate 到期，在节奏刚异常时就发出；每次预感留痕，事后用真实 completedDate 校准，沉淀「预感准确率」——系统越用越准，不是黑箱概率。
4. **时间树·反事实分支**：里程碑达成/重大 ADL 决策时自动打「胚胎快照」（只冻结决策涉及的任务子树、当时 plan-mode 计划文本、goal 状态，比 R18 全量 backup 轻）；从快照 fork 出独立命名空间的「幽灵分支」，用 plan-mode 换方案重排、把被否的替代方案捡起来推演「假如当初」；复用 `report-diff` 从「主干相邻期对比」扩展为「幽灵分支结局 vs 主干实际结局」并排对照。真正回退不覆盖历史，而是把当前状态存成旁支再回去——回退被理解为「分叉」而非「撤销错误」。

**颠覆点**：违反「项目记忆＝人手动维护的文档，录进系统就永久客观存在」（项目成为记忆主体，宿主会话是它的短期记忆，compaction 是它的海马体，结项项目是它可以遗传的祖辈）；违反「录进系统的信息永久保存，提醒＝到点按截止日报警」（记忆必须维护、系统应当会遗忘，主动复习是为了加固而非催促，沉默的承诺应该被体面地埋葬）；违反「项目计划单向前进，回退＝操作失误」（决策从一次性拍板变成可在平行宇宙里做对照实验的可推演对象）。

**对用户的价值**：人员流动/交接频繁时，新接手者拿到的是项目「自己记得」的来龙去脉（为什么当时这么定、哪条路被否过）；同类私有化项目代代相传——上一个交付项目的真实工期、客户侧坑、审批卡点变成下一个项目的先天先验；长周期项目大量口头承诺不会因没到截止日就被悄悄忘掉；客户侧阻塞、资源抽空、方向反复这类延期前兆在还没滑出日期时就被「身体感觉」捕捉，提前介入而不是救火。

**实现路径与风险**
- P0：衰减遗忘＋schedule 复述（材料最现成：schedule 投递、确定性衰减曲线、session-query 提及计数，离线可用）
- P1：compaction 摘要→记忆痕迹＋FTS5 召回；代谢基线采集（纯函数，只输出离均差事实，不下判断，样本不足诚实标注）
- P2：夜间 consolidation、结项基因提炼与新项目继承；预感校准闭环；胚胎快照＋幽灵分支（二期起只做离线纯函数重排，不调模型）
- 风险：compaction 摘要质量不稳定、跨会话归属判定；复述频率打扰（须克制、可静音、可白名单）；单项目样本太少时基线不稳（诚实标注「样本不足」，不造伪精确）；反事实推演若让 goal 续行真实重演有算力成本；预感是概率提示不是承诺，不得作为对外追责依据

**排期**：P0（衰减遗忘＋复述）→ P1（记忆痕迹＋代谢基线）→ P2（基因遗传、预感校准、反事实分支）

### 方向四：幕僚与空间 —— 项目成为可相处的存在

> 来源：拟人空间派（幕僚长、天际线府邸、围城之战、群岛与天气）＋ 界面消亡派（状态即呼吸）碰撞收敛

**核心机制**
1. **幕僚长（情绪确定性派生，只改措辞不改事实口径）**：每项目建档诞生一个「幕僚」——名字、语气档位、任职档案。情绪由现有 `health.js` factors **确定性派生**（critical 风险未关＝焦虑、逾期堆积＝疲惫、里程碑达成＝振奋、长期无更新＝沉默），不做自由 LLM 情绪，llm 不稳时退回模板句。打开项目幕僚先开口：晨间简报＝`war-room.js` KPI/agenda＋`report-diff.js` 周间变化＋meetings 未闭环 action 点名；需拍板的岔路经 `interaction/user-questions` 直接提问而非摊在面板。`completion-history`＋历次 progress-report 沉淀「任职日记」用 `document` 落盘，它记得上周承诺过什么：「上周跟客户保证联调周三完成，现在逾期两天，我得给你说法」。**状态即呼吸并入**：把健康度编码进宿主输出节律（风险升高时多一个停顿式确认问句、建议密度上升、主动复述承诺次数变多）——低阶情绪层，让用户「像感知同伴紧张一样感知项目」。
2. **天际线府邸（全局空间感知，不是看板换皮）**：看板是列表的排列，府邸是感知的压缩。所有项目聚成夜间天际线（浅态）：楼＝项目、灯光明暗＝health 得分、楼顶风暴云＝openCriticalRisk、楼层拥挤＝`people-load.js` assignee 密度、整栋漆黑＝超 N 天无 activity；一眼判断「哪栋在失火」。走进楼（深态）：楼层＝WBS 分支、房间＝任务、门锁＝依赖未通/blocked、奖杯柜＝deliverables、塔楼＝里程碑、中央大厅＝war-room。布局是纯确定性派生引擎，不新增表；浅深双态对应用户习惯，键盘漫游复用 panel-kbd/nav。
3. **群岛与天气（项目生态＋被动觉察）**：岛＝项目、航线＝真实耦合（同一 assignee、共享供应商/客户依赖、里程碑相邻），连线粗细＝耦合强度；风险传染 what-if：假设岛 X 延期 N 天，沿同人/同供应商连线算哪些岛被迫顺延（dueDate＋people-load 现算），回答「先救哪个会引发什么」。**项目的天气**：health factors 派生环境气候——晴朗/多云/浓雾（关键风险无 owner）/风暴（critical 风险、里程碑逾期）/回南天（长期停滞发霉）；低能耗环境层，不打开面板扫一眼云层即外周觉察，像出门前看天。项目老去：长期 active 但交付缓慢逐渐起雾生苔，paused 岛被海雾吞没。
4. **围城之战（验收闸门，见方向五合并）**：游戏化的反常规点——**无 XP、无装饰、无奖励皮肤**，只有紧张感与不可跳过性。详见方向五。

**颠覆点**：违反「管理工具必须理性、克制、无感情，事实自己会说话」（红灯只是灯，同事说「我有点撑不住了，R-3 挂了 14 天没人接」产生的是关系性问责压力，纯仪表盘结构上不存在）；违反「进度必须沿时间轴以表格/数字阅读」（人对城市夜景是瞬间并行判断，对甘特是串行枚举——把「检查 6 个项目」变成「看一眼天际线」）；违反「项目是彼此独立的台账条目，觉察必须主动打开面板」（风险在「查看」前先被「感到」）。

**对用户的价值**：同时扛 4–6 个私有化项目，最大死法是「忘了哪个在流血」——幕僚把逐个查面板变成「谁先敲门、谁语气最慌」，天然分诊；第一人称自述经 `report-narrate.js` 直接转成对客/上级叙事稿；会前 30 秒完成跨项目巡检；资源冲突（同一架构师被三项目抢）与延期连锁日常化，救一个不以引爆另一个为代价；避免烂尾到客户投诉才发现。

**实现路径与风险**
- P0：幕僚长情绪映射表＋开门语模板＋晨间简报（零模型零新表）
- P1：天际线总览（纯派生三因子，并列现有 overview）；user-questions 提问；任职日记
- P2：单楼楼层=WBS 下钻；群岛图（同人连线）；确定性延期 what-if；天气层＋老去海雾＋与幕僚敲门联动；schedule 敲门、feedback 校准、语气档位
- 风险：最易滑向「3D 皮相」（验收标准：**不读数字也能说出哪个最危险**；空间与台账严格等价、可反查原记录，布局做成可回归测试纯函数）；拟人接受度（严肃场合可一键退回纯客观，人格是皮肤层不是数据层）；情绪伦理红线（焦虑只呈现风险不 guilt-trip）；图易过密（支持只看风暴/浓雾过滤）

**排期**：P0（幕僚长晨间简报）→ P1（天际线）→ P2（群岛/天气/敲门联动）

### 方向五：承诺法庭 —— 交付先过项目的审判

> 来源：引力场派（验收法官、承诺契约）＋ 拟人空间派（围城之战）碰撞收敛

**核心机制**
1. **验收法官（rubric 凌驾模型自评）**：在 deliverable 上新增机器可检验收 rubric（勾选项＋阈值，由用户/项目定义，不由模型自由发挥「什么叫好」）；监听 `deliverables` 的 present 事件与 workspace-changes 快照，在 submitted 之后、用户可见之前，PM 用 `ctx.llm` 按 rubric 逐项打分写入项目记忆 scores；未达标走 pre-step 的 `ask` 打回让 agent 先修。分数按项目累积成质量分布档案；模型自评与法官分差值作为 agent 自我认知的校准信号（模型说「完成了」 vs 项目判「未达标」的差距被显式记录）。
2. **围城闸门（里程碑不可无声滑过）**：每个私有化里程碑（联调/试运行/初验/终验割接）＝一场围城 Boss 战，Boss＝客户验收。备战值由确定性因子合成（openCriticalRisk 数、逾期任务、未闭环 meeting action、未交付 deliverable、临期漂移）；不足时经 `interaction/user-approval` 设闸门：推里程碑 achieved 必须先关 critical 风险，**或留一条「明知带病推进」的书面豁免决策**（落盘 `document` 可追溯）——系统不替 PM 决定，但拒绝无声滑过。风险＝城内游荡怪物（HP＝影响等级×暴露天数，不清除会在战斗中反扑）；Boss 击破自动生成战报（report-diff 前后对比＋meetings 决议＋被关风险列表，经 report-narrate 写成可直接对客/上级的验收叙事）；paused＝围城暂歇，须记「休战协议」。
3. **承诺契约（说了就要算）**：agent 对项目作出的日期承诺被捕获为签名承诺记录（承诺方/内容/死线/验收证据标准）；到期时 PM 比对证据（deliverables 状态、workspace-changes git 快照、reports 留痕）判定 fulfilled/slipped/broken，只增不改写进「履约账」；违约自动序列：反思轮次（滑期原因写进 risk_issues/reports）→ 透明报告（经 interaction 流向用户，绝不静默翻篇）→ 可选降权档位。履约率按项目沉淀为可查历史曲线，下次对外承诺前先给用户看历史兑现率。

**颠覆点**：违反「模型自己定义什么叫做好、自我声明完成即可」（评判权从模型移交项目；质量是被测量出来的，不是被声明出来的）；违反「风险管理应是冷静、可选、文书化的后台工作，工具不该制造紧张」（风险登记册的死穴是「写了等于管了」；闸门把「不可跳过」变成身体纪律）；违反「软件从不守约，截止日只是愿望」（承诺不再是一句话，而是带自动后果的债）。

**对用户的价值**：验收标准来自客户合同，PM 先按 rubric 预检，把不成熟交付物拦在见客户之前；私有化生死线就是一次次验收/割接，最常见崩盘是「带病推进、验收日集中暴雷」——闸门把「我觉得差不多了」变成显式备战清单＋书面豁免，保护 PM 不在客户面前被动；战报天然就是验收汇报材料；对外承诺前先看 agent 历史兑现率，减少「说了没做」的沟通事故。

**实现路径与风险**
- P0：验收法官离线打分写档案（不拦截）；承诺登记＋到期证据比对＋透明报告（无惩罚）
- P1：ask 打回；反思轮次；围城备战值＋豁免闸门
- P2：降权档位（须显式开启）；关键路径梯队；履约率历史曲线
- 风险：rubric 编写负担落在用户；LLM 法官误判；闸门影响流畅度（紧急决策永远有书面豁免通道且留痕）；「自动降权/惩罚模型行为」敏感，与宿主 feedback 包「反馈是单向信号、绝不进入模型历史」哲学存在张力（见 §6-D6）；承诺识别误报（用户自己推迟不应记 agent 违约，需区分责任方）

**排期**：P0（法官离线打分＋承诺履约账透明版）→ P1（打回、反思、围城闸门）→ P2（降权、履约率曲线）

被淘汰/降级的脑洞要素：纯回忆无库路线（问则有的激进版）——不可用于对外签字场景，仅在方向一保留「按需投影」机制而放弃「删除一切记录」；状态即呼吸的激进版（输出节律语气调制）——落地度 2/10，降级为幕僚情绪层的低阶选项。

### 3.2 四个碰撞洞察（Organizer 碰撞产出，非任一单派观点）

1. **三个派各自发明了「项目主动开口」**：记忆派的衰减复述、引力场派的心跳、拟人派的幕僚敲门——共享同一条投递通道（`schedule` → 原会话 follow-up）。**这条通道本身应该成为 PM 的基础设施**（即方向一的出向流），而不是三个孤立功能。P0 的正确形态：先建「项目主动说话」的最小设施，再挂三种语义。
2. **潜意识层与引力场常数是同一技术接缝的两种语义**：一个管「状态不可见地在场」，一个管「行为被约束在场」——合并为方向二后，注入是手段，塑造是目的。
3. **问则有与量子态是同一哲学（状态是回忆/投影的产物）的两种表述**：一个从对话形态出发，一个从存储形态出发——都指向「状态不是被保存的，是被重新生成的」。
4. **验收法官、围城、承诺契约共享「项目拥有裁决权」**：打分、闸门、履约账本质是同一个主权转移——交付好不好、能不能算数，由项目定义，不由模型声明、也不由面板默认。

### 3.3 元观察

所有方向共同杀死同一个假设：**「项目状态是死的、被动的、需要人去看的」。** 新范式的共同内核是项目成为**主动的、在场的、有记忆的、会裁决的存在**。这就是「System of Record → System of Agency」——这不只是 pm-tool 的进化，是「项目管理工具」这个品类在 agent 时代的物种更新：**当 agent 是执行者，项目管理就不再是「记录」，而是「治理」**。

## 4. 推荐组合拳（P0 / P1 / P2）

### P0 —— 能动系统的第一块地基（1–2 周量级，全部只读/可逆/不推翻现状，互不阻塞）

| 项 | 内容 | 复用材料 | 为什么能起步 |
|---|---|---|---|
| **P0-1 双流最小闭环**（方向一） | 离线抽取承诺入事件日志＋人工确认；schedule 定时 fold，逾期/风险经 interaction 回注会话（先提醒不自动改状态） | session/session-query-sqlite、schedule、interaction、idempotency | 宿主全现成；不实时订阅，先验证准确率 |
| **P0-2 项目主动开口通道**（方向二+三） | 衰减遗忘强度曲线＋schedule 复述投递；心跳确定性简报（纯汇编、不触发模型轮次） | schedule、session-query 提及计数、确定性曲线 | 零模型轮次、零新表，离线可用 |
| **P0-3 幕僚长晨间简报**（方向四） | health factors → 情绪映射表＋开门语模板＋晨间简报 | health.js、war-room.js、report-diff.js、interaction | 零模型零新表，情绪是确定性函数 |

**组合拳的洞察**：P0 三项不是三个独立功能，而是同一个范式的最小骨架——**项目第一次学会「说话」（出向）、「听懂」（入向）、「有性格」（情绪层）**。三者共用 schedule→会话 通道，天然长出方向一的事件流内核雏形。

### P1 —— 范式成型（让项目「在场」）

- 方向二：场方程只读注入（system-prompt＋持久场消息，compaction 不可压缩块）；pre-step 软拉回（rewrite/ask）
- 方向一：health/stats 现场 fold 化（不观测不坍缩起步）；回放（选日期→静态快照→两时刻 diff）
- 方向三：compaction 摘要→记忆痕迹＋FTS5 召回；代谢基线采集（纯函数，只输出事实不下判断）
- 方向五：验收法官离线打分写档案；承诺登记＋到期证据比对＋透明报告
- 方向四：天际线总览（纯派生三因子）

### P2 —— 颠覆形态（让项目「存在」）

- 方向三：结项基因提炼与新项目遗传；预感校准闭环；胚胎快照＋幽灵分支反事实推演（离线纯函数重排起步）
- 方向一：全量事件化（表成缓存→停写→.jsonl 文件化）；任意时刻回溯与因果线缝合
- 方向二：block 硬约束（显式开启）；plan-mode 里程碑检查点
- 方向四：群岛耦合图＋延期 what-if；天气层＋老去海雾＋敲门联动
- 方向五：围城闸门＋书面豁免；降权档位；履约率曲线

## 5. 待用户决策点（不替用户拍板）

- **D1 隐私与同意边界**（方向一/三）：会话流静默捕获/转写是否可接受？范围＝全部会话 / 仅关联项目 / 仅指定会议？保留对话原文还是只存结构化事件？是否本地-only、可关闭、可擦除、可导出？（私有化交付常含客户保密信息）
- **D2 拟人化档位**（方向四）：①纯客观 ②情绪只作措辞修饰 ③完整幕僚人格？对客/上级场景是否强制剥离人格？情绪伦理红线（焦虑只呈现风险、禁止 guilt-trip）由谁定？
- **D3 自动捕获 vs 显式登记**（方向一/五）：抽取事件「待确认后入册」还是「直接入真相流」？误报容忍度是多少？（影响承诺契约的责任判定）
- **D4 约束强度档位**（方向二）：软提示 / 改写 / 询问 / 硬拦（block）？硬拦权是否开放？多项目并行时 active project 的会话级绑定与切换规则？
- **D5 惩罚性后果**（方向五）：承诺违约是否允许降权，还是永久只做透明记录＋反思？（与宿主 feedback 包「绝不回灌模型」哲学冲突）
- **D6 法官打分回灌**（方向五）：验收分数是否回灌模型校准行为？（同样与 feedback 哲学正面冲突，需拍板）
- **D7 离职独立维护的宿主耦合边界**（全局）：哪些脑洞保留为可移植核心、哪些随宿主丢弃？项目资产是否彻底脱离 storageDomain 退化为单个 .jsonl＋无状态 fold？（决定方向一/三/四的终点形态）

## 6. 落地护栏（防走偏清单）

1. **空间/游戏隐喻只进私人视图**：对外导出（汇报/验收材料）自动剥离隐喻与天气拟人，只留事实口径。
2. **情绪与事实严格分离**：情绪只改措辞与开门第一句，不改任何数值与结论；llm 不稳退回模板句。
3. **无信号不造伪精确**：样本不足的预感/基线诚实标注，不伪装精确概率。
4. **闸门不硬堵合法推进**：紧急决策永远有书面豁免通道且留痕（围城），系统裁决权不等于系统阻塞权。
5. **AI 产物可区分可撤销**：延续 G5 原则，自动捕获的事件/承诺一律「待确认」→ 确认 → 可撤销。
6. **预感是概率提示不是承诺**：不进入对客承诺与追责依据。
7. **每层都留「客观证据出口」**：再激进的范式（纯回忆/体感/拟人）都必须保留可导出、可签字的正式记录通道——这是 PM 职业的向上交付底线，不算「没彻底颠覆」。

## 附录：派系宣言（原始视角，供回溯）

- **界面消亡派**：项目管理工具的原罪，是假设「状态需要一块地方被看见」；项目只在被谈起、被想起、被说出的那一刻存在——界面是多余的器官，应当被切除。
- **流原教旨派**：项目不是一张表，而是一条只追加的事件河；任务、进度、健康度都只是这条河在某个时刻的临时倒影——表可以删，河不能断。
- **记忆生命体派**：传统 PM 把项目当「任务文件柜」；项目本身是一个会把宿主会话吃进自己神经系统、会遗忘、会把教训写进基因、会在自己要延期之前先「感觉到」的生命体。
- **引力场派**：常规 PM 把项目做成「被查阅的档案」；我们把它做成「包裹 agent 的力场」——agent 不是在工具里查项目，而是永远在项目引力场内思考，偏离即被场本身拉回。
- **拟人空间派**：品类把项目压成表格；我把项目还原成一个你共事的生命和一片你身处的地方——管理不再是「读指标」，而是「与它相处、在场感知它」。
