# S2「对话里推进项目，说完即沉淀」说明

> 场景 2 / 5 · 覆盖能力：K4 承诺浮出 · K2 受限直写 · K9 单向结存 · K3 证据闭环
> 配套页面：`s2-dialog-work.html`（浅色默认）、`s2-dialog-work_dark.html`（烘焙深色副本）
> 本页为纯设计示意，不修改产品源码/配置/依赖，不代表已上线。

## 一、五问白话全文

### 什么时候用
白天在 dsh 里围绕 G3验收项目边聊边推进时：不切页面、不停对话，说着话就把该记的备注、承诺、归属落进台账。典型时段是 10:00–17:00 的日常对稿、补材料、接着干。

### 你点什么 / 说什么
1. 在对话里说：「帮我把这段说明补到 R-07 备注里：视觉验收需要浏览器截图凭证。」
2. 聊天中自然带出承诺，如「我周三前给评审版」「这周要补截图凭证」。
3. 说：「这个会话先挂到 T-102 上，待会儿接着做。」
4. 会话里贴入附件、发生本地文件改动（如贴了评审稿截图、保存了原型线框）。

### 系统替你做什么
- **K2 受限直写**：把要写进「备注 / 证据链接」的内容先做成变化预览（原备注 −、将追加 +），你点「确认写入」才落盘，写错可撤销；**只动备注字段，不碰状态、负责人、到期时间**。
- **K4 承诺浮出（观察模式）**：从你的发言里整理出承诺建议（预填标题 + 到期占位待你填），先放在建议区，**不进待办箱、不落库**；你逐条点「采纳进待办 / 忽略」才进箱。他人承诺（如测试同学「周四前回反馈」）仅在会话内留痕，不进待办、不跟进、不催办。
- **K9 单向结存**：会话单向沉淀到任务（会话→台账，不是双向镜像）；高置信（本会话与 T-102 直接相关）自动挂上、可撤销；低置信（结存到 m-g3 里程碑记录）给建议，你一键采纳 / 忽略；**只沉淀记录，不改任务状态、不改负责人**。
- **K3 证据闭环**：只收本会话内出现的文件与改动，收成证据候选；你点「归属 R-07 / 归属 T-102」才落盘，也可暂不归属；公司系统里的动作仍需你人工粘贴链接，本页不承诺覆盖。

### 你看到什么结果
- 对话里出现「待确认的承诺建议卡」列表：预填标题、到期占位（虚线框「日期待你确认」）、高/中置信标记、来源发言时间。
- 「将写入备注」的变化预览卡：原备注划线、新增行绿色 +，下面写明「仅写入备注字段，不改动状态/负责人/到期；写入后可撤销」，配「确认写入 / 取消」。
- 会话挂上任务后的回显：T-102 已自动绑定（可撤销），m-g3 低置信建议等你决定。
- 证据候选归属确认：附件与改动各带「归属 / 暂不归属」，确认后变绿并标注归属对象。
- 右侧「本会话待你确认」面板实时计数（待裁决 / 已处理），点条目可跳到对应确认。

### 和现在有何不同
以前承诺散在聊天里翻不到、备注要自己切到任务页手改、会话关掉就找不到头绪；现在说一句即可沉淀，关键变更先给你核对再落笔，写错能撤销，会话与任务、证据之间留得住痕迹。

## 二、专家方法落实记录

### 1. design-human-ai-workflow（AI 控制点 propose / confirm 分工）
- **AI proposes（只提建议，不落笔）**：K4 承诺建议卡、K9 低置信结存建议、K3 证据候选都是「提议态」——带置信标记与来源，但不进箱、不落库、不改状态。
- **AI acts with confirmation（确认后才动作）**：K2 先给变化预览（diff：原备注 − / 追加 +），「确认写入」后才落盘，并提供「撤销写入」；K4 逐条「采纳进待办 / 忽略」；K3「归属 / 暂不归属」；K9 高置信自动挂但给「撤销绑定」，低置信「采纳 / 忽略」。
- **provenance 可溯**：每条建议标注来源（你 10:32 的发言 / 10:28 贴入的附件），AI 提议与已确认内容视觉可区分（建议灰底虚线 vs 已处理绿底）。
- **recovery 可逆**：K2 撤销写入、K9 撤销绑定/撤销结存，全部给出退路；没有隐藏的外部动作。
- **不消灭判断负担**：K4 收益主张是「字段预填减负 + 逐条裁决」，画面不出现「自动全录」「录入趋零」。

### 2. ui-ux-pro-max（dsh 视觉 token 与交互规格）
- **token 沿用不换板**：浅深两态直接复用宿主 token（浅：#f7f8fa/#fff/#e5e7eb/#1f2329；深：#0f1115/#171a20/#2a2f3a/#d7dce3），语义色不变——临期/待确认=警示黄橙、风险=红、已完成/已确认=绿、链接强调=蓝；ID/计数用 SF Mono/Menlo 等宽 + tabular-nums。
- **语义状态色编码**：高置信=蓝 pill、中置信=黄 pill；待确认卡左边框黄，已处理/已归属绿底绿边；不用颜色单独传信息（文字同时写明状态）。
- **触摸热区**：移动端按钮 min-height 40px、padding 8–12px，满足 44px 级可点热区方向；桌面保持 dsh 紧凑密度。
- **浅深独立 token**：深色换底板/线/文字（非反色），语义色各自在深浅底上取可读值。

### 3. ux-ui-audit（可达性走查）
- **键盘可达**：全部操作为原生 `<button>`，可 Tab 遍历；`:focus-visible` 给 2px 蓝色焦点环（outline-offset 2px），不删除默认 outline。
- **对比度**：正文 #1f2329/#5b6472 对浅底、#d7dce3/#9aa3b2 对深底，满足正文 4.5:1 方向；辅助说明用 --fg2 而非浅灰叠浅灰。
- **确认前预览、可拒绝、可撤销**：K2 落笔前 diff 可见；取消/忽略路径齐全；已写入状态保留「撤销写入」。
- **AI 产出与人工内容可区分**：建议态（观察模式）与已确认态分色分框；他人承诺单独留痕块，不混入本人待办。
- 说明：本页为静态设计稿，未做屏幕阅读器实测，可达性为走查级落实。

## 三、能力边界清单（本页严格遵守，不夸大）

| 能力 | 本页承诺 | 本页明确不做 |
|---|---|---|
| K2 受限直写 | 仅备注字段、证据链接字段；先预览→确认写入→可撤销 | 不自动改状态 / 负责人 / 排期 / 到期；无「批准即自动落库队列」第三项 |
| K4 承诺浮出 | 观察模式先行：只记录浮出结果、不进箱不落库；人逐条确认才进待办；预填标题 + 到期占位 | 不做零确认落库；不宣称「录入趋零/消灭维护」；第三方承诺仅会话留痕，不跟进不催办 |
| K9 单向结存 | 会话→台账单向结存；高置信自动挂可撤销、低置信人一键采纳/忽略；1 个只读适配点 | 非双向镜像；不改任务状态/负责人；不做扇出执行/无人值守油门/规则刹车/常驻 jobs |
| K3 证据闭环 | 仅会话内工作痕迹自动收成候选；人点归属才落盘；证据库唯一落盘 | 不承诺覆盖公司系统动作（仍人工粘贴链接）；git 仅为线索之一；不做自动闭环归责 |
