# S3「交付前查缺口，完成后留复盘草稿」说明

> 分片B · 场景 S3 · 覆盖 **K6 交付检查** + **X6 即时复盘草稿**。
> 纯设计效果图，不修改产品源码/配置/依赖，不 push，不生成云文档。页面内全部为虚构示例数据。

## 一、五问白话叙事

1. **什么时候用**：里程碑达成或交付前，准备宣布完成之前。
2. **你点什么**：在任务/里程碑上点「准备完成」，或直接对 AI 说「帮我检查 m-g3 能不能交付」。
3. **系统替你做什么**：K6 把承诺、进度与已有材料放一起核对，只列一致性和缺口（「未覆盖≠未完成」），**不下完成裁决、不背书完成**；宣布完成后 X6 自动生成粗糙的即时复盘草稿，缺证据处留白不编造，你补材料、开正式复盘会后再定稿。
4. **你看到什么结果**：
   - 交付前核对面板：已覆盖 2 条（T-102 原型设计、交付物 D-01），待留意 3 条（无材料支撑的承诺「10-15 视觉走查」、未闭环风险 R-07、已改期未记录原因的 T-103）；
   - 完成后「即时复盘草稿」卡片：句级「已核 / 待核」标注、证据不足的留白块、补充材料 / 打开正式复盘会 / 仅保存草稿三个动作；
   - 右侧把**业务完成状态**与**复盘状态**分成两块显示，互不影响。
5. **和现在有何不同**：以前凭记忆检查遗漏、复盘靠事后回忆；现在交付前有一份核对清单，完成后趁新鲜留下草稿。

## 二、页面结构与真实交互（无僵尸按钮）

- 导语条：五问默认收起，点击展开（`guide-detail` toggle）。
- K6 核对面板：
  - 每条缺口行有「补一句说明 / 补记原因 / 打开风险 / 查看材料」等动作，均为受限备注写入或打开详情，带确认口径；
  - 「我已知悉这些缺口」点击后勾选态常驻（`acknowledge()`），缺口仍留在清单可回看；
  - 「我确认宣布达成 m-g3」是**人**的声明按钮（`declareAchieve()`）：点击后右侧业务状态变绿、按钮置灰，**系统不自动达成**。
- X6 草稿卡：补充材料 / 打开正式复盘会 / 仅保存草稿，均有反馈；草稿徽章「未定稿·粗糙草稿」。
- 右侧状态栏：业务完成状态、复盘状态分两块；底部「普通任务完成→轻量记录 / 里程碑达成→完整草稿」用业务语言呈现（不出现内部分层词）。
- 顶部 ◐ 切换浅深；导航项全部挂 `navHint()` 反馈；底部输入框为 dsh 真实样式。
- 关键交互态烘焙副本：`s3-completion_state-achieved.html`（已宣布达成后的静态态），截图在 `_shots/interaction/`。

## 三、能力边界（非目标，页面已写明）

- K6 只列一致性 + 缺口，**不下完成裁决、不背书完成**；「未覆盖≠未完成」。
- X6 是粗糙即时草稿，**完成≠定稿**；业务完成状态在宣布当时落库，不等复盘、不依赖草稿。
- 无积分 / 连胜 / 徽章 / 动效，只做克制文本归档。
- 普通任务完成只留轻量记录；里程碑达成才生成完整草稿并进正式复盘会（内部分层机制不在画面出现）。
- 不做自动完成判定、不自动关闭风险、不自动补写承诺。

## 四、专家方法落实记录

- **design-human-ai-workflow（AI 控制点 propose/confirm）**：核对结果由系统「提议列出」，达成声明、关闭风险、补备注全部由人确认后生效；草稿由系统代起草，定稿权在人（正式复盘会）；每个受限写入都有「确认/取消」口径与可撤销说明。
- **review-product-plan（非目标显式）**：页脚与面板脚注明确写出「本场景不做：自动完成裁决、完成背书、积分/连胜/徽章动效」，把不做的事与做的事同屏列出。
- **ui-ux-pro-max**：沿用 dsh 视觉 token（浅深独立变量、语义状态色：绿=已覆盖/达成、黄=待留意、红=未闭环风险）；计数用 mono + tabular-nums；可点控件热区足够、不只靠 hover。
- **ux-ui-audit**：文字对比度按 token 取值（浅深两套 fg/fg2/fg3）；按钮均为真实 `<button>` 可键盘聚焦；状态同时用颜色与文字标签表达（不只靠颜色）；移动端单列堆叠，无横向溢出。
