# S4「给不同的人一份合适的进展材料」说明

> 分片B · 场景 S4 · 覆盖 **K18 分受众只读分发** + **X5 述职素材** + **X2 毕业标记** + **X3 失败教训**。
> 纯设计效果图，不修改产品源码/配置/依赖，不 push，不生成云文档。页面内全部为虚构示例数据。

## 一、五问白话叙事

1. **什么时候用**：要给团队、朋友、领导看项目进展，或述职、求职整理成果时。
2. **你点什么**：主界面点「分享/导出」，选受众（团队技术版 / 朋友非技术版 / 纯文本）；或进「述职素材」选条目。
3. **系统替你做什么**：按受众生成三档只读材料（技术 MD / 非技术增强 / 纯文本兜底），单向只增、外部是唯一事实源、本地只留已发出日志；述职素材把自述数字与可核验证据分栏、待核标注、导出默认排除待核；毕业=人工声明+洁净度勾选+回潮自动摘标；失败项目中性归档（个人可改进/外部原因双栏，锚点缺失不开归因栏）。
4. **你看到什么结果**：导出预览（带受众/范围/排除待核 N 条）；已发出列表（只读日志）；「标记毕业」勾选清单；失败教训库双栏条目。
5. **和现在有何不同**：以前整理分享材料靠手工拼、范围难控；现在一键按受众出只读材料，且明确不是双向同步。

## 二、页面结构与真实交互（无僵尸按钮）

页签切换三个面板（`switchTab`）：

- **对外材料（K18）**
  - 受众三选一（`selectAudience`）：团队技术版 Markdown / 朋友非技术版增强说明 / 纯文本兜底；切换后预览文案与摘要同步刷新（`refreshPreview`）。
  - 范围勾选（已完成任务/里程碑/风险处理记录/述职素材仅已核），预览头显示受众、范围、「排除待核 2 条」。
  - 预览卡标注「目标平台：待确认」；动作：重新生成预览 / 导出只读文件 / 记录到已发出日志（`logSent`）。
  - 明确写出：**只读分发·单向只增，不是飞书/Jira 双向同步**，不级联、不镜像，外部为唯一事实源。
  - 「已发出」只读日志列表（时间/受众/范围/文件名/只读标），只增不回写。
- **述职素材（X5）**：条目/自述数字/可核验证据/状态四栏；已核 1 条、待核 2 条；「导出已核条目（走 K18）」默认排除待核；可补证据转已核（需确认）。
- **毕业与归档（X2·X3）**
  - X2：人工声明 checkbox + 三项洁净度勾选，全部勾选后「声明毕业」按钮才可点（`refreshGrad`/`graduate`）；说明回潮（出现未完成项/回潮承诺）自动摘标，不做「N 周未打开即成功」自动判定。
  - X3：有锚点条目开放「个人可改进/外部原因」双栏；锚点缺失条目只存事实、不开归因栏。
- 顶部 ◐ 浅深切换；导航项全部挂 `navHint()`；底部为 dsh 真实输入框。
- 页签态烘焙副本：`s4-state-x5.html`、`s4-state-x2x3.html`，截图在 `_shots/interaction/`。

## 三、能力边界（非目标，页面已写明）

- K18 是**只读分发/受控单向动作**，**不是飞书/Jira 双向同步**；目标平台「待确认」，不预设 GitHub/飞书/Jira。
- X5 是成就备忘录，**不承诺信用证明**，**不是完整贡献记录**；待核条目不进对外素材。
- X2 毕业=人工声明 + 洁净度勾选 + 回潮自动摘标；**不做自动洁净判定、不做 KPI**。
- X3 中性归档；锚点缺失只存事实，不开主观归因栏。
- 本地不留外部镜像，外部改动不回写本地。

## 四、专家方法落实记录

- **design-human-ai-workflow（AI 控制点 propose/confirm）**：材料由系统按受众代生成（propose），导出、声明毕业、补证据均由人确认后生效；系统不直接向外部平台写状态，外部动作受控单向。
- **review-product-plan（非目标显式）**：预览卡下黄条与右侧「本页边界」同屏写出「非双向同步/平台待确认/非信用证明/人工声明」，把不做的事显式列出。
- **ui-ux-pro-max**：沿用 dsh token 与语义状态色（绿=已核、黄=待核/待确认）；计数 mono + tabular-nums；受众选项为等宽三栏可点卡片；表格固定列宽 `table-layout:fixed`。
- **ux-ui-audit**：浅深两套 fg/fg2/fg3 对比度；所有控件为真实 `<button>`/`<label>`/`<input>`，可键盘聚焦；状态同时用颜色与文字标签；移动端单列堆叠、表格横向不溢出、无横向滚动。
