# K12 自我计量与可信底座 · 设计说明

> 裁决档位：**修正采纳（撤哈希链/法律举证，描述统计口径）**｜推荐组合内（第 0 层底座，排在最前）｜证据等级：E5（`core/backup.ts`、completion-history、provenance 现状）+ E6（来源类型相关性、路由成本回包待本机样本）
> 原型：`原型.html`（示例数据；含只增日志物理删除、采纳率样本不足/达标两态、来源档提示；浅/深两态）

## 1. 该方案改变了什么

**场景改变**：为 K1–K11 提供「可回看、可计量、删除权优先」的底座，但不充当防篡改审计或法律举证。

**结构改变**：
- **回滚账本定位收敛**：只回答「这条记录被谁、何时、改成什么」，供人回看与手工订正；**不做操作回滚引擎、不做防篡改哈希链、不做法律举证包**（X4 对外举证归并，R4-K12-02 撤哈希链闭合）；
- **独立记录编号 + 只增日志（append-only）**：新变更以新编号追加、不改写历史；同时保留**物理删除/归档通道，删除权优先**（B12-K12-01 致命项闭合：个人软件无合规留存义务，用户删除权优先）；
- **采纳率 N/M 描述统计**：N=被采纳/签字建议数，M=唤起过并进入裁决数；未唤起（模型没提出）从分母分离、不计失败；零调用不裁决；样本未达 Wilson/精确区间门槛时只给 N/M 描述分布，不下「建议质量差」失败裁决（B12-K12-02 闭合）；
- **来源档降提示**：agent 建议/手动/外部粘贴只作来源 chip，不显示 A/B/C 可靠度档、不进排序权重（R3-B-K12-01 闭合）。

**交互改变**：日志流每条可物理删除（删除即移除，无断链校验概念）；采纳率提供样本不足/达标两态切换，不足态明确「不下失败裁决」。

**视觉改变**：不做审计蓝/法律感纹饰；日志行用等宽编号 + 单行信息；采纳率三格（N / M / 未唤起分离）并列，避免把未唤起混进失败率。

## 2. 采用的专家方法

- **design-human-ai-workflow**：计量用于反馈回路（trust calibration），但不把未评审反馈当真、不做奖惩式裁决；删除权与撤销出口明确给人。
- **review-product-plan**：E6 待补项显式列出（来源类型相关性、路由成本回包），达标前不做定量主张；非目标（哈希链、法律举证、自动回滚）写明排除。
- **ui-ux-pro-max / 统计审慎**：小样本不显示百分率成败结论，只给原始 N/M，避免 3/7 被读成「43% 失败」。

## 3. 与攻防结论的关系

| 攻防条目 | 终局结论 | 本设计落点 |
|---|---|---|
| B12-K12-01 个人软件防篡改法律举证 | 致命否决：删除权优先，撤法律举证（X4 归并） | 账本定位节 + 删除通道 |
| B12-K12-02 小样本采纳率误读为失败 | 修正：未达门槛只描述统计，未唤起分离 | 采纳率两态 |

| E6 待补 2 处 | 登记：来源相关性、路由成本回包 | E6 待补清单 |

## 4. 残留与待补

- E6（本地）：来源类型与正确率相关性、路由成本回包，样本积累后回填；三计数埋点供 K3/K4 启用区间判定。
- 局部：物理删除后的备份链清理口径、归档入口位置。

## 5. 定位标注

**推荐组合内（底座，最先落地）**：不直接面向用户新功能，为其余单元提供日志与计量出口；系统内核类变化通过日志可见、删除/统计控制与证据出口呈现，不虚构全新页面。
