# K2 写边界与自主度光谱 · 设计说明

> 裁决档位：**修正采纳（条件性）**｜推荐组合内（第 0 层底座，可与 K1 并行）｜证据等级：E5（`commands/ask.ts` applyCore 源码）+ E4（放行依据须为服务端可查持久事实）
> 原型：`原型.html`（示例数据，不调用生产 API；含浅/深两态与闸门交互演示）

## 1. 该方案改变了什么

**场景改变**：现状写动作全部走 L2「AI 提议、人点确认即时落库」的 ask-apply 草稿流。K2 在人裁决保留（C3）的前提下，于自主度光谱第 3 档（AI 限内直写）开放一个极窄的写面，回应 H5「期望 agent 代执行 PM 动作、不是只做草稿」，但不滑向全自治。

**结构改变（双层闸门）**：
- 类型闸：动作枚举 ∈ 服务端白名单（解决「这是哪类动作」）；
- 字段闸：载荷字段 ⊆ 该动作允许字段集，未知/非允许字段整体拒收（解决 R2-A-K2-01「类型闸不校验载荷字段集、夹带面」）。
- 两层缺一不放行；拒收即回 L2 草稿流，不部分落库、不静默成功。

**交互改变**：
- 第一期窄集仅 2 项：①纯文本/备注修改（notes/description）；②补挂证据链接（evidenceUrl/repoUrl）。
- 直写成功写 provenance（kind=auto-whitelist-write），提供事后撤销出口；标完成/状态流转移出白名单（完成判据归 K6）。
- 第 3 项「采纳已批草稿落库」本期挂起：现状 ask-apply 确认即即时落库、provenance 仅记已应用历史，无「已批准未落库」持久队列，规则仅凭模型声明放行即回到误放路径（R3-A-K2-01）。

**视觉改变**：光谱五档横向标尺，仅第 3 档点亮；白名单以「动作—允许字段—拒收字段—状态」四列表达，开放/挂起/移出三态 chip；拒收用窄结果条，不扩成告警面板。浅深两态均按 dsh token 真实设计（深色非机械反色，accent 提亮、面板层级加深）。

## 2. 采用的专家方法

- **design-human-ai-workflow** 责任分配五档（human only / AI proposes / AI acts with confirmation / AI acts within limits / AI acts with retrospective review）：K2 第一期落在「AI acts within limits（限内直写）+ retrospective review（provenance 事后可撤销）」，L2 现状为「AI acts with confirmation」，L4/L5 不开放；审批步骤有效前提是审阅者有上下文与实质替代项，故直写面只给即时可核验、错误可手动重填的低风险写。
- **review-product-plan** 可核验性：每条放行承诺对应服务端可查事实（白名单枚举、字段集、队列记录），模型声明不作为证据；挂起件显式列入拍板清单而非静默放行。
- **ui-ux-pro-max**：错误靠近发生位置（窄结果条）、焦点环可见、44px 可点热区、语义色 token（成功/警告/拒收三色分工）。

## 4. 残留与待拍板

- **待用户拍板**：approved-pending 待落库队列是否纳入本期路线（H5×C3 边界，裁判拍板清单第 1 条）；直写扩界节奏（拍板清单第 8 条 H5×C3）。
- 局部登记：字段集随 schema 同步维护；队列快照与当前白名单重放复核；C7 无常驻下 expiresAt 惰性过期；approvedBy=本人单写者由 C3 覆盖。
- E6：无新增无证据定量主张。
