# K3 工作痕迹自动证据闭环 · 设计说明

> 裁决档位：**修正采纳 / 条件性采纳（限会话内支流）**｜推荐组合内（第 1 层会话采集主线，排在 K12 之后）｜证据等级：E5（`core/task.ts` evidenceUrl 单链、`core/backup.ts`、workspace-changes README）+ E4（证据既可证完成也可否证；自动挂接只承诺已绑定子集）+ E6（绑定率待 K12）
> 原型：`原型.html`（示例数据；含开工绑定确认、线索认领、唯一落盘视图；浅/深两态）

## 1. 该方案改变了什么

**场景改变**：回应 H1（真实沟通进展/文档更新不在 PM 系统实时更新）与 H3（日常跑会话），把 dsh 会话内完成的工作痕迹（git diff 线索、附件、会话轮次）自动收成证据候选，人只做归属确认；不承诺覆盖公司系统动作。

**结构改变（最小绑定先于 K9）**：
- 开工绑定从「依赖未建成的 K9 开工会话机制」降为「会话开始 agent 代挂一个 taskId 草案、人一键确认/忽略」的小动作，机制先于 K9 存在（R2-B-K3-01 闭合）；
- 绑定任务仅作主归属，会话内夹带改动不整会话错挂，进候选池/孤儿池由人认领；
- 证据候选库为新证据族**唯一落盘处**，旧 `task.evidenceUrl` 单链降级兼容只读、迁移逐条提升，复用 `core/backup.ts` 备份链，不并行第二真源、不新建第二条恢复路径（R2-B-K3-02 闭合）。

**交互改变**：
- 每条线索带来源类型提示（非可靠度档位、不进排序权重）；
- present 声明类线索（「应该够评审用了」）结构上不可勾选、不作完成证据；
- 客观改动类（git diff、附件）由人点「归属 / 进候选池」才落库，守 C3。

**视觉改变**：绑定建议条用 accent-soft 浅蓝承载待确认动作；声明类线索用虚线框 + warn chip 与可勾选线索区分；落盘视图三态（已落盘/待认领/兼容只读）用 chip 表达。

## 2. 采用的专家方法

- **design-human-ai-workflow**：AI proposes（代挂草案、候选收成）+ human confirms（归属确认）；上下文与 provenance 明示来源类型；异常路径（低置信落空不绑定、git 失效静默跳过记日志、未绑定进孤儿池）均有出口，无静默继续。
- **ui-ux-pro-max**：声明类线索直接禁用勾选并给理由，避免误把陈述当证据；动作按钮靠近对应线索，44px 热区。
- **review-product-plan**：覆盖域收窄为「已绑定会话子集」，未绑定部分认领成本如实承认与现状手动贴链接同量级，不宣称全量闭环。

| 攻防条目 | 终局结论 | 本设计落点 |

## 4. 残留与待补
