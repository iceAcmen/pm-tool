# K4 台账吃对话 · 设计说明

> 裁决档位：**修正采纳（观察模式先行，条件性启用）**｜推荐组合内（第 1 层会话采集主线，排在 K12 之后）｜证据等级：E5（`commands/ask.ts` 草稿确认、prod Key 检查、R1 模型不稳）+ E6（触发成功率/漏报率/单条裁决时长/净减负待 K12）
> 原型：`原型.html`（示例数据；含观察/启用模式、主档候选箱批签字、待收建议、第三方承诺留痕；浅/深两态）

## 1. 该方案改变了什么

**场景改变**：回应 H2（边聊边推进，回头想不起答应过什么）。两条互补入口：
- **显式主档**：人在会话收尾喊收/标记段落 → 高置信进候选箱，预填标题/到期/负责人占位，人逐条判真、归并、签字后落库；
- **被动低置信待收补档**：会话结束系统只列出会话内低置信建议，不进箱、不催、可整条忽略，为「忘了喊收」提供可见补捞面。

**结构改变（预填减负的精确边界）**：被消灭的只是「打开台账新建条目、构造标题字段」的录入动作；逐条阅读、判真、归并、签字的认知动作完整保留（C3 人裁决）。不宣称「录入趋零」「台账消失」。

**交互改变**：
- 观察模式默认：只记录浮出结果与人工核对，不进箱、不落库；样本积累后按**本机分布**自定阈值再切启用，不预设 recall/precision 下限；
- 第三方承诺（协作方不登录本工具）：仅会话内留痕或作 task 备注，标注「仅记录、不跟进、不催办」，不建独立观察区死数据列表；
- 到期相对日期只填「待确认」占位，不臆造具体日期。

**视觉改变**：高置信箱与低置信待收分区陈列；第三方承诺用 warn 左边框 + 标注 chip；批量签字条与单条判否/归并动作分层，避免一键全落库。

## 2. 采用的专家方法

- **design-human-ai-workflow**：AI proposes（预填候选）+ human confirms（签字落库）；观察模式是「retrospective review」先行形态——先计量误报/漏报分布再放权；异常态（样本不足、Key 未配）安全默认回退全手工。
- **review-product-plan**：启用前置条件显式（稳定模型通道、本机阈值样本），净收益按「只捕获会话内承诺」子集折算，不拿全量场景主张。
- **ui-ux-pro-max / ux-ui-audit**：预填字段给可编辑输入而非只读文本；错误/拒绝出口（判否丢弃、整条忽略）靠近条目；观察模式与启用模式状态分明。

## 3. 与攻防结论的关系

| 攻防条目 | 终局结论 | 本设计落点 |
|---|---|---|
| B4-K4-01 零录入→精确判真漏报 | 修正：剔除「零录入」「无需人工」宣称，保留判真/归并/签字 | 显式主档节 |
| B4-K4-02 模型噪声/幻觉/术语偏差 | 修正：观察模式计量、本机阈值自定、概率不前置 | 模式切换节 |
| B4-K4-03 第三方承诺造死数据 | 修正：仅留痕/备注、不跟进、不催办、不建观察区 | 待收建议第二条 |
| B4-K4-04 prod Key 不稳 | 前置：Key 未配/样本不足全手工 | 启用前置节 |
| B4-K4-05 只覆盖会话内（H2 下收敛） | 收窄：公司系统/线下承诺归 K3/K18，净收益按子集折算 | 边界登记节 |
| R1 模型响应不稳 | 修补：稳态自检、计数达成前不切启用 | 观察模式默认 |
| R2-B-K4-01 双模式/低置信补档/第三方承诺 | 闭合为现设计 | 三段分区 |
| R3-B-K4-01 观察样本与启用后同一分布 | 局部登记：分布漂移后阈值需重校 | 待补登记 |

## 4. 残留与待补

- E6（本地）：触发成功率、漏报率、单条裁决时长、净减负（手动录入基线对比），由 K12 三计数验证，未达区间不扩大启用。
- 局部登记：阈值随分布漂移重校；噪音条目的「轻判否不计入拒绝」规则口径；观察模式记录落盘位置。

## 5. 定位标注

**推荐组合内（条件性采纳）**：与 K3 互补——K4 管承诺/决议原料，K3 管执行证据原料；均守 C3，人签字/确认为落库唯一出口。
