# K5 会议流三段捕获 · 撤并说明（概念可视化 + 不推荐理由）

> 裁决档位：**撤并**（无独立方向）｜不推荐组合｜证据等级：E5（C7 无常驻、meeting-summarize 现状）+ E4（概念独立性判据）
> 原型：`原型.html`（概念页，非功能原型；三段去向图 + 四条可展开不推荐理由；浅/深两态）

## 1. 撤并判定

按 E4 判据：一个概念只有在不被相邻方向吸收、且自身带机制增量时才独立成立。K5 三段均被相邻方向吸收，独立方向不产生新的 schema、命令或视图，故撤并，不建独立产品形态。

## 2. 三段去向（概念可视化）

| K5 原始段 | 承接方 | 去向说明 |
|---|---|---|
| 会前应读包（开会前自动列应读历史） | **K1 时间触发变体** | 应读快照作为 K1 触发载荷的一种内容形态，不新建独立会前模块 |
| 会后 60s 行动项认领 | **K4 候选箱同一机制** | 与会话结束被动低置信待收建议共用候选箱与签字流，不另设认领窗口 |
| 会中分段 STT 捕获 | **meeting-summarize 输入方式** | 粘贴文本/附件作为现有 summarize 的输入增强，不做独立实时监听 |

## 3. 不推荐独立成立的理由

1. **会中连续监听撞 C7 无常驻约束**（B5-K5-01 / R2-C-K5-01）：宿主无常驻进程、无后台监听，dsh 非会议容器，无日历/会议生命周期感知；「边开边落」需持续在线采集，第一期无承载通道。
2. **FTS5 选译依赖**（B5-K5-02）：会中/会后检索依赖宿主 session-query FTS5 选译属可选依赖，独立方向会把实现复杂度压到本体。
3. **硬时间窗已取消**（R2-C-K5-02）：「散会后 60 秒黄金认领窗口」是独立方向标志性机制，取消后会后认领退化为普通候选箱条目。
4. **三段均被吸收、无机制增量**（E4）：独立 K5 不产生新 schema/命令/视图。

## 4. 采用的专家方法

- **review-product-plan**：以「可核验性 + 非目标可见」检验独立主张，三段均能落到既有机制上，独立方向无可承诺的增量。
- **ui-ux-pro-max**：概念页用去向图（源段 → 承接方）表达归并关系，理由用可展开条目避免信息堆砌，不伪装成交互功能。

## 5. 残留登记

- 局部：现有 meeting-summarize 可继续接受粘贴文本/附件作为输入方式增强，不升级为独立会议流。
- 无独立原型承诺；本页仅作撤并说明供用户决策时查阅。

## 6. 定位标注

**被撤并 / 不推荐组合**：不占用第一期资源；三段原料分别由 K1、K4、现有 summarize 承接。
