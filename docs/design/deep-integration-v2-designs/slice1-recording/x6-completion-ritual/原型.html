X6 完成仪式感

三层触发判据（服务端读字段判定，模型不判定）

触发层由服务端依据完成事件挂载的对象字段确定，模型不做层位判断；默认锚 L1。完成状态在业务时刻已落库，与复盘定稿是两个时点。

层触发条件（读字段）产物是否进定稿流
L0 完成事件未挂接 task done（个人做完一件事，台账无对应条目） 仅记一条成就（纯文本归档），不产草稿 否
L1 · 默认锚 挂接 milestone / deliverable 的 task done 轻量草稿：固定短篇幅、不补材料 否（不进定稿流）
L2 milestone achieved / deliverable accepted 完整草稿 → 补充材料 → 复盘会 → 定稿 是

触发演示：选一个完成事件，看落到哪一层（点击选项后点判定）

L1 轻量草稿样例：句级已核/待核，证据不足留白，绝不编造

草稿明确标注「未定稿」；每句带已核/待核标注，证据不足处留白标注；句级标注同时作为导出闸门的过滤键，待核句不进定稿导出。

L2 定稿流：草稿 → 补充材料 → 复盘会 → 定稿（完成状态早已落库）

进入复盘流程后草稿冻结 TTL；归档稿保留重开路径。业务完成状态在完成时刻已落库，不等定稿；「交付完成必须等复盘」不是用户要求，本设计不做绑定。

S1
完整草稿
自动生成，未定稿
S2
进补充材料
用户补材料，冻结 TTL
S3
正式复盘会
人主持，逐句核
S4
定稿
待核句补齐才导出
时点分离：任务 done（业务完成）在 S1 之前已落库；S4 定稿只产出复盘文本，不回改、不等待业务完成状态。二者互不绑定。

L0 成就记录：纯文本归档，无积分/连胜/动画/徽章

克制仪式：只留一条可回看的文本记录，不做廉价正反馈包装，不改变产品机制。
