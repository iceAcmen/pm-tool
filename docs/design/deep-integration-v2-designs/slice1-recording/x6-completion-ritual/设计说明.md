# X6 完成仪式感 · 设计说明

> 裁决档位：**采纳（克制仪式版，三层触发）**｜推荐组合内（可独立落地，低成本）｜证据等级：E4（完成≠复盘定稿、草稿未定稿）+ E5（deliverable accepted / task done 字段现状）
> 原型：`原型.html`（示例数据；含三层判定交互、L1 留白草稿、L2 定稿流推进、L0 成就归档；浅/深两态）

## 1. 该方案改变了什么

**场景改变**：回应「完成时刻需要被看见」的动机层需求（X6 新类别，D2-N3 原始命中），但以克制文本仪式落地，拒绝积分/连胜/动画/徽章堆砌（反向覆盖游戏化角度 F）。

**结构改变（三层触发，服务端读字段，模型不判定）**：
- **L0**：完成事件未挂接 task done → 仅记一条成就（纯文本归档），不产草稿；
- **L1（默认锚）**：挂接 milestone/deliverable 的 task done → 轻量草稿（固定短篇幅、不补材料、不进定稿流）；
- **L2**：milestone achieved / deliverable accepted → 完整草稿 → 补充材料 → 复盘会 → 定稿流。

**关键边界（用户确认版）**：
- 事件触发自动生成的是**粗糙即时草稿，明确未定稿**；句级「已核/待核」标注，证据不足处**留白标注、不替用户编造**；句级标注作为导出闸门过滤键，待核句不进定稿导出；
- 用户补充材料并开正式复盘会之后才定稿；进入复盘流程冻结 TTL，归档稿保留重开路径；
- **完成 ≠ 复盘定稿**：业务完成状态在完成时刻已落库，S4 定稿只产出复盘文本，二者分处两时点、互不绑定；「交付完成必须等复盘」不是用户要求，本设计不做绑定（F-K20-X6-01 闭合）。

**交互改变**：完成事件选择器 → 服务端判定层位 → 对应产物；L2 流程条逐步推进（草稿→补材料→复盘会→定稿），每步只做文本状态变化，无庆祝动效。

**视觉改变**：三层用 chip 色阶区分（灰/蓝/绿）但不做发光徽章；留白句用斜体灰字「— 证据不足，留白待补 —」；时点分离用固定 callout 钉在 L2 区。

## 2. 采用的专家方法

- **design-human-ai-workflow**：AI 自动生成草稿（propose），定稿权在人主持的复盘会（confirm）；草稿标注不确定性（已核/待核），不把未核内容伪装成事实；冻结 TTL 与重开路径提供恢复手段。
- **review-product-plan**：非目标显式（不绑定完成与定稿、不编造、不游戏化），每条承诺可核验（读字段、句级标注、导出闸门）。
- **ui-ux-pro-max**：克制动效（仅状态切换），不靠颜色 alone 传达层位（同时给文字标签），44px 可点热区。

## 3. 与攻防结论的关系

| 攻防条目 | 终局结论 | 本设计落点 |
|---|---|---|
| F-K20-X6-01 完成绑定复盘 | 关闭：完成状态与定稿分离，不绑定 | 时点分离 callout |
| F-K20-X6-02 自动草稿编造 | 修正：草稿未定稿、句级标注、留白不编造 | L1 草稿样例 |
| F-K20-X6-03 游戏化堆砌 | 反向：无积分/连胜/动效/徽章 | L0 纯文本归档 |
| R2-F-X6-01 三层触发判据 | 闭合：服务端读字段，默认锚 L1 | 判据表 |
| R2-F-X6-02 定稿流闸门 | 闭合：待核句过滤、TTL 冻结、重开路径 | L2 流程条 |

## 4. 残留与待补

- 局部：TTL 冻结时长、归档稿重开入口位置为实现口径；L0 成就记录的检索/回看形态低成本另议。
- E6：无新增定量主张；成就记录是否被回看由 K12 被动计数观察。

## 5. 定位标注

**推荐组合内（采纳，克制版）**：可独立落地、成本低；与 K6 无绑定关系——X6 不做完成评判，只在完成时刻留文本痕迹。
