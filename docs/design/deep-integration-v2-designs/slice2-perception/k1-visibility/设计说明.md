# K1 模型可见性供给面 · 设计说明

> 终局判定：接近饱和（裁判 A 修正采纳·条件性先证消费方；裁判 B 采纳接近饱和形态）。
> 组合定位：**本期核心组合（第 2 位，K12 底座之后）**。
> 原型：`原型.html`（示例数据，未接生产 API；浅深两态可切换）。

## 1. 事实/场景核对（设计前提）

- E5 源码/一手文档事实：宿主 `context` 注入消息以 user 角色进入会话历史，与其他对话内容一样持久保留、可回放、**可压缩（compaction）**——长会话被摘要化后，「常驻注入」承诺自相矛盾（A1-K1-01，致命已闭合）。
- E5：宿主无 fs watcher，文件载体变更不自动重渲染；免费车道 function-calling 不保证（漏调用率 E6 待实测）。
- E4：供给面不产生消费需求，N≈0 即证伪（A1-K1-02 条件性致命；H3「日常跑」解除条件，但消费方仍须 N/M 实测落地）。
- E5：`/pm ...` 命令由人直接触发、不消耗模型轮次；模型侧工具经 `defineTool` 注册、schema 自动进系统提示词。
- 场景（H2/H3）：PM 日常在 dsh 跑 PM agent 会话；真实沟通进展/文档更新不在系统实时更新（H1），模型需要不靠人转述即可读到台账。

## 2. 设计：改变了什么

### 结构（三路线浅耦合，排序即取舍）
1. **poll 按需工具（主路线）**：`pm_board_snapshot` 只读工具，scope=all/active，只返回服务端派生事实（逾期/临期计数与清单），模型不做主题分类。不常驻、不占每轮预算；项目细节缺口由它补位。
2. **文件只读投影（载体）**：台账渲染为工作区 `PROJECTS.md`，经宿主 agent-instructions 装载；**无 watcher，显式命令 `/pm board-export` 刷新**；派生件 gitignore，ledger.json 为唯一 git 真源。
3. **push 全局轻量计数（降级，非常驻）**：撤常驻 push；只载全项目逾期/临期条数，**不做主题门控、不做单项目全文门控**；注入层自去重（替换非追加）。

### 交互
- 会话内调用回显：工具名、scope、耗时、只读标注随消息可见，人可核对模型取数路径。
- 文件刷新为显式动作（按钮/命令），刷新 toast 反馈；不假装自动同步。
- 证伪挂接位：N（被调用次数）/M（被引用台账回合）占位，N≈0 即收。

### 视觉
- 沿用 dsh 语言：Inter 无衬线、mono 承载 ID/计数、1px 发丝线、小圆角卡片、状态色（逾期红 #E5484D 系、临期黄）；浅深两态均真设计（深色换底色板与线色，非反色）。
- push 计数用虚线框区别于主动卡片，表达「这是降级片段，不是通知」。

## 3. 采用的专家方法

- **design-human-ai-workflow**：把「模型取数」归入 AI retrieves（只读检索），责任图上不授予 AI decide/act；上下文契约明确只读、新鲜度靠显式刷新、不注入主题判定。
- **html skill（确定性原型）**：单文件自包含、原生 JS、无僵尸按钮（每个 tab/按钮有 handler）、shot.py 自检。
- **review-product-plan（grounding）**：每条能力标注证据等级 E5/E6，E6 项（锚点开放度、漏调用率、计数范围口径）只登记不写成承诺。

## 4. 与攻防论证的关系

| 攻防条目 | 闭合处置 | 本设计落点 |
|---|---|---|
| A1-K1-01 push 常驻在 compaction 下破产（致命） | 撤常驻，退每轮可重建的全局计数 | push 路线降级为纯计数条 |
| A1-K1-02 供给面不产生消费需求（条件性致命） | 上线即挂 K12 N/M，N≈0 证伪即收 | 证伪挂接位卡片 |
| R2-A-K1-01 主题门控双向误判无信号 | 撤门控，push 只载全局计数 | 计数条「不做分类判定」标注 |
| R2-A-K1-02 重注重复/锚点开放度 | 注入层自去重（替换非追加）；锚点开放度 E6 登记 | 自去重说明；E6 chip |
| R2-A-K1-03 git 噪音/补探被动 | 派生件 gitignore，ledger.json 唯一真源；宿主补探被动登记 | 文件投影 note |

## 5. 残留登记项（局部，不挑战方向）

1. 全局计数项目范围口径（全量 vs 当前工作集）未定义，由 poll 补位。
2. 稳定前缀锚点对插件开放度 E6，待实测，不写进承诺。
3. 免费车道漏调用率 E6，待 K12 长期配对样本。

## 6. 明确不做（non-goals）

- 不做常驻后台注入、不做每轮全量上下文重推、不做模型主题门控、不做单项目全文推送、不伪造文件自动同步。
