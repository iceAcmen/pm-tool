# K10 多 agent 角色组织 · 设计说明（撤并概念页）

> 终局判定：饱和（独立方向撤并；裁判 A/B 撤并确认成立）。
> 组合定位：**撤并不立项**；仅 4 项规则集并入规则视图方向，spawn 作 E6 登记。
> 原型：`原型.html`（撤并去向图 + 4 规则集；示例数据；浅深两态）。

## 1. 事实/场景核对

- E1 源码：`core/health.ts` 仅 L37 单点 milestoneOverdue；`core/reminders.ts` 仅 task/milestone 单点 overdue/due-soon；`core/risk-issue.ts` 无 slaDays 字段（dueDate nullable、updatedAt、status 三态）。
- E1：宿主无常驻副驾载体（C7 禁常驻后台）；单人空台账无第二被考核人。
- E2：多角色独立性来自独立信息集，四角色同读一份台账不构成独立。
- E4：独立方向需不可被相邻方向吸收的机制，K10 不满足。

## 2. 设计：撤并页如何呈现

### 结构
- **撤并去向图**：K10 独立方向（虚线消亡盒）→ 规则视图方向（纯函数扫描承载）；常驻班底/副驾/三独立稿/考核/预埋以删除线标签列出，表达已撤回。
- **4 项留存规则集**（纯函数，无 agent 常驻）：
  1. 里程碑偏差趋势（现有单点不判趋势）；
  2. 风险超期 SLA 未处理（缺 slaDays，借 dueDate/updatedAt 近似或补字段，L-K10-01）；
  3. 跨周期承诺未闭环；
  4. 已完成但缺证据。
- **spawn 可选**：虚线 E6 登记，接 K3 外部证据后才有第二信息源，不写成功能承诺。

### 视觉
- 消亡盒虚线+删除线；留存规则集实线卡片；每条标注「现有派生为何不覆盖」的 E1 依据，避免重复建设。

## 3. 采用的专家方法

- **review-product-plan（撤并可见性）**：撤并不等于删除记录，去向、残留、登记项全部显性列出。
- **ux-ui-audit（证据分级）**：E1 源码核验逐条对应规则集增量，不把灵感当功能。

## 4. 与攻防论证的关系

| 攻防条目 | 闭合处置 |
|---|---|
| C-K10-01 无常驻载体（致命） | 放弃常驻班底/副驾，撤并 |
| C-K10-02 单人无对象+同读一表（致命） | 放弃考核/三独立稿；独立方向消亡 |
| R2-C-K10-02 巡检与 health/reminders 重叠 | 仅留 4 项源码确认不覆盖的新规则集 |
| R2-C-K10-03 spawn 无信息独立 | E6 登记 N/M/命中率，接 K3 后再议 |

## 5. 残留登记项

1. L-K10-01：风险 SLA 缺 slaDays，实现时近似或补字段。
2. L-K10-02：spawn 净增益 E6 待 K12。
3. 归属措辞待收敛：规则集并入规则引擎/规则视图方向（非 K8 本体），拍板清单第 8 条。

## 6. 明确不做

- 不建常驻 PMO 班底、常驻副驾、考核 agent、三独立稿；不把低频 spawn 写成当期功能。
