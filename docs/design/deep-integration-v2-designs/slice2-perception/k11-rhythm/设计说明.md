# K11 节奏、沉默与噪音治理 · 设计说明

> 终局判定：接近饱和（裁判 A 条件性采纳·仅呈现层；裁判 B 修正采纳·H6 显式剥离悬置）。
> 组合定位：**第 2 层呈现与降噪核心**；H6 主动触达 leg 悬置待拍板。
> 原型：`原型.html`（补记队列 Top1+折叠、二态 mute、豁免、H6 告示；示例数据；浅深两态）。

## 1. 事实/场景核对

- E3：宿主 `schedule` README——到期提醒作为普通 follow-up 消息进入原对话，**不是邮件/短信/推送通知**；宿主无外部通知渠道，逾期只发最新一次、错过不补发。
- C7：不引入常驻后台进程/系统推送（阶段0 已裁决，未被 H 解除）。
- E1/E2：Cascading Bandits 自适应降频适用多用户高投递量，单人个位数样本 regime 不匹配；Wilson 区间 n=10 采纳 3 次 95% 区间约 10.8%–60.3%，点估计无判别力。
- H6：常驻推送是真实痛点，但主动触达不由 K11 承担。

## 2. 设计：改变了什么

### 结构（全部作用于「到达后 / 打开时」，不依赖主动通道）
1. **读时派生主轴**：本次打开补齐自上次打开以来到期未达条目（补记窗口），不承诺实时到达；schedule 仅可选辅助，错过不补发。
2. **补记队列三件套**：
   - 排序键：严重度（逾期 > 临期）优先，同级按到期时间升序；
   - 迟到标识：每条标「积压 N 天」，区分条目紧迫性与积压时长；
   - 首屏 Top1 + 其余 N 条折叠露出。
3. **二态静音 mute/all**：mute 压主动投递、**不隐藏打开视图**；关键项豁免与 high opt-in 复用同一份登记表，mute 期打开仍可见豁免项。
4. **配额/TTL + high opt-in 登记**：控制建议积压，关键项单独登记。
5. **H6 主动触达悬置告示**：界面诚实标注「主动触达悬置待宿主能力」，不做红点/常驻弹窗假象。

### 交互
- mute 开关切换仅改变投递状态文案，队列保持可见（演示「不隐藏」）；
- 折叠/展开 Top1 之外条目；豁免标签点按切换。

### 视觉
- H6 悬置用虚线告示条置于顶部，与可用功能明确分区；Top1 用逾期色描边突出，折叠条中性灰；无徽章堆砌、无动效。

## 3. 采用的专家方法

- **design-human-ai-workflow（异常与缺席处理）**：把「忙/在公司系统/忘」记为缺席而非拒绝，不据此自动降频；静音是用户显式二态，不是系统猜测。
- **ux-ui-audit（证据分级）**：自适应降频因单人样本不匹配而外置，不写成默认功能。
- **html skill**：折叠/开关真实状态机。

## 4. 与攻防论证的关系

| 攻防条目 | 闭合处置 |
|---|---|
| R2-D-K11-01 积压无排序键/迟到标识/首屏上限（局部） | 严重度+到期排序、积压 N 天、Top1+折叠 |

## 5. 残留登记项

- H6 主动触达悬置为宿主级通知能力（外部依赖，非 K11 内部缺陷）；归属里程碑与负责主体待用户拍板（拍板清单第 2 条）。

## 6. 明确不做

- 不做系统推送/常驻弹窗/到点必达承诺；不做自适应降频默认启用；不隐藏 mute 期打开视图；不替 H6 痛点宣称已解决。
