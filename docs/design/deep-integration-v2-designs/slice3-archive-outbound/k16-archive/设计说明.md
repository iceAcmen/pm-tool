# K16 档案长寿与数据契约 · 设计说明

## 终局定位
- **台账判定**：饱和（最小保存包）；裁判 A「采纳（最小保存包：通用语法 + 语义字典 + 结项一次性 PDF/A；撤迁移器）」；裁判 B「采纳」。
- **推荐档位**：**核心层（纳入本期最小交付）**；与 K14 格式层作为单一单元合并计分。

## 设计前提
- 事实（E1 本机）：备份为人类可读 JSON + manifest（`core/backup.ts`）；现状 export 仅 Markdown/JSON；无 PDF/A 管线。
- 用户假设（H9）：2 年 API 稳定为预期非保证——长寿设计不得把上游稳定当既成事实。
- 攻防事实（R2-D-K16-01，E1/E2）：裸人类可读 JSON 不保证十年可读——编码演进、字段漂移、语义丢失、查看器缺失；长寿靠契约不靠裸文件。
- 攻防事实（R2-D-K16-02，E1）：当前无确定性离线作者管线，在线生成的 PDF 不可复现；PDF/A 只承诺成品留档。

## 改变点
1. **真源单一化**：活库人类可读 JSON 是唯一可计算真源；固化切片只承载结项静态叙述，不保留实体关系、不参与计算（双轨计算被拒）。
2. **通用语法契约**：JSON / RFC 8259，无专有依赖；不维护迁移器、不做周期再固化、不建格式版本号与双轨。
3. **语义字典构建期对账**：schema 字段/枚举与随数据落盘的语义字典在构建期最小比对；漂移在构建期报错（演示态：新增枚举 `accepted` 未覆盖即构建失败），零运行时成本，不累积到十年后。
4. **结项一次性 PDF/A**：项目结项时一次性生成静态叙述，字体内嵌自包含，标注「结项时刻切片、不再刷新」；明示不承诺可复现/可再生成。
5. 十年档案浏览为只读结项切片时间线，活库视图不被冻结。

## 采用的专家方法
- product-design §4 状态与失败路径：把「漂移」建成构建期失败态（报错框 + 阻断构建），而非运行时静默。
- ux-ui-audit 证据纪律：E1 现状能力与 R2 核验事实分栏；可复现能力标 unknown，不写承诺。
- design-human-ai-workflow：对账由构建器确定性执行，人只在报错时补字典条目；成品生成由人在结项时点触发。
- 视觉：档案区用时间线（grid 三列、圆点 0px 对齐）承载结项切片；对账表用固定列宽；浅深 token 独立。

## 与攻防结论的关系
- R2-D-K16-01（裸 JSON 浪漫错觉）：由「通用语法 + 语义字典 + 构建期对账」闭合，迁移器被撤。
- R2-D-K16-02（可复现管线不成立）：由「一次性成品 + 不承诺可复现」边界声明闭合。
- 撤回项：格式版本号、周期再固化、双轨计算、可复现管线、独立离线 viewer（由 K14 登记件承载）。

## 验证结果（shot.py 实测）
- 浅态 desktop/mobile pass（blocker0/error0）；深色态 pass；对账通过表、漂移报错态（页内 tab 切换）、结项时间线、一次性成品边界声明渲染正常。
- 修复记录：移动端对账表初版四列挤撞 → 改为横向滚动容器（dsh 单行横滚），min-width 560px，复验 pass。
- 评审 L2 修复（2026-10-18）：横滚容器首屏右侧列被切且无滚动提示 → 窄屏（<640px）在表上方加「字段较多，可左右滑动查看完整对账表」提示行，容器右侧加 26px 发丝渐隐（fade 到面板底色 var(--surface)，不遮挡文字）；桌面 ≥640px 不显示提示与渐隐。浅态 desktop/mobile + 深色 desktop 复验 pass（blocker0/error0/warning0，findings 0）。
- 漂移报错态、结项时间线窄屏对齐、无外部资源、示例数据标注虚构，均已核对。
