# K17 平台终局三姿态 · 设计说明

## 终局定位
- **台账判定**：附注（吞并两端落空；退出依附 K14/K16；冻结为被动默认）；裁判 A「附注（E6 触发器悬空）」；裁判 B「附注（依附 K14/K16，无独立交付）」。
- **推荐档位**：**附注层**——只在路线图/说明中记录立场关系，不产生独立 schema、视图、命令、切换界面。

## 设计前提
- 事实（E1/E2）：product/11 协作契约「域接口是唯一边界，换后端零改动」反对内化 agent runtime 的吞并方向。
- 事实（E5/H9）：用户有意留在 dsh，2 年 API 稳定为预期非保证。
- E6 悬空：dsh 原生长出 PM 能力的触发信号、被动修补预算阈值，均无数据，不写数值。

## 改变点
1. 三姿态概念卡片：吞并（内化/被替代两端均落空，标不采纳）、退出（条件性，机制全部由 K16/K14 承载）、冻结（被动默认，无主动动作，E6 悬空）。
2. 当前立场条：明确「留在 dsh 融合使用（H9）」，三姿态是未来讨论框架而非今天可点选项。
3. 依附关系陈列：数据可移植→K16；脱离核对→K14；触发信号共用 K14，防止被误读为新建切换界面。

## 采用的专家方法
- review-product-plan：非目标显式化（不建切换界面、不写触发阈值）。
- ux-ui-audit：E6 悬空项只登记不量化；吞并落空两侧分别给证据，不单凭倾向否定。
- 视觉：三栏概念卡，非采纳卡降透明度但不删除（保留历史主张可见性）。

## 与攻防结论的关系
- R2-E-K17-01（吞并两端落空：内化违反契约、被替代触发信号不存在）：卡片标「两端落空·不采纳」。
- R2-E-K17-02（退出依附 K14/K16，独立退出协议=重复造轮子）：由依附关系陈列闭合。
- E6：触发器悬空标注，未填数值。
