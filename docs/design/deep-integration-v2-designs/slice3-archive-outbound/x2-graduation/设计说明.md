# X2 毕业导向 · 设计说明

## 终局定位
- **台账判定**：条件性采纳；裁判 A「条件性采纳（人工声明+洁净度+失效规则；取消零干预 KPI）」；裁判 B「条件性采纳（人工声明+洁净度标签+失效规则；取消零干预）」。
- **推荐档位**：**附加层**——轻量标签与声明动作，不建成功度量引擎。

## 设计前提
- 原始主张（D1-N1）：以「用户连续 N 周无需打开/项目可毕业」为成功 KPI，主动建议自身退场。
- 攻防修正（R2-E/F-X2）：零干预自动 KPI 不可行——「未打开」可能是搁置/遗忘而非成功，自动判定会误报；取消完全零干预，保留低强度召回。
- 事实（E1）：现状项目仅 archived 状态，无毕业概念。

## 改变点
1. **人工声明毕业**：归档视图中由人手动触发，弹层内逐条勾选洁净度清单（无未完成项 / 无回潮承诺 / 无悬挂风险），全勾才可确认；系统不代判。
2. **洁净度标签**：声明后项目挂「已声明毕业 · 洁净度标签」。
3. **失效规则**：之后出现未完成项或回潮承诺，标签自动失效摘标，回到普通归档态。
4. **取消零干预**：不统计连续未打开周数、不自动毕业；保留低强度召回（年度回顾可见）。

## 采用的专家方法
- design-human-ai-workflow 责任分配：毕业判断=human only，系统只做状态记录与失效提醒，不把「未使用」推断为「成功」。
- ux-ui-audit 失败/误报路径：自动 KPI 的误报（搁置被当成功）作为被拒方案显式写出。
- 交互：确认门（清单全勾才解锁确认按钮）、弹层点遮罩关闭，满足可取消路径。

## 与攻防结论的关系
- 取消项：连续 N 周未打开成功 KPI、自动毕业判定、完全零干预消失。
- 保留项：人工声明、洁净度标签、失效规则、低强度召回。
