概念可视化：该方向若立项，会呈现为一套「主动保护」控件

以下为概念推演，用于让决策者看见「独立方向」原本主张的完整形态；它不是当前产品已具备的功能，也不代表推荐立项。

概念推演框 · 六件主张过的保护控件

WIP 硬上限闸

在途任务超过阈值 N 时，新条目录入被拦截。

拒单闸

在录入口拦截新承诺，代用户说「这个先不接」。

非工作时间静默

夜间 / 周末不推送提示。已并入 K11。

留白配额

每周预留无承诺时段，工具主动腾空日历。

负荷体检

陈列在途数、改期次数、深夜/周末编辑记录。

合法烂尾两列

把可体面终止与应继续的项目分两列收纳。

致命缺口：闸门装在下游，拦截不到上游的承诺

WIP 硬上限与拒单闸的拦截对象是「正在形成的承诺」，但本工具无入站请求通道，承诺在公司系统（飞书项目 / Jira）内形成后才被录入。录入口闸门位于因果链下游。

上游 · 公司系统（H2）
承诺在这里形成
协作方提出、会议口头认领、邮件答应——本工具看不到。
→
下游 · 本工具录入口
闸门只能拦已录入条目
此时承诺已成立，拦得住记录、拦不住接单。

降级后存活的唯一形态：纯事实陈列（无触发、无裁决）

撤除独立方向后，剩余内容只是把已有事实摆出来。它不设阈值、不下「过载」结论、不主动提醒，被忽略即结束。

在途条目数 12（todo 4 · in_progress 8 · blocked 3，示例） 只读计数 · 无阈值
改期次数（近 30 天） 5 次（示例，逐条可点开） 只读事实 · 无警告
深夜 / 周末编辑记录 工作日 22:00 后 3 次 · 周末 2 次（示例） 只读事实 · 不贴健康标签
本陈列不含触发判定：没有阈值线、没有「过载」文案、没有主动弹窗；与现有 people-load 聚合、health 派生、progress 陈列同用途，不新增计算原语。

红线（用户确认版）：当前形态仅纯事实陈列，无触发阈值、不宣称过载警告，不虚构「智能提醒保护」。带宽锚、漏标率、本人接受度三项为 E6 待用户数据，不构成独立方向存续理由。

不推荐独立立项的理由（引用台账致命/显著攻击）

F19-K19-01 · 致命（当前阶段）

WIP 硬上限 / 拒单闸执行不到因果节点

无入站请求通道、承诺在上游形成，闸门装在台账录入口；降级为「对已录入条目建议砍/缓」后退化为 K8 组合取舍的保护面文案变体。

R2-F-K19-01 · 显著

相对负载提示无个人带宽锚

撤回绝对 N 后改「相对近期在途量偏离」，慢性过载下基线长期偏高，相对值不指向保护触发；无个人带宽历史校准，触发含义失效。

R2-F-K19-02 · 局部

等待项剔除依赖人主动标 blocked，漏标即绕过

task 状态枚举仅 todo / in_progress / blocked / done，无独立 waiting；等待关系在公司系统，工具无法自动识别，剔除规则无兜底。

R2-F-K19-03 · 局部

合法烂尾列与 paused / archived 构成第三套停滞语义

project 已有 paused（已暂停）、archived（已归档）两个停滞态；烂尾列应收敛为其上面的视图过滤标签，非新收纳位。

剩余组件去向（撤除名分后不散失）

原组件终局形态去向
负载纯事实陈列在途数 / 改期次数 / 深夜周末编辑记录，只读无阈值并入现有陈列层（people-load / health / progress）
台账内可见事实提示（劝停改）无触发、无裁决、被忽略即结束陈列层静态文案，不独立成机制

保留项：立场留原则，不留名分

撤除的是「独立方向名分」，不是「保护人」价值取向——5 名发散者独立趋同。该立场作为全局设计原则贯穿 K8（组合取舍：允许缓/砍/休眠）与 K11（沉默：到达后安静呈现）的陈列层，不单独建实体、不建触发。
