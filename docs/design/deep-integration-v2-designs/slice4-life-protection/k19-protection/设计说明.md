## 二、改变点（本页相对现状给出的是什么）

1. **概念可视化**：把「若立项会怎样」的六件主张控件（WIP 硬上限闸、拒单闸、非工作时间静默、留白配额、负荷体检、合法烂尾两列）画成一张可对照的概念板，并用一条上下游因果链标出致命错位——承诺在公司系统形成（上游），闸门装在工具录入口（下游）。
2. **降级存活形态单独成页**：只展示撤除后唯一站得住的「纯事实陈列」（在途数 / 改期次数 / 深夜周末编辑记录），明确无阈值线、无「过载」文案、无主动弹窗，被忽略即结束。
3. **去向映射表**：四件剩余组件逐一落到现有陈列层 / K11 / paused·archived 标签，说明撤除名分后内容不散失。
4. **立场与名分分离**：「保护人」价值取向（5 人独立趋同）保留为贯穿 K8/K11 的全局设计原则，不保留独立方向实体。

## 三、关键界面与状态（浅深两态均真设计）

- 三页签：概念推演 / 降级存活形态 / 不推荐理由与去向，切换有真实 handler。
- 浅深双主题：CSS 变量双套 token（浅色 `#fff` 画布 / `#f5f6f7` 表面-2；深色 `#17191d` 画布 / `#26292f` 表面-2），红/绿/蓝语义色在两套明度下分别调过，非简单反色。
- 概念控件用虚线框标注「概念推演，非当前功能」，与存活事实卡的实线框视觉区分。

## 四、采用的专家方法

- **design-human-ai-workflow · Autonomy must match uncertainty / control point**：闸门属于「AI acts within limits」类强控制，但控制点必须位于因果链上游；本工具无入站通道，控制点错位即控制失效——据此判定 WIP 闸/拒单闸不成立，而非弱化文案后保留。
- **review-product-plan · Non-goals / blocking defect 分离**：把致命缺陷（F19-K19-01）与可存活的事实陈列分开展示，不把「有剩余价值」误读为「方向成立」。
- **ui-ux-pro-max · 语义色与对比度**：危险色仅用于致命标记，不滥用；事实陈列一律中性灰，不制造告警感（对应红线：不虚构智能提醒保护）。

## 五、与攻防论证结论的关系
