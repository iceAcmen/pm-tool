## 二、改变点（相对现状给出什么）

1. **死因卡双栏归因**：第一栏原始材料锚点（当时承诺快照 + 证据指针），归因拆「个人可改进（下次可规避）」/「外部原因（仅背景）」两栏，对抗自利偏差（Miller & Ross 1977）。
2. **锚点空缺留白态**：锚点缺失时只存外部事实（项目名/终止日期/终止方式），双栏整体关闭，不渲染空输入框、不催填。
3. **一句话快照撬点**：启动期低摩擦采集（一句话即可存档），完整四字段延迟补填，化解「达标前自愿记录冷启动环」（R2-F-X3-02）。
4. **检索栏位隔离**：新立项前检索默认只返回个人可改进栏，外部原因折叠为背景（R2-F-X3-03）。
5. **中性归档**：删除「止损为荣」荣誉叙事，也不做失败耻辱墙；墓地墙入二级页，不阻断新项目立项。

## 三、关键界面与状态（浅深两态）

- 四个页签：有锚点卡 / 无锚点留白 / 一句话撬点 / 检索结果，均有真实 handler。
- 有锚态：锚点引用块 + 双栏网格（窄屏堆叠）；无锚态：锚点栏灰显 + 归因区整体留白占位。
- 撬点：textarea + 存档/清空，存档结果本地反馈，不写库。
- 检索：确定性词面子串匹配（非伪语义），结果只渲染可改进栏，外部栏用 `<details>` 折叠。
- 浅深双套 token，非反色。

## 四、采用的专家方法

- **design-human-ai-workflow · evidence cues / system must never infer**：锚点是归因的唯一证据来源，无证据时系统不得代填主观死因——结构上关闭自填通道，而非靠提示语约束。
- **ux-ui-audit · observed / inferred / unknown 分离**：外部事实（可核验）与主观归因（推断）分区陈列，unknown（锚点缺失）显式留白，不把推断当观察。
- **ui-ux-pro-max · progressive disclosure**：外部原因栏默认折叠，避免检索层把不可控事件稀释成可规避教训。
