# PM 工作台 · 前瞻设计方案（Forward Design Proposal）

> 主题：**冷静的指挥台（Calm Command Deck）**
> 日期：2026-10-17 ｜ 依据：全页面走查报告 `docs/verification/full-regression-20261017/walkthrough-report.md`（S1×1 / S2×5 / S3×8 / Opportunity×5）

> 适用形态：dsh 宿主内的桌面优先 Web 插件；浅 / 深两套主题同时成立；窄窗（≤560，含 390×844）可用。

## 1. 背景与目标

### 1.1 起点：走查总体诊断（来自报告 §2）

1. **桌面态已整体成熟**：9 个历史反馈问题全部消除或通过，浅 / 深两套视觉成立、设计感在线；剩余缺陷集中在窄窗（≤560 / 390）响应式——任务表标题列塌缩为 0px 是唯一 S1。
2. **「派生口径」两处不一致**：里程碑概览统计与卡片延期判定不同源（S2-2）；会议过滤后右侧详情不随过滤收敛（S2-4）。这是状态 / 数据作用域问题，会直接误导健康判断，不是视觉问题。
3. **视觉体系残留两套「主按钮」token**（视图页蓝 CTA vs 抽屉 / 看板中性黑白），叠加浅色次要文字对比度不足（muted 3.71:1、faint 2.13:1），属 System 级一致性漂移。

### 1.2 本方案要解决的三层问题

| 层 | 现状 | 本方案目标 |
|---|---|---|
| **止血（P0）** | 1 个阻断（S1）+ 5 个中等（S2）+ 关键 S3，改动小、杠杆高 | 用最小代码修复阻断与误导项，同时沉淀可复用规范 |
| **成型（P1）** | 组件各自为战、移动只有横滑、表单校验双轨、AI 在独立抽屉 | 把修复沉淀为正式组件契约与移动卡片模式，高保真设计图先行 |
| **前瞻（P2）** | 9 视图平铺为标签、无总览驾驶舱、无视图保存 / 分享、AI 无溯源 | 给出 IA 重构、token 2.0、高级分析与 AI 治理的设计图，不承诺本期落地 |

### 1.3 设计目标（可检验）

- **G1 主任务不被阻断**：390 下可辨认并打开任意任务；任意过滤条件下看到的详情与条件一致。
- **G2 口径唯一**：健康度、延期、逾期、关键路径、完成率在概览、卡片、看板、汇报中数值一致，单一规则层产出。
- **G3 主操作统一**：全产品只有一个主按钮语义（中性 primary），蓝色 / 绿色只作语义强调；浅色次要文字 ≥4.5:1。
- **G4 密度为专家服务**：桌面保留高效信息密度，窄窗换卡片式重排而非简单横滑；卡片高度贴合内容，拒绝空荡、拒绝贴边。
- **G5 AI 可信**：AI 内容与人工 / 已验证内容可区分，写操作一律草稿 → 确认 → 可撤销。

### 1.4 必须保护的既有优点（走查 §6，改动中不得回退）

- 甘特依赖三态路由（tight 凹形 / overlap U 折返 / gap0 小肘）清晰无歧义；关键路径只读派生、缺日期诚实降级并显式提示跳过。
- 抽屉反馈链完整：受控内联错误 + 原生必填 + 保存成功 Notice 带回写 payload，出错后保留输入。
- 空态诚实：不伪装零值、给下一步 CTA；AI「草稿需确认才入库 / 只读诊断·确认后执行」的控制文案与风险提示保留。
- 深色态成立：表面 / 语义色一致、次要文字对比反优于浅色，重设计不得回退。

## 2. 设计愿景

### 2.1 一句话主题

> **冷静的指挥台（Calm Command Deck）**：专家型 PM 在一块安静的面板上扫视全局、定位异常、精确行动——界面退到数据之后，颜色只用来报状态，不用来喊口号。

### 2.2 签名级元素（Signature）

只保留一个可被一眼认出的签名，不堆装饰：

1. **「状态灯环 + 单行结论」**：项目概览健康环（`ov-ring`，内联 SVG，环色由 `data-lamp` 映射 `--ov-lamp`）是全产品的视觉锚点；环内分数 + 一行 `健康 / 关注 / 风险` 结论，环外不做渐变、不做光晕（现网 `--glow-*: none` 已落实，继续保持）。
2. **「细描边、平表面、无投影堆叠」的扁平卡片**：dsh-flat 语言（`--surface` 三级 + `1px --line` 描边 + `--shadow-1` 仅用于悬浮 / 弹层），卡片靠留白与描边分区，不靠重阴影分层。
3. **「tabular-nums 数据行」**：全壳已开 `font-feature-settings:'tnum' 1`，所有日期 / 进度 / 计数右对齐等宽，扫视时纵向成列（甘特轴、汇报快照条、统计卡、人员负载条沿用）。

### 2.3 要避免的俗套（显式负面清单）

- ❌ 不使用品牌蓝做大面积主 CTA 或品牌渐变；不新增品牌色，不出现偏黄 / 暖黄（走查历史 #4 已 grep 0 命中，继续保持）。
- ❌ 不用渐变背景、玻璃拟态、彩色光晕、3D 仪表、装饰性大数字动画。
- ❌ 不把每个指标都做成卡片 / 圆环；一句话或紧凑表格能说清的，不强行图表（dashboard-redesign §2：先决策后控件）。
- ❌ 不靠 hover 暴露关键信息或关键操作（visual-craft：Do not rely on hover for values/actions）。
- ❌ 不用颜色单独承载状态：红 / 绿 / 蓝必须配合文字标签、图标或形状（非颜色信号，见 §10）。
- ❌ 不为「高级感」放大标题或铺满留白；专家工具的高级感来自对齐、口径一致与克制，不是字号。

## 3. 设计原则（5–7 条，每条可检验）

| # | 原则 | 可检验标准（怎么做算符合） |
|---|---|---|
| **P1 一个口径，处处同源** | 所有派生值（健康分 / 延期 / 逾期 / 完成率 / 关键路径）由唯一规则层计算，UI 只渲染不二次推导 | 同一项目在概览、任务表、甘特、看板、汇报里的「已延期 / 已完成 / 逾期」数值逐字相等；代码中不存在第二份 `isMissed` / `isOverdue` 谓词 |
| **P2 一个主操作** | 全产品主 CTA 只有中性 primary 一种；蓝 = 进行 / 链接 / 选中，绿 = 完成，琥珀 = 阻塞 / 临期，红 = 逾期 / 危险，均为语义色 | 任意视图页头主按钮取色 = `--dsw-alias-button-primary-fill`；grep 不到视图 CTA 直接 `background: var(--c-prog)` |
| **P3 卡片贴合内容** | 卡片高度由内容决定，容器不 stretch 拉高；空卡给去向而非占位 | 单行内容的卡片不出现 75px 等高拉伸；空卡要么引导 CTA，要么折叠 / 被邻卡补位 |
| **P4 先决策，后表示** | 每个区域回答一个 PM 决策（哪条要干预 / 是否延期 / 谁过载）；不支撑决策的数据降级或移除 | 逐区追问「这回答哪个决策」，答不上的区域降级为元信息或删除 |
| **P5 密度为专家，断点为内容** | 桌面保留紧凑行高与多列；≤560 按内容改为卡片堆叠，不靠横向滚动暴露身份列 | 390 下任务标题完整可读、无列叠印；折叠 / 堆叠 / 保留规则在 §9 表中逐视图写明 |
| **P6 颜色报状态，文字下结论** | 语义色只标状态，结论由文字 / 标签给出；次要文字永远可读 | 浅色 muted/faint 实测 ≥4.5:1；仅靠红绿无法区分的状态都带文字 chip |
| **P7 AI 先草稿后落库，可区分可撤销** | AI 产出带来源标记，写操作草稿卡 → 显式确认 → 可撤销；人工已验证内容不带 AI 标记 | 每张 AI 草稿卡有「AI 生成 · 待确认」标记、确认按钮、失败 / 撤销路径；落库内容可回溯来源 |

## 4. 信息架构（IA）

### 4.1 现状结构（as-is）

```
dsh 宿主
└─ PM 工作台（.pm-shell）
   ├─ 顶栏 .pm-topbar
   │   ├─ 项目切换器 .pm-project-switcher（下拉，仅名称 + ✓，S3-5 同名未消歧）
   │   ├─ [总览看板] 按钮 → BoardBento 全屏 overlay
   │   └─ [新建项目] [AI 助手] [AI 副驾] [更多] [刷新]
   ├─ 视图标签条 .pm-view-tabs（9 个 tab 平铺：
   │   全部任务 / 里程碑 / 风险与问题 / 会议纪要 / 进度汇报 / 交付物 / 项目概览 / 甘特排期 / 人员负载）
   └─ 视图区 + 右侧抽屉（task / milestone / risk / deliverable / meeting / report / project / ai / copilot）
```

问题：9 个同级标签平铺，无「先总览后执行」的层次；总览看板是独立 overlay 而非入口；AI 助手 / 副驾是两个并列抽屉，与上下文脱节。

### 4.2 目标层级（to-be，P2 驾驶舱方向，P0/P1 不改变导航骨架）

```
L0 跨项目指挥台（总览看板 BoardBento，升级为默认落点）
    │  决策：哪个项目需要我先看？（异常优先：逾期 / 高风险 / 过载 / 临期里程碑）
    ▼ drill-down（保留作用域，返回不丢过滤）
L1 项目概览 overview（单项目健康结论 + 元信息 + KPI + 阶段 / 负载）
    │
    ├── 计划与排期组（A 组）
    │     ├─ 全部任务 tasks（执行队列，主工作区）
    │     ├─ 甘特排期 gantt（时间视角，依赖 / 关键路径）
    │     ├─ 里程碑 milestones（交付节点）
    │     ├─ 风险与问题 risk-issues（登记与闭环）
    │     └─ 人员负载 people（谁过载 / 谁闲置）
    │
    └── 协作与记录组（B 组）
          ├─ 会议纪要 meetings（决策 / 行动项闭环）
          ├─ 进度汇报 reports（周期沉淀）
          └─ 交付物 deliverables（产出物验收）

横切层（不占主导航）：
├─ 抽屉：记录级编辑（CRUD），从任意视图 drill 进入，Esc / 外部点击关闭，返回保留列表状态
└─ AI 层：从独立抽屉 → 内嵌建议层（P1 方向 / P2 成型），附着在当前上下文旁，不另起房间
```

### 4.3 IA 设计规则

- **阅读顺序**（dashboard-redesign §3）：scope 与数据状态 → 需要关注的异常 → 核心结论与对比 → 成因 / 维度 → 记录与行动。总览看板按此重排：顶部「需要关注」区优先于纯统计。
- **控制贴近数据**：过滤 / 粒度 / 密度控件放在它影响的区域附近（甘特粒度在甘特工具条、任务过滤在任务工具条），全局过滤（项目切换）留在顶栏。
- **drill-down 契约**：概览 → 列表 → 抽屉，每一步保留过滤条件、选中态与滚动位置；返回原位，不重置（S2-4 的根因即选中态未随作用域收敛）。
- **导航分组**：P2 左导航把 9 视图归为「计划排期 / 协作记录」两组，组间用细分隔线；当前 P0/P1 阶段先在标签条上用分组间距 + 分组小字 eyebrow 过渡（不强行改骨架）。

## 5. 视觉体系（token 规范，浅 / 深两套值）

> 约定：现网 token 分两层——旧语义层 `--pm-*`（panel.css :root，消费 `--dsw-*` 宿主别名）与 dsh-flat 层 `--*`（`.pm-shell`，被新视图消费）。本方案**不推翻两层**，只补语义角色、修对比度、统一主按钮，并在 P2 收敛为 token 2.0 单层。
> 标注：**沿用** = 保留现值；**改值** = 调整 fallback（宿主别名仍优先）；**新增** = 目前缺失需补。

### 5.1 色彩语义角色

#### 5.1.1 表面（Surface 三级）

| 角色 | token | 浅色值（fallback） | 深色值（fallback） | 状态 | 用途 / 依据 |
|---|---|---|---|---|---|
| 画布（最底层） | `--bg` / `--pm-canvas` | `#ffffff`（沿用 `--dsw-alias-bg-base`） | 宿主深色底（现网 ride alias，不硬编码） | 沿用 | 页面最底，视图区底色 |
| 表面 1（卡片 / 弹层） | `--surface` / `--pm-surface` | `#ffffff` | 宿主 layer-1 | 沿用 | 卡片、抽屉、下拉、输入框底 |
| 表面 2（凹陷 / 字段 / 悬浮 track） | `--surface-2` / `--bg-elev` / `--field-bg` | `#f5f6f7` | `rgba(255,255,255,0.06)`（现网深色已覆盖） | 沿用 | 输入框底、分段控件底、进度 track、斑马凹陷 |
| 表面 3（选中 / 按压） | `--surface-3` | `#edeef2` | 宿主 layer-3 | 沿用 | 分段控件选中、chip 按压、hover 强化 |
| 悬浮底 | `--pm-hover` | `rgba(0,0,0,0.04)` | 宿主 interactive-hover | 沿用 | 行 hover、按钮 hover，不叠加在 surface-3 上 |

#### 5.1.2 文字（Ink / Muted / Faint）

| 角色 | token | 浅色现值 → 建议值 | 浅色实测对比（白底 / `#f5f6f7`） | 深色建议 fallback | 状态 | 依据 |
|---|---|---|---|---|---|---|
| 主文字 | `--ink` / `--pm-ink` | `#1c1c1e`（沿用） | — | 宿主 label-primary | 沿用 | 标题、正文、数据 |
| 次文字 | `--ink-2` / `--pm-secondary` | `#61666b`（沿用） | 5.80 / 5.36 ✓ | 宿主 label-secondary | 沿用 | 正文补充、列值 |
| 弱化文字 | `--muted` / `--pm-muted` | `#81858c` → **`#696e74`（rgb 105,110,116）** | 现 3.71 ✗ → 改后 5.14 / 4.75 ✓ | `rgb(155,158,163)`（6.55/5.56） | **改值** | S2-3：12–13px 辅助信息（gantt-sub / pt-sub / ms-dt / pp-sub / placeholder）必须 ≥4.5 |
| 最弱说明 | `--faint` | `#adb2b8` → **`#71767c`（rgb 113,118,124）** | 现 2.13 ✗ → 改后 4.58 ✓（白底） | `rgb(140,143,148)`（5.42/4.60） | **改值** | 10–11px 统计标签 / eyebrow；**仅用于白底 surface**，落在 `--surface-2` 字段上时改用 `--muted`（该处实测 4.23，不达 AA） |

> 实施注：浅色在 `.pm-shell`（非 `body[data-ds-dark-theme]`）显式覆盖 `--muted/--faint` fallback；宿主别名仍优先，若宿主别名本身不达 AA，以本方案 fallback 为准并回写宿主别名诉求。深色不回退（现网 8.54/4.24/4.92 已通过或临界）。

#### 5.1.3 描边（Line）

| 角色 | token | 浅色 | 深色 | 状态 | 用途 |
|---|---|---|---|---|---|
| 主分隔线 | `--line` / `--pm-line` | `rgba(0,0,0,0.10)` | 宿主 border-l2 | 沿用 | 卡片边、表格行线、抽屉边界 |
| 次分隔线 | `--line-2` | `rgba(0,0,0,0.12)` | 宿主 border-l3 | 沿用 | 输入框 hover、父条描边 |
| 弱分隔线 | `--line-3` / `--pm-line-soft` | `rgba(0,0,0,0.04)` | 宿主 border-l1 | 沿用 | 表内细分、卡片内分组 |

规则：**边框与阴影不同时上**（visual-craft §Color）；平卡片只用 `--line`，悬浮 / 弹层才加 `--shadow-*`。

#### 5.1.4 主操作与语义色

| 角色 | token | 浅色 | 深色 | 状态 | 语义 / 规则 |
|---|---|---|---|---|---|
| **主按钮填充** | `--dsw-alias-button-primary-fill`（经 `.pm-button-primary`） | 近黑 `rgb(15,17,21)`（实测） | 反白 | **沿用宿主，全产品统一** | Linear / Vercel 风格中性 primary；白字对比 18.9:1 ✓。所有视图蓝 CTA 迁入此 token（见 §6.5） |
| 主按钮 hover | `--dsw-alias-button-primary-hover` | 宿主加深 / 减黑 | 宿主 | 沿用 | — |
| 主按钮文字 | `--dsw-alias-label-primary-foreground` | 白 | 近黑 | 沿用 | **新增别名 `--pm-on-primary` 指向它**，替换现网未定义的 `--on-primary`（deliverables.css:28、milestones.css:189） |

## 6. 核心组件升级规范

### 6.1 DataTable（桌面表格 + 移动卡片双形态）

- **用途**：tasks 执行队列、meetings 行动项、reports 快照、记录列表的通用载体。现网两套并存：任务表用 CSS Grid 固定 9 列（`tasks.css:115`，`22px 28px 62px minmax(0,1fr) 128px 64px 108px 148px 72px`）；旧通用表用 `<table class="pm-record-row">`（panel.css:406+）。
- **结构（桌面 ≥561）**：
  - 表头吸顶（`--z-sticky:20`），列宽策略：身份列（编号 + 标题）`minmax(0,1fr)` 且**必须保留最小可读宽度**；其余为固定或 `auto`；数字列 tnum 右对齐。
  - 行：hover 底 `--pm-hover`；选中行 `outline:2px solid --c-prog; outline-offset:-2px` + 极浅蓝底（现网 `.pm-row-active` 沿用）。
  - 行内操作（编辑铅笔、勾选、grip）常驻 hover 显现但**键盘 focus 常显**；主操作（打开）落在整行 / 标题。
- **结构（≤560 卡片形态，P0 先落地 tasks，P1 推广全视图）**：
  - 每条记录一张卡片：第一行 = 勾选 + 标题（完整不截断）+ 状态 chip；第二行 = 编号 · 负责人 · 优先级；第三行 = 日期 / 进度（按需）。
  - 废弃 9 列横滑；标题列不再可能塌缩为 0。
- **状态**：默认 / hover / 选中 / 展开（WBS 分组，ChevronRight 转向沿用）/ 空态 / 过滤无结果（右侧同步清空，见 §6.6 与 S2-4）。
- **响应式**：≥561 表格；≤560 卡片；密度切换（舒适 / 紧凑，现网 tasks 已有本地 `dense` 开关，P1 提升为全局偏好）只改行高与单元格 padding，不改列结构。
- **可访问性**：表头 `scope=col`；行可聚焦（`tabindex=0`），Enter/Space 打开；排序按钮带 `aria-sort`；状态不仅靠色（chip 带文字）；卡片形态保留全部列信息，不删除字段。

### 6.2 Gantt 甘特

- **用途**：时间视角排期、依赖关系、关键路径；保留现网三态依赖路由（tight 凹形 / overlap U 折返 / gap0 小肘）与「缺日期诚实降级·跳过关键路径」提示，不得改动。
- **结构**：左 WBS 标签列（吸顶 + 吸左）/ 顶部日期轴（42px，现网沿用）/ 任务条（16px 胶囊，父条 10px 范围带）/ 今天红竖线 / 里程碑菱形。
- **任务条状态与升级**：
  - 现网：`st-done`（绿 14% 底 + 45% 边）/ `st-prog`（蓝）/ `st-todo`（灰）/ `--parent`（中性细带）/ `is-overdue`（红边 55%）/ `is-blocked`（琥珀边 55%）；**只有 `:active{cursor:grabbing}`，无 `:hover` 规则**（gantt.css:126-158）。
  - **P0 hover 高亮**：`bar:hover` 加深底色一档（同色 14%→22%）、边框提至 70%、轻微抬升；键盘 focus 环沿用 `outline:2px solid --c-prog`。
  - **P1 resize 手柄 + 键盘微调**：条体左右 6px 热区作为 resize 手柄（视觉为 2px 圆点 /  grip，仅 hover/focus 显现）；方向键 ←→ 移动 1 天、Shift+←→ 调整 1 天工期，Enter 打开抽屉改期（现网已有 Enter/Space 开抽屉，gantt.tsx:157-163）；拖拽改期落库白名单仍限 startDate/dueDate（待验证 #7）。
- **粒度控件（P0 修复 S2-1）**：现网类名 `.pm-seg` 与 panel.css:1758 通用进度条 `.pm-seg{height:10px;overflow:hidden}` 碰撞导致文字裁切。修法二选一（推荐前者）：① `.pm-gantt-root .pm-seg{height:auto;overflow:visible}` 补重置；② 控件改名 `.pm-granularity-seg` 消除碰撞。日 / 周 / 月三字完整可见，选中态 `--surface-3` 底，390 换行不裁切。
- **响应式**：≤560 标签列收窄为编号 + 标题两行，时间轴保留横向滚动（时间轴允许横滑，身份信息不进横滑）；粒度控件换行。
- **可访问性**：条体 `role` 携带日期 / 工期文字（`aria-label="任务 X，开始 ~ 结束，N 天"`）；依赖箭头不单独承担关系，tooltip / 抽屉里给前置任务文字；键盘可完成移动 / 微调 / 打开。

### 6.3 BentoCard（贴合内容的卡片）

- **用途**：概览 KPI、看板 widget、汇报分区。现网 `ov-card`、board widget、`rp-card`。
- **结构**：eyebrow（`--t-10` + ls-cap）→ 标题（`--t-16/650`）→ 内容 → 可选 meta / 操作；**容器 `align-items:start`，禁止 stretch 等高**（修 S3-4：reports 三卡 `rp-cols` 现网默认 stretch，单行内容被拉到 75px）。
- **空态（P1 重设计 S3-6）**：空卡不再按占位尺寸渲染大片空白，改为三选一：① 紧凑空态（图标 + 一句诚实说明 + 单个去重 CTA）；② 可折叠为一行「暂无 X · 添加」；③ 栅格紧凑补位（邻卡延展消弭空场）。风险矩阵 / 未来按周计划 / 客观进度清单三类空卡统一此规范。

- **可访问性**：空态不朗读为 0 值（「尚无数据」≠「0 项」）；图表卡给文本等价摘要。

### 6.4 抽屉表单（分区 + 校验统一）

- **用途**：task / milestone / risk / deliverable / meeting / report / project 的记录级编辑；现网 `.pm-drawer-form` 2 列网格（panel.css:741），字段平铺无分区。
- **结构（P1 分区）**：按「基础信息 → 排期与进度 → 关联与仓库 → （AI 预览区）」分组，组标题 `--t-13/650` + 弱分隔线；组内字段收紧到 `sp-3`；底部操作条固定：左 `删除（danger，仅编辑态）`，右 `取消（ghost）` + `保存（primary 中性）`。
- **校验统一（P1，Opportunity 3）**：现网双轨——repoUrl 走 `form-validation.ts` 受控内联错误（`repoFieldErrors / validateProjectForm / validateMilestoneForm / firstInvalidField`），标题等走原生 required 气泡。**统一为受控内联**：所有字段错误在字段下方 `--c-late` 文字 + 边框，提交时 `firstInvalidField` 聚焦首个错误；移除原生气泡依赖；保存成功 Notice 保留带回写 payload、出错保留输入（现网优点，不回退）。
- **状态**：默认 / 聚焦 / 校验错误 / 禁用提交 / 保存中 / 成功 Notice / 失败保留输入。
- **响应式**：≥560 右抽屉 2 列；≤560 塌 1 列（现网 task 390 已 1 列，推广全部抽屉）。
- **可访问性**：label 与控件 `for/id` 关联；错误 `aria-describedby`；打开抽屉焦点落入首个字段、关闭归还触发按钮（现网 `core/drawer-focus.ts` 已有，沿用）；Esc 关闭。

- **诚实**：区分「无记录」（空态引导）与「过滤无匹配」（右侧清空 + 左侧无结果，S2-4），二者文案不同，都不伪装成 0 统计。

### 6.7 标签 / 徽标（Chip / Tag / Badge）

- 现网 `.pm-tag[data-value]` / `.pm-priority-tag` / `.pm-type-tag` / `.pm-impact-tag` 用 `color-mix(色 10~12%, transparent)` 底 + 同色字，沿用此模式；新增 chip 必须走同一 mix 比例（10% 底 / 文字实色），不自定义底色。

- 计数徽标（视图 tab 上的 `22/1/0`）：`--surface-2` 底 + `--muted` 字，选中态不反白成实心。

- **结构**：
  1. 头部：`AI 生成 · 待确认` 标记（Sparkles 图标 + 虚线左边框区分人工内容）+ N 步 · X 新建 / Y 更新 元信息。
  2. 步骤列表：每行 checkbox + 标题 + 实体徽标（新建绿边 / 更新蓝边）+ 可选风险提示（softRisks）；可编辑。
  3. 操作条：`整批执行（N）` primary + `逐步执行` ghost + `拒绝 / 放弃` 文本按钮；失效行置灰并注明原因（现网 rejected 列表沿用）。
- **P7 可信规则**：AI 内容带「AI」标记，人工 / 已确认落库内容不带；确认落库后提供**撤销**（恢复上一快照，现网备份 / Notice 链路可扩展）；失败可重试或改手工，核心台账不受影响（现网脚本文案保留）。

### 7.1 全部任务 tasks（执行队列，主工作区）
- **核心决策**：今天先推进 / 处理哪条任务？谁逾期？
