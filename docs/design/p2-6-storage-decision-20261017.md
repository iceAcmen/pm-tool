# P2-6 溯源存储决定（2026-10-17，候选未提交）

## 决定（一句话）
溯源账本复用既有 `settings` 自由键值表的**一个固定行** `pmProvenanceLedger`，内部按项目有界数组（每项目 20 条，丢最旧），不新增领域表、不引入独立无限增长文件。

## 候选与取舍（基于真实存储/写机制）
仓库领域写统一经串行写队列（先持久化成功再改内存并发事件，写失败不动内存）；`settings` 为自由键值表，已有短 TTL 幂等标记固定行的有界先例。

| 方案 | 优点 | 问题 | 取舍 |
| --- | --- | --- | --- |
| 新增独立领域表 `provenance` | 关系清晰 | 需走领域 spec version/兼容加载与旧记录迁移，面大、回归风险高 | 不采纳（本批） |
| 每项目独立 JSON 文件自由写 | 直观 | 绕开串行写队列，易并发交错/无限增长，缺事务边界 | 不采纳 |
| **settings 固定行 + 内部有界数组** | 与既有串行队列/幂等标记同机制，零 schema 变更，读取为内存同步读 | 单行聚合，靠裁剪保证有界 | **采纳** |

## 事务边界与失败恢复（F13）
- 业务落库（apply/import/快照/建会）是主事务，经串行写队列成功后才继续。
- 溯源记录是**附件证据、best-effort**：账本写失败不回滚已成功的业务落库，也不阻断用户；失败项可在恢复后由人工核对。业务主流程不依赖账本成功。
- 幂等沿用既有 60s 短 TTL 顺序重放标记；溯源条目本身按项目有界，不重复无限堆积。

## 内容边界
只存：来源 typed refs（表/ID/项目/角色/内容指纹/口径版本）、不可变重校历史、最小 undo 句柄元数据（句柄、过期时刻、是否已用、落库后 postimage）。
不存：动作正文/patch 明文、任何模型凭据、用户隐私扩展；置信度统一「未提供」，不按来源数或模型造分。

## 撤销（F14）
undo 沿用既有真实限制（10 分钟 TTL、最多 3 条、一次性、重启失效），本批不新增时限、不做假持久回滚。撤销前用落库后全对象 postimage 比对：确认后已被人工修改则拒绝覆盖/删除并说明，绝不静默覆盖。

## 未决（留产品负责人拍板，不擅自定值）
快照保留期、在线分享口径、置信分档阈值（本批恒为「未提供」）。

## 离线/降级交互（F07/F16）
- 模型不可用（缺 Key / 路由失败）只拦截「新生成」：沿用既有 `PROD_KEY_MISSING` 中文引导，不调用模型、不出网。
- 已落库的草稿缓存、溯源账本、历史快照仍可正常查看；核心 CRUD（增删改查七类实体）完全不受影响，不因无 Key 被禁用。
- 生成失败时可重试或改用手工录入；业务主台账不受影响，错误给出可恢复路径，不静默吞掉。
- 「无可用模型」与「未配置 Key」区分对待：前者是临时不可用，后者是配置引导，二者都不关闭核心台账能力。

## 撤销限制展示（F14）
撤销沿用真实限制：10 分钟 TTL、最多 3 条、一次性、重启失效（不造新时限、不做假持久回滚）。撤销前用落库后全对象 postimage 比对，确认后已被人工修改则拒绝覆盖/删除并说明；撤销成功/冲突/失败写入账本审计。
