# 02 · 用户体验问题评估报告

> 视角：国内一线 PM 的真实工作流（立项/排期/WBS → 例会纪要 → 进度汇报 → 风险问题 → 交付物 → 跨项目/跨人协同 → 代码仓库联动 → AI 辅助）。
> 严重度定义：**S1=阻断核心心智/高频痛点**；**S2=明显效率损耗或认知负担**；**S3=打磨/锦上添花**。
> 证据均落到 `packages/dsh-pm-tool/src/` 具体文件与大致行号，供研发直接定位。面板文件统一简称 `panel.tsx`。

## 二、S1 问题（优先解决，直接影响 PM 核心心智）

### UX-01 WBS 任务树在 Web 上是「断的」
- **现象**：PM 拆任务最自然的心智是一棵树（1 → 1.1 → 1.1.1）。面板里任务却**先按状态分成「未开始/进行中/受阻/已完成」四组**，父子被拆散在不同组里，仅靠标题前缩进 `paddingLeft = depth*16px` 暗示层级。
- **证据**：`panel.tsx` TaskTable `groups`（约 L1107–1113）按 `taskStatus` 分组；`TaskGroup` 渲染（L1250+）；缩进仅 `task.code.split('.').length`（L1273）。没有树节点折叠/展开，没有「父子在同一组」。
- **PM 痛点**：一个 3 层 WBS 摊成四张状态表后，**看不出某个父任务下面到底拆了什么、整体进展如何**；想给某父任务加个子任务，得靠记住编号。这与 R2「≥3 层父子结构」的产品承诺脱节——数据有树，界面没有树。
- **方向**：默认改为树视图（按父子组织、可折叠），状态分组降级为可选开关。见 PROD-01。

### UX-02 没有「排期」这个视图
- **现象**：任务有 startDate/dueDate、里程碑有 targetDate，但界面只能在表格里读两个日期文本列，**没有任何条形/时间轴**。PM 排期时最需要的「谁在哪个时间段做什么、时间是否打架、里程碑落在哪一周」完全不可见。
- **证据**：`panel.css` 全文 grep 无 gantt/timeline/burndown；任务表头「开始日期/截止日期」就是纯文本 `<td>`（L1218–1219、L1309–1310）。R3 验收里的「时间线视图」在 Web 侧并未真正实现。
- **PM 痛点**：排期是 PM 一半的工作。现在要在脑子里把一堆日期列还原成时间轴。
- **方向**：增量先做里程碑/任务的「周视图条带」；长期做甘特排期台（PROD-22）。

### UX-07 项目概览太薄，撑不起「打开即知重点」
- **现象**：「项目概览」tab 只有 4 张数字卡（总任务/已完成/已延期/里程碑）+ 一条任务状态分布横条。没有里程碑时间线、没有风险热力、没有个人负载、没有「接下来 2 周要交什么」。
- **证据**：`Overview` 组件（L1726–1761），Summary 卡 4 个 + 状态分布一条。
- **PM 痛点**：Persona A 要的「10 秒内知道最该盯的三件事」做不到；Persona B 的多项目健康度只能靠逐项目点卡片。
- **方向**：概览 = 接下来日程 + 异常 Top 列表 + 里程碑时间线 + 风险矩阵。见 PROD-06。

### UX-09 没有「按人」的跨项目视角，且人员身份不统一
- **现象**：assignee/owner 全是**自由文本字符串**（zod `z.string()`，见 `task.ts` L24、`project.ts`），没有人员字典。PM 想知道「张三手上现在压了多少活、有没有过载」既无视图，也会因为「张三/张 三/zhangsan」这类输入漂移而统计不准。
- **证据**：`task.ts` assignee 无枚举；面板里 Persona 头像就是 `assignee.slice(0,1)`（L1306）；无任何按 assignee 聚合的组件。
- **PM 痛点**：跨人协同 / 资源调配是 Persona B 的核心诉求，目前为空白。
- **方向**：先做人员花名册（从现存值去重生成候选），再做「我的/某人」视图。见 PROD-07/08。

### UX-11 与代码仓库零联动
- **现象**：交付物 location 是一句自由文本（`deliverable.ts` L36 注释明确「离线优先不强制可访问性」），任务与分支/MR/commit 无任何关系。PM 记在本工具里的任务，和研发真正提交代码的地方是两张皮。
- **证据**：deliverable 表无 repo/branch/MR 字段；任务表无任何代码关联字段；grep 无 git/github/branch/MR。
- **PM 痛点**：国内 PM 天天被问「这个需求代码到哪了、MR 合了没」，现在要跑去 Git 看再回这边手填。
- **方向**：这是颠覆性方向（PROD-21），需要架构演进（新字段 + 可选 Git 桥）。

## 三、S2 问题（明显效率损耗 / 认知负担）

### UX-03 提醒点了不直达
- 提醒条（`ReminderStrip` L595+）每条 `onClick` 只调 `onPickProject(it.projectId)`（L659）——切到那个项目就停了，**不打开那个任务行/抽屉**。OPT-01 标题叫「可点击定位」，实际只定位到项目级。PM 还得在任务表里再找一遍。
- 改进：点提醒 → 切项目 + 打开该记录抽屉 / 高亮滚动到行。见 PROD-02。

### UX-04 全局搜索命中不直达记录
- `GlobalBoard` 搜索结果每条 `onClick={() => onPickProject(hit.projectId)}`（L1868），同样只切项目，不打开对应 drawer。命中「里程碑 X」后用户仍要自己切到里程碑 tab 找。
- 改进：命中携带 `type+id`，前端按类型直接唤起对应 Drawer。见 PROD-03。

### UX-05 高频更新必须开长抽屉
- 把任务从「进行中」拖到「完成」、改个截止日、调个进度，都得点标题 → 开右侧 11 字段长抽屉 → 保存。唯一例外是行首那个完成勾选按钮（L1283）。PM 一天更新几十次状态，抽屉往返很重。
- 改进：单元格行内编辑（状态下拉/进度步进/日期），不打断列表上下文。见 PROD-05。

### UX-06 moveTask 能力在，界面没暴露
- core 已实现 `moveTask(id, newParentId)`，含自环/子孙/跨项目三重保护（`tasks.ts` L271–316），命令 `task move` 也在（commands/task.ts L221）。但 Web 端：`TaskForm` 只有「新建时选父任务」（L2048），**编辑态不能改父任务、不能拖拽、不能调顺序**。WBS 搭错层级只能去命令行。
- 改进：行内「移动到…」/ 拖拽改父与同级排序（注意：moveTask 目前只追加到同级末尾，同级插序需先补 order 重排能力）。见 PROD-04。

### UX-08 风险矩阵没画出来
- 风险的概率、影响是 PM 最关心的二维坐标，目前只是表格里两个小标签列（L1452–1455）。PM 没法一眼看出「哪几个是高概率高影响的红色项」。
- 改进：概览/风险 tab 加 概率×影响 热力矩阵，气泡大小=未关闭项数。见 PROD-06 的一部分。

### UX-10 AI 是「三个一次性按钮」，不是副驾
- `AiAssistant`（L698+）固定三模式 wbs/narrate/summarize，每次独立、不读当前选中任务/风险/上下文、不能多轮追问。生成完确认入库就结束。
- PM 真正想要的是「帮我看看这项目哪要炸」「把下周排期拉一下」这种对话式求助。
- 改进：短期在各模块加「就地 AI 草稿」入口；长期做对话式项目副驾（PROD-20）。

### UX-12 没有任务依赖
- 任务表无 predecessor/依赖字段，无法表达前置关系，排期只能全靠人脑和手动日期。
- 这是 UX-02 甘特/关键路径的前置数据基础。见 PROD-12（schema 演进，domain v2）。

### UX-15 顶栏 8 个按钮不分主次
- 顶栏同时放：总览看板 / 新建项目 / AI 助手 / 备份 / 从备份恢复 / 导出 MD / 导出 JSON / 刷新（L330–431）。新建/AI 是高频主操作，备份/导出是低频运维操作，混在一起。新用户易误点低频按钮。
- 改进：主操作（新建/AI）保留，备份/导出/恢复收进「⋯ 更多」菜单。见 PROD-11。

## 四、S3 问题（打磨）

- **UX-13 汇报无趋势**：`ProgressReportTable` 每条快照孤立展示（L1592+），无「较上期完成率↑/逾期↓」徽标。PROD-09。
- **UX-14 会议→任务单向**：行动项 `promote` 建任务后回写了 `action.taskId`，但任务详情看不到「来自 mtg-xxx 会议」。PROD-10。
- **UX-16 导航割裂**：`view` 是组件内 useState，切项目不记忆 tab；提醒条/总览看板与主区是两层不同视图，跳转后用户「我刚才在哪」丢失。PROD-11/05 顺带改善。

## 五、做得好、不要动的地方（保护资产）

评估也要明确**哪些已经是优点，别在迭代中改坏**：
1. **离线优先 + 草稿确认制**：AI 一律先预览、确认才入库，核心台账零模型可用——这是定位基石。
2. **七实体闭环与留痕**：交付物变更 history、汇报冻结 snapshot、行动项转任务幂等——数据严谨。
3. **提醒条纯读时派生**：不引入常驻进程，守住离线定位。
4. **高密度表格 + 右侧抽屉 + 稳定选择器 + 键盘导航**：高频用户效率已不错。
5. **双模型车道 PoC/生产隔离**：免费网关不进生产，风险可控。
