# 03 · 增量优化方案（功能 + UI）

> 原则：**先在现有架构内增量做**，不动 domain 版本、不引入常驻进程、不破坏「离线优先 + 草稿确认」。每个方案都标注它解决 02 的哪条 UX 痛点。
> 成本：S≈1–2 人日、M≈3–6 人日、L≈1–2 周。优先级 P0/P1/P2。

---

## PROD-02 · 提醒/搜索命中「直达记录」（S，P0）— 解决 UX-03 / UX-04

**痛点**：现在点提醒、点全局搜索命中，只切换到对应项目，用户还得自己在 Tab 里二次找记录。

**方案**：提醒条和全局搜索的每条命中携带 `{type, id}`，点击时前端：① `setSelected(projectId)` 切项目；② 切到对应 view tab；③ 打开该记录的抽屉（或高亮滚动到行）。

**落地**：`ReminderStrip` 的 `onClick` 从 `onPickProject(it.projectId)` 改为同时发一个 `onOpenRecord({type:'task'|'milestone', id})`，由 `PmPanel` 统一 `setView` + `setDrawer({kind, record})`（Drawer 已存在，复用）。`GlobalBoard` 的 `onPickProject` 同理带上 hit.type/hit.id。纯前端，基于现有 snapshot 与 drawer，**零 schema 改动**。

**线框（交互流，非视觉）**：
```
点「任务 登录页崩溃（逾期2天）」
  → 顶部项目切到「官网改版」
  → 视图 tab 自动切到「全部任务」
  → 右侧抽屉直接打开该任务详情
```

- 收益：把「切项目→找记录」两次以上操作压成一次。高频。
- 成本：**S**（前端组件 wiring + 一个 onOpenRecord 回调）。风险：低（复用既有 drawer）。
- 适用场景：所有项目数≥2、提醒/搜索频繁的 PM。

## PROD-01 · 任务视图默认改「树」，状态分组变可选（M，P0）— 解决 UX-01

**痛点**：WBS 父子被状态分组打散，PM 看不见任务树。

**方案**：任务表默认按**父子树**渲染（缩进 + 折叠/展开三角），把现在的「按状态分组」改成一个**可切换的视图开关**：`[树视图 | 看板(按状态分组)]`。树视图下状态用行内 StatusTag 体现，不拆组。

**线框**：
```
工具条: [+添加记录] [视图: 树 ▾] [排序: WBS编号▾] [🔍搜索]
  ▼ ▸ 1. 需求确认            [进行中] [P0]  张三
    ▸ 1.1 需求评审会          [已完成] [P1]  李四
    ▾ 1.2 原型设计            [进行中] [P0]  张三
        1.2.1 首页线框        [未开始] [P1]  王五
        1.2.2 交互走查        [受阻]  [P1]  李四
```

**落地**：`TaskTable` 现有 `groups`（按状态）旁新增一棵树构建函数（利用 `parentId`/`code`/`order`，数据里都有）；折叠态存组件内 state。排序下拉保留。**纯前端**，读的是同一份 `tasks` snapshot。

- 收益：WBS 心智终于在界面闭合，是 PM 最高频视图。
- 成本：**M**（树构建 + 折叠交互 + 与现有键盘导航 j/k 兼容）。风险：中（键盘导航、批量选择要在树结构下重新对齐，需补 verify-keyboard 用例）。
- 取舍：不强制废掉状态看板——做两态切换，照顾习惯看板的人。见 05 的 A/B 对比。

## PROD-05 · 单元格行内快速编辑（M，P1）— 解决 UX-05

**痛点**：改状态/进度/截止都要开右侧 11 字段长抽屉。

**方案**：任务行上 3 个高频字段支持行内控件，不打断列表：
- 状态：点 StatusTag → 弹出四态小菜单（todo/in_progress/blocked/done），直接 `task update`。
- 进度：点 Progress → 步进 ±10% 或滑条。
- 截止：点日期单元格 → 原生 date 弹层。

**线框**：
```
| WBS | 任务        | 状态▾      | 优先级 | 进度        | 截止       |
| 1.2 | 原型设计    | 进行中 ▾   | P0     | ████░ 40%▾ | 2026-10-20▾|
        点状态→ [未开始][进行中][受阻][已完成]
```

**落地**：复用 `run('task update <id> {..}')`（core 已支持），前端在单元格上包一层 popover。保存后 `refresh()`。**零 schema 改动**。

- 收益：日常状态更新从「开抽屉→保存」降到「点一下」。
- 成本：**M**（3 类行内控件 + 弹层定位 + 键盘守卫）。风险：低–中（注意与 j/k 键盘导航焦点冲突）。
- 适用场景：每天站会批量过状态的 PM。

## PROD-04 · Web 暴露任务移动/改父（M，P1）— 解决 UX-06

**痛点**：core 有 `moveTask`，Web 却改不了任务层级。

**方案**：任务行加「⋯ 移动到…」菜单 → 弹出「选择父任务」树选器；树视图下支持**拖拽缩进**改父（拖到某行下方/缩进处即 `task move`）。

**落地**：调既有 `task move <id> <newParentId|null>`（环路/跨项目保护 core 已做）。**注意**：现有 moveTask 只把新节点追加到同级末尾，同级「插入到中间」需要 core 补一个 order 重排（小改 tasks.ts，非 schema 变更）。
- 收益：WBS 搭错层级不再依赖命令行。
- 成本：**M**。风险：中（拖拽与排序/级联删除边界要测，补 verify-cascade 用例）。
- 取舍：先做「移动到…菜单」（低风险），拖拽作为增强。

## PROD-06 · 项目概览增强：接下来日程 + 里程碑时间线 + 风险矩阵（L，P1）— 解决 UX-07 / UX-08

**痛点**：概览太薄；风险矩阵没画。

**方案**：把「项目概览」tab 从 4 卡升级为 PM 的「作战室首页」：
```
┌─ 顶部 4 卡（保留）：总任务 / 已完成% / 已延期🔴 / 距交付 N 天 ─┐
├─ 「接下来 14 天」条带：按日列出临期任务+里程碑（点直达，复用 PROD-02）
├─ 里程碑时间线：横向轴，里程碑按 targetDate 落点，状态色
├─ 风险矩阵：概率(纵)×影响(横) 3×4 格子，风险/问题按坐标落位，气泡=条数
└─ 待办异常 Top5：逾期任务 + 未关闭高影响风险，按严重度排
```

**落地**：全部基于 snapshot 前端派生（里程碑 `targetDate`、风险 `probability`/`impact` 都在）。里程碑时间线=一条横向 flex 轴；风险矩阵=固定 3(概率)×4(影响) 网格。**零 schema 改动**。

- 收益：打开面板 10 秒知道「最该盯的三件事」，直接命中 Persona A。
- 成本：**L**（三个新区块 + 响应式）。风险：低（纯展示派生）。
- 适用场景：项目概览首页、给 PMO 看的一页纸。

## PROD-07 · 人员花名册（M，P1）— 解决 UX-09（前置）

**痛点**：assignee 自由文本，无法可靠聚合。

**方案**：从现存所有 `tasks.assignee`/`project.owner`/`riskIssues.owner`/`meetings.participants` **去重生成人员候选清单**，各表单的 assignee/owner 输入改为「可输入的自动补全下拉」（已有值可下拉选，新值照填）。不强制建表，先做**派生花名册 + 输入归一化**（trim、去空格）。

**落地**：snapshot 里聚合出唯一人名单；前端 input 加 datalist/自动补全。后续若要真人员字典，再走 settings 表存（非 schema 变更）。
- 收益：为「按人聚合」打基础，消除拼写漂移。
- 成本：**M**。风险：低。
- 说明：不做强制枚举（离线、单用户、自由录入是现有灵活性），只做引导与归一。

## PROD-08 · 跨项目「某人/我的」负载视图（M，P1）— 解决 UX-09

**痛点**：PMO 想知道谁过载了。

**方案**：总览看板加一个「按人」维度：选一个人 → 列出其跨项目所有未完成任务（按临期/逾期排序）+ 逾期数。可作为看板的一个子 tab 或顶部人选器。

**线框**：
```
总览看板: [全局统计 | 逐项目 | 按人▾]
按人视图: 选 [张三▾]
  进行中 5 · 临期 2 · 逾期 1
  ├ [官网改版] 登录接口联调      截止10-15 🔴逾期1天
  ├ [App迭代] 支付页埋点         截止10-18
```

**落地**：纯前端聚合 snapshot（filter tasks by assignee）。依赖 PROD-07 的归一化让名单干净。
- 收益：资源调配一眼清，命中 Persona B。
- 成本：**M**。风险：低。

## PROD-11 · 顶栏信息架构重整（S，P2）— 解决 UX-15 / UX-16

**痛点**：8 个按钮不分主次。

**方案**：
```
现在: [项目▾] [总览][新建项目][AI助手][备份][恢复][导出MD][导出JSON][⟳]
改为: [项目▾]                          [✨AI助手][+新建] [⋯更多▾][⟳]
                                              └ 更多: 备份 / 从备份恢复 / 导出Markdown / 导出JSON / 项目概览
```
高频主操作（新建、AI）外露；低频运维（备份/恢复/导出）收进「⋯」菜单。顺带把 `view` 改为 localStorage 记忆（切项目后回到上次看的 tab）。

- 收益：降低误点与认知负担。
- 成本：**S**（一个菜单组件 + localStorage）。风险：低。

## PROD-09 · 汇报趋势对比徽标（S，P2）— 解决 UX-13
- 方案：`ProgressReportTable` 每行与「上一份汇报」比关键数字（完成率↑↓、逾期数↑↓、异常数↑↓），加小箭头徽标。
- 落地：前端按周期排序后相邻两份 diff。成本 **S**。风险：低。

## PROD-10 · 会议↔任务反向链接（S，P2）— 解决 UX-14
- 方案：任务若由某会议行动项 promote 而来（`action.taskId` 已回写），任务详情抽屉显示「来自会议 mtg-xxx」链接。需要在 task 补一个 `sourceMeetingAction` 或前端反查（前端反查零 schema）。
- 落地：前端遍历 meetings.actions 反查 taskId→meeting。成本 **S**。风险：低。
