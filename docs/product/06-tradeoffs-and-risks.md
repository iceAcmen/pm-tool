# 06 · 风险与取舍说明

> 产品决策的价值在于「不做什么」。本文把每条方案的取舍、放弃的替代路线、以及对产品定位的坚守讲清楚。

## 一、贯穿全局的三条定位红线（任何方案不得违背）

1. **离线优先**：核心台账不依赖模型/网络可用。提醒走「打开面板即派生」，不引入常驻后台进程（守 ADL-039）。
2. **草稿确认制**：任何 AI 写库动作必须先出草稿、显式确认；核心台账零模型可用。
3. **单用户本地**：不做实时多人协作（ADL-031），多设备靠 `backups/` 同步盘 + 单写者。

> 所有看起来「更性感」的方案（Git 自动桥、常驻推送、多人协同）只要违反这三条，一律降级为长期观望。

## 二、重大取舍记录

### 取舍 1：任务视图——树 vs 看板（PROD-01 的 A/B）
- **A. 纯树视图**：完全按父子组织。优点=WBS 心智直接；缺点=按状态看进度的人不适应。
- **B. 纯看板（现状）**：按状态分组。优点=站会过状态方便；缺点=打散了 WBS 树（UX-01）。
- **选择**：**默认树、保留看板为可切换**。理由：树是 PM 拆任务的第一心智，看板是站会的第二心智，做成切换成本可控，谁也不得罪。风险=键盘导航/多选在树下要重新对齐，已在验收标准里要求补 verify-keyboard。

### 取舍 2：AI——增强固定三模式 vs 对话副驾（PROD-20）
- **A. 继续给固定模式加功能**（如更多 WBS 模板、更多周报模板）。成本低，但天花板低，PM 还是得知道「用哪个按钮」。
- **B. 对话式副驾**。体验跃迁，但要做编排、防误写、免费车道不稳。
- **选择**：**B 作为长期旗舰（v0.7.0+），A 在 v0.5 顺带做**。理由：B 才是发挥「dsh=LLM 框架 + 结构化台账」独有优势的方向；但 B 依赖生产车道稳定 Key，不宜过早押注。写操作一律草稿卡，把风险锁死。

### 取舍 3：仓库联动——手填链接 vs 自动 Git 桥（PROD-21）
- 详见 04 构想二 A/B。**选手填链接先上（低成本、离线安全），自动桥长期观望**。理由：自动桥要凭证/联网/常驻，踩三条红线中的两条，ROI 低。

### 取舍 4：排期——只读甘特 vs 关键路径（PROD-22）
- 详见 04 构想三 A/B。**先只读拖拽甘特（补 UX-02 这个 S1），依赖+关键路径长期按需**。理由：90% 的「看不见排期」痛点，靠只读甘特就解决了；关键路径要新增依赖数据+排期算法，复杂度跳一档。

### 取舍 5：人员——强制字典 vs 派生补全（PROD-06）
- **A. 强制人员枚举**：干净但牺牲离线单用户的自由录入。
- **B. 从现存数据派生花名册 + 输入补全**：不强制，但逐步归一。
- **选择 B**。理由：单用户本地工具，强制枚举是过度设计；派生补全已能让按人统计（PROD-07）可用。

## 三、风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 任务树化( PROD-01) 破坏现有键盘导航/批量选择 | 高频用户效率回退 | 树下保留 j/k/多选；补 verify-keyboard；渐进上线先做默认树、看板可切回 |
| 行内编辑(PROD-03) 与 j/k 焦点冲突 | 误触 | 弹层打开时劫持键盘；输入框守卫（现有 panel-kbd 已有 input 守卫惯例） |
| domain v2 加字段破坏旧记录读回 | 数据损坏 | 新字段全 optional；读旧记录不报错；恢复前自动安全快照(现有 R18 能力) |
| AI 副驾(PROD-20) 免费 PoC 车道输出不稳 | 结论错、草稿误确认 | 只读结论可容忍；写操作必须确认卡；无 Key/超时降级到手工（现有降级链路） |
| 甘特(PROD-22) 拖拽改期引发日期倒挂 | 数据矛盾 | 复用现有 startDate≤dueDate 校验；倒挂弹中文错（task schema 已有 validateDateOrder） |
| 与另一开发线并行提交冲突 | 合并冲突 | 本批只动 docs/product/，不碰 src/ 与 changelog/requirements；提交前 pull --rebase |
| 概览作战室(PROD-05) 前端派生过重 | 大数据量下面板卡顿 | snapshot 全量已在内存；派生为 O(n)，项目数<50 无虞；超过再谈分页 |

## 四、明确不做（本期）

- 不做常驻后台/系统通知推送（守离线优先）。
- 不做实时多人协作/权限。
- 不做 Git 自动桥与 webhook。
- 不做关键路径自动排期。
- 不重写面板技术栈（不引入路由/状态库），保持单 snapshot 派生架构。
- 不动上游 deepseek-harness。
