## 二、用户故事

- **US-1（PMO/Persona B）**：打开一个视图，按人看到跨项目未完成数、逾期/受阻/临期、跨几个项目、最近截止，10 秒判断要不要重新分派。
- **US-2（交付型 PM/Persona A）**：一眼看到「哪些活还没认领（未分配）」与「本周谁要交」，站会/周报不漏无主任务。
- **US-3（非技术 PM/Persona C）**：只点鼠标；点某人展开其跨项目任务，点某条任务直达该任务详情。
- **US-4（高频用户）**：键盘在人员卡片间移动、展开/收起；风险不只靠颜色传达。

## 三、信息架构（关键决策）

**D-A：新增顶层 tab「人员」**，与现有 8 个 tab 并列（全部任务/里程碑/风险问题/会议/汇报/交付物/项目概览/甘特）。不藏在 `GlobalBoard` 弹层里。

**D-B：进入「人员」视图时，顶栏项目选择器从「硬作用域」降级为「可选过滤器」**，默认值＝「全部项目」。本视图跨项目聚合，不要求先选项目；选了某项目则只聚合该项目。

## 四、聚合口径（纯前端派生 snapshot，可确定性单测）

- **数据源**：全量 `data.tasks`（不经项目过滤）＋ `data.projects`。仅统计**未完成任务**（`status!=='done' && (progress??0)<100`）；done 不计入负载。
- **归一化分组键**：`trim()` → 折叠内部连续空白为单空格 → `casefold()`。中文姓名 casefold 无副作用，主要归一英文/拼音大小写。
- **不拆多负责人**：`"张三,李四"` 这类字符串按原样整体入一个桶，不做逗号/顿号切分。
- **展示名**：casefold 合并到同一组的多条原始写法，卡片显示组内**出现次数最多的原始写法**（并列取最先出现）。
- **每卡指标**：

| 指标 | 定义 |
|---|---|
| 未完成总数 | open 任务数 |
| 待办/进行中/受阻 | 按 `todo/in_progress/blocked` 拆段 |
| 逾期数 | open 且 `dueDate<today`（与 `stats.ts`/`reminders.ts` 同口径） |
| 临期数 | open 且 `0≤daysUntil≤7`、未逾期 |
| 受阻数 | `blocked` 数（独立风险信号） |
| P0 未完成 | open 且 `priority==='P0'` |
| 跨项目数 | 该人 open 任务涉及的 distinct projectId 数 |
| 最近截止 | open 任务中最近的未来 dueDate（无则 `—`） |

- **不做**：不发明产能/FTE/工时/负载分；不把里程碑、交付物、风险计入个人负载（无 task assignee）。

## 五、排序与未分配

- **默认排序（风险优先）**：逾期数 desc → 受阻数 desc → 临期数 desc → 最近截止 asc → 未完成总数 desc。把「最快要炸的人」顶到最前。
- **未分配桶**：归一化后仍为空的 open 任务，收入「⚠ 未分配」，**固定置顶**，作为一等风险区（无主工作＝隐患），不参与人名排序。

- 风险信号**同时有文字**（「逾期 1 天」），不只靠红/黄色。

## 七、筛选交互

- 项目过滤（默认全部）、姓名子串搜索、「只看有风险」开关（隐藏 逾期=0 且受阻=0 且临期=0 的人）、排序下拉（默认按风险；另给按未完成数/按姓名）。
- 视图打开与交互全程**只读**：不下发任何 `execute()` 写命令，纯本地 state。

## 八、空状态 / 无负责人

| 场景 | 文案 |
|---|---|
| 无任务/无项目 | 「还没有可汇总的任务。先在某个项目里拆解 WBS 并指定负责人，这里会自动按人归集。」 |
| 有任务但全部完成 | 「目前所有人手上都没有未完成任务。」 |
| 筛选后无人 | 「没有匹配的负责人。可清除搜索或切回『全部项目』。」 |
| 有 open 任务但空 assignee | 收入「未分配」桶常显（见 §五）。 |

## 九、移动端 / 键盘 / 可访问性

- **窄窗**：现状 CSS 无 `@media`、仅保证 Chrome 桌面（ADL-033）。P0 只承诺窄窗优雅（卡片纵向堆叠、任务表横滚），不做独立移动布局。
- **键盘**：P0 人员卡为可聚焦按钮，Enter/Space 展开，Tab 序自然，`aria-expanded` 正确，展开后任务行可 Tab+Enter 打开；j/k 全量导航列 P1（与任务树键盘对齐一起做）。
- **可访问性**：风险文字+颜色双通道；沿用现有 `.pm-view-tabs` tablist 语义；新控件一律加稳定 `data-*`/语义 class（verify-web 依赖此契约）。

## 十一、验收标准（可测试、确定性）

- AC-1：≥2 项目 fixture open 任务，每个 trim 后不同的 assignee 一张卡；done 不计。
- AC-2：逾期＝`status!=='done' && progress<100 && dueDate<今天`，与 R16 同边界（注入固定 today，第 7/8 天临期边界正确）。
- AC-3：默认列表逾期最多者在前；并列按受阻→临期→最近截止打破。
- AC-4：空 assignee 的 open 任务全部进「未分配」桶且置顶可见。
- AC-5：点任务行 → 切到该任务 projectId、切「全部任务」tab、打开任务抽屉（断言行 `data-*`）。
- AC-6：项目过滤改聚合范围；姓名搜索过滤名单；「只看有风险」隐藏三者皆 0 的人。
- AC-7：人员视图打开与交互全程无写命令下发。
- AC-8：§八空态出现。
- AC-9：固定 today 结果可复算（新增 `verify-people-load.mjs` 断言分组数/各计数/排序首位）。
- AC-10：人员卡 `aria-expanded`；逾期信息含文字标签。

## 十二、反例（明确不做）

- 不自动合并「张三 / 张 三 / zhangsan」——按归一化精确串分组，漂移只软提示。
- 不建人员表/持久花名册/owner 实体/settings 字典；不升 domain、不动 `core/task.ts`。
- 不把只有 done 任务的人与正在负载者并列（P0 仅列有 ≥1 open 任务者）。
- 不统计 done 进负载；不计里程碑/交付物/风险入个人负载。
- 不要求先选项目才能进人员视图。
- 不展示工时/产能/负载分值。
- 不在本视图内改派负责人（改派走既有任务编辑抽屉，本视图只读）。
- 不复抄 `war-room.ts` 的 `'doing'` 状态笔误（真实枚举 `in_progress`）。
