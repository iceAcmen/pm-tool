## 二、PROD-10 · 任务抽屉「来自会议」直达（P2，S）

### 用户故事
- **US-10a**：PM 打开一个从会议行动项 promote 来的任务，抽屉顶部看到一行只读「来自会议 mtg-0003 · 评审会」，点一下直接跳进该会议纪要抽屉。
- **US-10b**：手工建的任务（没有任何行动项指向它）不显示该行，抽屉布局与现在一致。
- **US-10c**：同任务被多场会议行动项关联（手工关联所致）→ 显示确定性第一条 + 一行小字「另关联 1 场会议」，不堆链接列表。

### 裁决边界（所有者拍板）
1. **前端反查，零 schema**：不在 task 记录上加 `sourceMeetingId`；TaskForm 拿当前 `task.id` 在 `snapshot.meetings` 里遍历 `actions[].taskId === task.id` 取来源。
2. **多来源确定性排序**：候选会议沿用既有会议列表口径排序（`meetingDate` 倒序 → `id` 倒序，与 `listMeetings`/前端 meetings 排序一致），取**第一条**作为展示链接；候选数 >1 时在该行尾部以小灰字提示「另关联 N 场会议」，不做下拉、不跳转其余。**排序确定性必须可测**：同数据两次渲染、跨进程重启读回，展示的来源链接一致（对齐冻结验收门 WP 用例）。
3. **只读展示、不可编辑**：该行是系统派生信息，不并入表单 submit 字段、不随保存写库。
4. **点击直达**：复用既有 `openRecord(task.projectId, 'meeting', meeting.id)`（切项目→切 tab→开抽屉），不新写导航。
5. **来源会议已删/反查落空**：安全隐藏该行，不报错、不留空链接。
6. **范围**：仅任务详情抽屉；会议侧「已转 t-xxxx」徽标（MeetingForm 现有）不动。

### P0 验收条件
1. promote 产生的任务：抽屉顶部出现来源会议链接（含 mtg-id 与会议标题），点击打开对应会议抽屉，行为与提醒条直达一致。
2. 手工新建/无关联任务：不出现该行。
3. 多来源：链接指向排序后第一条（meetingDate 倒序→id 倒序），且提示「另关联 N 场会议」；N 计算正确；同数据两次渲染与重启后展示的来源链接一致（确定性）。
4. 删除来源会议后重开任务抽屉：该行消失且无报错。
5. 任务移动/改父后来源链接不变（来源关系挂在行动项上，与父子无关）。

### 文件级改动（预估）
- `src/client/panel.tsx`：TaskForm 增加来源区块（新增 `meetings`/`onOpenMeeting` 两个 props，调用处 PmPanel 内补传；反查为约 10 行纯函数）。
- `scripts/verify-web.mjs`：补 promote→任务抽屉出现 mtg 链接→点击开会议的 GUI 断言。
- 后端零改动。

## 三、PROD-09 · 汇报表相邻对比徽标（P2，S）

### 用户故事
- **US-09a**：PM 在进度汇报表扫一眼，每行除当期数字外带「完成率 ↑5% · 逾期任务 ↓1 · 异常 ↑2」，知道本期比上期是好是坏。
- **US-09b**：项目只有 1 份汇报时，整列对比徽标干脆不出现，不空摆箭头。
- **US-09c**：某项指标与上期持平 → 显示「完成率 持平0」文字，不留空白也不画箭头。

### 裁决边界（所有者拍板）
1. **相邻＝时间相邻，与筛选无关**：在**全量**项目汇报列表上（已按 periodEnd desc、id desc 排序）预计算「每份的上一份」映射（periodEnd 更早、再按 id 升序的最近一份）；顶部搜索词/状态筛选只影响行可见性，**不改变「上一份是谁」**。
2. **diff 三个指标**（全部取自不可变快照，不回算源数据）：
   - 完成率：`snapshot.tasks.averageProgress`（百分点）；
   - 逾期任务异常数：`snapshot.exceptions` 中 `kind === 'overdue_task'` 的条数；
   - 总异常数：`snapshot.exceptions.length`。
3. **首份（最旧、没有上一份）不显示任何徽标**。
4. **零值显示「持平0」**：某项 delta 为 0 → 该项渲染文字「完成率 持平0」/「逾期 持平0」/「异常 持平0」，不画箭头。
5. **文字+箭头，非仅靠颜色**：徽标必须同时有方向箭头与数值（如 `↑5%`、`↓1`、`持平0`）；配色（向好/向坏）只作辅助，**绝不靠颜色单独传达方向**（无障碍与打印友好）。
6. **草稿/定稿混排**：仍按 periodEnd 相邻比，状态不影响口径。
7. 快照不可变是特性：徽标只反映「生成那一刻 vs 上一份那一刻」，不随源数据变化。

### P0 验收条件
1. ≥2 份汇报：最新行与相邻上一份比，三指标箭头方向与 delta 数值正确（构造 +5% / -1 / +2 样本可断言）。
2. 仅 1 份：无任何徽标。
3. delta=0：该项显示「持平0」，无箭头。
4. 在搜索框输入关键词/切状态筛选：可见行的「上一份」仍按时间相邻，不因筛选漂移。
5. 徽标同时含箭头与文字，单看文字即可读出方向与数值（不能只靠红绿）。

### 文件级改动（预估）
- `src/client/panel.tsx`：ProgressReportTable 增加相邻 diff 纯函数（约 25 行：预计算 prev 映射 + 三指标 delta + 渲染）；`panel.css` 徽标样式。
- `scripts/verify-reports.mjs`：补快照不变式回归 + 相邻 diff 口径断言（逾期数＝overdue_task 条数）。

## 四、PROD-04 · Web「移动到…」改父 + 原子重编号（P1，M）

### 用户故事
- **US-04a**：PM 在任务表某行点「⋯ 移动到…」→ 弹出同项目任务树选择器（含「根层级」）→ 选目标父任务 → 一次确认 → 任务改父成功，WBS 编号立刻连续正确，不产生环。
- **US-04b**：选择器里任务自身及其全部后代**灰显不可选**；即使手滑，后端再次拒绝并给中文原因，数据不变。
- **US-04c**：确认弹窗点「取消」→ 磁盘零字节变化。
- **US-04d**：移动到新父后，该任务成为新父下最末子，编号已按新树重建连续（不出现 1.2 下面挂着旧编号 3.1 的错位）。

### 裁决边界（所有者拍板）
1. **Web 入口**：TaskRow 行尾「⋯ 移动到…」→ 任务树选择器（复用 `tasks` 的 parentId/code/title 构造）。**先做菜单选择器，拖拽缩进改父为后续增强，本期不做。**
2. **选择器前端防呆**：可选项排除**任务自身 + 其全部后代**（沿 parentId 链展开子树）；同项目任务才可选，跨项目不出现在列表里。**前端排除是体验优化，后端拒绝才是硬门**——两处口径以后端为准，不在前端另造环算法。
3. **改父 + 项目全量 renumber 是同一个用户动作**：一次确认 = `moveTask` + `renumberTasks(该项目)` 落在一起，**禁止前端分两条命令各调一次**（那会留下「父改了、编号没重排」的半状态）。
4. **后端原子/回滚保证（本批唯一 core 小改）**：新增复合写函数（建议 `moveTaskAndRenumber`）在**同一个** `enqueueDomainWrite` 内：先按既有规则校验（存在/同项目/非自身/非后代/无脏环）→ 移动 parentId → 对该项目全量重编号；**写前快照该项目全部任务原件，任一步失败即整体回滚到原件**。验收红线：**不允许「move 成功、renumber 失败」的半状态**——要么两步都成，要么数据回到操作前。
5. **取消零写**：不带 confirm / 弹窗取消 / 校验拒绝，磁盘零变化（沿用 dry-run 模式）。
6. **同级位置 P0 不选**：移动后任务落为新父下最末子；「插序到中间」/ 拖拽为后续增强，不在本批。
7. **命令形态不变**：仍对外是 `/pm task move <id> <新父|root> [confirm]`（confirm 后原子完成改父+重编号）；Web 复用该命令，不新增命令。`renumber` 独立命令保留不动。

### P0 验收条件
1. Web 选 B 确认 → A 成为 B 的子任务，且列表树缩进与 WBS code 立即一致、连续。
2. 选择器中 A 自身与 A 的后代不可选；强行发请求（含手测 API）选自身/后代 → 后端拒绝、中文原因、数据零变化。
3. **原子性**：模拟 renumber 阶段失败（注入故障）→ 父关系与编号全部回到操作前，无半状态；正常路径两步同成。
4. 取消/不带 confirm：磁盘字节零变化。
5. 移到「根层级」成功；跨项目目标不可选且后端亦拒。
6. 移动后该项目 code 连续无重号/跳号；重启读回一致。
7. `verify-cascade.mjs` 按契约扩展（原子复合 + Web 菜单断言）。

### 文件级改动（预估）
- `src/core/tasks.ts`：新增 `moveTaskAndRenumber()`（单写队列内移动+全量重编号+写前快照回滚；复用既有环检测与 `renumberTasks` 的连续编号逻辑）。
- `src/commands/task.ts`：`move` 分支 confirm 改调复合函数；dry-run 文案同步「改父后自动重编号」。
- `src/client/panel.tsx`：TaskRow 增加「移动到…」菜单 + 树选择器组件（排除自身/后代）。
- `scripts/verify-tasks.mjs` / `verify-cascade.mjs`：扩原子复合与故障回滚用例；`verify-web.mjs` 补菜单 GUI 断言。
