## 一、本版本主题：稳定性地基 S4 + war-room KPI 热修（零 schema）

> 内容口径：本补丁不含新业务功能，只做「地基加固」与一处真实 KPI bug 热修。**全程零 schema**——domain 仍 v1、表集合未变、`taskStatusSchema` 仍 `z.enum(['todo','in_progress','blocked','done'])`（拒收 `doing`），不新增表/列、不升 domain、不动既有落盘布局。

### A1 = 原子落盘（fs-atomic）契约钉死 + tmpNameFactory 测试缝（默认行为不变）
- **rename 是唯一切换点**：`src/core/fs-atomic.ts` 的 `atomicWriteFile` 发布协议保持「同目录临时文件 `.{basename}.{uuid}.tmp` → `open(tmp,'wx',0o600)` 排他创建 → `writeFile` → `handle.sync()` fsync → `close` → `rename(tmp,target)` POSIX 原子覆盖 → `fsyncDirectory(dir)`」。
- **rename 之前任一阶段失败只清 tmp、绝不碰目标**：open / write / sync / close / rename 本身任一失败，`finally` 仅在「rename 未发生」时 `rm(tmp,{force:true})`，目标文件逐字节不变、tmp 不残留；rename 成功后目标已是新内容、tmp 已消失。
- **`wx` EEXIST 排他闭环**：`open(tmp,'wx',0o600)` 对已存在 tmp 抛 EEXIST，失败阶段诚实暴露、不静默覆盖。
- **tmpNameFactory 仅测试注入、生产默认不变**：新增可选 `options.tmpNameFactory?: (dir, base) => string`——**仅用于测试注入以制造确定性 tmp 名/真实 EEXIST**；生产调用方不传该选项时仍用默认 `randomUUID`，对外行为、命名与并发语义完全不变（测试缝，非产品行为变更）。
- 专项 `scripts/verify-fs-atomic.mjs` 退出 0（含 A/B/C/F 成功路径顺序探针、D1/D2/D3/E 失败阶段、A1-02 wx EEXIST 排他闭环、tmpNameFactory 注入下目标内容/mtime 不变、预置 tmp 按上游契约清理）。

### A2 = LLM optional 真实 Context（核心台账不依赖 LLM）
- **llm 不列入 inject、懒读真实 Context**：`src/index.ts` 不再把 `llm` 列为注入依赖（缺 llm 的 profile 仍激活本插件）；运行期用 `ctx.reflect.get('llm', false)` **安全懒读真实 Context**（缺失返回 `undefined`），命令被调用时才取，命令层把 `optionalLlm()` 透传给 task/meeting/report 三条 AI 子命令。
- **无 LLM 核心离线可用 + 优雅降级零写**：缺 provider 时 `generateDraft` 抛中文 `NO_LLM` 降级（「你仍可手工录入」），核心 domain 与全部非 AI 命令照常加载跑通，业务零写；硬错误码（RATE_LIMIT/QUOTA/INVALID_CREDENTIAL/MODEL_TIMEOUT/NO_LLM 等）不跨池轮换、直接抛原中文，英文/stack 不外泄。
- **有（mock）网关回归正确**：有 fake llm 时走 `generateDraft` + 兜底路由，流式 chunk 经 `BlockAssembler` 组装 trim 返回。
- 专项 `scripts/verify-llm-optional.mjs` 退出 0（契约 A 缺 llm 仍加载+核心台账离线+中文 NO_LLM 降级；契约 B 有 fake llm 走 generateDraft+兜底路由）。

### A3 = verify runner 全跑聚合 / timeout 分类 / 正式资产 manifest
- **跑完全部并聚合全部失败（不在首个失败 break）**：`scripts/verify-isolation.mjs` 主循环改为任一子进程失败也立即记录、但**不中止后续 target**——全部跑完后聚合「脚本：共 N / 通过 P / 失败 F」+ 失败清单；每条目标收集 exit status / signal / spawn 异常 / 耗时(ms)。
- **timeout 分类不误标**：单目标默认超时 10min/个（`PM_TOOL_ISOLATION_TARGET_TIMEOUT_MS` 可调）；`describeFailure` 对 `ETIMEDOUT` / `killed` **单独分类为「超时（上限…实际…）」**，不再误落「spawn 异常」。
- **正式资产 before/after manifest 零污染**：跑前对受守护正式资产 root（产品 `data/`、共享 `backups/`、`exports/`，守护清单见 `verify-isolation.mjs` 的 `WATCH`）逐文件算 sha256+mtimeMs 得 before manifest；子进程 env 显式 scrub（剔除 `PM_DATA_ROOT`/`DSH_PM_BACKUP_DIR`，只打变量名不打值）；无论中间是否失败，after manifest 无条件再算一次做集合 diff（新增/删除/hash 变/mtime 变任一出现即单独计污染失败）。退出码契约无歧义：任一脚本失败或任一资产污染 → exit 1；全绿且 diff 空 → exit 0。
- **聚合纯函数复用同一套判定**：`walk/buildManifest/diff/WATCH/runOne/runGuard` 导出，供 `scripts/test-isolation-guard.mjs` 与 `scripts/test-verify-runner-aggregate.mjs` 复用，避免另写一份不一致逻辑。

### war-room「进行中」KPI 热修（`doing` → `in_progress`）
- **根因**：作战室 `computeKPI` 误判 `status==='doing'`，而真枚举为 `in_progress`——导致「进行中」KPI 恒为 0（blocked 也不得计入）。
- **修复（3 文件，语义不变除 bug 本身）**：`src/core/status.ts` 新增纯谓词 `isDoneStatus`/`isInProgressStatus`（单一来源、仅判状态字段；`TASK_STATUSES=[todo,in_progress,blocked,done]` 未变）；`src/core/war-room.ts` 的 `inProgress` 由 `status==='doing'` 改为 `isInProgressStatus(t.status)`（修复点），done/overdue 口径抽闭包 `isTaskDone = isDoneStatus(s) || progress>=100`、KPI 与 buildAgenda 复用同一份，**语义不变**；`scripts/verify-war-room.mjs` 补真枚举五态回归守卫。
