> 本文件记录产品「要做哪些功能、优先级如何、怎样算验收通过」；给开发与验收使用，按模块增删条目，并在阶段 2 评审后定稿。当前为**阶段 1 预置草稿**，仅做需求盘点，**不在环境搭建阶段展开实现**。

## 一、目标用户与核心场景

- 目标用户：项目经理 / 项目负责人（PM）。
- 核心价值：在 dsh 智能体框架之上，提供一套可对话、可沉淀、可追踪的项目管理工作台，覆盖项目从计划到交付的关键动作。

## 三、非功能需求（草拟）

- 可运行：每个迭代都必须「能跑起来、能演示」，不仅是代码或说明。
- 不破坏上游：所有自研能力以 dsh 插件形式挂载，不改 `deepseek-harness/` 源码。
- 可迁移：成果为标准 Markdown + 独立 git 仓库；数据可导出为通用格式。
- 安全：密钥不入库；命令执行与文件访问遵循 dsh 沙箱与安全说明。
- 代码质量：命名规范、关键逻辑有注释、无明显安全问题。

## 四、待确认问题（阶段 2 集中决策）

1. 是否需要真实 LLM 接入（DeepSeek API Key）？哪些功能必须联网调用模型，哪些可离线？
2. 数据存储优先使用 dsh 自带 storage，还是落地为我们自己的 Markdown/JSON 文件以便迁移？
3. 交互形态优先级：先做 Web UI，还是先做命令行 / 对话式？
4. 单用户本地使用，还是需要多人协作？
5. 是否需要导入既有项目文件（Excel / Markdown）？
