# 三轮开放对抗、修正与裁决记录

> 本文记录实际发生的角色研究、跨稿质疑和独立审证，给后续 Agent 复核归因强度。原稿保留，综合裁决不替代原证据，不构成产品 PASS。不要把下表改写成五人实时会谈、全员互答或五模型共识。

## 1. 实际执行过程

第一轮五角色独立读取相同现象台账与各自定向材料，要求不读他人复盘、提出竞争假设、支持/反证/证伪条件，不提前定责。初稿形成期间台账由 128 扩至 164，角色分别补记冻结范围，部分晚增事实未展开原件，均在原稿声明。

第二轮交换报告：产品、开发、协作架构和运维读取其他稿时，测试首稿尚未在指定位置出现；后来找到并保存测试首稿，测试角色读取产品/运维并反向提出九条质疑。四角色明示了缺件，不假称已经审阅完整测试稿；有些对 QA 的争论只针对主端转达的争点或历史 QA 原件。

主端尝试在原执行者完成后继续发回挑战，工具不接受已结束线程的 followup。因此第三轮由两位新的独立研究执行者仅对书面争点审证：合同审证人读测试/开发 R2，范围审证人读测试/产品/运维 R2。其后主端回到已核原件作终局研究分类。没有让新角色冒充首轮作者；两位审证人也明确未新查原件，不把继承引用当自己的复现。

共形成五份 R1（73 假设）、五份 R2（41 项编号挑战）和两份 R3 审证。数量仅为记录规模；部分挑战限制假说的推广，而非反驳对方已经主张的极端观点。原稿明确区分这两种情况。

## 2. 有记录的争点与终局研究判断

### D-01：“看起来没改”是缓存、违约，还是汇总错位？

产品 PM06 先强调设计认可被扩大为完整实现；运维 OPS05 保留旧 bundle 假设。测试 X-QA-01 提供 B1 默认 OFF 的验收合同，反对把开关本身判遗漏。产品 R2质疑四、运维 R2-01/02 均接受收缩：任务页新视觉试点与共享 dark/底层工程不同，摘要全量落地表述有前后冲突。

第三轮范围审证接受“默认OFF合同”和“摘要错误”同时成立，但不判所有实现违约。主端据 M01805/01807/01824、工具读代码/映射、B1合同裁决：**摘要扩大高置信；唯一运行技术原因与全量批准链待证。** 不以强刷建议代替范围检查。

### D-02：一次保存成功，能否证明历史没有损坏？

产品 PM07 重完整旅程；测试 X-QA-07 反驳旅程足以解决数据问题：打开、编辑、保存、重开都能成功，旧稳定 ID、软删审计仍可被替换。开发 Q-DEV2-09 支持数据保全与进度语义分层。

第三轮合同审证接受双方不同证明对象。主端以 B2原件判：**错误编辑模型是产品根因；空数组种子是漏出机制；GUI只验证可用路径不能证明历史全保全。**

### D-03：P-154 是否直接观察到 active 多修订塌缩？

开发 Q-DEV2-02 指出 active种子原本仅rev1，结果仍rev1，是1→1；直接观察是重编号及软删两修订记录消失。固定rv1的代码支持 active多修订塌缩预测，但不是这次种子的实测。

第三轮合同审证接受该收缩，不否认已见严重损坏。主端据 BEFORE/AFTER 表修正文中证明边界：**软删多修订丢失、active改号是历史观察；active多修订压成1是代码机制推断，需独立输入。** 不把三项报告标题当三个都已实验的证明。

### D-04：“整批零写”和“已成功项不回滚”如何并存？

开发 Q-DEV2-03 指向 B2原报告 §4/§7：若“已成功项”指本批前半段写入，两句矛盾；若指事务前已存事实，则可以一致。测试 R2没有对这句单独澄清，不能以沉默当认可。

第三轮合同审证登记待澄清。主端只确认**文本歧义**，不推断当前出现半批写入，也不修改 `docs/testing/`。后续由原专家确认时间归属与失败后预期，开发不得自行选方便解释。

### D-05：可信 J/K 是否证明所有键盘和390项本可自动完成？

测试首轮 QA01 强调人工分层扩大；第二轮 X-QA-03 根据历史记录主动收缩：J/K等可信，但Space无事件、390会话失败、某次运行提交未验证。产品/Agent第二轮也要求区分角色能力与真正本人依赖。

第三轮范围审证接受时间限制。主端裁决：**人工包过宽有据；不能由后期可执行倒推早期所有项能做。** 应分别追问用例本质、当时执行能力和有无转交。

### D-06：认证安全是否解释整轮全页人工验收？

运维强调Cookie隔离与Main-only是真边界；测试 X-QA-04 反驳把一次本人入场扩成认证后所有页面仍本人测试。产品 PM13 要入口纳入交付。

裁决：**认证可需本人；入场后客观页面走查需具备能力者继续；Main-only不是user-only。** 不能取消认证，也不能借安全边界无限扩大人工包。

### D-07：17ahead与未提交是不是同步失责？

运维初稿保留迁移缺口；测试 X-QA-02 提供已有候选diff/新文件指纹冻结反证；产品 R2质疑三保留异机接续问题。运维R2-07明确不能以数量推导竞态、丢成果或拒不同步。

裁决：**本地状态确定，冻结合理性及实时远端未由数字证明。** 独立门未过保持候选可以正确；跨机恢复材料充分与否需实测，不能为干净而绕门推送。

### D-08：构建共享是负责人并行安排造成的吗？

开发/Agent以M01628/01630保留共享产物再写入；产品/运维对负责人安排净贡献下调；测试QA12指出候选可并行但共享依赖要隔离。

裁决：**源文件分片不能保证lib单写；实际再写入有据；具体多builder及责任人待证。** 用户允许并行不等授权互相覆盖，单人合法重建也会使旧证据过期。

### D-09：预载 schemas 假阳性意味着全面禁mock？

测试X-QA-08与开发Q-DEV2-04共同支持：宿主不会预置的业务factory被测试提前赠送，才构成假阳性。第三轮接受真实平台依赖与真实异步加载序列仍可模拟。

裁决：**忠实范围是判据，不是mock有无。** 静态entry-only能提前查错，但公开bench不因此等同真实宿主GUI。

### D-10：更严矩阵是否自然提高质量？

测试X-QA-06区分根6A.1待表决、当批first checkpoint与最终交付承诺；产品/Agent反对追溯，运维保留能力成本。已有ADL-045真实GUI仍有效。

裁决：**未生效提议不追溯；当批批准合同约束当前交付；更严门要有能力和fixture。** 增加视口不能补预载假阳性，减矩阵也不能隐藏已经承诺覆盖。

### D-11：提权样本证明负责人授权后仍违规吗？

运维R2-03实际核原参数：限定段4条显式提权均在广泛授权E00358之前；后段9条默认只代表采样。Agent区分工具schema、嵌套回显与真实参数。负责人多次“还弹窗”证明反馈，不证明具体发起层。

裁决：**混层承诺有据；实际弹窗致因待配对。** 不用授权前样本指控授权后，不把默认调用成功说成全链零弹窗。新授权在明确平台动作范围内优先于旧确认条款。

### D-12：最初五方向脑暴是否已经违反后来的辩论要求？

AgentR2修正A/B指出最初M00861只要多Agent脑暴汇总，正式质疑和辩论要求在M00869以后；父派单“不动仓库/可写讨论稿”有文字冲突，但讨论稿不当然越权。产品方法假设因此收窄。

裁决：**预设方向事实成立；初始无跨作者辩论不追溯违约。** 要批评首次虚称论证，须找到当时完成表述；后期已要求开放对抗，则汇总不能再替代。拒绝强度转译另有原句证据，保留。

## 3. 不收敛为真实根因的项目

| 假设 | 为什么保持待证 |
| --- | --- |
| 压缩引发失忆 | 没有压缩前正确约束→摘要遗漏→同候选恢复后错误行动链；旧摘要可由异步或候选更新造成 |
| 五角色同模型导致同错 | 共享派单前提有据，模型元数据及对照没有；角色多不等独立，仍不能指定同模型因果 |
| 用户实际迁移云端Linux | 负责人多次否认、Darwin单点有据；缺每次对应原断言与工具拓扑 |
| 真实日均成本、套餐足够程度 | 提交、截图、回合不等计费请求；没有去重trace与账单 |
| Impeccable造成UI差 | 无同需求、同内容、同状态的受控应用对照；取审美锚点有效不证明原工具主因 |
| 普遍开发自签PASS | 早期自检不追溯，后期有独立审证反证；每批须审签身份链 |
| 正式数据已受P154损害 | 富种子在隔离域；没有正式历史前后损坏证据 |

## 4. 后续追加方式

新增证据要标“支持/反证/限定/撤回”，指向 P 与 H，保存原句、被测对象和规则时点。若撤回只影响子分支，不删整条强证据；若某个家族被新原件证伪，不以多数角色同意继续保留。原稿中的未审、缺件和自修正也保留，便于后来判断方法本身有没有误导。
