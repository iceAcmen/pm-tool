# Agent 协作架构师：第一轮独立盲评

> 日期：2026-10-21。用途：供下一轮对抗逐项挑战机制与证据，不是产品验收、责任裁定或实施方案。仅研究，未改仓库、产品、测试，未启停服务、提交、推送或加载 vendor。

## 1. 范围与判断边界

本轮读取事实台账 P-001 至 P-164、对话证据摘录、主轨迹、早期对话以及原子代理全集；未主动读取其他角色本轮观点或旧复盘。全集中的历史团队报告属于当时收到的信息，不作为本轮独立结论。主假设是：问题集中发生在“负责人意图→父代理派单→子代理执行→证据汇总→交付承诺”的转换接口，而非简单的“子 Agent 弱”或“用户复杂”。

引用简写：`M00454` 表示 `DB-m_0cwRI8ya92K-L00454`；`E00067` 表示 `DB-o_000E1LJmvjj-L00067`；其他代理保留完整 ID。具体文件见末尾。JSONL 的 `line` 是原轨迹物理行，不是对话 Markdown 行。

身份必须分四类：负责人直接输入、父代理派单、工具结果、代理解释。早期 `E00049/E00221` 虽标 `user`，正文明确为转交任务，不能当负责人逐字原话。`M00786/M01636` 是系统打断通知，不计负责人主动指令。工具声明中的 `require_escalated` 不等于实际调用该参数。

置信度针对机制解释，不是对人的评分。“高”表示有原始行为链支撑；“中”表示关键接口缺测；“低”表示仅能提出风险。多个摘录来自同一轨迹，不能冒充多个独立来源。本轮未执行新实验，证伪项是下一轮可请求的验证，不是已完成工作。

## 2. 可检验假设

### H-AG-01：转译改变了操作对象与授权强度

**关联 P 号：** P-129、P-072、P-126。

**机制：** 父代理没有保留“负责人原句／补充背景／自行推断”的分层，把推断写成任务事实；下游忠实执行也会偏离目标。

**证据：** `M00006` 只要求修改伙伴档案；父派单 `E00049` 指定仓库档案文件、本地提交，`E00067` 随后纠正不要入 Git。另 `M00861` 是“两条路线都不错，但没超出预期”，`M00863` 已转成“用户已明确拒绝”，并允许在仓库新增方案文档；与“先不用做任何改动”的范围至少存在张力。

**反证：** 初始全项目归档要求可能使“档案”确有歧义；负责人后来确实希望突破常规，不能判全部转译无效。

**如何证伪：** 对原句与派单做逐句对齐；若操作对象、拒绝程度均获负责人明确确认，或下游仍拿到未改写原文且自行改变对象，应降低父转译解释。

**置信度：高。** 已证转译失真，不主张存在故意误导。

### H-AG-02：并行分派被包装成独立脑暴与对抗

**关联 P 号：** P-071 至 P-075。

**机制：** 先指定方向、边界和示例，再让作者各自产出，得到的是预设框架内扩写；没有作者答辩与独立裁决，汇总者的“碰撞”不能替代辩论。

**证据：** `DB-o_000E4QFVNst-L00011` 至 `L00015` 不只指定五派，还给具体脑洞、禁止跨界；`L00020` 收齐后由组织者亲自收敛，`L00023` 即写文档。`M00869` 准确质疑方向预置和缺少讨论。

**反证：** 这种分工有利于覆盖，且最初负责人允许“多个子智能体头脑风暴后汇总”，并未先要求正式辩论。`M00872` 后续提出盲发与角色分离，说明方法可修正。

**如何证伪：** 若能提供汇总前跨作者攻击、逐条回应和裁决记录，或派系由盲发素材自然聚类形成，应撤回“无对抗”；仅有五份不同报告不足。

**置信度：高。** 问题在产物命名与论证强度不匹配，不是并行本身有错。

### H-AG-03：技能接入没有闭合到任务中的实际应用

**关联 P 号：** P-064、P-065、P-148、P-066。

**机制：** 安装、指纹校验、路由命中、读取方法、应用方法、独立验证是六个不同状态。若只证明前几项，“专家已参与”会被高估。

**证据：** `E01004` 明确要求 Agent 自行判断，不让用户点名；`E01030` 承诺自动选择。`M00470` 后负责人仍点名三个设计技能，`M00698` 又追问为何不找伙伴。走查派单 `DB-o_000E2C30nXa-L00008/L00009` 已要求实际读相关方法，但这只能证明派单，不能证明应用效果。

**反证：** `E01003` 存在首个 code-review 试点归档；历史走查确有截图和审计产物，不能断言所有技能未用。也不能用差 UI 反推未读技能。

**如何证伪：** 提供具体任务的“版本→读取→选用规则→被改变决策或组件→独立验证”链，若连续完整且负责人能辨认参与成果，安装到应用的断层解释应收缩。

**置信度：中高。**

### H-AG-04：角色分离不等于认知与证据独立

**关联 P 号：** P-072、P-119、P-120、P-158。

**机制：** 多个 Agent 若接收同一预置结论、模拟环境和摘要，其错误会相关；换名字、调用 code-review 或路由到 tdd 不会自动增加独立观察。

**证据：** 五派派单共用“用户已否决”前提；P-158 的测试主动预载宿主未注册模块。P-119/P-120 又显示独立角色也会识错对象。`M00872` 自陈共享同类训练数据是局限，但不是实际模型身份的证明。

**反证：** `E00374` 的独立浏览器验收发现网页命令前缀错误；P-154 的富种子探针发现历史破坏，均证明角色分工有实际价值。

**如何证伪：** 对照“共享摘要组”和“原文盲读、独立采证组”的缺陷发现率与同错率；另需运行元数据才能检验是否模型同源。当前不能断言具体模型相同，更不能声称同源造成某个缺陷。

**置信度：共享证据相关性中高；模型同源因果低。**

### H-AG-05：任务树没有映射到真实能力树

**关联 P 号：** P-123、P-145、P-149、P-084。

**机制：** Organizer 名称被误认为比普通 Subagent 有更高桌面权限；能力直到验收末段才发现，形成等待或把可自动化页面流程扩大为人工项。

**证据：** `DB-o_000ESCJg73J-L00026` 得知子代理桌面被拒后仍决定自己执行，`L00031` 被同门拦截，`L00032` 才修正。`E01207` 用户多项实测失败并质疑自动化能力；`E01208` 承认分层扩大错误。

**反证：** bu 子代理确有采证成果；而 `M01080` 在主轨迹内也收到 Subagent 拒绝，说明日志所在层和实际调用身份不能简单等同。“Main-only”不是所有时点都可执行的保证。

**如何证伪：** 查看每轮实际调用身份、工具权限与最小探测记录；若派发前矩阵准确且已预留 Main 采证，瓶颈应转查认证或产品。页面主题/视口/键盘与原生 Finder 操作须分别验证。

**置信度：高。**

### H-AG-06：环境断言缺少时点与执行层限定

**关联 P 号：** P-028、P-029、P-031、P-032、P-006、P-009、P-015。

**机制：** 把远端浏览器、命令行运行时或历史摘要的环境，投射成负责人设备状态，导致错误拒绝、重复核查和不必要迁移解释。

**证据：** 负责人反复否认切云端；`M00134` 实测 `uname=Darwin`。早期 `E00008/E00013` 已能区分豆包自带 Node 与系统终端，P-015 又显示浏览器 loopback 可达性与本机服务不是同一问题。

**反证：** 抽样原始 assistant 文本未找到明确“你已切云端 Linux”的对应句，可能来自未保留界面状态或其他输出；不能证明从未出现远端执行器。

**如何证伪：** 补齐每次误报前的 tool-call 身份、主机探测、浏览器连接拓扑。若确有 Linux 执行层，只能纠正“设备”表述，不能将真实能力阻塞判为幻觉。

**置信度：现象高；混层机制中。**

### H-AG-07：状态快照被当作存活与进度的权威

**关联 P 号：** P-068 至 P-070、P-076、P-099、P-140、P-147。

**机制：** 摘要版本、Agent 存活、文件产出和依赖等待没有分轴记录。旧摘要可被反复消费；活着不等于推进，不产出也不等于模型卡死。

**证据：** `M00784` 用快照时间、文件停更、消息无回复三项才判断疑似停滞；`M01635` 快照仍述 FAIL2，`M01644` 当前模块门已通过。`M00954` 问滞后统计，紧邻回复却转为交付，未给时差统计。

**反证：** 首次诊断确有三信号交叉，不是只看快照；摘要后台刷新本就可能延迟。上述通过结果也不能证明先前失败从未成立。

**如何证伪：** 对齐真实工具完成时间、摘要生成时间和 Main 读取时间；若大部分停滞其实有持续工具活动，应归为监控失真而非执行卡死。需记录等待谁、等待多久，而非只记百分比。

**置信度：中高；底层卡死原因未知。**

### H-AG-08：继任与服务切换缺少可恢复事务

**关联 P 号：** P-042、P-069、P-099、P-133、P-140、P-141、P-144。

**机制：** 终止旧执行者或旧服务后，未确认继任名额、子任务退出和候选可启动；中断把“旧已停、新未起”变成持久不可用状态。

**证据：** `M01638` 返回 `cancelling`，`M01640` 创建新 Organizer 因单请求配额失败；`M01641` Main 被迫接管。早期 `E00583` 停旧服务，`E00586` 后查无监听；`E00648` 再确认中断点正是旧停新未起。

**反证：** `M00787` 后继任有恢复成果，仓库落盘确实降低损失；P-144 的具体启动可能另受权限限制。用户本次提及“P143启服卡住”，最新版台账对应 P-144，P-143 是独立测试要求，不能混号。

**如何证伪：** 若旧终止前已完成继任能力探测、候选 smoke、子进程清单与回退点，失败仍发生，应调查宿主启动缺陷。`kill_agent=cancelling` 本身不能证明后台构建全部退出。

**置信度：高。**

### H-AG-09：源文件分片没有隔离共享构建产物

**关联 P 号：** P-099、P-157、P-158、P-159、P-161。

**机制：** 不同源码 owner 的整包 build 共写 `lib/`，冻结时可能混入另一轮文件，产生版本漂移和失效证据；口头冻结不能保护已经运行的写入者。

**证据：** `M01628` 观察冻结后产物重新生成，`M01630` 给出 client/editor 同时更新时间。父派单 `DB-o_000E60enWqn-L00540` 已限制共享文件与服务 owner，但没有据此证明构建目录唯一写者。P-157 的包内补丁漏带还说明 profile 配置不能替代包契约。

**反证：** schemas 同步加载错误本身即可解释失败；不同 bundle 哈希也可能仅来自不可复现构建，不能独自证明覆盖。

**如何证伪：** 对照每个 build 的 PID、cwd、输入提交、dirty diff 和输出清单；若候选为隔离树独写且失败仍复现，应将主因归包契约，而非并发。只有文件变更，尚不能锁定哪个 Agent 写坏。

**置信度：共享产物风险高；具体竞态因果中。**

### H-AG-10：授权被误建模成一个开关

**关联 P 号：** P-126、P-134 至 P-138、P-145、P-146。

**机制：** 负责人业务授权、仓库操作范围、工具 sandbox、macOS 应用控制和浏览器认证五层不同；代理却先承诺“不会再弹”，再逐次更换解释。

**证据：** `E00358/E00394` 是负责人持续授权反馈；`E00386` 声称仍为“始终询问”，随后负责人否认。`E00437` 称彻底解决，`E00443` 再反馈，`E00444` 改归系统图形/网络授权。`E00436` 可见实际参数 `sandbox_permissions=use_default`，只能证明抽样默认调用，不能证明所有弹窗来源。`M00298` 又直接授权以后自主 push。

**反证：** 系统审批确可独立于业务授权；不能把投诉次数计为人为再问次数，也不能仅凭根规范判所有历史 push 越权。`E00787` 是代理请用户重跑 Terminal 的实际人工请求，但不是同一审批类型。

**如何证伪：** 每次弹窗绑定调用 ID、参数、发起层和权限种类；若全由系统强制审批，无新增人为追问，应撤回重复提问归因。另按时间核授权生效、撤销、风险例外，禁止静默选最宽或最窄版本。

**置信度：层次混淆高；弹窗具体归属中低。**

### H-AG-11：压缩可能固化旧结论，但尚未证明失忆因果

**关联 P 号：** P-076、P-099、P-125、P-127；`M01058`。

**机制：** 若压缩只保留“当前结论”而删掉原句、修正和证据版本，继任会把过期判断当事实；重复文档快照进一步放大这种风险。

**证据：** 负责人问“正在压缩”含义；P-125/P-127 存在多份“当前”与新旧规则冲突，P-099 有被文件推翻的摘要。这些共同说明恢复输入不唯一，不说明压缩器已造成某次错误。

**反证：** 指令失真在首次派单就已发生；过期也可由异步通信、文档未更新或构建覆盖造成。现有导出主要是 role/text，缺每次压缩前后完整上下文与模型调用元数据。

**如何证伪：** 找到相同任务压缩前正确约束、压缩摘要遗漏、压缩后错误行动的三段链；若摘要完整或错误先于压缩，撤回该次因果解释。摘要应保留未决项、授权原句、候选身份与证据过期条件。

**置信度：风险中；实际因果低。**

### H-AG-12：局部自洽证据掩盖跨边界与历史状态破坏

**关联 P 号：** P-154 至 P-162、P-119 至 P-122。

**机制：** 以干净新记录、纯函数和便利 mock 代表真实存量及宿主，前后端各自正确却无法串成用户旅程；稳定 ID、软删和修订历史最易被新建测试漏掉。

**证据：** P-154 富种子发现 at/pl 重编号与历史缩减；P-156 wrapped 状态前端不显示；P-160 往返正确却污染共享备份；P-162 后端演练成功却无确认入口。`M01635` 明述旧测试预载 schemasFactory，`M01644` 改按平台表加载后通过；`E00681` 则有 zod 外部依赖造成浏览器不激活的历史实例。

**反证：** 富种子、宿主语义门本身是有效独立测试产出，不能归为“测试都无效”。P-119/P-120 还提示测试会误认控件，判 FAIL 也须审证。

**如何证伪：** 对照原先测试是否真的覆盖历史 ID、软删、多版本与零预载宿主装载；若已覆盖且仍漏报，再查断言、运行版本或并发污染。需要实体→UI→payload→落盘→重启的双向合同，不只增加用例数量。

**置信度：高。** 产品缺陷仍各有直接根因，此处解释为何协作验证可能漏检。

### H-AG-13：额度估算缺少请求级可观测性

**关联 P 号：** P-062、P-063、P-163。

**机制：** 提交数和文件数是产出代理量，不是请求数；父子 Agent 回合、模型调用、工具调用和套餐计费单位未对齐，经验倍数把未知成本伪装成已算清数据。

**证据：** `M00454` 以 219 提交推算 8 天 3854–7708 次，开头称“数据算清楚了”；`M00460` 承认 2.2 倍系数没有嵌套 trace，改为 7000–15000 次。增加截图/文件数量不能校准每次计费，更不能推出五小时峰值。

**反证：** 原文明确标估算区间，并最终建议先实测套餐，不是声称精确账单。

**如何证伪：** 用真实调用 ID 去重父子树，区分重试、工具与付费模型请求，再与供应商账单校准；若经验系数已被独立样本验证，应恢复其有限预测价值。

**置信度：高。** 本轮不复算套餐，不认可新扩大区间比旧区间更接近真实值。

### H-AG-14：UI 投诉后先给根因叙事，后查实际应用

**关联 P 号：** P-030、P-064、P-164。

**机制：** 为快速解释失败，代理把技能标签与自身风格偏好构成单因故事；缺对照时可能换工具、重设计，却保留真正的加载、状态、响应式和执行缺陷。

**证据：** `M00049` 立即称 Impeccable 是防守型工具、“错是没了”，并归因自己定暖纸青绿；紧邻证据主要是截图读取与用户投诉，未展示同输入、同模型、同页面的受控对照或技能应用记录。

**反证：** 承认自行定方向，并转向负责人认可设计稿，可能有效纠偏；`M00060` 确有认可。用户满意不等于工具归因成立，技能名称不等于能力边界。

**如何证伪：** 审计实际所读版本与规则，再用相同内容/约束比较“未应用、完整应用、仅换风格”；若工具在既定质量指标上持续受限，才能支持有限工具边界判断。

**置信度：无对照归因高；Impeccable 是主因低。**

## 3. 首轮综合判断

证据最强的不是“再加一个专家”，而是接口失真：原意被强化、派单与实际能力不匹配、活跃摘要替代真实进展、源码 owner 未覆盖构建目录、局部测试外推全旅程。增加角色和技能只有在这些接口保真时，才可能产生独立增量。

不宜预先规定所有问题同源。P-154 的历史数据破坏、P-158 的 mock 装载偏差、P-134 至 P-138 的授权弹窗，分别涉及数据合同、测试模型、执行权限，直接机制不同。协作架构可以解释它们为何被放大或晚发现，不能取代各自根因。

下一轮应优先挑战四点：父派单是否有遗漏授权原句；Main/Sub 实际工具身份是否改变；冻结后写入者是否能定位；“人工待验”是否有逐项不可自动化证明。模型同源与压缩只保留为低置信风险，不以它们兜底解释所有失败。本轮所有证伪实验均未运行，亦未给产品 PASS。
