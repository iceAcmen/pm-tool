## 2. 最小 Oracle

这是对本单已授权有限合同的独立细化，不是自由设计平台规格。字段名采用 A12 建议的 `sorts` / `columns` 作为先行测试载荷；若后续实现使用等价名字，**由独立专家**调整载荷/选择器并保留修订证据，不让开发删断言或改变语义来变绿。

| 项 | 唯一最小预期 |
| --- | --- |
| 原两规则 | `[{field:"priority",dir:"asc"},{field:"dueDate",dir:"desc"}]`；按数组顺序，第一非并列比较决定，方向独立。priority 使用既有 P0<P1<P2；不用看板模型代替 TaskTable |
| 合法字段/方向 | 字段仅现有 `code/dueDate/priority/progress`，方向仅 `asc/desc`；不允许表达式/任意字段。日期比较 ISO 日历值；progress 继续生产 `resolveTaskProgressMeta(...).display`，不改用 raw progress |
| 稳定 tie | 先保持旧同层 numeric WBS code 顺序作为稳定基序；新规则全并列保这个顺序，相同 code 防御性并列再保输入相对顺序。它不是可配置第三规则，不自动重编号 |
| 空日期 | 合法 record 无日期使用**缺键**；新规则 asc/desc 均将无日期置同层末尾，多个无日期再按下一规则/tie。空串/null 不是当前 record schema 的合法种子，不注入生产库；clear update 的 null 不冒充 read record |
| 规则坏值 | 缺省/空数组走旧单 sort；非数组、任何未知字段/坏方向/非对象成员使整链回旧单 sort，不部分执行丢意图，不抛；保 query/chip/grouped/sort |
| 重复字段 | 合法规则按首条保留，重复项移除，后续不同字段保序；`priority asc, priority desc, dueDate desc` 有效为原两规则。非法项仍按整链兜底 |
| 新旧互斥 | 非空合法 sorts 优先；选择已有快捷单 sort 明确退出多规则，并保列偏好。空链仍沿旧四 sort 的方向/进度口径和树路径 |
| 树 | 根之间、同父兄弟之间应用新规则；前序父在子前、后代连续；不同父的子不混排，折叠整支有效。旧无规则仍旧 WBS 树；不改 code/order/parentId/ID，不写任务 |
| 可选列 | 仅 `assignee/priority/dueDate/progress` 布尔显隐；缺键=true，坏值逐键=true，未知键忽略。不开放编号/标题/必要操作的隐藏，不造新列/schema/列宽/列序 |
| 列实际效果 | 表头、叶行、父行、状态头占位和 grid 轨道同源；隐藏无空轨/错列，恢复回原列。编号/标题/选择/折叠/编辑及原编号复制保留，任务字段、记录数、全字段导出不删 |
| 加法兼容 | 旧四态精确默认和六内置 ID 不变，旧 v1 JSON 可读。新偏好 optional，不写业务 schema、不清库/清 localStorage/重建视图 ID；当前 version=1 加法足够，不强制版本升级 |
| equality/摘要 | 同有效规则/列值相等；方向、顺序、显隐改变 dirty。缺偏好与空规则+全显等效。摘要表达规则顺序/方向/隐藏列，不只显示 legacy sort |
| 持久 | 项目键 `pm-task-views:<id>`；save-as/new ID、update同 ID/原位置、default/rename/delete 保完整偏好与四态。默认属于各项目；B无默认重置旧默认而非继承A；回A恢复其默认 |
| 存储失败 | 缺属性、属性访问/读失败、仅写失败分别验证；不抛、会话保输入/视图且项目隔离。不承诺禁存储时跨刷新永久恢复，不加后台/跨设备/团队同步 |

不设任务表 max3，不把看板上限移植进来；本单的三条重复测试只测去重。排序/显隐仅展示偏好，不扩 WBS 领域操作、任意自定义 schema、同步服务或原设计提议矩阵。

## 5. 原始结果与红原因

正式评审使用 **r3**，保留 bootstrap/r1/r2，不覆盖、不删红。

| 轮次 / 命令 | 退出码 / 原事实 | 判读 |
| --- | --- | --- |
| bootstrap `node ...-run.mjs r1` | 1，检查误要求顶层vite，尚未创建r1/执行测试 | 设施BLOCKED；已有Vitest会解析其依赖，取消不必要顶层要求，不安装 |
| r1 `node ...-run.mjs r1` | fixture=0（2通过）；red=1（36失败/8通过/2筛选跳过） | 21个组件用例 `React is not defined` 来自漏冻结原tsconfig，不计产品红。有效SOURCE/函数失败保留 |
| r2 `node ...-run.mjs r2` | fixture=0（2通过）；red=1（30失败/14通过/2筛选跳过） | 原tsconfig加入冻结，组件真实运行；修自有progress cell选择器为生产 `.pt-prog`。无产品修改 |
| r3 `node ...-run.mjs r3` | fixture=0（2通过）；red=1（36失败/15通过/2筛选跳过） | 补实际apply、父/叶占位、属性访问异常、旧态set-only隔离例；53例分两阶段覆盖，无加载/ReferenceError/TypeError冒产品红 |

r3逐层：**SOURCE 3红；AUTO 32红/6通过；BASE 1红/9通过；FIXTURE 2通过**。两阶段的筛选skip仅是另一阶段所跑用例，不是豁免、不是GUI通过。36红是36个断言失败，不是36个独立产品缺陷。

最小原因：

- **RA-GAP-U4维持 SOURCEFAIL**：`TaskViewState` 无 sorts/columns，`normalizeTaskViewState/saveTaskView` 丢偏好，`sameTaskViewState` 只比四态。首载/apply/update/项目恢复仍不处理新偏好。
- **RA-U401实组件红**：期望 C,A,B，实际 B,A,C；grouped也读不到新链，默认树的 `indexChildren` 再按WBS序。只补有序数组不能证明树实际呈现已修。
- **RA-U402实组件红**：隐藏四列的表头均仍存在；父/叶行 cell 数不减，不能把窄屏CSS隐藏当用户偏好实现。保存/薄层回读同样丢新键。
- **U4-LS-01有限旧缺陷**：`persistTaskViews` 的 setItem 抛错后把仓留在memory；下一次 `loadTaskViews` 若 getItem 成功返回null，却用空仓覆盖memory。只用旧四态的专例实际返回undefined而不是旧state，证明不是新增字段才触发。交Main有限修复/复验，不在本单改薄层，不要求永久同步。

红例证明范围有限；稳定tie/坏值的绿可能由缺实现兜底得到，不能抵消原多规则红，也不能关闭 RA-U401/402。
