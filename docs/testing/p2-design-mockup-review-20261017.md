# P2 设计独立审查：可验收边界与偏差（2026-10-17，按最新实现复核）

> 是什么：开发前对设计提案与 4 张 P2 mockup 做只读审查，把「设计意图」翻译成可实测的验收边界，并标出 mockup 自身与提案/现网不一致、会直接改变验收判定的点。
> 范围声明：本批**实施 P2-2 Token 2.0**（经所有者从 §11.3「设计图不进代码」提升为本批实施项）。**P2-1 左导航、P2-5 命名视图/复合过滤/MD-CSV-JSON 导出/离线只读快照上一批已实现**，本批不重做功能，但其视觉纳入 Token 校准与非回归（§3、§4）。**P2-6 AI 溯源此前只有设计、未实现**，本批不实现、不按已实现计分；离线治理闭环可受控验证（§5）。
> 证据等级：Observed（逐行读 HTML/CSS/源码）> Measured（待执行阶段实测计算）> Inferred（标注）。

## 0. 审查方法与依据（如何落到验收）

- 提案 §5 token 规范、§6 组件契约、§9 断点、§10 a11y、§12.3 P2 验收、§12.4 跨批不变量为**验收基线**；mockup 是表达载体，**mockup 标注不得替代实测**。
- 设计系统治理方法（Stabilize→Consolidate→Adopt→Evolve、迁移必须带映射表、token 按意图命名、暗色非机械反色）直接转化为 Token 批的 AUTO 门：缺映射表/一次性改名/别名即删 → FAIL，而非「样式差不多」。
- AI 四控制门（Distinction 区分 / Inspection 可预览 diff / Recovery 可撤销 / Traceability 可溯源）与「不给无依据的精确置信分」直接转化为 P2-6 未来验收门；离线治理闭环用确定性缝验证，不依赖收费模型。
- 对比度一律**计算实测**（正文 ≥4.5:1、大字 ≥3:1、组件/图标 ≥3:1），不采信肉眼或 mockup 上的「已达标」标注；自动化结果只是输入，最终以真实渲染目视 + 实测为准。

## 2. p2-2-token-2.html（本批实施对象）逐条边界

### 2.1 可采纳的验收边界（Observed）

1. **两层收敛为单层语义**：现状 `--pm-*`（旧语义，panel.css :root）与 dsh-flat `--*`（.pm-shell）并存，同角色两套命名（实测消费计数：`--pm-line` 154、`--pm-ink` 92、`--pm-secondary` 100；同时 `--muted` 72、`--faint` 99、`--surface` 70、`--field-bg` 41）。新层一个角色一个 token，内部映射「宿主别名 → fallback」。
   - **验收影响**：AUTO 门要求产出旧→新映射表（mockup 已给样例：`--pm-ink/--ink→--color-ink`、`--pm-surface/--surface→--color-surface`、`--bg-elev/--field-bg→--color-surface-2`、`--pm-line/--line→--color-line`）；映射表缺项或新层无宿主别名优先回退 → FAIL。
2. **补未定义/缺失项**：`--on-primary`（主按钮文字色）、`--c-link`（链接色）补定义；新增图表序列 `--color-chart-1..5`、动效 `--ease/--dur-*`。
   - **验收影响（实测发现，比 mockup 更具体）**：现网 `--pm-on-primary` 已在 panel.css:62 定义并被 16 处消费；但 `--c-link` 在 `views/tasks.css:218-219` 仍被消费而**全仓未定义**（颜色落到继承值，是现存 unresolved var）。Token 批必须：要么定义 `--c-link`、要么把消费点迁到新链接 token，**验收时不允许存在解析不到的 var()**。
3. **四阶段渐进迁移**（mockup §迁移与废弃顺序）：①建立新 token+映射+补项 → ②新页面消费新 token、旧 token 作别名保留、逐视图验证 → ③别名收敛、标 deprecated、保留一个版本周期 → ④安全删除旧定义+回归浅深。
   - **验收影响**：本批只允许落在阶段 1–2。**禁止一次性改名、禁止本批删除旧别名**（删除会破坏未迁移视图与宿主/自定义板卡）；旧别名在本批结束时仍须解析到同值。
4. **图表序列 S4 violet 本批不定义、不启用**：mockup 把 `--color-violet #7c5cf0` 列入色板仅为设计表达；现批准口径为 S4 **不定义、不启用，未来多项目序列再另定**（不在 CSS 写死 #7c5cf0 槽位）。
   - **验收影响**：本批**不落地该 token、不在任何 UI 面启用紫色填充/品牌面**；出现可见 violet 状态面或写死 S4 hex → FAIL（§12.4-4 零新品牌色）。

### 2.2 会改变验收口径的偏差（Observed，必须在计划中纠偏）

| # | mockup 现状 | 与提案/现网冲突 | 验收口径（据此判） |
|---|---|---|---|

| T2-D2 | 深色切换用 `body[data-theme="dark"]` 自切 | 现网主题机制是 `body[data-ds-dark-theme]`，宿主主题跟随 | 实现不得新建第二套主题开关；新 token 深浅双值仍挂在 `body[data-ds-dark-theme]` 下，宿主别名优先 |
| T2-D3 | 字阶 display 23/750、页面大标题 27px、卡片圆角 14px、间距含 40px | 与提案 §5.2/§5.3（display 22/750、卡片 r=12、间距 4/8/12/16/20/24/32）和 MOCKUP-SPEC 不完全一致 | 以提案 §5 与现网 `--t-*`/`--r-*`/`--sp-*` 为准；mockup 的 27/14/40 是排版示意，验收不要求照抄数值 |
| T2-D4 | 迁移表只列 8 行，未覆盖现网全部消费（如 `--pm-secondary/--ink-2`、`--c-done/prog/block/late/todo`、`--field-bg`、`--bg-elev` 实测 0 消费、`--pm-hover`、`--shadow-*`、`--sp-*`/`--t-*`） | 映射表不完整会导致漏迁 | 验收要求映射表覆盖**现存全部被消费 token**（以执行期全仓 var() 清点为准），未消费项可列「保留/废弃」而非漏项 |

### 2.3 现网只读勘察（Observed，供开发对码、供验收清点）

- 双层消费计数（执行期以新清点为准）：`--pm-line`154 / `--faint`99 / `--pm-ink`92 / `--c-prog`86 / `--pm-secondary`100 / `--muted`72 / `--surface`70 / `--c-done`59 / `--c-block`58 / `--c-late`58 / `--field-bg`41 / `--pm-surface`57 / `--c-todo`22 / `--pm-canvas`14；`--bg-elev` 当前 0 消费。
- 现存待处理 drift（记录为观察项，不要求本批擅自改语义）：
  - `views/tasks.css:218-219` 消费未定义 `--c-link`（T2-D1 同源）。
  - `panel.css:163` `.pm-rail-logo` 用 `linear-gradient(135deg, var(--c-prog), var(--c-prog-d))` 品牌蓝渐变；提案 §2.3 禁品牌渐变。属既有品牌标，是否压平由产品/开发定，**验收只要求 Token 批不新增渐变、不把渐变推广到 CTA/卡片**。
  - `views/tasks.css:134-135` 吸顶表头 `backdrop-filter: blur(14px)` 毛玻璃；提案 §2.3 禁玻璃拟态。属功能性吸顶，记录为观察项，不强制本批移除。
  - `views/overview.css:230` 一处裸 `rgb(255,255,255)`（彩色底上的白字），清点时核对是否应由 on-primary 语义色替代。

## 5. p2-6-ai-provenance.html（未实现；本批不实现，离线治理闭环受控可验）

> 重申：P2-6 此前只有设计，**不是已实现功能**；离线治理闭环（草稿预览、确认前零写、确认落库、撤销回滚、拒绝/失败、离线降级）可用确定性缝/受控 fixture 在不调收费模型下验证；真实模型生成需用户本人提供受控通道，标 MANUAL_PENDING。以下是为未来批次冻结的验收框架，本批全部 NOT_RUN。

### 5.1 四控制门映射到未来验收（Observed）

| 门 | mockup 表达 | 未来可观察验收标准 |
|---|---|---|
| Distinction 区分 | AI 草稿卡「AI 生成·草稿」标记 + 虚线框；已确认落库不带 AI 标记 | 人工内容/AI 草稿/已确认落库/已失效四类可区分，**不只靠颜色**（图标+虚线+文字标签并存，读屏可达） |
| Inspection 可预览 | 每段带「基于 N 条任务·N 里程碑·口径版本」来源 chip，展开分组列依据记录；更新=旧值删除线→新值 | 落库前能看到影响对象、字段 diff、来源记录；引用须实质支撑该句，不堆砌来源列表 |
| Recovery 可撤销 | 草稿→确认落库→撤销三态，落库前快照，撤销回滚且留痕不删除 | 人工确认前**绝不写入、不自动执行**；撤销入口可见；撤销限制/窗口真实可见；撤销后台账回滚、操作留痕 |
| Traceability 可溯源 | 来源分组（任务/里程碑/口径版本）+ 确认人 + 时间 + 快照号；失效行置灰警告、重新校验前后对比 | 失效/口径变更行自动置灰、不删除、不参与汇总、给「重新校验」；重校写新结论并留旧版；离线降级仅显缓存、不生成新建议 |

### 5.2 现网已具备的撤销能力（Observed，未来验收在此基础上复核，不假设缺失）
- `commands/ask.ts` 已实现 ask-undo：落库成功返回 undoId，10 分钟进程内 TTL、最多保留 3 条；update 恢复原始快照、create 删除新建、回滚顺序与落库相反、一次性失效；重启失效并引导 `/pm restore` 备份兜底。前端落库后 `ask-undo list` 取句柄、渲染撤销按钮。
- **验收口径**：未来 P2-6 不重复造轮子，先复核现有 ask-undo 的可见性、限制披露、回滚正确性；缺的是 mockup 里的来源分组/失效重校/置信诚实等未建能力，而非从零补撤销。

### 5.3 会改变未来验收口径的偏差（Observed）

| # | mockup 现状 | 原则冲突 | 未来验收口径 |
|---|---|---|---|
| P6-D1 | 建议卡「86% 置信度」环形精确数字 + 高/中/低阈值 ≥80/60-79/<60 | 无可验证、未校准的精确置信分制造虚假确定性（默认不加置信分，除非已校准、可解释、对决策有用） | **没有可验证模型置信度时必须写「未提供」**；只允许定性高/中/低分档且说明依据，禁止裸百分比环；阈值须由产品/评估定，不照抄 mockup |
| P6-D2 | 离线降级条「仅展示已缓存溯源」 | 离线治理闭环可由确定性缝验证，**不被迫调用收费模型**；真实模型生成才需用户受控通道 | 离线治理项 AUTO/GUI 可验；真实生成 MANUAL_PENDING，不以「未配 Key」把治理闭环判 BLOCKED |
| P6-D3 | 草稿保留 7 天、链接 7 天有效等数字 | 属产品策略，mockup 自定；现网撤销窗口已编码为 10 分钟 | 保留期/阈值/权限全部标「待产品决定」，不由测试或实现自造；改动现网 TTL 须负责人另立决策 |

## 6. 跨批视觉不变量（Token 批 GUI 走查统一口径，源自用户已认可/已拒绝 + §12.4）

**已认可（保持，不回退）**：任务页现行密度与 dsh 主题；合理多色允许（状态语义色）。
**已拒绝（出现即 S2/S3 缺陷）**：
1. 暖黄/偏黄调色、新品牌色、品牌蓝大面积 CTA、品牌渐变、玻璃拟态、光晕、3D 仪表、装饰大数字动画；
2. 廉价大数字卡（把每个指标做成孤立大数字卡片/圆环）；
3. 重复信息（同一数字/结论在卡内卡外重复）；
4. 贴边（内容顶到容器/视口边缘无呼吸）、窄表单错位；
5. 无意义留白（里程碑大 padding 式反例；卡片贴合内容，空态紧凑而非占位大片空白）。
**一致性硬指标（GUI 目视 + 抽测实测）**：字体角色/字重、间距阶、圆角、边框、状态层级全产品一致；所有日期/进度/计数数字 `tabular-nums`；边框与阴影不同时上；状态必须带文字标签不单靠色；不靠 hover 传值/传操作。

## 7. 审查结论
