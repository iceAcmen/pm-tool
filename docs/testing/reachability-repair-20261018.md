### A1 导航可达（宽屏 / 675 / 窄窗同源）`[切]`
- 前置：已选中一个项目；三视口分别执行。
- 步骤：

  3. N(390)：ViewSwitcher 下拉保留「目标（OKR）」项，不回归。
- 通过标准：三个视口都能从导航一次点击进入 OKR 视图；`aria-current="page"` 表达选中；无入口隐藏在二级以上菜单。
- 证据：三视口 rail/下拉截图 + 点击后 URL/视图状态；675 帧必采。

### A2 真实空态（无 OKR 记录）`[浅][深][刷]`
- 步骤：进入 OKR 视图（无种子）→ 核对空态卡「暂无 OKR 记录」文案；切深色；手动刷新/重进视图。
- 通过标准：空态文案诚实（「由人录入或经收件区确认归属后在此呈现；前端不自动创建、不自动定稿」）；深浅两态文字对比达标（≥4.5:1，沿用 token，不新造近黑色）；刷新后仍为空态，不杜撰记录。
- 证据：浅/深空态截图各 1；刷新前后 DOM 记录。

### A3 OKR 收件区 · 三种数据态诚实区分 `[键][刷]`
- 前置：隔离种子覆盖三态（无快照携带 / 携带且空 / 携带且有 1 条 pending 建议）。
- 步骤：
  1. 未携带 inbox → 显示命令行提示分支（`/pm okr inbox <pid>`），**不伪造建议**；
  2. 携带且无 pending → 「暂无待处理建议…未确认不进入主档」；
  3. 携带且有 pending → 列出建议（ID/标题/类型/时间/理由），「采纳并写入归属」「忽略」按钮可用；
  4. `[键]` Tab 依次聚焦两按钮，Enter 触发；点「采纳并写入归属」→ 命令成功 → `onSaved` 重拉快照 → 建议转为已采纳态、对应 OKR 进入主档树；「忽略」→ 保留并标「已忽略」（可逆语义成立）；
  5. `[刷]` 手动刷新/重进：pending 计数与列表状态与命令行 `/pm okr inbox <pid>` 一致。
- 通过标准：三态不串味；confirm/ignore 走命令通道、成功后刷新闭环；未确认不进主档；失败给出中文错误且不静默。
- 证据：三态截图、命令通道请求/响应日志、刷新前后计数对比。

### A4 收件区透传契约（对 S2）
