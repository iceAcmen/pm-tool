## 键盘交付探针（关键环境事实）
- 在 top document（无 iframe，.pm-shell/.pm-record-row 均在 top doc）window 挂 keydown 探针 window.__k。
- 真实坐标 click_xy(650,300) 中性区 → document.activeElement=BODY。
- 随后 bu.press_key('j') / bu.press_key('k') / bu.press_key(' ') / bu.hotkey('j')：探针捕获 = []（零 keydown 到达 renderer window）。
- 结论：本 Browser Use 栈的 press_key/hotkey 不向该页面 renderer 派发 keydown；无法以原生按键实测 R3-01/02 真实行移动。按纪律 JS dispatch 仅诊断、不算通过，故 R3 真实键盘项不签 PASS。

## 可静态/DOM 观察的事实（不替代真实键盘）
- 纯函数 nextRowId(visibleIds,currentId,delta)：currentId=null→base=0→j 取第二行、k 钳首行（ui-feedback.js:42-49）。
- 门控 shouldHandleGlobalKbd：焦点在 INPUT/TEXTAREA/SELECT/BUTTON/A 或浮层打开时让位（ui-feedback.js:71）——即真实鼠标点行后焦点落在 BUTTON，全局 j/k 会被让位（这本身可能是用户『j/k 无反应』的产品侧原因，待真实键盘环境复验）。
- 行高亮：tr.pm-row-active（+aria-current）；初始列表渲染时 activeId=首行 t-0001。
- 抽屉 input 聚焦时按 k（探针前观察）active 行未移动 → 门控在代码层生效。
